# Angular — интерактивный курс

Интерактивный учебник по **Angular 22** на русском языке. Ученик проходит курс в браузере: слева текст урока, в центре редактор кода с вкладками файлов (`.ts`, `.html`, `.css`), справа живое приложение в iframe с адресной строкой и консолью. Это тот же формат, что у соседнего курса `../pixi-js` (по образцу официальных туториалов angular.dev), и та же платформа, переделанная под Angular.

Сквозной проект курса — **«Ход конём»**, интернет-магазин настольных игр: каталог с поиском и фильтрами, карточка товара, корзина, оформление заказа, вход и личный кабинет, админка. Ученик пишет его с нуля, шаг за шагом. В последней части курса он переносит приложение в настоящий проект Angular CLI и разбирает код настоящего большого приложения на Angular.

## Целевая аудитория

- Хорошо знает JavaScript и TypeScript (классы, модули, async/await, декораторы — хотя бы на уровне «видел», дженерики).
- Знает HTML, CSS и DOM. Может быть знаком с React или Vue, но это не обязательно.
- **Ни разу не писал на Angular.**
- Цель — разобраться в Angular **максимально глубоко**: не только «как сделать», но и «почему так устроено» и «что происходит под капотом» (компилятор, сигналы, обнаружение изменений, DI).

Следствие: основы JS/TS и веба не объясняем; всё, что касается Angular (шаблоны, компилятор, сигналы, DI, роутинг, формы, обнаружение изменений), объясняем подробно, с нуля.

## Ключевые решения

- **Angular 22.2.1** (все пакеты `@angular/*` зафиксированы точно, см. architecture.md). Только современный Angular: standalone-компоненты, сигналы, `input()`/`output()`, `@if`/`@for`, `inject()`, зонлесс. Устаревшие паттерны (`NgModule` в коде приложения, `*ngIf`, `@Input()`, конструкторный DI, zone.js) показываем только в отдельных врезках «Вы встретите в старом коде». Полный список — в `docs/modern-angular.md`.
- **Код ученика выполняется в браузере без сборщика**: TypeScript 6 + JIT-трансформ из `@angular/compiler-cli` в веб-воркере, затем JIT-компилятор Angular в iframe. Проверено прототипом (`spikes/jit-preview`). Отличия JIT от AOT честно объясняем в уроках (глава 1 и часть 3).
- **Язык уроков** — TypeScript, HTML, CSS. Тексты — на русском, идентификаторы в коде — на английском, комментарии в коде — на русском, тексты интерфейса магазина — на русском.
- **Данные** — учебный бэкенд внутри превью (перехват `fetch` по адресам `/api/...`), с задержкой и ошибками, которыми управляет урок. Никаких внешних API.
- **Картинки товаров** — свои SVG-обложки в `public/assets/` (без проблем с лицензиями).
- **Сторонние библиотеки** (RxJS глубже минимума, Angular CDK, Material) появляются только после того, как ученик понял, как то же самое делается средствами самого Angular.
- **NgRx** — отдельная глава 18 в конце части 2 (Signal Store и классический Store), после того как ученик сделал то же самое сервисами на сигналах (глава 9). **Авторизация** — отдельная глава 14 (сессия, токены, интерцептор, 401, гарды, `returnUrl`, роли, обзор refresh-токена, cookie и XSRF).
- **Чего нет в превью** (CLI, AOT-сборка, SSR и гидратация, `ng test`) — изучается в части 3 в настоящем проекте на машине ученика.

## Команды

- `npm run dev` — платформа на **http://localhost:5180** (5173 и 5174 заняты курсом PixiJS)
- `npm run validate` — структура уроков, цепочка start/solution, сборка каждого шага и типы кода (после любых правок в `content/`)
- `npm run build` — проверка типов платформы и продакшен-сборка
- `npm run covers` — пересоздать SVG-обложки после изменения `public/backend/data/games.json`
- `node tools/e2e/run-dir.mjs <папка шага> [адрес] [мс]` — код шага в чистом превью: консоль, запросы, адрес, текст страницы, скриншот в `tools/e2e/out/`
- `node tools/e2e/run-chapter.mjs <папка главы>` — все шаги главы в интерфейсе платформы с «Решением»
- `node tools/e2e/exp.mjs <папка> <сценарий.mjs> [адрес]` — эксперимент из текста урока со своим сценарием действий
- `node tools/e2e/checks/platform.mjs` и `checks/ch00-sandbox.mjs` — проверки платформы (после любых правок в `src/`, `public/`, `shared/`); `checks/ch02-templates.mjs`, `checks/ch03-signals.mjs`, `checks/ch04-control-flow.mjs`, `checks/ch05-components.mjs` — проверки глав 2–5
- Все проверки требуют запущенного `npm run dev` и Chrome (`CHROME_PATH`, по умолчанию путь macOS). Другой адрес — `BASE_URL=http://localhost:5181`

## Как работать над уроками

1. Найти шаг в `docs/course-plan.md`, проверить, какие API и понятия он вводит и что уже известно ученику из предыдущих шагов.
2. Писать по `docs/writing-guide.md`; термины — строго по `docs/glossary.md` (новый термин сначала добавить в словарь).
3. Старт шага N+1 — решение шага N (`startFrom: previous`), и **папку `start/` для него не создаём**: платформа, валидатор и `tools/e2e` берут старт из предыдущего шага. Своя `start/` — только у шагов `startFrom: custom` (первый шаг главы, заготовки с `TODO`). Генераторы пишут шаги через `write_steps` из `tools/authoring/steps.py` — он соблюдает это правило сам.
4. Решение каждого шага должно запускаться без ошибок и давать видимый результат. После правок — `npm run validate`.
5. **Проверять факты об API по типам и исходникам установленной версии `@angular/*`, а не по памяти**: в интернете и в памяти модели много Angular 2–17 (NgModule, zone.js, `@Input`, `*ngIf`). Уже выяснилось, что в v22 OnPush — стратегия по умолчанию, зонлесс включён по умолчанию, появился декоратор `@Service()`, `withFetch` устарел — см. `docs/modern-angular.md`.
6. Каждое утверждение и каждый эксперимент из текста урока проверять запуском кода (`tools/e2e/run-dir.mjs`). Полный процесс — в `docs/authoring-process.md`.
