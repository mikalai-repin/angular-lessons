Шаблон в строке внутри `app.ts` удобен, пока он в две строки. Но у магазина будут шаблоны на десятки строк, и писать HTML внутри TypeScript неудобно: редактор не подсветит разметку и не подскажет теги. Поэтому в проектах на Angular шаблон и стили компонента обычно лежат в отдельных файлах рядом с классом.

В шаге появились новые файлы (откройте их через вкладки или «☰ Файлы»):

- `app.html` — пока только комментарий с заданием;
- `app.css` — готовые стили шапки магазина;
- `styles.css` — общие стили всего магазина: цвета, шрифт, кнопки.

## `templateUrl` и `styleUrl`

Вместо `template` в метаданных указываем путь к файлу шаблона, а стили подключаем через `styleUrl`:

```ts app.ts {5-6}
import { Component } from '@angular/core';

@Component({
  selector: 'app-root',
  templateUrl: './app.html',
  styleUrl: './app.css',
})
export class App {}
```

Пути — относительно файла компонента, как в `import`. Именно так выглядит `app.ts`, который создаёт Angular CLI: три файла одного компонента лежат рядом и называются одинаково — `app.ts`, `app.html`, `app.css`.

Шаблон магазина теперь посложнее — шапка и основная часть:

```html app.html
<header class="header">
  <span class="logo">♞ Ход конём</span>
</header>
<main class="page">
  <h1>Магазин настольных игр</h1>
  <p class="muted">Скоро здесь появится каталог.</p>
</main>
```

::: task
1. Перенесите шаблон в `app.html` — разметку выше (вместо комментария с заданием).
2. В `app.ts` замените `template` на `templateUrl: './app.html'` и добавьте `styleUrl: './app.css'`.
:::

## Что получилось

У магазина появилась красная шапка с логотипом, а заголовок стал фирменного цвета. Посмотрите в `app.html`: в редакторе разметка подсвечивается, а при вводе `<` появляются подсказки тегов.

::: tip
Если ошибиться в имени файла, например написать `'./app2.html'`, в консоли появится ошибка с меткой «Сборка»: файл не найден. В настоящем проекте такую ошибку покажет Angular CLI при сборке.
:::

## Стили компонента и глобальные стили

Стили лежат в двух местах, и это не случайно.

**Глобальные стили** — `styles.css` — действуют на всю страницу. В проекте Angular CLI файл с тем же именем лежит в `src/` и подключается в настройках сборки. Сюда кладут то, что нужно везде: переменные цветов, шрифт, общие классы вроде `.button`.

**Стили компонента** — `app.css` — действуют **только на шаблон этого компонента**. В `app.css` есть правило `h1 { color: var(--brand); }`. Оно перекрасит заголовки в шаблоне `App`, но не тронет `<h1>` в других компонентах, даже если они окажутся внутри `App`. Это называется **инкапсуляцией стилей**: каждый компонент может называть классы как угодно и не бояться, что стили «протекут» к соседям.

В курсе мы будем держать общий вид магазина в `styles.css`, а в стилях компонентов — только то, что относится к самому компоненту.

::: deep Под капотом: как Angular изолирует стили
В браузере нет встроенного способа «применить CSS только к этому куску разметки» (кроме Shadow DOM, о нём ниже). Angular добивается изоляции переписыванием. Добавьте в `main.ts` вывод готовой разметки — замените `.then(...)` на:

```ts main.ts
.then(() => console.log(document.querySelector('app-root')!.outerHTML))
```

В консоли окажется (переносы строк добавлены для читаемости):

```html
<app-root ng-version="22.2.1" _nghost-ng-c2047075213="">
  <header _ngcontent-ng-c2047075213="" class="header">
    <span _ngcontent-ng-c2047075213="" class="logo">♞ Ход конём</span>
  </header>
  ...
```

Каждый элемент шаблона получил атрибут `_ngcontent-ng-c…` с меткой компонента, а хост-элемент — `_nghost-ng-c…`. Число в конце у вас может быть другим. Стили из `app.css` Angular переписал и вставил в `<head>`:

```css
.header[_ngcontent-ng-c2047075213] { … }
h1[_ngcontent-ng-c2047075213] { color: var(--brand); }
```

Теперь правило для `h1` срабатывает только у заголовков с меткой этого компонента. А `styles.css` попал в страницу без изменений, поэтому действует везде.

Такой режим называется `ViewEncapsulation.Emulated` и включён по умолчанию. Есть ещё `ShadowDom` (настоящий Shadow DOM браузера) и `None` (без изоляции) — мы вернёмся к ним в главе про компоненты.
:::
