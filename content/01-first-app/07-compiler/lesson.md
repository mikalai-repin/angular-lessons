В первом шаге мы сказали, что Angular превращает шаблон в JavaScript. Этот шаг — необязательный взгляд под капот: посмотрим на этот код своими глазами. Для работы с Angular знать его не нужно, но с ним многое в следующих главах станет понятнее: почему шаблон — не HTML, почему Angular быстро обновляет страницу и чем превью отличается от настоящего проекта.

## Что компилятор сделал с `App`

Скомпилированный компонент хранит своё описание в статическом поле `ɵcmp` класса. Буква `ɵ` (греческая «тета») в начале имени — соглашение Angular: это **внутреннее** API, оно может меняться между версиями, и в коде приложения его не используют. Но для исследования — можно.

::: task
Добавьте в `main.ts` ещё один `.then` перед `.catch`, который выводит функцию шаблона:

```ts main.ts {3}
bootstrapApplication(App, appConfig)
  .then((appRef) => console.log('Магазин запущен. Корневых компонентов:', appRef.components.length))
  .then(() => console.log(String((App as any).ɵcmp.template)))
  .catch((err) => console.error(err));
```

`as any` нужен, потому что в типах класса `App` поля `ɵcmp` нет: его добавляет компилятор.
:::

В консоли появится функция:

```js
function App_Template(rf, ctx) {
  if (rf & 1) {
    jit___domElementStart_2(0,'header',0)(1,'span',1);
    jit___text_3(2,'♞ Ход конём');
    jit___domElementEnd_4()();
    jit___domElementStart_2(3,'main',2)(4,'h1');
    jit___text_3(5,'Магазин настольных игр');
    jit___domElementEnd_4();
    jit___domElementStart_2(6,'p',3);
    jit___text_3(7,'Скоро здесь появится каталог.');
    jit___domElementEnd_4()();
  }
}
```

Это и есть наш `app.html`, только записанный как последовательность команд — **инструкций**:

- `domElementStart(3, 'main', 2)` — создать элемент `<main>` и сделать его текущим родителем;
- `text(5, 'Магазин настольных игр')` — создать текстовый узел;
- `domElementEnd()` — закрыть текущий элемент и вернуться к родителю.

Первое число в каждой инструкции — номер узла (0, 1, 2…): Angular запоминает все созданные узлы в массиве и потом обращается к ним по номеру. Последнее число в `domElementStart` — номер набора атрибутов. Сами атрибуты лежат рядом, в `ɵcmp.consts`:

```js
[[1, 'header'], [1, 'logo'], [1, 'page'], [1, 'muted']]
```

Это классы `header`, `logo`, `page`, `muted` (`1` — пометка «дальше идут классы»). Инструкции можно вызывать цепочкой: `domElementStart(0,'header',0)(1,'span',1)` — два вызова подряд, так код получается короче.

Префикс `jit___` и номера в конце имён добавил JIT-компилятор: так он называет функции Angular, которые передаёт в сгенерированный код.

## Два режима: создание и обновление

Вся функция — внутри `if (rf & 1)`. `rf` — флаги отрисовки: `1` означает **создание** — первый раз построить элементы. У шаблона бывает и второй блок, `if (rf & 2)` — **обновление**: в нём Angular обновляет только то, что зависит от данных.

У нас данных в шаблоне нет, поэтому второго блока нет. В следующей главе мы выведем в шаблоне значение из класса — например `<h1>{{ title }}</h1>` — и появится:

```js
if (rf & 2) {
  advance();
  textInterpolate(ctx.title);
}
```

`ctx` — экземпляр компонента. При изменении данных Angular не перестраивает страницу и не сравнивает HTML: он вызывает функцию шаблона в режиме обновления, и та меняет ровно один текстовый узел. Отсюда скорость Angular и отсюда же ограничения шаблонов, о которых пойдёт речь в следующей главе.

## JIT в превью и AOT в проекте

В превью шаблон компилирует JIT-компилятор, прямо в браузере, при первом обращении к `App.ɵcmp` во время `bootstrapApplication`. В настоящем проекте Angular CLI это делает AOT-компилятор при сборке. Мы скомпилировали `app.ts` из этого шага настоящим AOT-компилятором (`ngc` из Angular 22.2.1) — получилось вот что (сокращено):

```js
export class App {
  static ɵcmp = i0.ɵɵdefineComponent({
    type: App,
    selectors: [['app-root']],
    decls: 8,
    vars: 0,
    consts: [[1, 'header'], [1, 'logo'], [1, 'page'], [1, 'muted']],
    template: function App_Template(rf, ctx) {
      if (rf & 1) {
        i0.ɵɵdomElementStart(0, 'header', 0)(1, 'span', 1);
        i0.ɵɵtext(2, '♞ Ход конём');
        // …то же, что в JIT
      }
    },
    styles: ['\n.header[_ngcontent-%COMP%] { … }'],
  });
}
```

Функция шаблона — та же самая, инструкция в инструкцию. Разница в том, **когда** она появляется:

- в AOT декоратора `@Component` в собранном коде уже нет: компилятор заменил его готовым полем `ɵcmp`. Браузер не тратит время на компиляцию, а сам компилятор Angular не попадает в приложение — оно меньше;
- стили тоже обработаны при сборке: `[_ngcontent-%COMP%]` — заготовка, в которую при запуске подставится метка компонента;
- ошибки в шаблонах AOT находит при сборке, а не у пользователя в браузере.

Поэтому настоящие приложения всегда собираются в AOT, а JIT остался для особых случаев — например, для интерактивных учебников вроде этого.

`decls: 8` — сколько узлов создаёт шаблон (8 номеров, от 0 до 7), `vars: 0` — сколько значений из данных он отслеживает. После `{{ title }}` будет `vars: 1`.

::: tip
Уберите добавленный `.then`: дальше он не понадобится. В следующей главе мы начнём выводить в шаблоне данные и обрабатывать действия пользователя.
:::
