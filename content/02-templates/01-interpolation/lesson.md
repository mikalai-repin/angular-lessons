В первой главе шаблон магазина был просто разметкой: что написано в `app.html`, то и на экране. Настоящий магазин так не работает: название, цена, наличие приходят из данных, а кнопки должны что-то делать. В этой главе мы свяжем класс компонента с шаблоном в обе стороны: данные класса попадут в разметку, а действия пользователя — в методы класса.

К концу главы у вас будет карточка игры, целиком построенная из данных:

```
┌─────────┐  Остров сокровищ
│         │  ★★★★★
│ обложка │  Игроков: 2–5 · 45 мин · 8+
│         │  1990 ₽  2490 ₽  −20 %
│         │  Описание с разметкой…
└─────────┘  [ В корзину ]
```

Обложка, рейтинг, старая цена и скидка, серая карточка для игры, которой нет в наличии, кнопка «В корзину» и поле поиска. Всё это — привязки (bindings): способы сказать Angular, какая часть страницы от чего зависит.

## Что изменилось в коде

Мы продолжаем с того места, где закончилась первая глава. Три отличия:

- `main.ts` теперь такой же, как в новом проекте Angular CLI: `bootstrapApplication(App, appConfig).catch(...)`. Вывод числа компонентов в консоль больше не нужен;
- в `app.html` появилась карточка игры. Пока это обычная разметка: название и цена вписаны прямо в HTML;
- в `app.css` — готовые стили всего, что мы сделаем в этой главе: карточки, рейтинга, скидки, поля поиска.

## Интерполяция

Название игры не должно быть вписано в шаблон: завтра это будет другая игра. Пусть оно хранится в классе компонента:

```ts app.ts {9-10}
import { Component } from '@angular/core';

@Component({
  selector: 'app-root',
  templateUrl: './app.html',
  styleUrl: './app.css',
})
export class App {
  protected readonly title = 'Остров сокровищ';
  protected readonly price = 1990;
}
```

А в шаблоне на месте текста напишем имя поля в двойных фигурных скобках:

```html app.html {4,5}
<article class="card">
  <img class="cover" src="/assets/covers/treasure-island.svg" alt="Остров сокровищ" />
  <div class="body">
    <h2 class="title">{{ title }}</h2>
    <p class="price">{{ price }} ₽</p>
    <button class="button">В корзину</button>
  </div>
</article>
```

Это **интерполяция** (interpolation). Angular вычисляет то, что стоит внутри `{{ }}`, превращает результат в строку и вставляет в текст. Откуда он берёт `title`? Из экземпляра класса `App`, который сам создал при запуске. Для шаблона этот экземпляр — **контекст**: любое имя в шаблоне ищется среди его полей и методов.

Два слова перед полями:

- `protected` — поле нужно только шаблону, а не другому коду. Так советует руководство по стилю Angular: публичные члены класса — это его API для других частей приложения, а то, что читает только шаблон, помечают `protected`;
- `readonly` — значение не меняется. В следующей главе мы увидим, как меняющиеся данные оформляют иначе.

::: task
1. Добавьте в класс `App` поля `title` и `price`, как в коде выше.
2. В `app.html` замените название и цену в карточке на `{{ title }}` и `{{ price }}`. Комментарий с заданием можно удалить.
:::

## Что получилось

Внешне ничего не изменилось — и это хорошо: карточка та же, но теперь название и цена приходят из класса. Поменяйте `price` на `1790`: после пересборки цена в карточке тоже станет другой.

## Выражения шаблона

Внутри `{{ }}` можно писать не только имя поля, а **выражение шаблона** (template expression) — почти как выражение в JavaScript. Попробуйте по очереди:

```html
<p>{{ price * 2 }}</p>                              <!-- 3980 -->
<p>{{ title.toUpperCase() }}</p>                    <!-- ОСТРОВ СОКРОВИЩ -->
<p>{{ price > 1500 ? 'дорого' : 'недорого' }}</p>   <!-- дорого -->
<p>{{ `Цена: ${price} ₽` }}</p>                     <!-- Цена: 1990 ₽ -->
```

Работают арифметика, сравнения, тернарный оператор, вызовы методов, `?.` и `??`, шаблонные строки, `typeof`. Результат превращается в строку по своим правилам: `undefined` и `null` выводятся как пустая строка, `false` — как `false`, объект — как `[object Object]`.

Но выражение шаблона — не любой JavaScript. Вот что компилятор шаблонов **не пропустит**:

| Нельзя | Пример | Что будет |
|---|---|---|
| Присваивания | `{{ price = 5 }}`, `{{ price += 1 }}` | `Bindings cannot contain assignments` |
| `++` и `--` | `{{ price++ }}` | `Unexpected end of expression` |
| `new` | `{{ new Date() }}` | `Unexpected token 'Date'` |
| Несколько выражений через `;` | `{{ price; title }}` | `Binding expression cannot contain chained expression` |
| Побитовые операторы | `{{ price & 1 }}` | `Unexpected token '&'` |

Знак `|` тоже не «побитовое ИЛИ»: в шаблонах это пайп, о них — в главе 7.

Отдельная история — глобальные объекты. Напишите `{{ Math.round(4.6) }}`: страница опустеет, а в консоли появится:

```
ERROR TypeError: Cannot read properties of undefined (reading 'round')
```

`Math` для шаблона — это не глобальный объект, а поле `Math` компонента, а такого поля нет, значит, `undefined`. То же самое с `window`, `console`, `JSON`: шаблон видит только свой контекст — экземпляр компонента. Почему так сделано, разберёмся в последнем шаге главы, когда заглянем в скомпилированный шаблон.

::: tip
Правило на практике: выражения в шаблоне — короткие и без побочных эффектов. Всё, что сложнее одной строки, — в метод или поле класса. Там работает TypeScript, там удобно тестировать.
:::

## Как в настоящем проекте

В превью шаблон компилируется в браузере, и ошибка с `Math` видна только во время работы. В проекте Angular CLI шаблоны проверяет TypeScript при сборке. Мы скомпилировали такой шаблон настоящим AOT-компилятором — он остановил сборку:

```
error TS2339: Property 'Math' does not exist on type 'App'.
```

Обратите внимание на формулировку: компилятор ищет `Math` именно в типе `App`.

::: legacy Вы встретите в старых статьях: «в шаблоне так нельзя»
Синтаксис выражений шаблона постепенно расширяется. В старых статьях можно прочитать, что в шаблоне нельзя использовать шаблонные строки или `typeof` и для этого нужен метод в классе. В старых версиях Angular так и было, но в Angular 22 всё это работает прямо в шаблоне — мы проверили.
:::
