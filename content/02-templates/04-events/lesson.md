Данные из класса уже попадают в шаблон. Теперь обратное направление: пользователь нажимает кнопку или клавишу, и об этом должен узнать класс. Кнопка «В корзину» пока ничего не делает, а поиска нет вовсе. Исправим оба.

## `(событие)="обработчик"`

**Привязка события** (event binding) записывается в круглых скобках:

```html app.html
<button class="button" [disabled]="inStock === 0" (click)="addToCart()">В корзину</button>
```

```ts app.ts
protected addToCart() {
  console.log('Добавлено в корзину:', this.title);
}
```

Слева в скобках — имя события DOM (`click`, `input`, `keydown`, `submit`, `focus`…), справа — **обработчик в шаблоне** (template statement). Когда событие происходит, Angular выполняет обработчик в контексте компонента: `addToCart()` — это метод экземпляра `App`.

Удобно запомнить по направлению: квадратные скобки `[ ]` — данные идут из класса в элемент, круглые `( )` — событие идёт из элемента в класс.

Обработчик в шаблоне похож на выражение, но правила у него мягче: в нём можно присваивать (`(click)="selected = true"`). Но лучше, чтобы обработчик был одним вызовом метода, а логика жила в классе. Метод называйте по тому, **что он делает**, — `addToCart`, а не `onClick` или `handleClick`: так советует руководство по стилю Angular, и шаблон читается как описание поведения.

## `$event` — объект события

Добавим поле поиска. Искать будем по Enter:

```html app.html {2}
<h1>Магазин настольных игр</h1>
<input class="search" type="search" placeholder="Найти игру" (keydown.enter)="search($event)" />
```

```ts app.ts
protected search(event: Event) {
  const input = event.target as HTMLInputElement;
  console.log('Ищем:', input.value);
}
```

Здесь две новых вещи.

**`$event`** — специальное имя, которое доступно только в обработчике события. Это объект события DOM — тот же, что получает обычный `addEventListener`. Для `click` это `MouseEvent`, для `keydown` — `KeyboardEvent`. Через `event.target` мы добираемся до поля ввода и читаем `value`. Приведение `as HTMLInputElement` нужно, потому что для TypeScript `event.target` — какой-то `EventTarget`, у которого нет `value`.

**`.enter`** — **фильтр клавиш** (key event filter). `(keydown)` срабатывал бы на каждую клавишу, а `(keydown.enter)` — только на Enter. Мы проверили и другие варианты: `(keydown.escape)`, `(keydown.shift.enter)` — Enter с зажатым Shift. Причём обычный `(keydown.enter)` на Shift+Enter **не** срабатывает: фильтр учитывает и клавиши-модификаторы.

2. Добавьте под заголовком `<h1>` поле поиска с привязкой `(keydown.enter)="search($event)"` и метод `search` в класс.

## Что получилось

Нажмите «В корзину» — в консоли появится `Добавлено в корзину: Остров сокровищ`. Наберите в поиске «шахматы» и нажмите Enter — `Ищем: шахматы`. Пока набираете, консоль молчит: обработчик срабатывает только на Enter.

Поставьте `inStock = 0` и попробуйте нажать кнопку: неактивная кнопка не генерирует событие `click`, поэтому в консоли ничего не появится. Верните `12`.

## Эксперименты

- Замените `(keydown.enter)` на `(input)`: метод `search` будет вызываться на каждую букву, и в консоли окажутся `ш`, `ша`, `шах`…
- Замените `(click)` на `(dblclick)`: товар добавится только по двойному щелчку.
- Напишите имя метода с ошибкой: `(click)="addToKart()"`. Пока вы не нажмёте кнопку, ничего не случится, а при нажатии появится `ERROR TypeError: ctx.addToKart is not a function`. Обратите внимание на `ctx.` — к этому имени мы вернёмся в последнем шаге главы. Верните `addToCart`.

::: deep Под капотом: кто снимает обработчик
Angular вешает обработчик на элемент обычным `addEventListener`. Писать `removeEventListener` не нужно: когда элемент исчезает со страницы (например, вместе с компонентом), Angular снимает обработчик сам. В обычном DOM-коде забытые обработчики — частая причина утечек памяти, в шаблонах Angular такой проблемы нет.
:::
