Пора собрать всё вместе. Сейчас данные карточки разбросаны по семи отдельным полям класса, и показать другую игру можно, только переписав их все. В настоящем магазине игра — это один объект с данными, и карточка должна уметь показать **любую** игру.

В шаге появились два файла в папке `core/`:

- `core/models.ts` — интерфейс `Game`: какие поля есть у игры в нашем магазине;
- `core/games-data.ts` — массив `GAMES` с двенадцатью играми. Позже они будут приходить с сервера, а пока лежат прямо в коде.

В `app.ts` уже импортирован `GAMES`.

::: task
1. Замените семь полей с данными одним полем `protected readonly game = GAMES[0];` и переведите шаблон на него: `game.title`, `game.cover` и так далее. Метод `addToCart` тоже должен брать название из `game`.
2. Под рейтингом добавьте строку характеристик: `Игроков: 2–5 · 45 мин · 8+`. Всё — из данных игры (`players`, `playTime`, `age`; посмотрите их типы в `core/models.ts`).
3. Если игры нет в наличии, на кнопке должно быть написано «Нет в наличии» вместо «В корзину».
4. Старая цена и бейдж скидки показываются, только если у игры есть `oldPrice`.
5. Проверьте карточку на игре `GAMES[6]` («Маяк»): её нет в наличии, и скидки у неё нет. Потом верните `GAMES[0]`.
:::

::: hint Подсказка 1: с чего начать
Начните с класса: удалите поля и добавьте `game`. Превью покажет пустую карточку (или ошибки в консоли) — это нормально. Потом идите по шаблону сверху вниз и добавляйте `game.` к каждому имени. Удобно искать по `{{` и `="`.
:::

::: hint Подсказка 2: характеристики и текст кнопки
`players` — объект `{ min, max }`, поэтому в шаблоне будет `game.players.min` и `game.players.max`. Для текста кнопки подойдёт тернарный оператор внутри интерполяции: `{{ условие ? 'один текст' : 'другой' }}`. Условие у вас уже есть в `@let`.
:::

::: hint Подсказка 3: как скрыть старую цену
Управляющих блоков вроде «если» мы ещё не проходили (они будут в главе 4), но есть знакомая привязка `[hidden]`. Оберните старую цену и бейдж в `<span [hidden]="!game.oldPrice">`. Не ставьте `[hidden]` прямо на `.badge`: у этого класса может появиться свой `display` в CSS, и тогда он перекроет `hidden`.
:::

::: hint Подсказка 4: скидка, когда старой цены нет
В интерфейсе `oldPrice?: number` — поле необязательное. Выражение `game.price / game.oldPrice` для игры без скидки даст `NaN`, а проверка шаблонов в настоящем проекте не пропустит деление на возможный `undefined`. Защитите вычисление: `@let discount = game.oldPrice ? (…) : 0;`
:::

## Проверьте себя

- Карточка «Острова сокровищ» выглядит как в начале шага, плюс строка `Игроков: 2–5 · 45 мин · 8+`.
- С `GAMES[6]`: «Маяк», серая обложка, нет старой цены и бейджа, кнопка «Нет в наличии» неактивна.
- «В корзину» пишет в консоль название текущей игры.
- Консоль без ошибок. Поиск работает как прежде.

Попробуйте и другие игры: `GAMES[3]` («Ночной экспресс») со скидкой, `GAMES[7]` (шахматы) — у них «Игроков: 2–2». Выглядит странно, правда? Когда в главе 7 мы будем делать пайпы, научим карточку писать «2 игрока».

::: deep Почему `@let` для `soldOut` стал ещё полезнее
Посчитайте, сколько раз шаблон зависит от наличия: класс карточки, `disabled` у кнопки, текст кнопки. Без `@let` это было бы три копии `game.inStock === 0`. С `@let soldOut` — одна.
:::

## Итоги главы

Теперь вы умеете связывать класс компонента с шаблоном:

| Запись | Что делает | Направление |
|---|---|---|
| `{{ выражение }}` | интерполяция: текст из выражения | класс → страница |
| `[свойство]="…"` | привязка свойства DOM | класс → страница |
| `[attr.имя]="…"` | привязка атрибута HTML | класс → страница |
| `[class.имя]="…"`, `[style.свойство.ед]="…"` | привязка класса и стиля | класс → страница |
| `(событие)="…"` | привязка события, `$event`, фильтры клавиш | страница → класс |
| `#имя` | ссылка на элемент в шаблоне | внутри шаблона |
| `@let имя = …;` | переменная шаблона | внутри шаблона |

И несколько важных идей:

- выражения шаблона — не JavaScript целиком: без присваиваний, без `new`, без глобальных объектов. Имена ищутся в экземпляре компонента;
- привязки пишут в **свойства** DOM, а не в атрибуты;
- интерполяция всегда вставляет текст, а `[innerHTML]` проходит санитизацию — защита от XSS по умолчанию;
- Angular не следит за данными сам: шаблон перепроверяется в определённые моменты, например после события с обработчиком в шаблоне.

Последняя идея — главная загадка, которую мы оставили открытой. Все данные карточки пока неизменны. Что будет, если добавить счётчик «В корзине: N», который растёт при нажатии кнопки, — или данные, которые меняются без всяких событий? Это тема следующей главы — **сигналы**. А перед ней — необязательный шаг «под капот»: посмотрим, во что компилятор превратил все привязки этой главы.
