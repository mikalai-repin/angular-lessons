В первой главе мы заглянули в скомпилированный шаблон, и там был только блок создания: `if (rf & 1)`. Теперь в шаблоне есть данные, события, ссылки и переменные. Посмотрим, во что компилятор их превратил, — и найдём ответы на вопросы, которые копились всю главу: почему в шаблоне нет `Math` и `window`, почему нельзя присваивать и как Angular узнаёт, когда перепроверить шаблон.

Как и в главе 1, этот шаг необязательный: для работы с Angular знать это не нужно.

## Блок обновления

Функция длинная. Блок создания (`rf & 1`) похож на тот, что был в главе 1: создать элементы, добавить текст. Самое интересное — второй блок, `rf & 2`. Вот он, без префиксов `jit___` и номеров:

```js
if (rf & 2) {
  var searchBox_r2 = reference(7);
  advance(8);
  domProperty('hidden', !searchBox_r2.value);
  advance();
  textInterpolate1('Ищем: «', searchBox_r2.value, '»');
  var soldOut_r3 = (ctx.game.inStock === 0);
  var discount_r4 = (ctx.game.oldPrice ? ((1 - (ctx.game.price / ctx.game.oldPrice)) * 100).toFixed(0) : 0);
  advance();
  classProp('sold-out', soldOut_r3);
  advance();
  domProperty('src', ctx.game.cover, sanitizeUrl)('alt', ctx.game.title);
  advance(3);
  textInterpolate(ctx.game.title);
  advance();
  attribute('aria-label', (('Рейтинг: ' + ctx.game.rating) + ' из 5'));
  advance();
  styleProp('width', ((ctx.game.rating / 5) * 100), '%');
  // …
  domProperty('innerHTML', ctx.game.description, sanitizeHtml);
  advance();
  domProperty('disabled', soldOut_r3);
  // …
}
```

Каждая привязка главы стала одной инструкцией:

| В шаблоне | В функции шаблона |
|---|---|
| `{{ game.title }}` | `textInterpolate(ctx.game.title)` |
| `Ищем: «{{ searchBox.value }}»` | `textInterpolate1('Ищем: «', …, '»')` — постоянный текст склеивается с выражением |
| `[src]="game.cover"` | `domProperty('src', ctx.game.cover, sanitizeUrl)` — с проверкой URL |
| `[innerHTML]="…"` | `domProperty('innerHTML', …, sanitizeHtml)` — та самая санитизация |
| `[attr.aria-label]="…"` | `attribute('aria-label', …)` |
| `[class.sold-out]="soldOut"` | `classProp('sold-out', soldOut_r3)` |
| `[style.width.%]="…"` | `styleProp('width', …, '%')` |
| `@let soldOut = …;` | `var soldOut_r3 = …` — обычная переменная |
| `#searchBox` | `reference(7)` — элемент с номером 7 |

`advance(n)` переводит «курсор» на n-й следующий узел — к тому элементу, к которому относятся следующие привязки.

## Откуда берётся `ctx`

Посмотрите на имена: везде `ctx.game`, `ctx.addToCart`. `ctx` — второй параметр функции шаблона, **контекст шаблона**: экземпляр компонента `App`. Компилятор делает с каждым именем в выражении простую вещь:

- если это переменная шаблона (`@let`, `#ссылка`, `$event`) — берёт её;
- иначе дописывает `ctx.`.

Теперь понятно, что случилось с `{{ Math.round(4.6) }}` в первом шаге: компилятор превратил его в `ctx.Math.round(4.6)`. У `App` нет поля `Math` — отсюда `Cannot read properties of undefined (reading 'round')`. И ошибка `ctx.addToKart is not a function` из шага про события — та же история. Шаблон не может случайно залезть в глобальные объекты страницы: он видит только свой компонент. Если шаблону действительно нужно что-то глобальное, это делают через поле класса.

## Почему в выражениях нельзя присваивать

Блок обновления выполняется **каждый раз**, когда Angular проверяет компонент. И каждая инструкция работает так: вычислить новое значение, сравнить с запомненным с прошлого раза и тронуть DOM, только если оно изменилось. Поэтому Angular быстр: при проверке он не перерисовывает страницу, а сравнивает значения.

Отсюда требование к выражениям: они должны быть **чистыми** — без побочных эффектов. Выражение, которое что-то меняет, при каждой проверке меняло бы данные снова, и результат зависел бы от того, сколько раз и в каком порядке Angular проверял шаблон. Поэтому компилятор запрещает присваивания, `++` и прочее в привязках.

Убедитесь, что выражения действительно вычисляются при каждой проверке. Добавьте в класс метод:

```ts app.ts
protected priceLabel() {
  console.log('priceLabel()');
  return `${this.game.price} ₽`;
}
```

и замените в шаблоне `{{ game.price }} ₽` на `{{ priceLabel() }}`. При запуске в консоли один вызов. Нажмите «В корзину» — ещё один, хотя цена не менялась. А пока вы печатаете в поиске — ни одного. Поэтому методы в шаблоне должны быть дешёвыми, а лучше — не вычислять там ничего тяжёлого. Верните `{{ game.price }} ₽`.

## Обработчики событий

Обработчики компилятор превращает в функции внутри блока создания:

```js
domListener('click', function App_Template_button_click_27_listener() {
  return ctx.addToCart();
});
```

У обработчика `keydown.enter` внутри появится ещё `reference(7)` — так он получает `searchBox`. А если бы мы написали `$event`, у функции появился бы параметр `$event` — объект события.

Почему же после клика Angular перепроверяет шаблон? Angular оборачивает каждый обработчик. Мы заглянули в исходники `@angular/core` 22.2.1: обёртка называется `wrapListenerIn_markDirtyAndPreventDefault` и **до** вызова вашего метода помечает представление компонента как «грязное» — требующее проверки. После этого Angular планирует проверку, и блок обновления выполняется заново. Отсюда загадка шага про ссылки: пока не сработал ни один обработчик, никто не помечал компонент, и шаблон не перепроверялся.

## Что дальше

Пометка «грязный» после события — лишь один из способов сообщить Angular об изменениях, и самый ограниченный: он ничего не знает о том, **какие** данные поменялись. В следующей главе вы познакомитесь с сигналами — значениями, которые сами сообщают Angular о каждом своём изменении.
