До сих пор данные карточки не менялись: игра одна, цена одна. В настоящем магазине всё время что-то меняется: покупатель добавляет игры в корзину, переключает товары, сервер присылает ответы. Эта глава о том, как Angular узнаёт об изменениях и обновляет страницу. Ответ — **сигналы** (signals), главное, что появилось в Angular за последние годы.

К концу главы у магазина будет корзина:

Переключатель игр, выбор количества, счётчик и сумма в шапке, мини-корзина с итогом и бесплатной доставкой. И всё это без единой строки, которая вручную обновляет страницу.

## Что изменилось в коде

Мы продолжаем с практикума второй главы. Два отличия:

- в шапке справа появилась надпись «В корзине: 0». Пока это просто текст;
- в `app.css` — готовые стили всего, что мы сделаем в главе: шапки, переключателя, кнопок количества, мини-корзины.

## Счётчик в шапке

Начнём с простого: пусть кнопка «В корзину» увеличивает счётчик в шапке. Заведём поле и будем увеличивать его в обработчике:

```ts app.ts {1,4}
protected cartCount = 0;

protected addToCart() {
  this.cartCount++;
}
```

```html app.html {3}
<header class="header">
  <span class="logo">♞ Ход конём</span>
  <span class="cart">В корзине: {{ cartCount }}</span>
</header>
```

Поле без `readonly`: его значение меняется.

::: task
1. Добавьте в класс поле `cartCount` и увеличивайте его в `addToCart` вместо вывода в консоль.
2. Выведите `cartCount` в шапке вместо `0`.
3. Понажимайте «В корзину».
:::

Счётчик растёт с каждым нажатием. Вы уже знаете почему (шаг про ссылки на элементы, глава 2): обработчик события в шаблоне помечает компонент для проверки, и после него Angular заново вычисляет выражения шаблона.

## Ответ сервера

В настоящем магазине кнопка «В корзину» отправляет запрос на сервер, и счётчик меняется, когда приходит ответ. Сервера у нас пока нет (он появится в главе 11), поэтому изобразим задержку таймером:

```ts app.ts {1-2,9-13}
// Через сколько миллисекунд «сервер» подтверждает добавление в корзину
const SERVER_DELAY = 500;

// … @Component и начало класса App …

protected cartCount = 0;

protected addToCart() {
  // Как будто ждём ответа сервера: счётчик меняется не сразу
  setTimeout(() => {
    this.cartCount++;
    console.log('В корзине:', this.cartCount);
  }, SERVER_DELAY);
}
```

Константа `SERVER_DELAY` — над декоратором `@Component`, рядом с импортами.

::: task
Оберните увеличение счётчика в `setTimeout`, как в коде выше, и снова понажимайте «В корзину».
:::

## Что получилось

Счётчик сломался. Нажмите «В корзину» один раз: через полсекунды в консоли `В корзине: 1`, а в шапке по-прежнему `0`. Нажмите ещё раз: в шапке `1`, в консоли — `2`. Экран всё время отстаёт на одно нажатие.

Наберите что-нибудь в поиске — счётчик не обновится. А при следующем клике по «В корзину» в шапке появится значение, которое на самом деле стало верным ещё полсекунды назад.

## Почему так

Angular **не следит** за полями класса. Он не знает, что `cartCount` изменилось. Вместо этого он перепроверяет шаблон, когда его об этом попросят. До сих пор просил только обработчик события в шаблоне. Посмотрим, что происходит по времени:

```
клик
├─ компонент помечен «проверить»
├─ addToCart() ставит таймер
└─ проверка: cartCount = 0 → на экране 0
        … 500 мс …
таймер
└─ cartCount = 1, проверку никто
   не запросил → на экране по-прежнему 0
клик
├─ компонент помечен «проверить»
├─ addToCart() ставит таймер
└─ проверка: cartCount = 1 → на экране 1
```

Проверка после клика выполняется сразу, когда таймер ещё не сработал. А когда он срабатывает и меняет поле, проверку никто не запрашивает. Набор в поиске тоже не помогает: обработчик `(keydown.enter)` ждёт только Enter.

Так Angular устроен намеренно. Это называется **зонлесс** (zoneless): Angular не перехватывает таймеры, запросы и прочие асинхронные операции браузера. Он делает проверку, только когда ему явно сообщили об изменении. Обработчик события в шаблоне — один способ сообщить. В этой главе вы узнаете главный — сигналы.

## OnPush

Есть и вторая половина той же идеи. В Angular 22 у каждого компонента по умолчанию стратегия обнаружения изменений **OnPush**: даже когда проверка идёт, Angular проверяет не все компоненты, а только помеченные. Пока компонент у нас один, разницы не видно. Она станет важной в главе 5, когда компонентов будет много.

Убедитесь, что дело не в OnPush. Укажите в `@Component` стратегию `Eager` — «проверять всегда». Раньше так по умолчанию работали все компоненты:

```ts app.ts {1,7}
import { ChangeDetectionStrategy, Component } from '@angular/core';

@Component({
  selector: 'app-root',
  templateUrl: './app.html',
  styleUrl: './app.css',
  changeDetection: ChangeDetectionStrategy.Eager,
})
```

Счётчик всё так же отстаёт. `Eager` означает «проверять этот компонент при каждой проверке», но после таймера проверки нет вообще. Верните всё как было: в настоящем коде `changeDetection` не указывают.

::: legacy Вы встретите в старом коде: zone.js
Раньше Angular подключал библиотеку **zone.js**. Она подменяла `setTimeout`, `Promise`, `fetch`, `addEventListener` и после каждой асинхронной операции запускала проверку всего приложения. С ней наш счётчик работал бы и с таймером: Angular проверил бы шаблон после срабатывания таймера.

Цена — проверки после любого таймера, даже не связанного с интерфейсом, лишний код в каждом приложении и трудная отладка. В старых проектах вы увидите `provideZoneChangeDetection()` в `app.config.ts`, `zone.js` в `polyfills` файла `angular.json` и иногда ручные вызовы `ChangeDetectorRef.markForCheck()` или `detectChanges()`. В новом коде для этого есть сигналы.
:::
