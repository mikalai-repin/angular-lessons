Счётчик отстаёт, потому что Angular не знает, когда поле `cartCount` изменилось. Нужно значение, которое само сообщает об изменениях. Это и есть сигнал.

## Что такое сигнал

**Сигнал** (`signal`) — значение в обёртке. Обёртка умеет две вещи:

- запоминать, **кто** её прочитал;
- сообщать этим читателям, когда значение изменилось.

Шаблон компонента — один из таких читателей. Если шаблон прочитал сигнал, а потом сигнал изменился, Angular сам запланирует проверку компонента. Неважно, откуда пришло изменение: из обработчика клика, таймера или ответа сервера.

## Создание и чтение

```ts app.ts {1,8}
import { Component, signal } from '@angular/core';

// … SERVER_DELAY и @Component …

export class App {
  // …

  protected readonly cartCount = signal(0);
```

`signal(0)` создаёт сигнал с начальным значением `0`. Тип TypeScript выводит сам: `WritableSignal<number>` — **изменяемый сигнал** с числом внутри.

Поле теперь `readonly`. Меняется значение **внутри** сигнала, а сам сигнал остаётся тем же объектом. `readonly` защищает от случайной замены сигнала целиком.

Чтобы прочитать значение, сигнал **вызывают** как функцию:

```html app.html {1}
<span class="cart">В корзине: {{ cartCount() }}</span>
```

Скобки обязательны. Вызов `cartCount()` возвращает текущее значение и заодно сообщает Angular: «этот шаблон зависит от `cartCount`».

## Изменение: `set` и `update`

У изменяемого сигнала есть два метода записи:

```ts
this.cartCount.set(0);                       // новое значение
this.cartCount.update((count) => count + 1); // новое значение из старого
```

`set` подходит, когда новое значение известно заранее: сбросить счётчик, записать ответ сервера. `update` — когда новое значение вычисляется из старого. Запись `update((count) => count + 1)` делает то же, что `set(this.cartCount() + 1)`, но короче и не требует отдельно читать сигнал.

В обработчике заменим `this.cartCount++` на `update`:

```ts app.ts {3}
protected addToCart() {
  setTimeout(() => {
    this.cartCount.update((count) => count + 1);
  }, SERVER_DELAY);
}
```

::: task
1. Импортируйте `signal` и сделайте `cartCount` сигналом: `protected readonly cartCount = signal(0);`
2. В шаблоне читайте его вызовом: `{{ cartCount() }}`.
3. В `addToCart` увеличивайте счётчик через `update`. Строку с `console.log` можно убрать.
4. Понажимайте «В корзину».
:::

## Что получилось

Через полсекунды после каждого нажатия счётчик в шапке увеличивается — без клика, без ввода, сам. Таймер изменил сигнал, сигнал сообщил шаблону, Angular проверил компонент.

Обратите внимание: мы не написали ни строчки «обнови экран». Мы только объявили, от чего зависит шаблон (вызвали `cartCount()`), и меняем данные. Остальное — забота Angular.

## Эксперименты

**Забыть скобки.** Напишите в шапке `{{ cartCount }}` без вызова. На экране появится `[Signal: 0]`, и после нажатий текст не изменится. Шаблон вывел сам сигнал, функцию, а не его значение. Сигнал при этом не прочитан, поэтому шаблон от него не зависит. В настоящем проекте сборка предупредит об этом: `NG8109: cartCount is a function and should be invoked: cartCount()`. Превью такую проверку не делает, поэтому следите за скобками сами.

**Сломать поле.** Попробуйте написать в `addToCart` по-старому: `this.cartCount++`. TypeScript не даст: `Cannot assign to 'cartCount' because it is a read-only property`. Это работает `readonly`: сигнал нельзя заменить, можно только изменить его значение через `set` или `update`.

**Посмотреть на сигнал в консоли.** Добавьте в `addToCart` строку `console.log(this.cartCount)` без скобок. Консоль превью покажет `signal(1)` — тип и текущее значение. В консоли браузера сигнал выглядит как обычная функция. Уберите строку.

## Убираем задержку

Таймер был нужен только для опыта: доказать, что сигнал работает, откуда бы его ни изменили. Дальше он будет мешать: с ним каждый эксперимент приходится ждать полсекунды.

::: tip
Если вы знаете React или Vue: сигнал похож на `ref` во Vue и на состояние из `useState` в React. Но в Angular компонент не «перезапускается» при изменении: класс создаётся один раз, а Angular перепроверяет только шаблон — и только тот, что прочитал изменившийся сигнал.
:::

::: deep Под капотом: что именно обновляет сигнал
Сигнал сообщает об изменении не отдельной привязке `{{ cartCount() }}`, а шаблону компонента целиком. Angular перепроверит все выражения шаблона, и вместе с сигналом обновятся даже обычные поля, изменённые в тот же момент. Мы проверили: если в таймере поменять обычное поле и сигнал, на экране обновятся оба.

Опираться на это не стоит. Если поле меняется и влияет на экран, пусть оно будет сигналом. Тогда шаблон будет верным при любом порядке изменений. Как Angular связывает сигнал с шаблоном, разберём в последнем шаге главы.
:::

::: tip
Если сигнал должен быть доступен другому коду только для чтения, у изменяемого сигнала есть метод `asReadonly()`: он возвращает тот же сигнал, но без `set` и `update`. Это пригодится в главе 8, когда корзина переедет в сервис.
:::
