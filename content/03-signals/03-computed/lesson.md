В магазине двенадцать игр, а карточка показывает одну. Сделаем переключатель: стрелки ‹ и › листают каталог. Для этого игра на карточке должна меняться. А вместе с ней — всё, что из неё вычисляется: скидка, «нет в наличии».

## Что меняется, а что вычисляется

Посмотрите, какие данные карточки на самом деле независимы. Покупатель меняет только одно — **номер** игры в каталоге. Всё остальное из номера следует:

```
gameIndex ──► game ──┬──► soldOut
                     └──► discount
```

Игра — это `GAMES[gameIndex]`. «Нет в наличии» — это `game.inStock === 0`. Скидка считается из цены и старой цены. Хранить их отдельно не нужно и даже вредно: стоит забыть обновить одно поле, и карточка покажет игру с чужой скидкой.

Правило, которое пригодится в любом приложении на сигналах: **храните минимум, остальное вычисляйте**. Минимум у нас — сигнал `gameIndex`. Остальное — вычисляемые сигналы.

## `computed`

**Вычисляемый сигнал** (`computed`) — сигнал, значение которого задаётся функцией:

```ts app.ts {1,5-15}
import { Component, computed, signal } from '@angular/core';

// …

  // Номер игры в каталоге — единственное, что меняет переключатель
  protected readonly gameIndex = signal(0);
  protected readonly gamesCount = GAMES.length;

  // Всё остальное о карточке вычисляется из gameIndex
  protected readonly game = computed(() => GAMES[this.gameIndex()]);
  protected readonly soldOut = computed(() => this.game().inStock === 0);
  protected readonly discount = computed(() => {
    const { price, oldPrice } = this.game();
    return oldPrice ? Math.round((1 - price / oldPrice) * 100) : 0;
  });
```

Как это работает:

- функция внутри `computed` читает другие сигналы. Angular запоминает, какие именно, — это **зависимости** вычисляемого сигнала. Перечислять их не нужно: `game` зависит от `gameIndex`, потому что прочитал его;
- результат запоминается. Пока зависимости не изменились, `discount()` возвращает запомненное значение и функцию не вызывает;
- когда зависимость изменилась, значение пересчитается — но не сразу, а при следующем чтении. Вычисляемый сигнал **ленивый**.

Читают вычисляемый сигнал так же, вызовом: `game()`, `discount()`. А записать в него нельзя: у него тип `Signal<T>`, без `set` и `update`.

Переключатель меняет только `gameIndex`:

```ts app.ts
protected showPrevious() {
  this.gameIndex.update((index) => (index - 1 + GAMES.length) % GAMES.length);
}

protected showNext() {
  this.gameIndex.update((index) => (index + 1) % GAMES.length);
}
```

Остаток от деления зацикливает каталог: после двенадцатой игры снова первая.

## Шаблон

Над карточкой — переключатель:

```html app.html
<div class="pager">
  <button class="icon-button" aria-label="Предыдущая игра" (click)="showPrevious()">‹</button>
  <span class="muted">{{ gameIndex() + 1 }} из {{ gamesCount }}</span>
  <button class="icon-button" aria-label="Следующая игра" (click)="showNext()">›</button>
</div>
```

`aria-label` нужен кнопкам со значками: скринридер прочитает «Следующая игра», а не «›».

В самой карточке `game` теперь сигнал, поэтому `game.title` превращается в `game().title`, `game.cover` — в `game().cover` и так далее. Вызовов `game()` в шаблоне много, но это дёшево: каждый возвращает запомненный объект.

Переменные `@let soldOut` и `@let discount` больше не нужны: их заменили `soldOut()` и `discount()`.

```html app.html {1,7}
<article class="card" [class.sold-out]="soldOut()">
  <!-- … -->
  <p class="price">
    {{ game().price }} ₽
    <span [hidden]="!game().oldPrice">
      <s class="old-price">{{ game().oldPrice }} ₽</s>
      <span class="badge">−{{ discount() }} %</span>
    </span>
  </p>
```

Почему мы перенесли их из шаблона в класс? `@let` — удобное сокращение **внутри шаблона**. А «нет в наличии» и скидка — знания о товаре, которые скоро понадобятся и коду класса (кнопкам количества, корзине). К тому же в классе доступен весь JavaScript: например, `Math.round`, которого нет в шаблоне.

::: task
1. Импортируйте `computed`. Замените поле `game` сигналом `gameIndex` и вычисляемыми сигналами `game`, `soldOut`, `discount`, как в коде выше. Добавьте `gamesCount`.
2. Добавьте методы `showPrevious` и `showNext`.
3. В шаблоне добавьте переключатель над карточкой, удалите обе строки `@let` и замените `game.` на `game().`, `soldOut` — на `soldOut()`, `discount` — на `discount()`.
:::

::: tip
Заменять удобно поиском: в редакторе нажмите Ctrl+H (на Mac — Cmd+Option+F), найдите `game.` и замените на `game().` во всём файле.
:::

## Что получилось

Над карточкой — «1 из 12» и стрелки. Листайте: меняются обложка, название, цена, скидка. Седьмая игра, «Маяк», серая и с неактивной кнопкой: `soldOut()` пересчитался сам. Счётчик в шапке работает как прежде.

## Эксперимент: ленивость и кэш

Убедимся, что вычисляемый сигнал не считает лишнего. Добавьте в функцию `discount` вывод в консоль:

```ts app.ts {2}
protected readonly discount = computed(() => {
  console.log('Считаем скидку');
  const { price, oldPrice } = this.game();
  return oldPrice ? Math.round((1 - price / oldPrice) * 100) : 0;
});
```

При запуске — одна строка `Считаем скидку`. Каждое переключение игры — ещё одна. А теперь понажимайте «В корзину» и поищите что-нибудь: новых строк нет. Каждый клик заставляет Angular перепроверить шаблон, и шаблон вызывает `discount()`, но зависимость, `game`, не изменилась. Поэтому возвращается запомненное значение.

Теперь пусть `discount` никто не читает: удалите бейдж `−{{ discount() }} %` из шаблона. После перезапуска строки `Считаем скидку` не будет ни разу, сколько ни листайте. Вычисляемый сигнал, который никто не читает, не вычисляется вообще.

Верните бейдж и уберите `console.log`.

## Чего нельзя в `computed`

- **Записывать в него.** `this.discount.set(5)` — ошибка TypeScript: `Property 'set' does not exist on type 'Signal<number>'`.
- **Записывать в другие сигналы внутри функции.** Функция `computed` должна только вычислять значение. Если внутри неё вызвать `set` у другого сигнала, Angular бросит ошибку ``NG0600: Writing to signals is not allowed in a `computed` ``.
- **Делать что-то «на стороне»**: запросы, запись в `localStorage`, вывод в консоль (кроме отладки). Неизвестно, когда и сколько раз функция будет вызвана. Для таких действий есть эффекты — о них через шаг.

::: tip
Если вы знаете React: `computed` похож на `useMemo`, но зависимости находит сам — никакого массива зависимостей, который легко забыть обновить.
:::
