Счётчик в шапке знает только число. Настоящей корзине нужно больше: какие игры в ней лежат и сколько каждой, чтобы посчитать сумму и показать список. Значит, в сигнале будет лежать массив. И тут сигналы требуют одного важного правила.

## Позиция корзины

Опишем позицию в `core/models.ts`, рядом с `Game`:

```ts core/models.ts
// Позиция корзины: какая игра и сколько штук
export interface CartItem {
  game: Game;
  quantity: number;
}
```

Корзина — сигнал с массивом позиций. А количество, сумма и список — вычисляемые сигналы: правило «храните минимум» из прошлого шага.

```ts app.ts {2,6-15}
import { Component, computed, signal } from '@angular/core';
import { CartItem } from './core/models';

// …

  // Корзина — массив позиций. Его не меняем, а заменяем новым
  protected readonly cart = signal<CartItem[]>([]);
  protected readonly cartCount = computed(() => this.cart().reduce((sum, item) => sum + item.quantity, 0));
  protected readonly cartTotal = computed(() =>
    this.cart().reduce((sum, item) => sum + item.game.price * item.quantity, 0),
  );
  protected readonly cartSummary = computed(() =>
    this.cart()
      .map((item) => `${item.game.title} × ${item.quantity}`)
      .join(', '),
  );
```

У `signal<CartItem[]>([])` тип указан явно: из пустого массива TypeScript не узнает, что в нём будут позиции.

`cartCount` раньше был изменяемым сигналом, а теперь вычисляется из корзины. Шаблон этого не заметит: читается он так же, `cartCount()`.

## Добавление в корзину

Если игры ещё нет в корзине, добавляем позицию. Если есть — увеличиваем количество:

```ts app.ts
protected addToCart() {
  const game = this.game();
  this.cart.update((items) => {
    const existing = items.find((item) => item.game.id === game.id);
    if (!existing) {
      return [...items, { game, quantity: 1 }];
    }
    return items.map((item) => (item === existing ? { ...item, quantity: item.quantity + 1 } : item));
  });
}
```

Посмотрите внимательно: старый массив здесь нигде не меняется. `[...items, …]` создаёт новый массив. `items.map(…)` — тоже новый, а в нём новый объект позиции `{ ...item, quantity: … }`. Почему не написать проще, через `push` и `existing.quantity++`? Об этом ниже, в эксперименте.

В шаблоне: в шапке — количество и сумма, под карточкой — мини-корзина со списком позиций.

```html app.html
<span class="cart">В корзине: {{ cartCount() }} · {{ cartTotal() }} ₽</span>
```

```html app.html
<section class="mini-cart" [hidden]="cart().length === 0">
  <h2>Корзина</h2>
  <p>{{ cartSummary() }}</p>
</section>
```

Список пока — одна строка через запятую. Настоящий список, с элементом на каждую позицию, сделаем в главе 4: для него нужен блок `@for`.

::: task
1. Добавьте интерфейс `CartItem` в `core/models.ts` и импортируйте его в `app.ts`.
2. Замените сигнал `cartCount` сигналом `cart` и вычисляемыми `cartCount`, `cartTotal`, `cartSummary`.
3. Перепишите `addToCart`, как в коде выше.
4. Выведите в шапке количество и сумму, а под карточкой добавьте мини-корзину.
:::

## Что получилось

Добавьте «Остров сокровищ» дважды и «Драконью почту» один раз. В шапке — `В корзине: 3 · 5270 ₽`, под карточкой — `Остров сокровищ × 2, Драконья почта × 1`. Пока корзина пуста, мини-корзины не видно.

## Эксперимент: изменить массив на месте

Замените тело `addToCart` «простым» вариантом:

```ts app.ts
protected addToCart() {
  this.cart().push({ game: this.game(), quantity: 1 });
  console.log('В массиве:', this.cart().length);
}
```

Нажмите «В корзину» пару раз. В консоли `В массиве: 1`, `В массиве: 2` — позиции добавляются. А на экране творится странное: появилась мини-корзина с **пустым** списком, а в шапке по-прежнему `0 · 0 ₽`.

Разберёмся. `push` меняет массив, который лежит в сигнале, но сигнал об этом не знает: никто не вызвал `set` или `update`. Вычисляемые сигналы `cartCount`, `cartTotal` и `cartSummary` не получили сообщения и вернули запомненные значения: ноль и пустую строку. А `[hidden]="cart().length === 0"` в шаблоне читает массив напрямую. Клик пометил компонент для проверки, шаблон перечитал `cart().length` и увидел изменённый массив. Получился экран, где одна часть верна, а другая — нет.

Может, сообщить сигналу вручную: `this.cart.set(this.cart())`? Попробуйте — ничего не изменится. Сигнал сравнивает новое значение со старым, и если они **равны**, никому не сообщает. Сравнивает он через `Object.is`, то есть для массивов и объектов — по ссылке. Тот же массив — то же значение, даже если внутри всё поменялось.

Отсюда правило: **значения в сигналах не меняют, а заменяют**. Новый массив (`[...items, x]`, `map`, `filter`), новый объект (`{ ...item, quantity: 2 }`). Верните правильный `addToCart`.

::: tip
TypeScript может следить за этим правилом сам. Объявите корзину как `signal<readonly CartItem[]>([])`, и `this.cart().push(…)` станет ошибкой: `Property 'push' does not exist on type 'readonly CartItem[]'`. А `map`, `filter`, `find` и `[...items]` работают как раньше.
:::

## Своё сравнение: `equal`

Сравнение через `Object.is` можно заменить своим — опция `equal` у `signal` и `computed`:

```ts
protected readonly cart = signal<CartItem[]>([], { equal: (a, b) => a.length === b.length });
```

Теперь сигнал считает массивы равными, если у них одинаковая длина. Попробуйте: первое нажатие «В корзину» добавит игру. Второе нажатие на ту же игру шапку не изменит: количество позиций то же, значит, для сигнала «ничего не изменилось». Переключитесь на другую игру и добавьте её — длина изменилась, шапка обновится.

Пример намеренно неудачный: он показывает, что `equal` решает, сообщать ли об изменении. В настоящем коде своё сравнение нужно редко. Например, сигнал с объектом фильтров каталога можно сравнивать по полям, чтобы новый объект с теми же значениями не вызывал повторный поиск. Уберите `equal`.
