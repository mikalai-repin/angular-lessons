Сигналы и вычисляемые сигналы описывают **данные**. Но иногда при изменении данных нужно **сделать** что-то за пределами Angular: записать корзину в `localStorage`, отправить событие в аналитику, обновить заголовок вкладки. Такие действия называются побочными эффектами, и для них есть `effect`.

Начнём с самого простого эффекта: будем писать в консоль каждое изменение корзины. В главе 9 этот же приём сохранит корзину между перезагрузками страницы.

## `effect`

```ts app.ts {1,5-10}
import { Component, computed, effect, signal } from '@angular/core';

// …

  constructor() {
    // Побочный эффект: сообщение в консоли при каждом изменении корзины
    effect(() => {
      console.log('Корзина:', this.cartSummary() || 'пусто');
    });
  }
```

**Эффект** (`effect`) — функция, которую Angular вызывает сначала один раз, а потом каждый раз, когда изменились прочитанные в ней сигналы. Зависимости он находит так же, как `computed`: что прочитано, от того и зависит. Здесь прочитан `cartSummary`, значит, эффект сработает при каждом изменении списка.

Главное отличие от `computed`: эффект ничего не возвращает. Его смысл — в действии.

## Почему в конструкторе

Это первый конструктор в нашем коде. Эффект нельзя создать где угодно: Angular должен знать, **чей** он. Эффект компонента живёт столько же, сколько компонент, и уничтожается вместе с ним. Поэтому `effect()` вызывают, пока Angular создаёт компонент: в конструкторе или в инициализаторе поля. Это называется **контекстом внедрения** (injection context); подробно он появится в главе 8, про внедрение зависимостей.

Попробуйте нарушить правило: перенесите вызов `effect(…)` из конструктора в `addToCart`. Приложение запустится, а при нажатии «В корзину» в консоли будет ошибка:

```
ERROR RuntimeError: NG0203: effect() can only be used within an injection context such as a constructor, a factory function, a field initializer, or a function used with `runInInjectionContext`. Find more at https://v22.angular.dev/errors/NG0203
```

Верните эффект в конструктор.

::: task
1. Импортируйте `effect` и добавьте в класс конструктор с эффектом, как в коде выше.
2. Добавьте в корзину несколько игр и посмотрите на консоль.
:::

## Что получилось

При запуске в консоли сразу `Корзина: пусто`: эффект выполняется хотя бы один раз, чтобы узнать свои зависимости. Каждое нажатие «В корзину» — новая строка со списком. А переключение игр строк не добавляет: от `gameIndex` эффект не зависит.

## Когда выполняется эффект

Эффект срабатывает не в момент `update`, а чуть позже. Проверьте: добавьте в конец `addToCart` строку `console.log('addToCart закончился')`. В консоли она окажется **раньше** строки `Корзина: …`. Angular собирает изменения и выполняет эффекты компонента вместе с проверкой компонента.

Поэтому несколько изменений подряд дают один запуск эффекта. Скопируйте в `addToCart` вызов `this.cart.update(…)`, чтобы он выполнялся дважды. Одно нажатие «В корзину» — и в консоли одна строка `Корзина: Остров сокровищ × 2`, а не две. Уберите эксперименты.

## Когда эффект не нужен

Эффект соблазнительно использовать для всего: «когда изменилась корзина, пересчитай количество». Например, так:

```ts
// Так не надо
protected readonly cartCount = signal(0);

constructor() {
  effect(() => {
    this.cartCount.set(this.cart().reduce((sum, item) => sum + item.quantity, 0));
  });
}
```

Это работает: писать в сигналы из эффекта разрешено. Но так хуже, чем `computed`:

- значение отстаёт: между изменением корзины и запуском эффекта `cartCount` хранит старое число;
- Angular делает лишнюю работу: эффект меняет сигнал, тот запускает ещё одну проверку;
- труднее понять код: чтобы узнать, откуда берётся `cartCount`, надо искать все эффекты, которые в него пишут.

Правило: **если значение можно вычислить из других сигналов — это `computed`**. Эффект — для действий за пределами сигналов: консоль, `localStorage`, сторонние библиотеки, ручная работа с DOM.

::: tip
Если вы знаете React: `effect` похож на `useEffect`, но массива зависимостей нет, Angular находит их сам. И, как и с `useEffect`, хороший код обходится небольшим числом эффектов.
:::

::: deep Очистка эффекта
Функция эффекта получает параметр — функцию регистрации очистки:

```ts
effect((onCleanup) => {
  const count = this.cartCount();
  const timer = setTimeout(() => console.log(`В корзине ${count} шт. уже 10 секунд`), 10_000);
  onCleanup(() => clearTimeout(timer));
});
```

Эффект зависит от `cartCount` и при каждом изменении корзины заводит таймер. Очистка вызывается перед следующим запуском эффекта и при уничтожении компонента. Поэтому сообщение появится, только если корзина не менялась 10 секунд: каждое новое добавление отменяет старый таймер. Так эффект отменяет то, что начал в прошлый раз: таймер, подписку, запрос.
:::

::: deep Под капотом: эффекты компонента и корневые эффекты
Эффект, созданный в компоненте, — **эффект компонента**: он выполняется во время проверки этого компонента, до обновления его шаблона. Это видно в консоли, если добавить `console.log` в `cartTotal` — вычисляемый сигнал, который читает только шаблон. После нажатия «В корзину» сначала появится строка эффекта, потом — строка из `cartTotal`.

Эффект, созданный вне дерева компонентов, например в сервисе приложения, — **корневой эффект**: он выполняется отдельно, в микрозадаче, и с проверкой компонентов не связан. Об этом — в главе 8.
:::
