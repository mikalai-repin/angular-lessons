Чтобы положить в корзину три одинаковые игры, сейчас нужно трижды нажать кнопку. Добавим выбор количества: «−», число, «+». Покупатель выбирает число, а «В корзину» добавляет сразу столько штук.

У количества два требования, которые на первый взгляд противоречат друг другу:

- покупатель может его **менять** кнопками;
- при смене игры оно должно **сбрасываться** на 1. Иначе вы выбрали три «Острова сокровищ», перешли к «Ночному экспрессу» — а там уже стоит 3. А у игры, которой нет в наличии, количество должно быть 0.

## Почему не подходит то, что мы знаем

Попробуем по очереди:

- `signal(1)` можно менять, но он не знает об игре. При переключении в нём останется прошлое число;
- `computed(() => (this.game().inStock > 0 ? 1 : 0))` следит за игрой, но его нельзя менять: у него нет `set` и `update`;
- `signal` плюс эффект, который сбрасывает его при смене игры, — тот самый «эффект для синхронизации сигналов», от которого мы отказались в шаге про `effect`.

Нужно что-то среднее: изменяемый сигнал, который **сбрасывается**, когда меняется его источник.

## `linkedSignal`

**Связанный сигнал** (`linkedSignal`) — именно такой:

```ts app.ts
// Сколько штук добавить. При смене игры сбрасывается: 1, а если игры нет в наличии — 0
protected readonly quantity = linkedSignal<number>(() => (this.game().inStock > 0 ? 1 : 0));
```

Функция внутри работает как у `computed`: читает сигналы и вычисляет значение. Пока зависимости не меняются, `quantity` — обычный изменяемый сигнал: его можно читать, менять через `set` и `update`. Когда меняется зависимость (здесь — `game`), значение вычисляется заново и всё, что записали руками, сбрасывается.

Зачем `<number>`? Без него TypeScript выведет тип из функции: она возвращает `0` или `1`, и тип сигнала будет `0 | 1`. Тогда `update((quantity) => quantity + 1)` не скомпилируется: ошибка TS2322, `number` нельзя записать в сигнал типа `0 | 1`. У `signal(0)` такой проблемы нет: из начального значения TypeScript выводит `number`.

Методы для кнопок:

```ts app.ts
protected decreaseQuantity() {
  this.quantity.update((quantity) => Math.max(quantity - 1, 1));
}

protected increaseQuantity() {
  this.quantity.update((quantity) => Math.min(quantity + 1, this.game().inStock));
}
```

Больше, чем есть на складе, выбрать нельзя. Меньше одного — тоже.

И `addToCart` добавляет `quantity()` штук вместо одной:

```ts app.ts {3,7,9}
protected addToCart() {
  const game = this.game();
  const quantity = this.quantity();
  this.cart.update((items) => {
    const existing = items.find((item) => item.game.id === game.id);
    if (!existing) {
      return [...items, { game, quantity }];
    }
    return items.map((item) => (item === existing ? { ...item, quantity: item.quantity + quantity } : item));
  });
}
```

В шаблоне кнопка «В корзину» встаёт в один ряд с выбором количества:

```html app.html
<div class="actions">
  <div class="quantity">
    <button class="icon-button" aria-label="Меньше" [disabled]="quantity() <= 1" (click)="decreaseQuantity()">
      −
    </button>
    <span>{{ quantity() }}</span>
    <button
      class="icon-button"
      aria-label="Больше"
      [disabled]="quantity() >= game().inStock"
      (click)="increaseQuantity()"
    >
      +
    </button>
  </div>
  <button class="button" [disabled]="soldOut()" (click)="addToCart()">
    {{ soldOut() ? 'Нет в наличии' : 'В корзину' }}
  </button>
</div>
```

## Что получилось

Выберите 3 и нажмите «В корзину»: в корзине три «Острова сокровищ». Перейдите к следующей игре — количество снова 1. Листайте до «Ночного экспресса»: на складе их три, и «+» перестаёт работать на тройке. У «Маяка» количество 0, и все три кнопки неактивны.

Попробуйте убрать `<number>` — увидите ошибку типов в методах. Верните.

## Ловушка: зависимость, которая не меняется

Вопрос «сколько штук, если нет в наличии» уже решает `soldOut`. Почему бы не написать короче?

```ts app.ts
protected readonly quantity = linkedSignal<number>(() => (this.soldOut() ? 0 : 1));
```

Попробуйте. Выберите 3 у «Острова сокровищ» и листайте вперёд: у «Драконьей почты», «Зельеваров» и дальше по-прежнему 3. Сброс сломался.

Связанный сигнал сбрасывается, когда меняется **значение** его зависимости. Теперь зависимость — `soldOut`, а у всех этих игр он одинаковый: `false`. Игра поменялась, но для `quantity` «ничего не изменилось». Только на «Маяке» `soldOut` становится `true`, и количество наконец сбрасывается в 0.

Правило: читайте в `linkedSignal` тот сигнал, **изменение которого** должно сбрасывать значение. У нас это игра, поэтому `game()`. Почему Angular так экономит, разберём в последнем шаге главы. Верните `this.game().inStock > 0 ? 1 : 0`.

## Полная форма: `source` и `computation`

Короткая форма всегда сбрасывает значение. Иногда нужно умнее: например, **сохранять** выбранное количество при переходе к другой игре, если на складе её хватает. Для этого есть полная форма:

```ts app.ts
protected readonly quantity = linkedSignal<Game, number>({
  source: this.game,
  computation: (game, previous) => Math.min(previous?.value ?? 1, game.inStock),
});
```

- `source` — источник: при его изменении вычисляется новое значение;
- `computation` получает новое значение источника и `previous` — прошлое состояние: `previous.source` (прошлая игра) и `previous.value` (прошлое количество, в том числе выбранное вручную). При первом вычислении `previous` нет.

Попробуйте этот вариант (добавьте `Game` в импорт из `./core/models`). Выберите 3 у «Острова сокровищ» и листайте: у следующих игр остаётся 3. Дойдите до «Маяка» — 0, ведь на складе пусто. А дальше у «Шахмат» тоже 0: прошлое значение теперь 0, а `Math.min(0, 9)` — ноль. Полная форма даёт больше власти, но и думать при ней приходится больше. Для нашей карточки сброс до 1 проще и понятнее, поэтому верните короткую форму.

::: tip
`linkedSignal` подходит везде, где выбор пользователя зависит от данных: выбранное издание или вариант товара при смене товара, выбранная страница при смене фильтра, выделенная строка таблицы при новых данных.
:::
