В шаблоне магазина накопилось несколько мест, где что-то нужно показать **или не показать**: старая цена, «Уже в корзине», мини-корзина, строка про доставку. Мы обходились привязкой `[hidden]`. Она прячет элемент, но элемент остаётся на странице, а вместо «или — или» приходится писать два элемента с противоположными условиями.

В этой главе появятся **управляющие блоки** (control flow blocks): `@if`, `@for`, `@switch`. Они решают, какая разметка вообще попадёт на страницу. К концу главы вместо одной карточки будет каталог:

```
┌──────────────────────────────────────────┐
│ ♞ Ход конём        В корзине: 3 · 7170 ₽ │
├──────────────────────────────────────────┤
│ [ Найти игру                           ] │
│ Корзина                                  │
│ 1. Остров сокровищ  [−] 2 [+] 3980 ₽ [×] │
│ 2. Ночной экспресс  [−] 1 [+] 3190 ₽ [×] │
│ Итого: 7170 ₽                            │
│ ☐ Только в наличии   [По умолчанию ▾]    │
│ ┌──────────┐ ┌──────────┐ ┌──────────┐   │
│ │ Семейная │ │ Семейная │ │Стратегия │   │
│ │ обложка  │ │ обложка  │ │ обложка  │   │
│ └──────────┘ └──────────┘ └──────────┘   │
│ Остров…      Драконья…    Зельевары      │
│ 1990 ₽       1290 ₽       2490 ₽         │
│ В наличии    В наличии    В наличии      │
└──────────────────────────────────────────┘
```

Поиск по мере ввода, «Ничего не найдено», фильтр «Только в наличии», сортировка, корзина со строкой на каждую позицию.

## Что изменилось в коде

Код — решение практикума главы 3. Изменился только `app.css`: в нём готовые стили всего, что мы сделаем в этой главе.

## `@if`

Начнём со старой цены. Сейчас она обёрнута в `<span [hidden]="!game().oldPrice">`. Перепишем через `@if`:

```html app.html {3-6}
<p class="price">
  {{ game().price }} ₽
  @if (game().oldPrice) {
    <s class="old-price">{{ game().oldPrice }} ₽</s>
    <span class="badge">−{{ discount() }} %</span>
  }
</p>
```

`@if (условие) { … }` — блок шаблона. Если условие истинно, Angular создаёт разметку внутри фигурных скобок. Если ложно — её **нет на странице вообще**: ни элементов, ни привязок, ни обработчиков. Обёртка `<span>` больше не нужна: блок сам по себе ничего не добавляет в DOM.

Условие — обычное выражение шаблона, как в привязках, и проверяется по правилам JavaScript: `0`, `''`, `null` и `undefined` ложны.

## `as`: имя для значения условия

Внутри блока мы дважды обращаемся к `game().oldPrice`. У `@if` есть удобная запись:

```html app.html {1-2}
@if (game().oldPrice; as oldPrice) {
  <s class="old-price">{{ oldPrice }} ₽</s>
  <span class="badge">−{{ discount() }} %</span>
}
```

`as oldPrice` даёт значению условия имя, которое видно внутри блока. Это не только короче. В настоящем проекте проверка шаблонов знает, что внутри блока `oldPrice` — уже `number`, а не `number | undefined`: блок выполняется, только когда значение есть. А вот `game().oldPrice` внутри того же блока для неё по-прежнему может быть `undefined`. Мы проверили `ngc`: `{{ oldPrice.toFixed(0) }}` компилируется, а `{{ game().oldPrice.toFixed(0) }}` — ошибка `TS2532: Object is possibly 'undefined'`. Компилятор не знает, что второй вызов `game()` вернёт то же самое.

::: warning
`@if (x; as y)` проверяет значение на истинность. Если ноль — нормальное значение, блок его пропустит. Мы проверили: `@if (price(); as p)` при цене `0` уходит в `@else`. Для чисел пишите условие явно: `@if (count() > 0)`.
:::

## `@else if` и `@else`

Покажем на карточке наличие: «Нет в наличии», «Осталось N шт.», если игр меньше пяти, или «В наличии». Это три взаимоисключающих варианта — цепочка `@if`, `@else if`, `@else`:

```html app.html
@if (game().inStock === 0) {
  <p class="stock stock-out">Нет в наличии</p>
} @else if (game().inStock <= fewLeft) {
  <p class="stock stock-few">Осталось {{ game().inStock }} шт.</p>
} @else {
  <p class="stock stock-ok">В наличии</p>
}
```

Сработает первая ветка с истинным условием, остальные не создаются. Порог `5` вынесем в константу и откроем шаблону через поле, как `gamesCount`:

```ts app.ts
// При каком остатке на складе писать «Осталось N шт.»
const FEW_LEFT = 5;

// … в классе App:
protected readonly fewLeft = FEW_LEFT;
```

Раз наличие теперь написано на карточке, кнопке больше не нужно менять текст: пусть всегда будет «В корзину».

## Что получилось

Внешне почти ничего не изменилось, и в этом смысл: те же условия, только записанные блоками. Новое — строка наличия. У «Острова сокровищ» — «В наличии», у «Ночного экспресса» — «Осталось 3 шт.», у «Маяка» — «Нет в наличии».

Откройте в браузере инструменты разработчика и посмотрите на DOM карточки. Пока игра не в корзине, абзаца «Уже в корзине» в DOM нет совсем. На его месте — комментарий `<!--container-->`: так Angular помечает место, куда вставит блок, когда условие станет истинным.

## `@if` или `[hidden]`

`@if` удаляет разметку, `[hidden]` прячет. Разница становится видна, когда у элемента есть своё состояние: текст в поле ввода, прокрутка, фокус. Мы проверили: если поле ввода спрятать через `[hidden]` и показать снова, введённый текст на месте. Если убрать его через `@if` и вернуть — поле создаётся заново, пустым.

Поэтому:

- `@if` — по умолчанию. Того, чего нет на странице, Angular не проверяет и не обновляет, а проверка шаблонов в настоящем проекте сужает типы внутри блока;
- `[hidden]` — когда элемент нужно спрятать, сохранив его состояние, и когда он часто показывается и прячется.

Абзац «Ищем: …» мы оставили на `[hidden]` не случайно: в шаге про `@empty` поиск заработает по-новому, и абзац уйдёт.

::: legacy Вы встретите в старом коде: *ngIf
```html
<s *ngIf="game.oldPrice as oldPrice; else noDiscount" class="old-price">{{ oldPrice }} ₽</s>
<ng-template #noDiscount><span>Без скидки</span></ng-template>
```
Это директива `NgIf` из `@angular/common`: её нужно было импортировать в компонент, а ветку `else` — описывать отдельным `<ng-template>` с именем. Блок `@if` встроен в шаблоны, импорт не нужен, а `@else if` у `*ngIf` не было вообще. `NgIf` устарела в Angular 20. Перевести старый проект на блоки помогает команда `ng generate @angular/core:control-flow`.
:::
