Магазин, где игры листаются по одной, неудобен: покупатель хочет видеть весь каталог сразу. Сделаем сетку с плиткой на каждую игру. Писать двенадцать плиток вручную мы, конечно, не будем: для повторения разметки по массиву есть блок `@for`.

## Что изменилось в коде

Карточка с переключателем уступает место каталогу, поэтому код шага подготовлен заранее:

- из `app.html` убраны переключатель и большая карточка. На их месте — комментарий `TODO`, куда встанет каталог. Мини-корзина переехала наверх, под поиск: каталог длинный, и внизу её никто бы не увидел;
- в `app.ts` больше нет сигналов открытой игры: `gameIndex`, `game`, `soldOut`, `discount`, `quantity`, `available`. Появилось поле `games = GAMES` — весь каталог;
- `addToCart(game: Game)` теперь принимает игру: какую именно добавить, скажет плитка. Добавляет одну штуку;
- `inCart` — уже не число для одной игры, а `Map`: id игры → сколько штук в корзине. Плитке нужно знать это о своей игре;
- эффект пишет в консоль только список корзины: открытой игры больше нет.

Выбор количества и подробная карточка вернутся позже, на странице игры (глава 10). А `linkedSignal` ещё встретится в главе 5.

## `@for`

```html app.html {2,14}
<div class="grid">
  @for (game of games; track game.id) {
    <article class="tile" [class.sold-out]="game.inStock === 0">
      <img class="tile-cover" [src]="game.cover" [alt]="game.title" />
      <h2 class="tile-title">{{ game.title }}</h2>
      <p class="price">
        {{ game.price }} ₽
        @if (game.oldPrice; as oldPrice) {
          <s class="old-price">{{ oldPrice }} ₽</s>
        }
      </p>
      <button class="button" (click)="addToCart(game)">В корзину</button>
    </article>
  }
</div>
```

`@for (game of games; track game.id) { … }` повторяет разметку внутри для каждого элемента массива `games`. Внутри блока `game` — текущий элемент, как переменная цикла `for…of` в JavaScript. Видна она только внутри блока.

Обратите внимание: `game` здесь — обычный объект `Game`, а не сигнал, поэтому `game.title` без скобок. А `games` — обычный массив: каталог пока не меняется. В шаге про `@empty` он станет вычисляемым сигналом, и запись превратится в `@for (game of visibleGames(); …)`.

Обработчик `(click)="addToCart(game)"` у каждой плитки свой: в нём `game` — игра именно этой плитки.

## `track` обязателен

Вторая часть, `track game.id`, — **выражение отслеживания** (track expression). Оно говорит Angular, как узнать элемент массива при следующей проверке: «плитка с `id` 4 — это та же игра, что была в прошлый раз». Когда массив изменится — игры отсортируют, отфильтруют, добавят новую, — Angular сравнит ключи и не будет пересоздавать плитки, которые уже есть, а только переставит их, добавит недостающие и удалит лишние.

Без `track` блок не скомпилируется. Попробуйте убрать `; track game.id` — в консоли превью ошибка:

```
Error: Errors during JIT compilation of template for App: @for loop must have a "track" expression
```

Что выбрать для `track`:

- **уникальный и постоянный идентификатор** элемента: `id` из базы, артикул, `slug`. Это правильный выбор почти всегда;
- `$index` — номер элемента в массиве. Подходит для списков, которые никогда не переставляются;
- сам элемент, `track game`, — когда это строки или числа или когда объекты в массиве никогда не заменяются копиями.

Что происходит с DOM при каждом варианте, мы увидим своими глазами в последнем шаге главы.

## `@let` и `@if` внутри `@for`

Плитке нужны ещё две вещи: строка наличия из прошлого шага и сколько штук игры уже в корзине. Количество понадобится в двух местах — для кнопки и для надписи, — поэтому заведём переменную шаблона `@let` прямо в теле цикла:

```html app.html {2,6-9}
@for (game of games; track game.id) {
  @let inCartCount = inCart().get(game.id) ?? 0;
  <article class="tile" [class.sold-out]="game.inStock === 0">
    <!-- … обложка, название, цена … -->
    <!-- строка наличия: @if / @else if / @else из прошлого шага, но с game.inStock -->
    <button class="button" [disabled]="inCartCount >= game.inStock" (click)="addToCart(game)">В корзину</button>
    @if (inCartCount > 0) {
      <p class="in-cart muted">В корзине: {{ inCartCount }} шт.</p>
    }
  </article>
}
```

`@let` внутри `@for` вычисляется для каждой плитки заново, со своей `game`. Кнопка становится неактивной, когда в корзине уже весь остаток со склада. Для игры, которой нет в наличии, это условие истинно сразу: `0 >= 0`.

## Что получилось

Двенадцать плиток в три колонки. «Маяк» серый, с надписью «Нет в наличии» и неактивной кнопкой. Нажмите «В корзину» у «Ночного экспресса» трижды: на плитке «В корзине: 3 шт.», кнопка погасла — больше на складе нет. В мини-корзине наверху — список и итог, в шапке — количество и сумма.

Всё, что мы сделали в главе 3, работает и здесь: плитки читают сигнал `inCart`, и при изменении корзины Angular обновляет именно то, что от неё зависит.

::: legacy Вы встретите в старом коде: *ngFor
```html
<article *ngFor="let game of games; trackBy: trackById" class="tile">…</article>
```
```ts
trackById(index: number, game: Game) {
  return game.id;
}
```
Директива `NgForOf` из `@angular/common`. `trackBy` был **необязательным**, и про него постоянно забывали: без него Angular сравнивал объекты по ссылке и при каждом обновлении массива с сервера пересоздавал весь список. В `@for` выражение `track` обязательно и пишется прямо в шаблоне, без отдельного метода. `NgForOf` устарела в Angular 20.
:::
