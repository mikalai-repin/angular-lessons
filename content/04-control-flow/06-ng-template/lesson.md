Два элемента с приставкой `ng-` вы будете встречать постоянно — в документации, в библиотеках, в любом проекте старше пары лет. С блоками `@if` и `@for` писать их самому приходится редко, поэтому этот шаг обзорный: задания нет, только эксперименты. Всё, что вы поменяете, можно вернуть кнопкой «Сброс».

## `<ng-container>`: группировка без элемента

`<ng-container>` — элемент, которого нет на странице. Внутри него может быть что угодно, но сам он не создаёт тега в DOM.

Попробуйте: оберните строку наличия в плитке в `<ng-container>…</ng-container>` и посмотрите на DOM в инструментах разработчика. Тега `ng-container` там нет. Вместо него — комментарий `<!--ng-container-->`, а содержимое стоит прямо на его месте.

Зачем такое нужно? В старом коде условия и циклы были **директивами**, а директиве нужен элемент, на котором она стоит: `<div *ngIf="…">`. Если лишний `div` ломал вёрстку, писали `<ng-container *ngIf="…">`. Блокам `@if` и `@for` элемент не нужен вообще, поэтому для них `ng-container` больше не требуется.

Сегодня `ng-container` нужен там, где директиву всё-таки нужно на что-то поставить, а лишний элемент не нужен. Пример — ниже.

## `<ng-template>`: шаблон как значение

`<ng-template>` — кусок разметки, который **не отрисовывается сам**. Добавьте в конец `app.html`:

```html
<ng-template>
  <p>Этого текста на странице не будет</p>
</ng-template>
```

Текста действительно нет. Шаблон — это заготовка: Angular компилирует его в функцию отрисовки и хранит, а показывает только когда кто-то попросит.

Попросить можно директивой `NgTemplateOutlet` из `@angular/common`. Сделаем из цены шаблон, который можно вставить в любое место:

```html app.html
<ng-template #priceTpl let-game>
  {{ game.price }} ₽
  @if (game.oldPrice; as oldPrice) {
    <s class="old-price">{{ oldPrice }} ₽</s>
  }
</ng-template>
```

- `#priceTpl` — ссылка на шаблон, как ссылка на элемент в главе 2;
- `let-game` объявляет **переменную шаблона**: её значение передадут при отрисовке.

В плитке замените содержимое `<p class="price">` вставкой шаблона:

```html app.html
<p class="price">
  <ng-container *ngTemplateOutlet="priceTpl; context: { $implicit: game }" />
</p>
```

`*ngTemplateOutlet` — директива, и ей нужен элемент. Вот и пригодился `ng-container`: лишнего тега внутри `<p>` не появится. `context` — объект со значениями для переменных шаблона; `$implicit` — значение для `let-` без имени, то есть для `let-game`.

Директиву нужно подключить к компоненту:

```ts app.ts {1,5}
import { NgTemplateOutlet } from '@angular/common';

@Component({
  selector: 'app-root',
  imports: [NgTemplateOutlet],
  templateUrl: './app.html',
  styleUrl: './app.css',
})
```

Цены в плитках на месте — теперь их рисует шаблон. Уберите `imports` — цены исчезнут, а в консоли появится знакомая по главе 2 ошибка: ``NG0303: Can't bind to 'ngTemplateOutlet' since it isn't a known property of 'ng-container'``. Без импорта Angular не знает такой директивы.

::: warning
Внутри `<ng-template>` переменные `let-` не типизированы: для проверки шаблонов `game` здесь — `any`. Мы проверили `ngc`: опечатка `{{ game.prise }}` в шаблоне цены компилируется без ошибки, а в плитке она была бы ошибкой. Это ещё одна причина не выносить разметку в `ng-template` без нужды. Для повторяющихся частей интерфейса есть компоненты — с ними вы начнёте работать в следующей главе.
:::

## Где вы встретите `ng-template`

- В старом коде — ветки `else` у `*ngIf` (`<ng-template #noDiscount>`).
- В библиотеках компонентов: таблице передают шаблон ячейки, выпадающему списку — шаблон пункта. Компонент сам решает, где и сколько раз его отрисовать.
- В собственных компонентах, когда часть разметки задаёт тот, кто компонент использует (глава 5).

И главное: **каждый блок** — `@if`, `@for`, `@empty`, `@case` — компилируется в такой же шаблон. Вспомните скомпилированный код из первой главы. Если вывести функцию шаблона сейчас, в ней будут функции с именами вроде `App_For_28_Template` и `App_ForEmpty_29_Template`: тело цикла и тело `@empty`. Angular создаёт из них разметку, когда условие становится истинным или в массиве появляется элемент, — ровно как `NgTemplateOutlet` из `priceTpl`.

Верните код шага кнопкой «Сброс».
