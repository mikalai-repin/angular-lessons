Каталог умеет искать. Настоящей витрине нужно больше: скрыть то, чего нет в наличии, и отсортировать игры по цене или рейтингу. А когда фильтры отсекли всё, покупателю нужен не тупик, а кнопка «Сбросить фильтры».

В коде шага — заготовки: комментарии `TODO` в `app.ts` (где появятся сигналы и методы) и в `app.html` (где встанут фильтры и что поменять в `@empty`). Стили для блока фильтров `.filters` уже в `app.css`.

::: task
1. **Только в наличии.** Над каталогом — флажок «Только в наличии». Когда он включён, игр с `inStock === 0` в каталоге нет.
2. **Сортировка.** Рядом — выпадающий список: «По умолчанию», «Сначала дешёвые», «Сначала дорогие», «По рейтингу».
3. **Пустой каталог.** Ничего не найдено теперь может быть и из-за фильтра, поэтому в `@empty` — нейтральное «Ничего не найдено» и кнопка «Сбросить фильтры». Она очищает поиск, снимает флажок и возвращает сортировку «По умолчанию» — и в сигналах, и **на экране**.
:::

::: hint Подсказка 1: какие сигналы нужны
Два новых изменяемых сигнала: `inStockOnly` (`boolean`) и `sortBy`. Для `sortBy` удобно объявить тип с вариантами: `type SortKey = 'default' | 'cheap' | 'expensive' | 'rating';` и `signal<SortKey>('default')`. Всё остальное по-прежнему вычисляет `visibleGames`: он должен читать и запрос, и флажок, и сортировку.
:::

::: hint Подсказка 2: сортировка и неизменяемость
`Array.prototype.sort` меняет массив, на котором её вызвали. Вызовите её на `GAMES` — испортите общий массив игр, и «По умолчанию» уже не вернёт исходный порядок. Но `filter` всегда возвращает **новый** массив: сортируйте результат фильтрации, и `GAMES` останется нетронутым.
:::

::: hint Подсказка 3: флажок и список в шаблоне
Ссылки на элементы из главы 2 работают и здесь: `<input #inStock type="checkbox" (change)="inStockOnly.set(inStock.checked)" />`. Для `<select #sort>` — `(change)` и `sort.value`. Значение списка — строка, а сигнал ждёт `SortKey`. Приведение типа `as` в шаблоне писать нельзя, поэтому сделайте метод `changeSort(value: string)`, который приводит тип и записывает в сигнал.
:::

::: hint Подсказка 4: почему сброс не очищает поле
Если после «Сбросить фильтры» в поле поиска остался старый текст, хотя `query()` уже пуст, — значит, поле не привязано к сигналу. Обработчик `(input)` передаёт значение из поля в сигнал, но не обратно. Нужна ещё привязка свойства: `[value]="query()"` у поля поиска, `[checked]="inStockOnly()"` у флажка, `[value]="sortBy()"` у списка.
:::

## Итоги главы

| Блок | Что делает |
|---|---|
| `@if (условие) { … } @else if (…) { … } @else { … }` | показывает одну ветку из нескольких; остальных нет в DOM |
| `@if (значение; as имя)` | даёт имя значению условия, сужает тип внутри блока |
| `@for (x of массив; track ключ) { … }` | повторяет разметку для каждого элемента; `track` обязателен |
| `$index`, `$count`, `$first`, `$last`, `$even`, `$odd` | переменные прохода цикла; `let i = $index` — переименование |
| `@empty { … }` | разметка для пустого массива |
| `@switch (x) { @case (…) { … } @default { … } }` | один вариант из нескольких по значению; `@default never;` — проверка, что разобраны все |
| `<ng-container>` | группа без собственного элемента в DOM |
| `<ng-template>` | разметка, которая отрисовывается по требованию |

И главные идеи:

- блоки решают, **какая разметка существует**; привязки — **какие у неё значения**;
- `@if` удаляет разметку целиком, `[hidden]` прячет, сохраняя состояние элементов;
- выражение `track` — это способ узнать элемент массива между проверками. Хороший ключ уникален и постоянен: `id`, а не номер и не копия объекта;
- данные для `@for` удобно готовить в `computed`: поиск, фильтры и сортировка — это вычисление из сигналов, а шаблон только перебирает результат.

Шаблон `app.html` вырос до сотни строк, а плитка каталога и строка корзины — самостоятельные кусочки интерфейса со своей разметкой и логикой. В следующей главе мы вынесем их в **отдельные компоненты** и научим компоненты передавать друг другу данные. А перед ней — необязательный шаг «под капот»: что именно делает `track` с DOM.
