Всё приложение «Хода конём» пока живёт в одном компоненте `App`. Шаблон `app.html` вырос до сотни строк: шапка, поиск, корзина, фильтры, плитки каталога. Плитка — самостоятельный кусочек интерфейса со своей разметкой, стилями и логикой. Такие кусочки в Angular выносят в **отдельные компоненты**.

В этой главе приложение станет деревом компонентов:

```
App
├─ app-rating          фильтр «Рейтинг от»
├─ app-quantity × N    строки корзины
└─ app-game-card × 12  плитки каталога
   └─ app-rating       звёзды игры
```

По ходу дела мы разберёмся, как компоненты передают друг другу данные (входы), как сообщают о событиях (выходы), как работает двусторонняя привязка, как вставить в компонент чужую разметку и как устроены стили компонента.

## Что изменилось в коде

Код — решение практикума главы 4 с такими изменениями:

- в `app.css` больше нет стилей большой карточки из главы 3: её давно нет в шаблоне. Стили плитки собраны в конце файла под комментарием «Плитка каталога». Добавлены стили для того, что появится в этой главе: фильтра по рейтингу и стикеров;
- появилась папка `shared/game-card` с тремя файлами будущего компонента. В `game-card.ts` и `game-card.html` — заготовки с `TODO`, `game-card.css` — готовые стили карточки.

## Компонент — класс с декоратором

Свой компонент мы уже писали: `App` из главы 1. Новый устроен так же — класс с декоратором `@Component`:

```ts shared/game-card/game-card.ts {7-11,13-16}
import { Component } from '@angular/core';
import { GAMES } from '../../core/games-data';

// При каком остатке на складе писать «Осталось N шт.»
const FEW_LEFT = 5;

// Карточка игры в каталоге
@Component({
  selector: 'app-game-card',
  templateUrl: './game-card.html',
  styleUrl: './game-card.css',
})
export class GameCard {
  // Пока карточка всегда показывает первую игру каталога
  protected readonly game = GAMES[0];

  protected readonly fewLeft = FEW_LEFT;
}
```

Разберём, что здесь важно.

- **Селектор** `app-game-card` — имя элемента, которым компонент вставляют в шаблон другого компонента. В имени обязателен дефис: так стандарт HTML отличает свои элементы от встроенных, и ни один будущий тег браузера не совпадёт с вашим. Префикс `app-` — соглашение Angular CLI, в больших проектах его заменяют своим (`shop-`, `admin-`).
- **Имена.** Файл `game-card.ts`, класс `GameCard`. Так называет файлы Angular CLI 22: без суффикса `.component`. Шаблон и стили лежат рядом, пути в `templateUrl` и `styleUrl` — относительно `.ts`-файла.
- **Константа `FEW_LEFT`** переехала из `app.ts`: порог «Осталось N шт.» нужен только карточке.
- **`game = GAMES[0]`** — временное решение. Карточке нужна игра, а как получить её снаружи, мы пока не знаем.

## Шаблон и стили карточки

Шаблон карточки — это разметка плитки из `app.html`, то, что было внутри `@for`:

```html shared/game-card/game-card.html {2,4,6}
<article class="tile" [class.sold-out]="game.inStock === 0">
  <img class="cover" [src]="game.cover" [alt]="game.title" />
  <span class="category">
    <!-- @switch по game.category — без изменений -->
  </span>
  <h2 class="title">{{ game.title }}</h2>
  <!-- цена и строка наличия — без изменений -->
</article>
```

Два отличия от прежней плитки:

- классы стали короче: `cover` и `title` вместо `tile-cover` и `tile-title`. Стили компонента действуют только на его собственный шаблон, поэтому имена не столкнутся с классами других компонентов. Длинные префиксы в именах классов больше не нужны;
- кнопки «В корзину» и строки «В корзине: N шт.» пока нет. Корзина живёт в `App`, и карточка не может до неё дотянуться. Вернём их в шаге про события.

## Вставляем компонент в App

Чтобы `App` мог использовать `<app-game-card>`, его нужно перечислить в `imports` декоратора:

```ts app.ts {1,5}
import { GameCard } from './shared/game-card/game-card';

@Component({
  selector: 'app-root',
  imports: [GameCard],
  templateUrl: './app.html',
  styleUrl: './app.css',
})
```

А в шаблоне на месте плитки остаётся одна строка:

```html app.html {3}
<div class="grid">
  @for (game of visibleGames(); track game.id) {
    <app-game-card />
  } @empty {
    <!-- … без изменений … -->
  }
</div>
```

`<app-game-card />` — самозакрывающийся тег. В HTML так можно писать только пустые элементы вроде `<img>`, а в шаблонах Angular — любые компоненты.

`imports` — список того, что компонент использует в своём шаблоне. Компилятор смотрит в этот список, когда встречает незнакомый тег: есть компонент с подходящим селектором — на месте тега будет он. Глобального реестра компонентов в Angular нет: каждый компонент сам объявляет свои зависимости. Поэтому по коду всегда видно, откуда взялся `<app-game-card>`, а сборщик не включает в приложение то, что нигде не импортировано.

::: task
1. В `game-card.ts` добавьте декоратор и класс `GameCard`, как в коде выше.
2. Перенесите разметку плитки из `app.html` в `game-card.html` — всё содержимое `<article>`. Переименуйте классы `tile-cover` → `cover`, `tile-title` → `title`. Кнопку «В корзину» и строку «В корзине» не переносите.
3. В `app.ts` импортируйте `GameCard` и добавьте его в `imports`. Константа `FEW_LEFT` и поле `fewLeft` из `App` больше не нужны — удалите.
4. В `app.html` замените плитку на `<app-game-card />`. Строка `@let inCartCount` тоже больше не нужна.
5. Удалите из `app.css` блок «Плитка каталога» в конце файла: эти стили теперь в `game-card.css`.
:::

## Что получилось

Каталог снова на месте, но все двенадцать плиток — «Остров сокровищ». При поиске и фильтрах число плиток меняется как положено, а на всех по-прежнему одна и та же игра.

Это ожидаемо. `@for` создаёт двенадцать **экземпляров** компонента `GameCard` — двенадцать объектов класса, у каждого своё поле `game`. Но каждый берёт его из `GAMES[0]`. Переменная `game` из `@for` живёт в шаблоне `App`, и карточка о ней ничего не знает. Передать данные внутрь компонента — задача следующего шага.

Откройте инструменты разработчика и посмотрите на DOM каталога. Внутри `.grid` — двенадцать элементов `<app-game-card>`, а уже в них — `<article>` с разметкой карточки. Элемент, на котором «живёт» компонент, называется **хост-элементом** (host element). С ним мы ещё поработаем в этой главе.

## Эксперимент: забытый `imports`

Уберите `GameCard` из `imports`. Плитки исчезнут, а в консоли появится:

```
NG0304: 'app-game-card' is not a known element (used in the 'App' component template):
1. If 'app-game-card' is an Angular component, then verify that it is included in the '@Component.imports' of this component.
2. If 'app-game-card' is a Web Component then add 'CUSTOM_ELEMENTS_SCHEMA' to the '@Component.schemas' of this component to suppress this message.
```

Для браузера `<app-game-card>` теперь просто неизвестный элемент без содержимого. Верните импорт.

В настоящем проекте эту ошибку покажет сборка, ещё до запуска: `NG8001: 'app-game-card' is not a known element`.

## Эксперимент: стили не проникают внутрь

Вырежьте правило `.tile` из `game-card.css` и вставьте его в конец `app.css`. Плитки потеряют серый фон, а бейджи категорий улетят в левый верхний угол страницы: правило `.tile` задавало им `position: relative`.

Класс `tile` у `<article>` есть, и правило в `app.css` есть. Но стили `App` действуют только на элементы его собственного шаблона, а `<article>` — уже в шаблоне `GameCard`. Это **инкапсуляция стилей**: каждый компонент оформляет только свою разметку. Как Angular этого добивается, разберём в конце главы. Верните правило на место.

::: deep Под капотом: что делает imports
Компилятор превращает `imports` в список зависимостей скомпилированного компонента: в выводе `ngc` у `App` появляется `dependencies: [GameCard]`. Компилируя шаблон, Angular сравнивает каждый элемент с селекторами зависимостей. Совпало — в функции шаблона на этом месте будет не просто элемент DOM, а создание компонента: экземпляр класса, его собственное представление и его функция шаблона. Поэтому «знать» компонент нужно именно на этапе компиляции шаблона, а не во время выполнения.
:::

::: legacy Вы встретите в старом коде: NgModule
```ts
@NgModule({
  declarations: [AppComponent, GameCardComponent],
  imports: [BrowserModule],
  bootstrap: [AppComponent],
})
export class AppModule {}
```
До Angular 14 компонент не мог импортировать другой компонент напрямую: все компоненты объявлялись в модулях `NgModule`, и шаблон видел всё, что объявлено в его модуле и экспортировано импортированными модулями. Найти, откуда взялся тег, было непросто. Потом появились standalone-компоненты (`standalone: true`), а с Angular 19 это значение по умолчанию. Обратите внимание и на имена: `game-card.component.ts` и `GameCardComponent` — так называли файлы и классы до стиля 2025 года.
:::
