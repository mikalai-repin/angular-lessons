Двенадцать одинаковых карточек — потому что компонент сам решает, какую игру показать. А решать должен тот, кто его использует: `App` перебирает игры в `@for` и знает, какая игра на каком месте. Нужен способ передать значение из шаблона родителя в дочерний компонент. Это **вход** (input).

## `input.required()`

```ts shared/game-card/game-card.ts {1,7-8}
import { Component, input } from '@angular/core';
import { Game } from '../../core/models';

// …
export class GameCard {
  // Игра, которую показывает карточка. Без неё карточка не имеет смысла — вход обязательный
  readonly game = input.required<Game>();

  protected readonly fewLeft = FEW_LEFT;
}
```

`input.required<Game>()` объявляет **обязательный вход** с именем `game`. Обратите внимание на три вещи.

- **Вход — это сигнал.** Тип поля — `InputSignal<Game>`, читать его нужно вызовом: `game()`. Значит, в шаблоне карточки `game.title` превращается в `game().title`, и так везде.
- **Его меняет только Angular.** Метода `set` у входа нет. Попробуйте написать в классе `this.game.set(…)` — TypeScript ответит `Property 'set' does not exist on type 'InputSignal<Game>'`. Данные текут сверху вниз: значение входа задаёт родитель.
- **Модификаторы.** Вход — публичный: его использует шаблон родителя. `readonly` — потому что само поле никто не переприсваивает, а значение внутри сигнала обновляет Angular. Так советует руководство по стилю Angular для всего, что задаёт фреймворк: входов, выходов, запросов.

Импорт `GAMES` карточке больше не нужен, а `Game` — нужен для типа.

## Привязка ко входу

Родитель передаёт значение привычной привязкой свойства в квадратных скобках:

```html app.html {3}
<div class="grid">
  @for (game of visibleGames(); track game.id) {
    <app-game-card [game]="game" />
  } <!-- … -->
</div>
```

В главе 2 `[src]` записывала значение в свойство DOM. Здесь у элемента есть компонент, и `[game]` попадает во вход `GameCard`. Слева — имя входа карточки, справа — выражение в контексте `App`: переменная `game` из `@for`.

Когда выражение справа даёт новое значение, Angular записывает его во вход. Карточка читает `game()` в шаблоне, поэтому её шаблон обновится — ровно так же, как любой шаблон, прочитавший изменившийся сигнал.

## Необязательный вход: `input()`

Карточке пригодится ещё одно значение — сколько штук этой игры уже в корзине. Вход необязательный: карточку можно показать и вне магазина с корзиной. Для таких входов — `input(значение по умолчанию)`:

```ts shared/game-card/game-card.ts {3-4}
export class GameCard {
  readonly game = input.required<Game>();
  // Сколько штук этой игры уже в корзине
  readonly inCart = input(0);
  // …
}
```

Тип `number` TypeScript выводит из значения по умолчанию. В шаблоне карточки вернём строку, которую мы убрали в прошлом шаге:

```html shared/game-card/game-card.html
@if (inCart() > 0) {
  <p class="in-cart muted">В корзине: {{ inCart() }} шт.</p>
}
```

А в `App` передадим количество из словаря `inCart`:

```html app.html
<app-game-card [game]="game" [inCart]="inCart().get(game.id) ?? 0" />
```

Не запутайтесь: слева `inCart` — вход карточки, справа `inCart()` — вычисляемый сигнал `App` со словарём «id игры → количество». У разных компонентов свои имена, и совпадать они могут.

::: warning `@switch` с `@default never;` и сигналы
В шаблоне карточки бейдж категории — `@switch` с проверкой полноты `@default never;`. Если написать `@switch (game().category)`, превью ничего не заметит, а проверка шаблонов в настоящем проекте выдаст ошибку `TS2322: Type '"family" | … | "kids"' is not assignable to type 'never'`. Компилятор сужает тип у переменной, но не у результата вызова функции: он не знает, что каждый вызов `game()` вернёт одно и то же. Мы уже встречали это с `@if … as` в главе 4. Решение — сохранить значение в переменную шаблона:

```html
@let category = game().category;
<span class="category">
  @switch (category) {
    <!-- @case — как раньше -->
  }
</span>
```
:::

::: task
1. В `GameCard` замените поле `game` на обязательный вход `input.required<Game>()`, добавьте вход `inCart = input(0)`.
2. В шаблоне карточки замените `game.` на `game().`; для `@switch` заведите `@let category`, как во врезке выше.
3. Добавьте в карточку строку «В корзине: N шт.» с `@if (inCart() > 0)`.
4. В `app.html` передайте карточке `[game]` и `[inCart]`.
:::

## Что получилось

Каталог как в главе 4: у каждой карточки своя игра, поиск и фильтры работают.

Строку «В корзине» пока не увидеть: кнопки «В корзину» нет. Проверим вход по-другому. В `app.ts` задайте корзине начальное значение: `signal<CartItem[]>([{ game: GAMES[0], quantity: 2 }])`. На карточке «Острова сокровищ» появится «В корзине: 2 шт.», в шапке — «2 · 3980 ₽». Нажмите «+» в мини-корзине — число на карточке тоже вырастет: `App` пересчитал `inCart`, а привязка передала новое значение во вход. Верните `[]`.

## Эксперимент: забытый обязательный вход

Уберите `[game]="game"` из `app.html`. Каталог исчезнет целиком, а в консоли появится:

```
ERROR RuntimeError: NG0950: Input is required but no value is available yet.
```

Первая же карточка попыталась прочитать `game()`, а значения нет. В превью это ошибка во время выполнения, и имени входа в ней нет. Настоящий проект найдёт её при сборке и назовёт точно:

```
NG8008: Required input 'game' from component GameCard must be specified.
```

Ещё два случая, которые сборка в настоящем проекте поймает точнее превью:

- опечатка `[gmae]="game"`: в превью — `NG0303: Can't bind to 'gmae' since it isn't a known property of 'app-game-card'` и следом та же NG0950: входа `game` ведь нет. При сборке — `NG8002` с тем же текстом и `NG8008`;
- не тот тип, `[game]="game.title"`: превью передаст строку молча, и от карточек останется только «₽ В наличии». При сборке — `TS2322: Type 'string' is not assignable to type 'Game'`.

Верните `[game]="game"`.

::: deep Под капотом: как значение попадает во вход
В скомпилированном шаблоне `App` привязки к карточке — обычная инструкция привязки свойства в блоке обновления: `ɵɵproperty("game", game_r13)("inCart", ctx.inCart().get(game_r13.id) ?? 0)`. Во время проверки шаблона `App` Angular сравнивает новое значение с прошлым. Изменилось — и элемент оказался хостом компонента с таким входом — значение записывается в узел сигнала-входа (`applyValueToInputSignal` → `signalSetFn`). Дальше всё как в главе 3: узел уведомляет потребителей, а потребитель — шаблон карточки — помечает её представление для обновления. Поэтому сигнальный вход работает с OnPush без всяких дополнительных усилий.
:::

::: legacy Вы встретите в старом коде: @Input()
```ts
export class GameCardComponent {
  @Input({ required: true }) game!: Game;
  @Input() inCart = 0;
}
```
До сигнальных входов (они появились в Angular 17.1 и стали стабильными в 19) входом было обычное поле с декоратором `@Input()`. В шаблоне — `game.title` без скобок. Чтобы отреагировать на новое значение, писали сеттер или хук `ngOnChanges` (глава 6), а вычисления на основе входа делали вручную. С сигнальным входом достаточно `computed(() => …this.game()…)`.
:::
