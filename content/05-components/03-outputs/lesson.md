Карточке пора вернуть кнопку «В корзину». Но корзина — сигнал `cart` в `App`, а кнопка — в шаблоне `GameCard`. Как связать их?

Можно было бы передать карточке всю корзину входом и менять её изнутри. Но тогда карточка будет знать, как устроена корзина, и её нельзя будет показать там, где корзины нет. Правильнее разделить обязанности: карточка только **сообщает**, что покупатель нажал кнопку, а что с этим делать, решает родитель. Для таких сообщений у компонента есть **выходы** (outputs) — собственные события.

## `output()`

```ts shared/game-card/game-card.ts {1,6-7}
import { Component, input, output } from '@angular/core';

export class GameCard {
  readonly game = input.required<Game>();
  readonly inCart = input(0);
  // Покупатель нажал «В корзину». Что с этим делать, решает родитель
  readonly add = output();
  // …
}
```

`output()` создаёт объект `OutputEmitterRef`. У него один метод для компонента — `emit()`: «событие произошло». Вызываем его по нажатию кнопки:

```html shared/game-card/game-card.html {1}
<button class="button" [disabled]="inCart() >= game().inStock" (click)="add.emit()">В корзину</button>
@if (inCart() > 0) {
  <p class="in-cart muted">В корзине: {{ inCart() }} шт.</p>
}
```

Кнопка неактивна, когда в корзине уже весь остаток со склада, — как в главе 4, только количество теперь приходит входом.

## Подписка на событие

Родитель слушает событие компонента так же, как событие DOM, — круглыми скобками:

```html app.html {4}
<app-game-card
  [game]="game"
  [inCart]="inCart().get(game.id) ?? 0"
  (add)="addToCart(game)"
/>
```

Когда карточка вызывает `add.emit()`, Angular выполняет обработчик `addToCart(game)` в контексте `App`. Метод `addToCart` из главы 4 менять не нужно: он и так принимает игру.

Получилась схема, по которой связаны почти все компоненты Angular:

```
          App
   [game] │  ▲ (add)
 [inCart] ▼  │
        GameCard
```

**Данные идут вниз — входами, события вверх — выходами.** Состояние (корзина) живёт у родителя, дочерний компонент его показывает и сообщает о намерениях.

## Событие с данными: `$event`

Наше событие ничего не несёт: родитель и так знает, какую игру показывает карточка. Но выход может передавать значение. Тип указывают в угловых скобках, значение — в `emit`, а в обработчике родителя оно доступно как `$event`:

```ts
readonly add = output<Game>();
// …
this.add.emit(this.game());
```

```html
<app-game-card [game]="game" (add)="addToCart($event)" />
```

Тот самый `$event`, что в главе 2 был объектом события DOM. Для выхода без типа (`output()`) это `void`. Если написать `(add)="addToCart($event)"` с нашим выходом, проверка шаблонов в настоящем проекте ответит `TS2345: Argument of type 'void' is not assignable to parameter of type 'Game'`.

1. Добавьте в `GameCard` выход `add = output()`.
2. Верните в шаблон карточки кнопку «В корзину» с `[disabled]` и `(click)="add.emit()"` — перед строкой «В корзине».
3. В `app.html` подпишитесь на событие: `(add)="addToCart(game)"`.

## Что получилось

Магазин снова работает полностью. Нажмите «В корзину» у «Ночного экспресса» три раза: на карточке «В корзине: 3 шт.», кнопка погасла, в мини-корзине строка, в шапке «3 · 9570 ₽».

Чем выход отличается от события DOM:

- **не всплывает.** Событие `click` поднимается от кнопки по всем предкам. Событие компонента слышит только тот, в чьём шаблоне стоит `<app-game-card>`. Компоненты выше по дереву о нём не узнают: если родитель хочет передать событие дальше, он объявляет свой выход;
- **синхронно.** `emit()` вызывает обработчики родителя сразу, прямо внутри себя. Строка после `emit()` выполнится, когда корзина уже обновлена;
- **без `preventDefault` и прочего.** Это не объект `Event`, а просто вызов функций-подписчиков.

## Эксперимент: имя как у события DOM

Документация Angular советует не называть выходы как события DOM. Проверим почему. Переименуйте выход в `click`: `readonly click = output();`, в шаблоне карточки — `click.emit()`, в `app.html` — `(click)="addToCart(game)"`.

Нажмите «В корзину» у «Драконьей почты» один раз — в корзине сразу 2 штуки. Щёлкните по обложке — 3. Привязка `(click)` на `<app-game-card>` слушает и выход компонента, и обычный `click`, всплывающий от любого элемента внутри карточки. Кнопка вызвала оба.

Заметьте и другое: в консоли после нажатия кнопки одна строка — `Корзина: Драконья почта × 2`. Два обновления корзины произошли в одном обработчике, и эффект из главы 3 выполнился один раз.

Верните имя `add`. Остальные советы документации об именах: без префикса `on` (`add`, а не `onAdd`) и в camelCase.

::: legacy Вы встретите в старом коде: @Output() и EventEmitter
```ts
@Output() add = new EventEmitter<void>();
```
До Angular 17.3 выход объявляли декоратором `@Output()` над полем с `EventEmitter` — это подкласс `Subject` из RxJS. Работает так же: `this.add.emit()` в компоненте, `(add)="…"` у родителя. Из-за наследования от `Subject` на него можно было подписаться через `subscribe` и применять операторы RxJS — этим часто злоупотребляли, и `EventEmitter` появлялся в сервисах, где ему не место. `output()` проще и не тянет RxJS.
:::
