В главе 4 рейтинг из плитки пропал. Вернём его звёздами — и сразу сделаем компонент, который умеет не только показывать оценку, но и выбирать её. Он понадобится в двух местах:

- в карточке — показать рейтинг игры;
- в фильтрах — «Рейтинг от ★★★★½»: покупатель щёлкает по звёздам, и каталог оставляет игры не ниже выбранной оценки.

У фильтра данные ходят в обе стороны. `App` задаёт значение (кнопка «Сбросить фильтры» обнуляет звёзды), а компонент сообщает, что покупатель выбрал другое. Это **двусторонняя привязка** (two-way binding).

## Что изменилось в коде

Появилась папка `shared/rating`: в `rating.ts` и `rating.html` — заготовки, `rating.css` — готовые стили звёзд. Звезда — пустой `<span class="star">`, символ ★ рисует CSS. Класс `full` закрашивает звезду целиком, `half` — левую половину.

## Вход и выход вместе

Из прошлых шагов мы уже можем собрать двустороннюю связь: вход `value` и выход `valueChange`, через который компонент сообщает новое значение. Родитель передаёт значение вниз и на каждое событие записывает новое значение к себе. Связка встречается так часто, что для неё есть отдельная функция — `model()`:

```ts shared/rating/rating.ts {1,9-10}
import { Component, model } from '@angular/core';

@Component({
  selector: 'app-rating',
  templateUrl: './rating.html',
  styleUrl: './rating.css',
})
export class Rating {
  // Оценка от 0 до 5. Родитель может и задать её, и узнать, что её изменили
  readonly value = model(0);

  protected readonly stars = [1, 2, 3, 4, 5];

  protected select(star: number, event: MouseEvent) {
    // Щелчок по левой половине звезды — половина звезды
    const rect = (event.currentTarget as HTMLElement).getBoundingClientRect();
    const selected = event.clientX - rect.left < rect.width / 2 ? star - 0.5 : star;
    // Повторный щелчок по той же оценке сбрасывает её
    this.value.update((value) => (value === selected ? 0 : selected));
  }
}
```

`model(0)` — это **модель**: изменяемый сигнал (`ModelSignal<number>`), который одновременно и вход, и выход.

- Как вход он называется `value`: родитель может написать `[value]="…"`.
- Как выход он называется `valueChange` — имя входа плюс `Change`. Каждое изменение через `set` или `update` внутри компонента отправляет событие `valueChange` с новым значением. Если записать то же самое значение, события не будет.
- Внутри компонента это обычный изменяемый сигнал: `value()`, `value.set(…)`, `value.update(…)`.

Метод `select` получает номер звезды и объект события щелчка. Сравнивая координату щелчка `clientX` с положением звезды на экране (`getBoundingClientRect()`), он узнаёт, по какой половине щёлкнули: левая половина пятой звезды даёт `4.5` вместо `5`. Повторный щелчок по той же оценке сбрасывает её в `0` — «любой рейтинг».

Шаблон рисует пять звёзд:

```html shared/rating/rating.html
@for (star of stars; track star) {
  <span
    class="star"
    [class.full]="star <= value()"
    [class.half]="star - 0.5 <= value() && value() < star"
    (click)="select(star, $event)"
  ></span>
}
```

При рейтинге `4.6` четыре звезды закрашены целиком, а пятая — наполовину: `4.5 <= 4.6 < 5`.

## `[(value)]`

В фильтрах `App` заводит сигнал и связывает его с моделью:

```ts app.ts
protected readonly minRating = signal(0);
```

```html app.html {3}
<span class="rating-filter">
  Рейтинг от
  <app-rating [(value)]="minRating" />
</span>
```

`[(value)]` — привязка «в квадратных и круглых скобках сразу», в англоязычной документации её называют «банан в коробке». Это сокращение для двух привязок:

```html
<app-rating [value]="minRating()" (valueChange)="minRating.set($event)" />
```

Обратите внимание: в `[(value)]` пишут сам сигнал, **без вызова** — `minRating`, а не `minRating()`. Angular нужен не текущий результат, а сигнал, в который можно записать новое значение. Напишите `[(value)]="minRating()"` — шаблон не скомпилируется: `Unsupported expression in a two-way binding`. Справа от `[( )]` может стоять изменяемый сигнал или поле, которому можно присвоить значение.

Осталось учесть `minRating` в `visibleGames` и сбрасывать его в `resetFilters`:

```ts app.ts {3}
(game.title.toLowerCase().includes(query) || game.tags.some((tag) => tag.includes(query))) &&
  (!this.inStockOnly() || game.inStock > 0) &&
  game.rating >= this.minRating(),
```

## Звёзды в карточке

Карточке двусторонняя связь не нужна: рейтинг игры она только показывает. Модель — это ещё и обычный вход, поэтому можно привязать только одну сторону:

```html shared/game-card/game-card.html
<h2 class="title">{{ game().title }}</h2>
<app-rating [value]="game().rating" />
```

Не забудьте добавить `Rating` в `imports` карточки — шаблон `GameCard` теперь использует `<app-rating>`. И в `imports` `App`, для фильтра.

::: task
1. Напишите компонент `Rating`: `model(0)`, массив `stars`, метод `select` и шаблон с пятью звёздами, как в коде выше.
2. В `App`: сигнал `minRating`, фильтр по нему в `visibleGames`, сброс в `resetFilters`. В `app.html` — блок «Рейтинг от» с `[(value)]="minRating"` между флажком и сортировкой.
3. В карточке под названием — `<app-rating [value]="game().rating" />`. Импортируйте `Rating` в обоих компонентах.
:::

## Что получилось

У каждой карточки звёзды: у «Шахмат» 4,9 — четыре с половиной, у «Тихой охоты» 4,1 — четыре.

В фильтре щёлкните по левой половине пятой звезды: «Рейтинг от 4,5», в каталоге 7 игр. По правой половине — 5, никого: «Ничего не найдено». Ещё раз по ней же — оценка сброшена, снова все 12. Выберите что-нибудь и нажмите «Сбросить фильтры» — звёзды погаснут: `App` записал `0` в `minRating`, а привязка передала его в модель.

## Эксперимент: односторонняя привязка к модели

Щёлкните по второй звезде в карточке «Драконьей почты». Звёзд стало две! Рейтинг игры в данных — по-прежнему 4,3. Модель карточки поменяла **своё** значение и отправила `valueChange`, но никто его не слушает: привязка `[value]` — односторонняя. Отсортируйте каталог — две звезды так и остались: `track game.id` сохранил компонент, а вход не изменился, и Angular не перезаписал его. Значение придёт сверху, только когда изменится `game().rating`.

Для карточки это ошибка: показывать рейтинг можно, менять — нельзя. Исправим в следующем шаге.

## Модель или копия входа

Иногда компоненту нужно как раз такое поведение: начать со значения родителя, дать пользователю его поменять, но родителю не сообщать — например, черновик, который потом отправят отдельной кнопкой. Для этого не нужна модель. Подойдёт вход и связанный сигнал из главы 3:

```ts
readonly value = input(0);
// Своя копия: меняется локально, сбрасывается, когда родитель передал новое значение
protected readonly current = linkedSignal(() => this.value());
```

Мы проверили: после `current.set(1)` у компонента `1`, у родителя прежнее значение, а когда родитель передаёт новое — `current` снова равен ему.

Правило простое: **модель** — когда значение общее у родителя и компонента и родитель должен знать об изменениях; **вход + `linkedSignal`** — когда это личный черновик компонента. Для обязательной модели есть `model.required<T>()` — пригодится в практикуме.

::: deep Под капотом: во что компилируется [(value)]
В выводе `ngc` для `App` двусторонняя привязка — две инструкции. В блоке обновления: `ɵɵtwoWayProperty("value", ctx.minRating)` — в модель передаётся сам сигнал, Angular прочитает его значение. В блоке создания — обработчик события:

```js
ɵɵtwoWayListener("valueChange", function ($event) {
  ɵɵtwoWayBindingSet(ctx.minRating, $event) || (ctx.minRating = $event);
  return $event;
});
```

`ɵɵtwoWayBindingSet` проверяет, изменяемый ли это сигнал. Если да — вызывает `set` и возвращает `true`. Если нет — срабатывает вторая половина: обычное присваивание полю. Поэтому `[(x)]` работает и с сигналами, и с простыми полями.
:::

::: legacy Вы встретите в старом коде: пара @Input и @Output
```ts
@Input() value = 0;
@Output() valueChange = new EventEmitter<number>();

select(star: number) {
  this.value = star;
  this.valueChange.emit(star);
}
```
До `model()` двустороннюю привязку собирали вручную: вход и выход с тем же именем плюс `Change`. Синтаксис `[(value)]` у родителя был тем же самым. Ещё одна частая встреча в старом коде — `[(ngModel)]` на полях ввода: это двусторонняя привязка директивы `NgModel` из шаблонных форм (глава 13).
:::
