Магазину нужны стикеры на обложках: «Хит» для игр с рейтингом от 4,8 и «Скидка» для игр со старой ценой. Где-то потом появятся «Новинка» и «Последний экземпляр».

Можно научить карточку рисовать стикеры сама. Но правила «что считать хитом» — решение витрины, а не карточки: на другой странице хитом может быть другое. Можно передавать карточке массив строк входом — но тогда родитель не сможет ни оформить стикер по-своему, ни добавить в него значок. Удобнее, когда родитель передаёт **готовую разметку**, а карточка решает только, **где** её показать. Это **проекция содержимого** (content projection).

## `<ng-content>`

Всё, что написано между открывающим и закрывающим тегом компонента, — его **содержимое**:

```html
<app-game-card [game]="game">
  <span class="sticker">Хит</span>
</app-game-card>
```

По умолчанию Angular это содержимое не показывает: у компонента свой шаблон. Чтобы показать, в шаблоне компонента ставят `<ng-content />` — место, куда Angular перенесёт содержимое:

```html shared/game-card/game-card.html
<div class="stickers">
  <ng-content />
</div>
```

`<ng-content>` — не настоящий элемент: в DOM его не будет, только перенесённые узлы. Место, куда попадает содержимое, называется **слотом**.

## Несколько слотов: `select`

В карточке может появиться и другое содержимое, которому место не на обложке. Поэтому слот для стикеров сделаем именным: `select` — это CSS-селектор, по которому Angular выбирает, что положить в слот.

```html shared/game-card/game-card.html {2}
<div class="stickers">
  <ng-content select="[sticker]" />
</div>
```

`[sticker]` — элементы с атрибутом `sticker`. Подойдёт любой простой селектор: тег (`select="h3"`), класс (`select=".sticker"`), атрибут. Слотов может быть сколько угодно. Правила такие:

- элемент попадает в первый слот, селектору которого он соответствует;
- всё, что не подошло ни одному `select`, попадает в слот без `select` — `<ng-content />`;
- если такого слота нет, неподошедшее содержимое **не показывается** вообще.

## Стикеры в App

```html app.html {6-11}
@for (game of visibleGames(); track game.id) {
  <app-game-card
    [game]="game"
    [inCart]="inCart().get(game.id) ?? 0"
    (add)="addToCart(game)">
    @if (game.rating >= hitRating) {
      <span sticker class="sticker">Хит</span>
    }
    @if (game.oldPrice) {
      <span sticker class="sticker sale">Скидка</span>
    }
  </app-game-card>
}
```

```ts app.ts
// С какого рейтинга игра получает стикер «Хит»
const HIT_RATING = 4.8;

// … в классе App:
protected readonly hitRating = HIT_RATING;
```

Атрибут `sticker` — без значения, только метка для слота. Классы `sticker` и `sale` оформлены в `app.css`. Не в `game-card.css`, а именно в стилях `App`: содержимое пишет родитель, оно часть **его** шаблона. Выражения внутри (`game.rating`, `hitRating`) вычисляются в контексте `App`, обработчики событий в нём вызывали бы методы `App`, и стили к нему применяются тоже от `App`. Карточка только выделила место. Положение этого места — угол обложки — задаёт уже карточка, правилом `.stickers` в `game-card.css`.

## `@if` в содержимом

Вокруг стикеров — блоки `@if`. Angular умеет проецировать их в именной слот, если у блока **один** корневой элемент: слот выбирается по нему. Если корневых элементов два:

```html
@if (game.rating >= hitRating) {
  <span sticker class="sticker">Хит</span>
  <span sticker class="sticker">★</span>
}
```

— блок целиком уходит в слот по умолчанию. У нашей карточки его нет, и в превью стикер «Хит» просто исчезнет, без единой ошибки. Проверка шаблонов в настоящем проекте предупредит:

```
warning NG8011: Node matches the "[sticker]" slot of the "GameCard" component, but will not be
projected into the specific slot because the surrounding @if has more than one node at its root.
```

и предложит варианты: обернуть содержимое блока в `<ng-container sticker>` или разбить его на несколько `@if`.

::: task
1. В шаблоне карточки после бейджа категории добавьте `<div class="stickers">` со слотом `<ng-content select="[sticker]" />`.
2. В `app.ts` — константа `HIT_RATING` и поле `hitRating`.
3. В `app.html` перепишите `<app-game-card … />` с открывающим и закрывающим тегом и добавьте внутрь стикеры «Хит» и «Скидка», как в коде выше.
:::

## Что получилось

У «Ночного экспресса» два стикера, «Хит» и «Скидка». У «Шахмат» и «Го» — «Хит», у «Острова сокровищ» и «Нард» — «Скидка». Остальные без стикеров.

## Эксперимент: содержимое без слота

Добавьте внутрь `<app-game-card>` после стикеров строку `<p class="muted">Подарочная упаковка</p>`. На странице её нет: атрибута `sticker` у неё нет, а слота по умолчанию у карточки нет. Добавьте в конец шаблона карточки `<ng-content />` — строка появится в каждой карточке под кнопкой. Уберите и то, и другое.

## Запасное содержимое

Внутри `<ng-content>` можно написать **запасное содержимое** (fallback content) — оно покажется, если в слот ничего не попало:

```html
<ng-content select="[sticker]">
  <span class="sticker-none">без стикеров</span>
</ng-content>
```

Попробуйте — и, скорее всего, удивитесь: у карточек без стикеров надписи нет. Мы проверили: запасное содержимое видно, только если в слот не попало **ни одного узла**. А блоки `@if` попадают в слот всегда, даже с ложным условием: на их месте остаётся служебный комментарий `<!--container-->`, куда Angular вставит разметку, когда условие станет истинным. У карточки, внутри которой совсем ничего нет, запасной текст появится.

::: deep Под капотом: когда создаётся содержимое
Содержимое — часть шаблона родителя, поэтому и создаёт его родитель: в скомпилированном шаблоне `App` стикеры — такие же инструкции, как всё остальное внутри `@for`. Дочерний компонент получает уже готовые узлы и инструкцией `ɵɵprojection` переносит их в свои слоты. Распределение по слотам компилятор знает заранее: у `GameCard` в описании есть список селекторов слотов (`ngContentSelectors`), а `ɵɵprojectionDef` раскладывает содержимое по ним. Отсюда и правило про `@if` с одним корнем: компилятор смотрит на корневой элемент блока, чтобы решить, в какой слот положить весь блок.
:::
