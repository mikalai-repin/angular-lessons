Посмотрите на DOM карточки:

```html
<app-game-card>
  <article class="tile">
    <img class="cover" …>
    …
```

Два элемента там, где хватило бы одного. `<app-game-card>` ничего не делает: просто обёртка вокруг `<article>`. Из-за неё понадобились `height: 100%` и `box-sizing` в стилях `.tile` — чтобы `<article>` растянулся на всю ячейку сетки. Пусть плиткой будет сам хост-элемент.

## Плитка — это хост

Первая мысль — поставить класс `tile` на хост через `host: { class: 'tile' }`. Попробуйте: класс у `<app-game-card>` появится, а серого фона не будет. Правило `.tile` из `game-card.css` описывает элементы **шаблона** карточки, а хост — не часть шаблона: он стоит в шаблоне `App`. Как Angular различает «свои» и «чужие» элементы, разберём в следующем шаге «под капотом». Для хоста есть `:host`, мы видели его в прошлом шаге:

```css shared/game-card/game-card.css {1,12,17}
:host {
  position: relative;
  display: flex;
  flex-direction: column;
  align-items: flex-start;
  gap: 4px;
  padding: 8px;
  border-radius: var(--radius);
  background: var(--surface);
}

:host(.sold-out) .cover {
  filter: grayscale(1);
  opacity: 0.6;
}

:host(.sold-out) .price {
  color: var(--muted);
}
```

`height: 100%` и `box-sizing` больше не нужны: хост сам — ячейка сетки, и сетка растягивает его на всю высоту ряда.

Класс `sold-out` теперь тоже должен оказаться на хосте — привязкой хоста. А `<article>` давал карточке смысл для программ чтения с экрана: «это статья». Сохраним его статическим атрибутом `role`:

```ts shared/game-card/game-card.ts {6-9}
@Component({
  selector: 'app-game-card',
  imports: [Rating],
  templateUrl: './game-card.html',
  styleUrl: './game-card.css',
  host: {
    role: 'article',
    '[class.sold-out]': 'game().inStock === 0',
  },
})
```

::: task
1. В `game-card.html` уберите обёртку `<article>` — содержимое остаётся на месте, просто на уровень выше.
2. В `game-card.ts` добавьте `host` с `role` и привязкой класса `sold-out`.
3. В `game-card.css` замените `.tile` на `:host` и удалите `box-sizing` и `height`; `.sold-out .cover` и `.sold-out .price` замените на `:host(.sold-out) …`.
:::

## Что получилось

Внешне ничего не изменилось — и это успех: та же сетка, «Маяк» серый, кнопки стоят на одной линии. Зато в DOM карточка — один элемент `<app-game-card role="article">` со всем содержимым внутри.

## Что куда достаёт

Соберём правила, которые мы встретили за главу:

| Чьи стили | На что действуют |
|---|---|
| компонента (`styleUrl`) | только на элементы его шаблона; на хост — через `:host` |
| родителя | на хост-элемент дочернего компонента (он в шаблоне родителя), но не внутрь него |
| родителя | на содержимое, которое родитель передал через `<ng-content>` (стикеры) |
| глобальные (`styles.css`) | на всю страницу, в том числе внутрь компонентов: `.button`, `.muted` в карточке |

И отдельно — **переменные CSS** (`var(--brand)`): они наследуются по дереву DOM и сквозь любые границы компонентов. Поэтому общие цвета магазина объявлены один раз в `:root` глобальных стилей, а пользуются ими все компоненты.

## Режимы инкапсуляции

То, что стили компонента не выходят за его пределы, — **эмулированная инкапсуляция** (`ViewEncapsulation.Emulated`), режим по умолчанию. Его можно поменять опцией `encapsulation` в декораторе. Значений четыре:

- `Emulated` — по умолчанию, как сейчас;
- `None` — стили компонента становятся глобальными;
- `ShadowDom` — настоящий теневой DOM браузера (shadow DOM);
- `ExperimentalIsolatedShadowDom` — теневой DOM, полностью отгороженный от внешних стилей, включая глобальные. Экспериментальный, появился в Angular 21.

Проверим два из них на карточке. Импортируйте `ViewEncapsulation` из `@angular/core` и добавьте в декоратор `GameCard`:

```ts
encapsulation: ViewEncapsulation.None,
```

Карточки потеряют серый фон, а бейджи категорий и стикеры соберутся в шапке. Без инкапсуляции `:host` ничего не означает, и правило не находит ни одного элемента: плитка без фона и без `position: relative`, и всё, что позиционировано абсолютно, улетает к краю страницы. А правила `.title`, `.price`, `.stock` из `game-card.css` теперь действуют на любой элемент с таким классом во всём приложении — короткие имена классов снова опасны.

Теперь замените `None` на `ShadowDom`. Плитки на месте, но кнопка «В корзину» стала серой системной кнопкой. Angular создал у каждого `<app-game-card>` теневой корень (shadow root) — отдельное поддерево DOM, куда стили страницы не проникают. Глобальный `.button` из `styles.css` остался снаружи. А серый фон и цвета на месте: переменные CSS через теневую границу наследуются. Стикеры тоже оформлены, хотя их стили в `app.css`, — как так получается, увидим в следующем шаге.

Уберите `encapsulation`. Эмулированная инкапсуляция — правильный выбор почти всегда. `ShadowDom` нужен в основном для веб-компонентов, которые встраивают в чужие страницы.

::: legacy Вы встретите в старом коде: ::ng-deep
```css
:host ::ng-deep .star {
  font-size: 24px;
}
```
`::ng-deep` отключает инкапсуляцию для части селектора: такое правило в стилях карточки достало бы до звёзд внутри `<app-rating>`. Его до сих пор много в проектах, которые подправляют чужие компоненты, например из Angular Material. Компилятор 22.2 его по-прежнему понимает, но документация Angular прямо пишет, что команда «настоятельно не рекомендует» новое использование: оно оставлено для обратной совместимости. Вместо него — входы компонента, переменные CSS или глобальные стили.
:::
