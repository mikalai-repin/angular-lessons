За главу мы несколько раз опирались на одно правило: стили компонента действуют только на его шаблон. В браузере такого механизма нет — `<style>` на странице действует на всю страницу. В этом шаге разберём, как Angular этого добивается. Шаг необязательный, кода в нём писать не нужно: только смотреть в инструменты разработчика.

## Метки на элементах

Откройте в инструментах разработчика DOM каталога и посмотрите на карточку «Ночного экспресса». Без лишнего у нас получилось так:

```html
<app-root _nghost-ng-c4255422415>
  …
  <app-game-card _ngcontent-ng-c4255422415 _nghost-ng-c402049626 role="article">
    <img _ngcontent-ng-c402049626 class="cover" …>
    <div _ngcontent-ng-c402049626 class="stickers">
      <span _ngcontent-ng-c4255422415 sticker class="sticker">Хит</span>
      …
    </div>
    <app-rating _ngcontent-ng-c402049626 _nghost-ng-c3744458125 readonly …>
      <span _ngcontent-ng-c3744458125 class="star full"></span>
```

У каждого компонента есть идентификатор: `c4255422415` у `App`, `c402049626` у `GameCard`, `c3744458125` у `Rating`. Префикс `ng` — идентификатор приложения (`APP_ID`, по умолчанию `ng`). Ваши числа могут отличаться: идентификатор — хеш описания компонента (селектора, входов, выходов, числа элементов шаблона…), и любая правка в шаблоне его меняет.

Angular ставит два вида атрибутов:

- `_ngcontent-<id>` — на каждый элемент, созданный шаблоном компонента `<id>`;
- `_nghost-<id>` — на хост-элемент компонента `<id>`.

Теперь видно всё, что мы наблюдали за главу:

- у `<app-game-card>` два атрибута: `_ngcontent` от `App` (тег стоит в шаблоне `App`) и `_nghost` от `GameCard`. Поэтому родитель может стилизовать хост, а сам компонент — через `:host`;
- стикер лежит внутри карточки, но помечен `_ngcontent` от `App`: его создал шаблон `App`. Поэтому к нему применяются стили `app.css`;
- внутри `<app-rating>` элементы помечены уже идентификатором `Rating`, и стили карточки до них не дотянутся.

## Переписанный CSS

Вторая половина механизма — стили. Найдите в `<head>` превью элементы `<style>`: по одному на каждый компонент, плюс глобальные. Селекторы в них переписаны. Из `game-card.css`:

```css
[_nghost-ng-c402049626] { … }                                         /* :host */
.cover[_ngcontent-ng-c402049626] { … }                                /* .cover */
.sold-out[_nghost-ng-c402049626] .cover[_ngcontent-ng-c402049626] { … } /* :host(.sold-out) .cover */
```

Из `rating.css`:

```css
.star[_ngcontent-ng-c3744458125]::before { … }
[_nghost-ng-c3744458125]:focus-visible { … }
.readonly[_nghost-ng-c3744458125] .star[_ngcontent-ng-c3744458125] { … }
```

К каждому простому селектору дописан атрибут компонента: `_ngcontent` к элементам шаблона, `_nghost` вместо `:host`. Псевдоэлементы вроде `::before` остаются в конце. Правило `.cover[_ngcontent-ng-c402049626]` подходит только к элементам с классом `cover`, созданным шаблоном карточки. Отсюда все эффекты главы:

- правило `.tile` в `app.css` превратилось в `.tile[_ngcontent-<id App>]` и не нашло `<article>` карточки;
- `host: { class: 'tile' }` не помог: у хоста нет `_ngcontent-<id GameCard>`, только `_nghost`;
- в режиме `None` переписывания нет: `.cover` действует на всю страницу, а `:host` остаётся как есть и в обычном DOM ничего не означает.

Заметьте побочный эффект: атрибут повышает специфичность селектора. `.button[_ngcontent-…]` из стилей компонента (класс + атрибут) сильнее глобального `.button` (только класс), поэтому стили компонента обычно перекрывают глобальные без всяких `!important`.

Это и называется **эмулированной** инкапсуляцией: Angular изображает изоляцию теневого DOM обычными атрибутами и переписанными селекторами.

## Когда стили появляются в `<head>`

Стили компонента добавляются в `<head>`, когда создаётся его первый экземпляр, и по умолчанию удаляются, когда уничтожен последний. Проверьте на `Quantity`. Пока корзина пуста, ни одного `<app-quantity>` нет — и в `<head>` нет `<style>` с его правилами. Добавьте игру в корзину — стиль появится. Нажмите «Очистить корзину» — исчезнет. Мы проверили: число элементов `<style>` в `<head>` растёт с 5 до 6 и возвращается к 5.

А вот компонент без стилей атрибутов не получает вообще. Компилятор видит, что стилей нет, и сам переключает его в режим `None`: метить элементы незачем.

## AOT и JIT

В превью CSS переписывает компилятор Angular прямо в браузере. В настоящем проекте это делается при сборке. Вот что `ngc` положил в скомпилированный `GameCard`:

```js
styles: ["\n[_nghost-%COMP%] {\n  position: relative; … background: var(--%NS%surface);\n}\n\n.cover[_ngcontent-%COMP%] { … }"]
```

Селекторы уже переписаны, но вместо идентификатора — заглушка `%COMP%`: идентификатор вычисляется во время выполнения, и Angular подставит его, когда будет добавлять `<style>`. Вторая заглушка — `%NS%` в именах переменных CSS. Это пространство имён для переменных, которое можно включить функцией `provideCssVarNamespacing()` из `@angular/platform-browser`, — тогда переменные компонентов перестанут пересекаться с переменными чужого кода на той же странице. По умолчанию заглушка заменяется пустой строкой, и `var(--%NS%surface)` становится обычным `var(--surface)`.

## Теневой DOM

В шаге про стили мы включали `ViewEncapsulation.ShadowDom` для карточки. Посмотрим, что было в DOM. У `<app-game-card>` появился теневой корень, и **всё** содержимое карточки — включая стикеры от `App` — лежало внутри него. Атрибутов `_ngcontent` у элементов карточки не было: изоляцию даёт браузер. А первыми в теневом корне стояли три `<style>`: собственные стили карточки и копии стилей `App` и `Rating`. Angular копирует в каждый теневой корень стили всех компонентов, которые сейчас на странице. Поэтому стикеры с правилами из `app.css` остались оформлены, а кнопка — нет: глобальный `styles.css` — не стиль компонента, и в теневой корень он не попал. Именно эту утечку закрывает экспериментальный режим `ExperimentalIsolatedShadowDom`.

## Что запомнить

- Изоляция стилей в Angular — это соглашение компилятора: атрибуты на элементах и переписанные селекторы. Внутри — обычный CSS;
- элемент принадлежит тому компоненту, чей шаблон его создал, а не тому, внутри которого он оказался в DOM. Отсюда правила для хоста и для проецируемого содержимого;
- глобальные стили и переменные CSS — легальные способы задать общее оформление для всех компонентов.

Эти правила понадобятся, когда в магазин придут компоненты из библиотек: если хочется поменять их вид, смотрите, какие переменные CSS и входы они предлагают, прежде чем тянуться к `::ng-deep`.
