Скидки в «Ходе конём» действуют до конца дня. Покажем это в окне «Подробнее»: под ценой игры со скидкой — «Скидка действует ещё 07:16:10», и секунды идут.

Для этого нужен таймер, который раз в секунду обновляет время. Таймер — это то, что компонент создал сам, за пределами Angular. Angular о нём не знает и при уничтожении компонента сам его не остановит. Окно закрыли, компонент уничтожен, а таймер продолжает тикать. Откроют окно ещё раз — тикать будут два. Убрать за собой — забота компонента.

## Что изменилось в коде

Появилась папка `shared/countdown`: в `countdown.ts` — две готовые функции и `TODO` на месте компонента, `countdown.html` и `countdown.css` готовы. В шаблоне `GameDetails` — `TODO` на месте таймера.

Готовые функции — обычный TypeScript: `untilMidnight(now)` считает, сколько миллисекунд осталось до полуночи, а `formatTime(ms)` превращает их в строку `07:16:10`.

## Таймер на сигнале

Текущее время сделаем сигналом, а оставшееся — вычисляемым из него:

```ts shared/countdown/countdown.ts {7-8,11}
export class Countdown {
  // Текущее время. Это сигнал: шаблон обновится, когда таймер запишет новое значение
  private readonly now = signal(Date.now());
  protected readonly left = computed(() => formatTime(untilMidnight(this.now())));

  constructor() {
    const timer = setInterval(() => this.now.set(Date.now()), 1000);
    // Компонент уничтожен (окно закрыли) — таймер больше не нужен
    inject(DestroyRef).onDestroy(() => clearInterval(timer));
  }
}
```

Шаблон — одна строка:

```html shared/countdown/countdown.html
Скидка действует ещё {{ left() }}
```

Таймер пишет в сигнал из `setInterval` — вне всяких событий шаблона. В главе 3 мы выяснили, что в зонлесс-приложении обычное поле, изменённое в таймере, экран не обновит. Сигнал — обновит: шаблон прочитал `left()`, `left` зависит от `now`, и запись в `now` сама попросит Angular перерисовать компонент.

## `DestroyRef`

`DestroyRef` — объект, который Angular выдаёт через `inject()`. Для компонента он связан с его жизнью: функции, переданные в `onDestroy()`, Angular вызовет, когда компонент будет уничтожен. Здесь мы останавливаем таймер.

Обратите внимание, где это записано: прямо рядом с созданием таймера. «Создал — тут же сказал, как убрать» — так уборку трудно забыть. `onDestroy()` можно вызывать сколько угодно раз, из любого места в контексте внедрения. Он возвращает функцию, которая отменяет регистрацию, а свойство `destroyed` говорит, уничтожен ли уже компонент.

Таймер нужен только играм со скидкой:

```html shared/game-details/game-details.html
<p class="price">…</p>
@if (game().oldPrice) {
  <app-countdown />
}
```

## Что получилось

Откройте «Остров сокровищ», «Ночной экспресс» или «Нарды» — под ценой красная строка с обратным отсчётом, секунды идут. У «Драконьей почты» скидки нет, и строки нет.

## Эксперимент: забытая уборка

Добавьте в таймер вывод в консоль:

```ts
const timer = setInterval(() => {
  console.log('тик');
  this.now.set(Date.now());
}, 1000);
```

Откройте и закройте окно «Острова сокровищ» три раза. Одинаковые строки подряд консоль превью сворачивает в одну и показывает рядом счётчик повторов — следите за ним. Пока окно открыто, счётчик у `тик` растёт на один в секунду, после закрытия — замирает. Теперь удалите строку с `onDestroy` и повторите. Мы проверили: после первого открытия — один `тик` в секунду, после второго — два, после третьего — три. И после закрытия всех окон три таймера продолжают тикать и писать время в сигналы компонентов, которых на экране давно нет. Каждый такой таймер держит в памяти свой экземпляр `Countdown`: функция таймера ссылается на `this`.

Это **утечка**: ресурсы, которые никто не освобождает. В маленьком примере она безобидна, но в настоящем приложении так копятся таймеры, подписки и слушатели, и через час работы вкладка тормозит. Верните `onDestroy` и уберите `console.log`.

## Что убирать самим

Убирать нужно то, что вы создали сами в обход шаблона:

- таймеры: `setInterval`, `setTimeout` (если он может сработать после уничтожения);
- слушатели, добавленные через `addEventListener` на `window`, `document` или чужие элементы;
- наблюдатели: `IntersectionObserver`, `ResizeObserver`, `MutationObserver` — в практикуме этой главы;
- соединения: `WebSocket`, `EventSource`; подписки RxJS (глава 12).

А вот слушатели из шаблона (`(click)`) и из `host` (`'(window:resize)': '…'`) Angular снимает сам. Мы проверили: обработчик `'(window:resize)'` в `host` компонента `Countdown` срабатывает, пока окно открыто, и молчит после закрытия. Эффекты, созданные в компоненте, тоже уничтожаются вместе с ним.

::: tip Эффект или DestroyRef
У эффекта есть своя уборка — `onCleanup` (глава 3). Она выполняется и перед следующим запуском эффекта, и при уничтожении компонента. Если ресурс зависит от сигналов (например, таймер с интервалом из входа), создавайте его в эффекте и убирайте в `onCleanup`: при смене интервала таймер пересоздастся. Если ресурс живёт столько же, сколько компонент, — `DestroyRef`.
:::

::: legacy Вы встретите в старом коде: ngOnDestroy
```ts
export class Countdown implements OnDestroy {
  private timer = setInterval(() => this.tick(), 1000);

  ngOnDestroy() {
    clearInterval(this.timer);
  }
}
```
До Angular 16 уборку писали только в методе `ngOnDestroy` — хуке жизненного цикла (о хуках — в шаге 7). Работает так же, но создание и уборка ресурса разнесены по разным местам класса, а ресурс приходится хранить в поле. С RxJS к этому добавлялась отдельная «кнопка отписки» — `Subject` с `takeUntil` и `next()` в `ngOnDestroy`. Сейчас для потоков есть `takeUntilDestroyed()` (глава 12), который сам берёт `DestroyRef`.
:::
