В шаге 5 мы сказали: директива — это компонент без шаблона. В этом шаге посмотрим, насколько это буквально, и ответим на вопрос, который оставался без ответа с главы 5: как Angular узнаёт, что на `<app-rating … [appTooltip]="…">` нужно создать компонент `Rating` и директиву `Tooltip`? Шаг необязательный, кода в нём писать не нужно.

## Определение директивы

В главе 1 мы видели, что компилятор превращает декоратор `@Component` в статическое поле класса `ɵcmp` — **определение** компонента. С директивами и пайпами то же самое. Вот что делает настоящий AOT-компилятор (`ngc`) из `Tooltip` и `PricePipe`:

```js
static ɵdir = ɵɵdefineDirective({
  type: Tooltip,
  selectors: [['', 'appTooltip', '']],
  hostBindings: function Tooltip_HostBindings(rf, ctx) {
    if (rf & 1) {
      ɵɵlistener('mouseenter', () => ctx.show())('mouseleave', () => ctx.hide());
    }
  },
  inputs: { appTooltip: [1, 'appTooltip'] },
});

static ɵpipe = ɵɵdefinePipe({ name: 'price', type: PricePipe, pure: true });
```

В превью то же определение строит JIT-компилятор — прямо в браузере, при первом обращении к классу.

`hostBindings` — функция с теми же двумя блоками, что у шаблона: `rf & 1` — создание (здесь — подписка на события), `rf & 2` — обновление привязок. У `Tooltip` привязок хоста нет, поэтому блока обновления тоже нет.

Определение компонента — то же самое плюс шаблон. Мы сравнили поля определений `Tooltip.ɵdir` и `GameCard.ɵcmp` в превью: всё, что есть у директивы, есть и у компонента. Только у компонента — `template`, `consts`, `decls`, `vars`, `styles`, `encapsulation`, `ngContentSelectors`, `dependencies`, `onPush` и ещё несколько служебных. То есть компонент — это директива, у которой есть свой шаблон, стили и представление. Поэтому у компонента есть всё, что у директивы: `selector`, входы, выходы, `host`, `hostDirectives`.

## Селектор — это массив

Строка селектора к моменту запуска уже разобрана в массив. Мы вывели в консоль `selectors` из определений:

```
GameCard   [["app-game-card"]]
Tooltip    [["", "appTooltip", ""]]
LazyImage  [["img", "appLazy", ""]]
InView     [["", "appInView", ""]]
```

Первый элемент — имя тега (`""` — любой), дальше пары «атрибут, значение» (`""` — любое значение). `img[appLazy]` — «тег `img` с атрибутом `appLazy`». Внешний массив — список вариантов через запятую: селектор `'a, b'` дал бы два внутренних массива.

Селекторы Angular — урезанный CSS: тег, атрибут (со значением и без), класс, `#id`, `:not()`, перечисление через запятую. Angular смотрит только на сам элемент, не на родителей и соседей, поэтому вложенности (`div span`) и псевдоклассов нет. Причём компилятор о них не предупреждает, а разбирает по-своему: из `div span` останется тег `span`. Пишите в селекторах только то, что в списке.

## С чем сравнивается селектор

Посмотрите, во что скомпилировано `<app-rating>` из шаблона карточки. Атрибуты элемента лежат в `consts` — в главе 1 мы видели там классы:

```js
['readonly', '', 3, 'value', 'appTooltip']
```

`readonly` — статический атрибут со значением `''`. Число `3` — маркер «дальше имена привязок»: `[value]` и `[appTooltip]`. Значений привязок здесь нет — они вычисляются в блоке обновления, — но **имена** есть. Именно с этим массивом Angular сравнивает селекторы. Поэтому `[appTooltip]="…"` подходит под селектор `[appTooltip]` так же, как статический `appTooltip="…"`, а `(appInView)="…"` — под `[appInView]`.

## Когда Angular ищет директивы

Не при каждой проверке и даже не при каждом создании компонента. У каждого шаблона есть общая для всех его экземпляров часть — `TView`. При **первом** создании шаблона Angular проходит по его элементам и для каждого перебирает **реестр директив** этого шаблона — то, что вы перечислили в `imports`, с раскрытыми зависимостями. Каждый подходящий селектор — совпадение. Результат запоминается в `TView`, и следующие экземпляры того же компонента его переиспользуют.

Мы заглянули в `TView` карточки: реестр директив — `GameCard, LazyImage, Rating, Tooltip`, реестр пайпов — `number, duration, players, price`. Сам `GameCard` тоже в реестре: компонент может встретиться в собственном шаблоне. А `InView` нет — её подключает `LazyImage`, а не селектор. Шесть карточек на странице — но сопоставление селекторов для их шаблона выполнилось один раз.

Отсюда же ошибки, которые мы видели в главе:

- директива не в `imports` — её нет в реестре, совпадения нет. Привязка `[appTooltip]` осталась без хозяина, и Angular пробует записать её в свойство DOM — NG0303;
- статический `appTooltip="…"` без директивы — просто атрибут, проверять нечего;
- пайпа нет в реестре — `ɵɵpipe` не находит его по имени, NG0302.

В настоящем проекте сопоставление выполняет ещё и компилятор при сборке: он должен знать, какие привязки — входы директив, чтобы проверить их типы. Поэтому в AOT те же ошибки появляются при сборке: NG8002, NG8004.

## Порядок на элементе

Подходящие директивы Angular складывает в список, и в этом порядке их создаёт. Из совпавших по селекторам компонент всегда первый. А хост-директивы встают перед тем, кто их подключил, — даже перед компонентом: поэтому в шаге 6 `InView` создавалась раньше `LoadMore`. Проверьте в консоли (в DevTools выберите контекст фрейма `preview.html`, как в главе 1): выделите обложку карточки на вкладке Elements и выполните

```js
ng.getDirectives($0).map((d) => d.constructor.name)
// ['InView', 'LazyImage']
```

Для `<app-rating>` в карточке — `['Tooltip']`: `ng.getDirectives` не включает компонент, его даёт `ng.getComponent($0)` — `Rating`. Для `<app-load-more>` — `['InView']`: хост-директива на месте, хотя атрибута `appInView` в разметке нет.

## Эксперимент: два компонента на элементе

Превратите `Tooltip` в компонент: `@Component` вместо `@Directive` и `template: ''` (импорт `Component` из `@angular/core`). Селектор тот же — `[appTooltip]`:

```
ERROR RuntimeError: NG0300: Multiple components match node with tagname app-rating: Rating and Tooltip.
```

Компонент владеет содержимым элемента: рисует в нём свой шаблон. Два шаблона в одном элементе не поместятся, поэтому компонент на элементе может быть только один — а директив сколько угодно. Верните `@Directive`.

## Пайп в скомпилированном шаблоне

И последнее — во что превращается `| players` в шаблоне карточки (вывод `ngc`):

```js
// создание
ɵɵpipe(17, 'players');
// обновление
ɵɵtextInterpolate(ɵɵpipeBind1(17, 15, ctx.game().players));
```

`ɵɵpipe(17, 'players')` при создании находит пайп по имени в реестре пайпов и создаёт экземпляр в ячейке 17 представления — свой у каждой карточки, как мы видели в шаге 4. `ɵɵpipeBind1(17, 15, значение)` при обновлении берёт экземпляр из ячейки 17 и, если пайп чистый, сравнивает значение с тем, что лежит в ячейках привязок со смещением 15. Совпало — возвращает сохранённый результат из соседней ячейки, нет — вызывает `transform` и запоминает. У пайпа с параметрами — `ɵɵpipeBind2`, `ɵɵpipeBind3` и так далее: каждый параметр — ещё одна сравниваемая ячейка.

## Что запомнить

- `@Component`, `@Directive`, `@Pipe` компилируются в определения `ɵcmp`, `ɵdir`, `ɵpipe`. Компонент — это директива с шаблоном.
- Селектор сравнивается со статическими атрибутами и с **именами** привязок элемента.
- Директивы на элементе ищутся один раз на шаблон, в реестре из `imports`.
- Компонент на элементе — один, директив — сколько угодно; хост-директивы создаются раньше того, кто их подключил.
- Чистый пайп — экземпляр в представлении плюс кэш аргументов и результата рядом с привязкой.
