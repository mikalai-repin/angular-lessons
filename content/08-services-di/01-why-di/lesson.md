Корзину в «Ходе конём» видят четыре места: шапка («В корзине: 3 · 4 870 ₽»), мини-корзина, карточки каталога и окно «Подробнее». А живёт она в одном — в корневом компоненте `App`. Всё, что о корзине знают остальные, `App` передаёт им входами и узнаёт от них выходами.

Эта глава — о **внедрении зависимостей** (dependency injection, DI): способе, которым Angular раздаёт компонентам общие объекты. DI — то, что сильнее всего отличает Angular от большинства фронтенд-библиотек. Вы уже пользовались им, сами того не замечая: `inject(ElementRef)` в главе 6, `inject(LOCALE_ID)` в пайпе `price`, `inject(InView)` в главе 7. Теперь разберёмся, как это устроено, и сделаем свои объекты, которые можно получить так же.

В этой главе «Ход конём» получит:

- корзину, которую шапка, карточки и окно «Подробнее» берут сами, без посредника `App`;
- демо-режим: при запуске в корзине уже лежат игры — для показа магазина;
- настройки магазина (порог бесплатной доставки и другие числа) в одном месте;
- аналитику, которая загружается, только когда браузер освободится;
- «Избранное»: сердечко на карточках и счётчик в шапке.

А в конце главы посмотрим, как Angular ищет зависимость и что значит ошибка NG0201.

## Что изменилось в коде

Код — решение практикума главы 7, в котором шапка вынесена в отдельный компонент:

- `layout/header/` — компонент `Header`: логотип и сводка корзины. Числа он получает входами `count` и `total`, стили шапки переехали из `app.css` в `header.css`. Папка `layout/` — для частей каркаса страницы, которые не относятся к каталогу;
- в `game-card.css` — стили ряда кнопок `.actions` и кнопки «В избранное» для практикума;
- `core/cart-store.ts` — заготовка для этого шага, и комментарии `TODO` в `app.ts` и `header.ts`.

## Посредник

Посмотрите, кто что получает от `App`:

```
App  ← корзина живёт здесь
├─ Header       [count] [total]
├─ GameCard ×6  [inCart] (add)
└─ GameDetails  [inCart] (add)
```

Самому `App` корзина нужна только для мини-корзины. Остальное — работа курьера: взять у корзины число, передать входом, получить событие выходом, вызвать метод корзины. Корзина живёт в `App` лишь потому, что это общий предок всех, кому она нужна. Появится компонент глубже — например, кнопка «В корзину» внутри карточки — и входы с выходами потянутся через каждый уровень. А в главе 10 шапку и каталог разделит роутер: страницы он создаёт сам, и привязать к ним вход из шаблона `App` уже не получится.

Нужен способ получить корзину там, где она нужна, не передавая её через всех предков.

## Самый простой способ — один объект на всё приложение

Вынесем корзину из компонента в отдельный модуль: класс `CartStore` со всем, что было в `App` (позиции, количество, сумма, действия), и единственный экземпляр, который импортируют все:

```ts core/cart-store.ts {6,34}
// С какой суммы заказа доставка бесплатная, ₽
const FREE_DELIVERY_FROM = 5000;

// Корзина магазина: позиции, количество, сумма и действия с ними
export class CartStore {
  readonly items = signal<CartItem[]>([]);
  readonly count = computed(() => this.items().reduce((sum, item) => sum + item.quantity, 0));
  readonly total = computed(() => this.items().reduce((sum, item) => sum + item.game.price * item.quantity, 0));
  readonly summary = computed(() => /* «Остров сокровищ × 2, …» — как cartSummary */);
  readonly deliveryLeft = computed(() => Math.max(FREE_DELIVERY_FROM - this.total(), 0));

  // Сколько штук каждой игры в корзине: id игры → количество
  private readonly quantities = computed(() => new Map(this.items().map((item) => [item.game.id, item.quantity])));

  // Метод читает сигнал, поэтому шаблон или computed, которые его вызвали, тоже зависят от корзины
  quantityOf(game: Game): number {
    return this.quantities().get(game.id) ?? 0;
  }

  add(game: Game) {
    /* как addToCart в App */
  }

  setQuantity(game: Game, quantity: number) {
    this.items.update((items) => items.map((item) => (item.game.id === game.id ? { ...item, quantity } : item)));
  }

  remove(game: Game) {
    this.items.update((items) => items.filter((item) => item.game.id !== game.id));
  }

  clear() {
    this.items.set([]);
  }
}

// Единственный экземпляр корзины на всё приложение: его импортируют все, кому нужна корзина
export const cartStore = new CartStore();
```

Это тот же код, что был в `App`, с двумя изменениями. Имена стали короче: внутри `CartStore` и так понятно, что `count` — количество в корзине. А методы получают игру, а не позицию корзины: `remove(game)`, `setQuantity(game, 3)`. Карточке так удобнее — позиции у неё нет, игра есть.

Обратите внимание на `quantityOf`. Это обычный метод, но внутри он читает сигнал `quantities`. Если метод вызвать из шаблона или из `computed`, они запомнят этот сигнал своей зависимостью — так же, как если бы прочитали его сами. Реактивность не теряется оттого, что чтение спрятано в метод.

Шаблон видит только поля своего компонента, поэтому `App` и `Header` кладут объект корзины в поле:

```ts app.ts {2}
// Корзина: позиции, сумма, действия. Её же показывают шапка и карточки
protected readonly cart = cartStore;
```

```html app.html
<app-header />
…
@for (item of cart.items(); track item.game.id) {
  …
  <app-quantity … [value]="item.quantity" (valueChange)="cart.setQuantity(item.game, $event)" />
  …
  <button class="icon-button" aria-label="Убрать из корзины" (click)="cart.remove(item.game)">×</button>
}
…
<app-game-card [game]="game" [inCart]="cart.quantityOf(game)" (add)="cart.add(game)" (open)="selectedGame.set(game)">
```

::: task
1. В `core/cart-store.ts` напишите класс `CartStore`: перенесите в него корзину из `App` — сигнал позиций, `computed` и методы. Ниже создайте и экспортируйте единственный экземпляр `cartStore`.
2. В `App` удалите поля и методы корзины и константу `FREE_DELIVERY_FROM`, а в поле `cart` положите `cartStore`. Эффект с журналом корзины пока оставьте в конструкторе `App` — он читает `this.cart.summary()`. В шаблоне замените обращения к корзине: `cart.items()`, `cart.total()`, `cart.deliveryLeft()`, `cart.add(game)` и так далее.
3. В `Header` уберите входы `count` и `total` и тоже возьмите `cartStore`. В `app.html` у `<app-header>` больше нет привязок.

## Что получилось

Внешне ничего не изменилось — так и должно быть. Положите в корзину «Драконью почту»: шапка показывает «В корзине: 1 · 1 290 ₽», карточка — «В корзине: 1 шт.», в консоли — «Корзина: Драконья почта × 1». Но шапка больше не ждёт чисел от `App`: она читает тот же объект корзины, что и все.

Способ работает, и в маленьком приложении на нём можно было бы остановиться. Посмотрим, где он ломается.

## Эксперимент: эффект в корзине

Журнал корзины логично держать в самой корзине. Перенесите эффект из конструктора `App` в конструктор `CartStore` (и добавьте `effect` в импорт):

```ts core/cart-store.ts
constructor() {
  effect(() => console.log('Корзина:', this.summary() || 'пусто'));
}
```

Превью пустое, а в консоли:

```
Error: NG0203: effect() can only be used within an injection context such as a constructor, a factory function, a field initializer, or a function used with `runInInjectionContext`.
    at effect (@angular/core/…)
    at new CartStore (core/cart-store.ts:…)
    at core/cart-store.ts:…
```

Номера строк зависят от того, куда вы вставили конструктор. Последняя строка стека указывает на то самое `new CartStore()` в конце файла. Оно выполняется, когда браузер загружает модуль: раньше, чем запустилось приложение и появился первый компонент. Эффекту нужно знать, чей он: когда его запускать и когда уничтожить вместе с владельцем. В главе 3 мы видели ту же ошибку для эффекта вне конструктора компонента. Объект, который создали сами, в стороне от Angular, ничьим не является. Верните эффект в `App`.

## Чем плоха глобальная переменная

`cartStore` — **глобальная переменная**: один объект, который создаётся при загрузке модуля и доступен любому, кто его импортирует. Кроме эффекта, у неё есть и другие проблемы:

- **Её не подменить.** Захотим показывать магазин с заполненной корзиной (сделаем в шаге 4) или проверить карточку в тесте с поддельной корзиной — придётся менять `import` в каждом файле. Каждый компонент сам решил, какую именно корзину берёт.
- **Она одна на всё.** В тестах (глава 16) состояние перетекает из теста в тест. На сервере (глава 20 — SSR) один модуль обслуживает запросы всех покупателей, и корзина одного стала бы видна другим.
- **Её создают, даже если она не нужна,** и живёт она вечно: никто не знает, когда её можно убрать.
- **Части приложения не получить свою.** Иногда нужен отдельный экземпляр на компонент — в шаге 6 мы так и сделаем.

## Внедрение зависимостей

Объект, без которого компоненту не обойтись, называют его **зависимостью** (dependency): корзина — зависимость шапки и карточки. Внедрение зависимостей — договорённость, при которой компонент **не создаёт и не выбирает** свои зависимости сам. Он только говорит, что ему нужно, — «мне нужна корзина», — а готовый объект ему выдают.

Выдаёт **инжектор** (injector) — объект Angular, который знает, как создать каждую зависимость, создаёт её при первом запросе и запоминает:

```
Header: inject(CartStore)
          │
          ▼
инжектор: уже создавал CartStore?
          ├─ да  → тот же экземпляр
          └─ нет → создать, запомнить, выдать
```

Как создать зависимость, инжектору говорит **провайдер** (provider) — запись вида «когда попросят X, выдай …». Вы уже писали провайдер в главе 7: `{ provide: LOCALE_ID, useValue: 'ru' }`.

Что это даёт:

- компонент и корзина связаны только типом: «мне нужна корзина». Какой именно экземпляр он получит, решает конфигурация приложения в одном месте — так подменяют корзину для показа или для теста;
- объекты создаёт Angular, и создаёт **в контексте внедрения** — поэтому эффекту внутри сервиса будет понятно, чей он;
- инжекторов много, они выстроены деревом вслед за деревом компонентов. Поэтому можно дать части приложения свой экземпляр.

Все три пункта разберём по шагам главы. А в следующем шаге превратим `CartStore` в настоящий сервис.

::: tip Если вы знаете React или Vue
Похожая задача решается контекстом (`createContext` + `useContext` в React) или `provide`/`inject` во Vue: значение кладут выше по дереву, а потомки его достают. В Angular этим механизмом пользуется всё приложение и сам фреймворк: роутер, `HttpClient`, формы — тоже зависимости, которые компоненты получают через `inject()`.
:::
