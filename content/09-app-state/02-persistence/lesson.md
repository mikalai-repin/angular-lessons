Положите в корзину пару игр и нажмите ⟳ в адресной строке превью. Приложение запускается заново — как после перезагрузки страницы, — и корзина пуста. Покупатель, который закрыл вкладку и вернулся вечером, начнёт выбирать заново. Сохраним корзину в `localStorage` браузера.

## Две задачи: записать и прочитать

`localStorage` хранит строки по ключу и переживает перезагрузку страницы и перезапуск браузера. Нам нужно:

- **записывать** корзину при каждом её изменении;
- **читать** её один раз — при создании хранилища, чтобы первая же отрисовка показала сохранённые позиции.

### Что сохранять

Позиция корзины — это игра целиком: название, описание, цена, остаток. Сохранять всё это незачем и вредно. Цена может измениться, игру могут убрать из каталога, остаток на складе уменьшится, а в `localStorage` останется снимок недельной давности. Поэтому сохраняем минимум — **id игры и количество**, а всё остальное при загрузке берём из каталога:

```ts core/cart-store.ts
// Ключ корзины в localStorage. Версия в имени: поменяется формат — поменяем ключ, и старые данные не помешают
const STORAGE_KEY = 'hod-konem:cart:v1';

// Что сохраняем о позиции: только id игры и количество. Название, цену и остаток берём из каталога
interface SavedItem {
  id: number;
  quantity: number;
}
```

Это то же правило «храните минимум», что и в главе 3, только для данных вне приложения. Версия в ключе — дешёвая страховка: если формат придётся поменять, новый код будет читать `…:v2`, а старая запись с другим устройством просто не найдётся.

### Когда записывать: эффект

Корзину меняют четыре действия: `add`, `setQuantity`, `remove`, `clear`. Можно дописать сохранение в каждое — и в каждое следующее, а однажды забыть. А можно сказать один раз: «когда меняются позиции — запиши их». Это ровно то, что делает `effect` из главы 3:

```ts core/cart-store.ts {6-10}
constructor() {
  // Побочный эффект: сообщение в консоли при каждом изменении корзины
  effect(() => {
    console.log('Корзина:', this.summary() || 'пусто');
  });
  // Побочный эффект: при каждом изменении корзины записываем её в localStorage
  effect(() => {
    const saved: SavedItem[] = this.items().map((item) => ({ id: item.game.id, quantity: item.quantity }));
    localStorage.setItem(STORAGE_KEY, JSON.stringify(saved));
  });
}
```

Эффект прочитал `this.items()` — значит, Angular выполнит его снова после каждого изменения позиций, кто бы и каким действием их ни поменял. Документация Angular среди случаев, для которых эффект и нужен, прямо называет «синхронизацию данных с хранилищами: `window.localStorage`, session storage, cookies». Это побочный эффект в точном смысле слова: действие за пределами сигналов.

Два эффекта, а не один, — потому что у них разные задачи. Журнал в консоли мы когда-нибудь уберём, а сохранение — нет.

### Когда читать: начальное значение

Прочитать сохранённое нужно один раз и до первой отрисовки — иначе покупатель на мгновение увидит пустую корзину. Самое простое место — начальное значение сигнала:

```ts core/cart-store.ts {2}
// Состояние корзины — позиции. Менять его может только сам сервис: поле закрытое
private readonly state = signal<readonly CartItem[]>(loadCart());
```

Инициализатор поля выполнится, когда DI создаст `CartStore`, — то есть когда корзина впервые понадобится шапке. А сама функция — ниже класса, в том же файле:

```ts core/cart-store.ts
// Корзина из localStorage. Данные могли испортиться или устареть — ничего не берём на веру
function loadCart(): CartItem[] {
  try {
    const saved: SavedItem[] = JSON.parse(localStorage.getItem(STORAGE_KEY) ?? '[]');
    return saved.flatMap(({ id, quantity }) => {
      const game = GAMES.find((g) => g.id === id);
      return game && Number.isInteger(quantity) && quantity > 0 ? [{ game, quantity }] : [];
    });
  } catch {
    // Не JSON или не массив — начинаем с пустой корзины
    return [];
  }
}
```

Данные из `localStorage` — внешние. Их могла записать старая версия приложения, другой код на том же сайте или сам покупатель в инструментах разработчика. Тип `SavedItem[]` у результата `JSON.parse` — только наше пожелание: `JSON.parse` возвращает `any`, и TypeScript поверит чему угодно. Поэтому:

- `try`/`catch` ловит строку, которая не JSON, и JSON, который не массив (у числа или объекта нет `flatMap` — будет `TypeError`);
- игры ищем в каталоге `GAMES`: исчезнувшая из каталога игра пропадёт из корзины;
- количество должно быть целым и положительным.

`flatMap` с массивом из одного или нуля элементов — способ за один проход и найти игру, и отбросить негодную позицию.

2. В конструкторе добавьте второй эффект, который записывает позиции в `localStorage`: массив `{ id, quantity }` в виде JSON.

## Что получилось

Положите в корзину «Остров сокровищ» два раза и нажмите ⟳. Корзина на месте: «В корзине: 2 · 3 980 ₽», а первая строка консоли после перезапуска — «Корзина: Остров сокровищ × 2».

::: warning Корзина живёт дольше шага
Превью работает на том же сайте, что и курс, поэтому сохранённая корзина видна во всех шагах и главах, где код её читает. Кнопка «Сброс» в редакторе возвращает код шага, но не трогает `localStorage`. Пустая корзина — кнопка «Очистить корзину»: эффект запишет `[]`.
:::

## Эксперимент: что записано

Добавьте в эффект сохранения строку:

```ts core/cart-store.ts
console.log('Сохранено:', JSON.stringify(saved));
```

После ⟳ в консоли — «Сохранено: [{"id":1,"quantity":2}]»: эффект выполняется и при запуске, записывая обратно то, что только что прочитали. Это его обычное поведение — первый запуск собирает зависимости. Лишняя запись здесь безвредна и даже полезна: если `loadCart()` отбросил негодные позиции, в `localStorage` сразу окажется исправленная корзина. Нажмите «+» — новая строка, с другим количеством.

Посмотреть запись можно и в инструментах разработчика браузера: вкладка Application (Приложение) → Local Storage → адрес курса. Рядом лежит ключ `angular-course:v1` — так курс помнит ваш прогресс.

## Эксперимент: испорченные данные

Запишите в `localStorage` мусор — первой строкой `main.ts`, до запуска приложения:

```ts main.ts
localStorage.setItem('hod-konem:cart:v1', '{oops');
```

Магазин запустился с пустой корзиной, ошибок нет — сработал `catch`. Теперь уберите из `loadCart()` `try`/`catch` (оставьте только тело `try`). Превью пустое, а в консоли:

```
ERROR SyntaxError: Expected property name or '}' in JSON at position 1 (line 1 column 2)
```

Исключение в инициализаторе поля сломало создание `CartStore`, а без корзины не создаётся шапка — и всё приложение. Одна испорченная запись в браузере покупателя — и магазин не открывается у него никогда, пока он не почистит данные сайта. Верните `try`/`catch`.

Замените мусор на правдоподобные, но негодные данные:

```ts main.ts
localStorage.setItem('hod-konem:cart:v1', '[{"id":99,"quantity":1},{"id":2,"quantity":"много"},{"id":3,"quantity":2}]');
```

Игры с id 99 нет, у «Драконьей почты» количество — строка. В корзине только «Зельевары × 2», и эффект тут же записал исправленную корзину. Удалите строку из `main.ts`.

::: deep Под капотом: когда выполняется эффект сервиса
Эффект в компоненте (глава 3) — эффект представления: он выполняется, когда Angular проверяет этот компонент. Эффект в сервисе, созданном корневым инжектором, — **корневой**: он не привязан ни к одному компоненту. По документации Angular корневые эффекты выполняются во время обнаружения изменений перед проверкой всех компонентов, и если эффект поменял сигналы, Angular учтёт это до проверки шаблонов.

Для сохранения это значит: «В корзину» → действие меняет `state` → Angular планирует проход обнаружения изменений → в нём сначала эффект пишет в `localStorage`, потом обновляются шапка, карточка и мини-корзина. Несколько изменений подряд в одном обработчике дадут одну запись — эффект выполняется не на каждое `set`, а один раз за проход, с последним значением.
:::

## Как в настоящем проекте

- **Серверный рендеринг.** На сервере (глава 20 — SSR) нет ни `window`, ни `localStorage`: `loadCart()` упал бы с `ReferenceError`. Код, которому нужен браузер, там проверяют: `isPlatformBrowser(inject(PLATFORM_ID))` из `@angular/common`, или переносят работу в `afterNextRender`, который на сервере не выполняется (глава 6). А `localStorage` иногда выносят в токен с фабрикой — тогда в тестах и на сервере его легко подменить (глава 8).
- **Несколько вкладок.** Каждая вкладка магазина держит свою копию корзины в памяти. Если покупатель поменял корзину в одной вкладке, другая узнает об этом только после перезагрузки — или если слушать событие `storage` у `window`: браузер шлёт его в другие вкладки того же сайта при каждой записи в `localStorage`.
- **Что хранить в браузере.** `localStorage` — не для секретов: его читает любой скрипт на странице. Корзина, избранное, настройки интерфейса — подходят; токены входа — отдельный разговор в главе 14.
