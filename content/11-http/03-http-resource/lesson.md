Посчитаем, что нужно главной, чтобы честно показать подборку с сервера. Сигнал с играми. Признак «загружается» — чтобы показать заглушки. Ошибка — чтобы написать «не удалось» вместо пустого места. Отписка при уходе со страницы. И всё это — для каждой из двух подборок.

Angular собирает всё это в один объект — **ресурс** (resource). Ресурс — это асинхронные данные, выраженные сигналами: значение, состояние загрузки и ошибка. Его создаёт функция **`httpResource`** из `@angular/common/http`: вы описываете запрос, а ресурс сам отправляет его через `HttpClient` и держит результат в сигналах.

## Ресурс вместо подписки

```ts home/home.ts {2-5,7-10}
// Хиты — четыре игры с самым высоким рейтингом. Запрос отправит сам ресурс, он же расскажет, как идут дела
protected readonly hits = httpResource<GamesPage>(() => ({
  url: '/api/games',
  params: { sort: 'rating', size: 4 },
}));
// Игры со скидкой
protected readonly sale = httpResource<GamesPage>(() => ({
  url: '/api/games',
  params: { onSale: true },
}));
```

`httpResource` принимает **функцию**, которая возвращает описание запроса: `url`, `params` и, если нужно, метод, заголовки, тело. Можно вернуть и просто строку адреса. Почему функция, а не объект, станет ясно в следующем шаге: если внутри прочитать сигнал, ресурс будет повторять запрос при каждом его изменении. Параметр `onSale=true` учебный бэкенд понимает как «только игры со скидкой».

Конструктор, `inject(HttpClient)`, `subscribe` — больше не нужны. `httpResource` вызывают там же, где `effect` и `inject`: в инициализаторе поля или в конструкторе. Ресурс привязан к компоненту, в котором создан: когда компонент уничтожается, ресурс отменяет свой запрос.

## Что есть у ресурса

| | Что возвращает |
|---|---|
| `value()` | ответ сервера; `undefined`, пока ответа нет |
| `hasValue()` | есть ли значение |
| `isLoading()` | идёт ли загрузка |
| `error()` | ошибка, если запрос не удался |
| `reload()` | повторить запрос |

`value`, `isLoading` и `error` — сигналы, а `hasValue()` — метод, который читает сигналы ресурса внутри. Поэтому шаблон, который вызывает любой из них, обновится сам.

## Три состояния в шаблоне

```html home/home.html
@if (hits.hasValue()) {
  <div class="grid">
    @for (game of hits.value().items; track game.id) {
      <app-game-card [game]="game" />
    }
  </div>
} @else if (hits.isLoading()) {
  <div class="grid">
    @for (n of skeletons; track n) {
      <div class="skeleton"></div>
    }
  </div>
} @else {
  <p class="error-message">
    Не удалось загрузить хиты.
    <button class="link-button" (click)="hits.reload()">
      Повторить
    </button>
  </p>
}
```

Есть значение — карточки. Идёт загрузка — **заглушки загрузки** (skeleton): четыре серых блока размером с карточку, `skeletons = [1, 2, 3, 4]` в классе. Ни того ни другого — значит, загрузка закончилась ошибкой: сообщение и кнопка «Повторить», которая вызывает `reload()`.

Обратите внимание на `hits.value().items` внутри `@if (hits.hasValue())`. Тип `value()` — `GamesPage | undefined`, но `hasValue()` объявлен в типах как проверка: после неё TypeScript знает, что значение есть. Так что `.items` без `?.` проходит проверку типов шаблона.

Почему сначала `isLoading()`, а потом ошибка, а не наоборот? Мы проверили, что происходит при нажатии «Повторить» после ошибки: пока идёт повторный запрос, `error()` по-прежнему возвращает **прошлую** ошибку. Если проверять `error()` раньше `isLoading()`, после нажатия кнопки на экране так и останется «Не удалось загрузить», и покажется, что кнопка не работает.

## Что получилось

На главной на мгновение мелькают серые блоки, потом появляются карточки. В «Сети» — два запроса: `GET /api/games?sort=rating&size=4` и `GET /api/games?onSale=true`. В «Со скидкой» теперь восемь игр: к трём знакомым добавились пять новых.

## Эксперименты

**Заглушки.** Поставьте задержку 3000 мс и перезапустите превью. Три секунды на месте подборок мигают серые блоки — покупатель видит, что магазин работает.

**Ошибка и повтор.** Включите «Ошибку 500» и перезапустите превью. Под заголовками — «Не удалось загрузить хиты» и «Не удалось загрузить игры со скидкой». Выключите флажок и нажмите «Повторить» у хитов: появятся заглушки, затем карточки. «Со скидкой» по-прежнему с ошибкой — у каждой подборки свой ресурс и свой повтор.

**Ушли, не дождавшись.** Поставьте задержку 3000 мс, перезапустите превью и сразу перейдите в «Каталог». В «Сети» оба запроса — «отменён». Ресурс заметил, что компонент уничтожен, и отменил запросы сам — то, что в прошлом шаге пришлось писать руками.

::: deep Под капотом: httpResource и HttpClient
`httpResource` не заменяет `HttpClient`, а использует его: внутри ресурс вызывает `HttpClient.request(…)` и подписывается на результат. Когда ресурсу нужно отменить запрос — компонент уничтожен или запрос устарел, — он отписывается, а отписка, как мы видели, прерывает запрос. Поэтому всё, что настроено для `HttpClient` (интерцепторы в главе 12, подмена сервера в тестах), работает и для `httpResource`.

У `httpResource` есть разновидности для других ответов: `httpResource.text` — строка, `httpResource.blob` — файл, `httpResource.arrayBuffer` — двоичные данные.
:::

## Чтение или изменение

`httpResource` — для **чтения** данных: показать каталог, игру, отзывы. Ресурс сам решает, когда отправить запрос, и отменяет его, когда тот больше не нужен. Для отправки заказа это опасно: покупатель ушёл со страницы — и заказ отменён на полпути. Поэтому изменения (`POST`, `PUT`, `DELETE`) отправляют через `HttpClient` — к этому мы придём в шаге 8.
