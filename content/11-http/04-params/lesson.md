Главная получает с сервера две подборки с постоянными параметрами. С каталогом сложнее: что показать, зависит от покупателя — строки поиска, флажка «Только в наличии», рейтинга и сортировки. Сейчас всё это делает `computed` `visibleGames`: фильтрует и сортирует массив `GAMES` прямо в браузере. С сервером так нельзя: игр могут быть тысячи, и присылать их все, чтобы показать три подходящие, — расточительно. Пусть ищет и сортирует сервер, а приложение передаёт ему условия.

## Сигналы внутри запроса

Фильтры каталога с главы 10 живут в адресе и приходят во входы `q`, `inStock`, `rating`, `sort` — а входы, как вы помните, сигналы. Прочитаем их внутри функции запроса:

```ts catalog/catalog.ts {4-7}
protected readonly games = httpResource<GamesPage>(() => ({
  url: '/api/games',
  params: {
    q: this.q(),
    inStock: this.inStock(),
    rating: this.rating(),
    sort: SORT_PARAMS[this.sort()],
    // Пока все найденные игры сразу; порции с сервера — в практикуме
    size: 100,
  },
}));
```

Вот зачем `httpResource` принимает функцию. Ресурс вызывает её так же, как Angular вызывает функцию `computed`: запоминает, какие сигналы она прочитала. Изменился любой из них — ресурс вызывает функцию снова и, если описание запроса стало другим, отправляет новый запрос. Покупатель поставил флажок — изменился адрес — изменился вход `inStock` — ушёл запрос с `inStock=true`. Связь «фильтр → запрос» больше нигде не нужно описывать.

Учебный бэкенд понимает параметр `rating` как «рейтинг от»: `rating=4.5` — игры с рейтингом 4,5 и выше. А сортировка в адресе магазина и в API называется по-разному: в адресе — понятные покупателю `cheap` и `expensive`, у сервера — `price` и `-price`. Переводит таблица:

```ts catalog/catalog.ts
// Сортировка каталога → параметр sort в API: price — по цене, -price — по убыванию цены
const SORT_PARAMS: Record<SortKey, string> = {
  default: '',
  cheap: 'price',
  expensive: '-price',
  rating: 'rating',
};
```

`Record<SortKey, string>` заставит TypeScript проверить, что перевод есть для каждого варианта сортировки. Адреса магазина при этом не меняются: ссылки, которыми покупатели поделились, продолжат работать.

`size: 100` — временно: просим сразу все найденные игры, а «Показать ещё» по-прежнему отрезает их порциями в браузере. Загружать каталог с сервера порциями — задача практикума.

## Найденные игры

`visibleGames` теперь не ищет сам, а берёт игры из ответа:

```ts catalog/catalog.ts
// Найденные игры. value() ресурса с ошибкой бросает исключение, поэтому сначала спрашиваем hasValue()
protected readonly visibleGames = computed(() =>
  this.games.hasValue() ? this.games.value().items : [],
);
```

Почему не короче — `this.games.value()?.items ?? []`? Потому что у ресурса с ошибкой `value()` не возвращает `undefined`, а **бросает исключение**. Ниже в экспериментах посмотрим, к чему это приводит. `hasValue()` при ошибке просто возвращает `false`.

В шаблоне каталога — те же три состояния, что на главной. Сетка и «Показать ещё» — внутри `@if (games.hasValue())`, над сеткой — сколько игр нашёл сервер:

```html catalog/catalog.html
<p class="found muted">Найдено игр: {{ games.value().total }}</p>
```

::: task
1. В `catalog/catalog.ts` добавьте таблицу `SORT_PARAMS` и ресурс `games` с параметрами `q`, `inStock`, `rating`, `sort` и `size: 100`.
2. Перепишите `visibleGames`: игры из ответа, если он есть, иначе пустой массив. Импорт `GAMES` больше не нужен.
3. В `catalog.html` оберните «Найдено игр», сетку и `<app-load-more>` в `@if (games.hasValue())`, а в `@else if (games.isLoading())` и `@else` — заглушки (`skeletons = [1, 2, 3, 4, 5, 6]`) и сообщение «Не удалось загрузить каталог» с кнопкой «Повторить».

## Что получилось

В каталоге — «Найдено игр: 40» и первые шесть игр. Фильтры работают как раньше, но в «Сети» на каждое изменение — новый запрос. Например, «Только в наличии» — `GET /api/games?q=&inStock=true&rating=0&sort=&size=100`. Пустые параметры (`q=`, `sort=`) тоже уходят на сервер: учебный бэкенд считает пустой параметр отсутствующим.

## Эксперименты

**Печатаем быстро.** Наберите в поиске «кот». Каждая буква меняет адрес, адрес — вход `q`, вход — запрос. Мы проверили при задержке 300 мс и паузе 100 мс между буквами: в «Сети» четыре запроса — без поиска, «к», «ко» и «кот», и запросы «к» и «ко» отменены. Ресурс не ждёт ответа на устаревший запрос: новые параметры — отменить старый, отправить новый. Поэтому на экране всегда ответ на последний запрос, а не на тот, что случайно пришёл последним. Найдена одна игра — «Космические коты».

Но отменённые запросы всё равно ушли на сервер. Отправлять запрос на каждую букву — лишняя нагрузка. Это исправим в шаге 7.

**Мигание.** Поставьте задержку 1000 мс и пощёлкайте сортировку. На каждое изменение сетка исчезает, на её месте — заглушки. Когда параметры ресурса меняются, его значение сбрасывается в `undefined` до прихода нового ответа: прежние игры уже не соответствуют условиям. Для каталога это неудобно — к этому тоже вернёмся в шаге 7.

**value() при ошибке.** Замените в шаблоне `@if (games.hasValue())` на `@if (games.value())`, включите «Ошибку 500» и перезапустите превью. Под фильтрами — пустота: ни сообщения, ни заглушек. В консоли:

```
ERROR ResourceValueError: Resource is currently in an error state (see Error.cause for details): Http failure response for /api/games?…: 500
```

Шаблон прочитал `value()`, получил исключение и не смог обновиться дальше. Отсюда правило: у ресурса, который может закончиться ошибкой, сначала `hasValue()` (или проверка ошибки), потом `value()`. Верните `hasValue()` и выключите флажок.

## Известная проблема: корзина

Добавьте в корзину «Глубокий космос» — игру, которой нет в `GAMES`, — и перезапустите превью кнопкой ⟳. Корзина пуста. Мы проверили: в `localStorage` игра сохранилась (`[{"id":34,"quantity":1}]`), но при запуске `loadCart()` ищет её по `id` в `GAMES`, не находит и отбрасывает. Пока игры знакомые, ошибки не видно. Исправим в шаге 6, когда избавимся от `GAMES` совсем.
