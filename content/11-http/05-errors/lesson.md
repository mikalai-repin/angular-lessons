Страница игры ищет игру в `GAMES` по `id` из адреса. Переведём её на сервер: `GET /api/games/4`. И здесь у ошибок появляется смысл. Раньше «Игра не найдена» значило «в массиве нет такого `id`». Теперь ответ может не прийти по двум совсем разным причинам:

- **404** — сервер ответил: такой игры нет. Повторять бессмысленно, нужно сказать покупателю и предложить каталог.
- **500** или обрыв связи — сервер не смог ответить. Игра, возможно, есть: стоит предложить повторить.

Покупателю важна разница, значит, и коду тоже.

## Игра по id

```ts game/game-page.ts
// Игра с сервера. Сменился id в адресе — новый запрос
protected readonly game = httpResource<Game>(
  () => `/api/games/${this.id()}`,
);
```

Здесь функция возвращает просто строку адреса — это короткая форма для `GET` без параметров. Внутри читается вход `id`, поэтому ресурс следит и за ним. Когда роутер переходит с `/games/4` на `/games/9`, он не пересоздаёт страницу, а только меняет её вход `id` — и ресурс сам загружает другую игру. Мы проверили: при таком переходе конструктор `GamePage` не вызывается второй раз, а в «Сети» появляется `GET /api/games/9`.

## Какая ошибка

`error()` ресурса возвращает ошибку загрузки. У `httpResource` это `HttpErrorResponse` — та же ошибка, что приходила в `subscribe` в шаге 2, с кодом ответа в `status`:

```ts game/game-page.ts
// Сервер ответил 404 — такой игры нет. Остальные ошибки — «не удалось загрузить»
protected readonly notFound = computed(() => {
  const error = this.game.error();
  return (
    error instanceof HttpErrorResponse && error.status === 404
  );
});
```

Тип `error()` — общий `Error | undefined`: ресурс не знает, кто его загружает. `instanceof HttpErrorResponse` проверяет, что это ошибка HTTP, и заодно сообщает TypeScript, что у неё есть `status`.

Шаблон разбирает четыре случая по порядку:

```html game/game-page.html
@if (game.isLoading()) {
  <p class="muted">Загружаем…</p>
} @else if (notFound()) {
  <h1>Игра не найдена</h1>
  …
} @else if (game.error()) {
  <p class="error-message">
    Не удалось загрузить игру.
    <button class="link-button" (click)="game.reload()">Повторить</button>
  </p>
} @else if (game.value(); as game) {
  … страница игры …
}
```

Порядок важен. `isLoading()` — первым, по той же причине, что на главной: во время повтора `error()` ещё помнит прошлую ошибку. Ошибки — раньше `value()`: при ошибке `value()` бросает исключение. А в последней ветке ошибки уже нет, и `value()` безопасен.

## Резолвер тоже спрашивает сервер

Название игры нужно ещё в двух местах: в заголовке вкладки и в хлебной крошке. Их даёт резолвер `gameTitleResolver` из главы 10. Он тоже должен спросить сервер. Резолвер — функция, а не ресурс: он вызывается один раз при переходе, и роутер ждёт его ответа. Поэтому здесь удобнее промис:

```ts game/game-title.ts {5,8-10}
export const gameTitleResolver: ResolveFn<string> = async (
  route,
) => {
  // inject — до первого await: после него контекст внедрения уже закончился
  const http = inject(HttpClient);
  try {
    // firstValueFrom подписывается на Observable и возвращает промис первого значения
    const game = await firstValueFrom(
      http.get<Game>(`/api/games/${route.paramMap.get('id')}`),
    );
    return game.title;
  } catch (error) {
    return error instanceof HttpErrorResponse &&
      error.status === 404
      ? 'Игра не найдена'
      : 'Игра';
  }
};
```

`firstValueFrom` из RxJS превращает Observable в промис: подписывается, ждёт первое значение и выполняет промис этим значением, а ошибку превращает в отклонённый промис. Дальше — обычные `async`, `await` и `try`/`catch`.

Обратите внимание на первую строку. `inject` работает только в контексте внедрения, а резолвер получает его лишь на время синхронной части вызова. После первого `await` функция продолжается позже, когда промис выполнится, — а контекста к тому времени уже нет. Поэтому все `inject` в асинхронной функции — до первого `await`.

Раньше резолвер стоял в маршруте дважды: в `title` и в `resolve.breadcrumb`. Пока он искал игру в массиве, это ничего не стоило. Теперь это два одинаковых запроса к серверу, а вместе со страницей — три. Оставим резолвер только в `resolve`, а заголовок вкладки пусть `ShopTitleStrategy` берёт из крошки, если своего `title` у маршрута нет:

```ts layout/shop-title-strategy.ts
let route = snapshot.root;
while (route.firstChild) {
  route = route.firstChild;
}
const title =
  this.buildTitle(snapshot) ?? route.data['breadcrumb'];
```

Цикл спускается к самому глубокому маршруту — как `Breadcrumbs`. Для страницы игры там лежит название от резолвера.

::: task
1. В `game/game-page.ts` замените `computed` с поиском в `GAMES` ресурсом `httpResource<Game>(() => `/api/games/${this.id()}`)`. Добавьте `notFound`, перепишите `inCart` через `hasValue()`.
2. В `game-page.html` разберите четыре случая: загрузка, «Игра не найдена», «Не удалось загрузить игру» с «Повторить», страница игры.
3. Перепишите `gameTitleResolver` на `HttpClient` и `firstValueFrom`. 404 — «Игра не найдена», другие ошибки — просто «Игра».
4. В `app.routes.ts` уберите `title: gameTitleResolver` у страницы игры, а в `ShopTitleStrategy` возьмите заголовок из `data.breadcrumb`, если `buildTitle` ничего не нашёл.
:::

## Что получилось

Превью открывается на `/games/4`: «Ночной экспресс», заголовок вкладки «Ночной экспресс — Ход конём». В «Сети» — два запроса `GET /api/games/4`: первый — резолвера, второй — самой страницы.

Наберите в адресной строке `/games/999`. «Игра не найдена», крошка и заголовок вкладки — тоже «Игра не найдена». В «Сети» — два ответа `404`.

## Эксперименты

**Сервер недоступен.** Включите «Ошибку 500» и перезапустите превью на `/games/4`. «Не удалось загрузить игру» и «Повторить», крошка — «Игра», вкладка — «Игра — Ход конём». Выключите флажок, нажмите «Повторить» — игра загрузится.

**Медленный сервер.** Поставьте задержку 1500 мс, перейдите в каталог и откройте любую игру. Полторы секунды ничего не происходит: роутер ждёт резолвер, и на экране остаётся каталог. Потом страница игры с «Загружаем…» — ещё полторы секунды: свой запрос делает страница. Два запроса подряд — плата за то, что резолвер и страница загружают игру независимо. В настоящем проекте повторный запрос убирают кэшем; кэш запросов как раз удобно сделать интерцептором — их мы напишем в главе 12.

**inject после await.** Поменяйте местами строки в резолвере: сначала `await`, потом `inject`. Например, добавьте `await Promise.resolve();` перед `const http = inject(HttpClient);`. Откройте `/games/4` адресной строкой — страница пустая, а в консоли:

```
ERROR RuntimeError: NG0203: The `HttpClient` token injection failed. `inject()` function must be called from an injection context such as a constructor, a factory function, a field initializer, or a function used with `runInInjectionContext`. Find more at https://v22.angular.dev/errors/NG0203
```

Переход не состоялся: резолвер упал, и роутер отменил навигацию. Верните порядок.

::: tip
В `fetch` из шага 1 ответ 404 был «успешным». У `HttpClient` и `httpResource` любой ответ с кодом не из 200–299 — ошибка, а код лежит в `status` у `HttpErrorResponse`. Разбирать коды — 404, 401, 409 — придётся часто: в главе 13 сервер ответит 409, если игр на складе меньше, чем в заказе, а в главе 14 — 401, если вход устарел.
:::
