Каталог, главная и страница игры уже работают с сервером. Массив `GAMES` остался нужен двоим: избранному и корзине. Избранное хранит `id` игр и по ним находит игры в `GAMES` для страницы «Избранное». Корзина при запуске восстанавливает позиции из `localStorage` по `id` — и, как мы видели в шаге 4, теряет игры, которых в массиве нет.

## Что изменилось в коде: корзина хранит снимок игры

Корзину мы уже поправили. В `localStorage` она теперь сохраняет не `id`, а **снимок игры** — весь объект `Game`, каким он был, когда покупатель положил игру в корзину:

```ts core/cart-store.ts
// Ключ корзины в localStorage. Формат поменялся (снимок игры вместо id) — поменяли и версию в ключе
const STORAGE_KEY = 'hod-konem:cart:v2';

// Что сохраняем о позиции: снимок игры и количество. Каталога в коде больше нет — искать игру по id негде
interface SavedItem {
  game: Game;
  quantity: number;
}
```

`loadCart()` больше не ищет игры — берёт их из снимка, проверив количество. Можно было при запуске загрузить каждую игру с сервера. Но тогда корзина в шапке несколько сотен миллисекунд показывала бы ноль. А снимок есть сразу. Цена или остаток в снимке могут устареть — их сверит сервер при оформлении заказа в главе 13.

Помните комментарий из главы 9: «поменяется формат — поменяем ключ». Он пригодился: старая корзина лежит под ключом `v1`, новая — под `v2`, и `loadCart()` не споткнётся о данные старого формата. Из-за этого сохранённая в прошлых главах корзина один раз окажется пустой.

## Избранное: игры по списку id

С избранным так не получится: у сердечка нет снимка, только `id`. Странице «Избранное» нужно загрузить игры с сервера. Запроса «дай игры по этому списку `id`» в API магазина нет — только `GET /api/games/:id` по одной. Значит, нужно несколько запросов, а их результаты — собрать в один список.

`httpResource` делает ровно один запрос. Для остального в Angular есть его основа — **`resource`** из `@angular/core`. Ему вы даёте не описание запроса, а свою функцию загрузки:

```ts account/favorites-page/favorites-page.ts
protected readonly games = resource({
  // Параметры загрузки. undefined — загружать нечего: ресурс в статусе idle
  params: () => {
    const ids = this.favorites.ids();
    return ids.length > 0 ? ids : undefined;
  },
  loader: ({ params, abortSignal }) =>
    loadGames(params, abortSignal),
});
```

- **`params`** — реактивная функция, как у `httpResource`: читает сигналы, и при их изменении ресурс загружает заново. Вернула `undefined` — загружать нечего, ресурс ничего не делает.
- **`loader`** — **загрузчик**: получает текущие `params` и возвращает промис значения. Чем он загружает — `fetch`, `HttpClient`, IndexedDB, — ресурсу всё равно.

Значение, `isLoading()`, `error()`, `hasValue()`, `reload()` — всё то же, что у `httpResource`. Да и сам `httpResource` устроен так же: это `resource` с готовым загрузчиком на `HttpClient`.

## Загрузчик и abortSignal

```ts account/favorites-page/favorites-page.ts
// Игры по списку id: запросы идут параллельно. abortSignal отменит их все, если список изменился раньше ответа
async function loadGames(
  ids: readonly number[],
  abortSignal: AbortSignal,
): Promise<Game[]> {
  const games = await Promise.all(
    ids.map(async (id) => {
      const response = await fetch(`/api/games/${id}`, {
        signal: abortSignal,
      });
      // Игры больше нет в каталоге — пропускаем её
      if (response.status === 404) {
        return null;
      }
      if (!response.ok) {
        throw new Error(`Игра ${id}: ответ ${response.status}`);
      }
      return (await response.json()) as Game;
    }),
  );
  return games.filter((game) => game !== null);
}
```

`abortSignal` — не сигнал Angular, а **сигнал отмены** (`AbortSignal`) из браузерного `AbortController`. Его понимает `fetch`: если сигнал сработал, запрос прерывается, а промис отклоняется. Ресурс создаёт новый `AbortController` для каждой загрузки и срабатывает им, когда загрузка больше не нужна: параметры изменились или компонент уничтожен. Передать `abortSignal` дальше — ваша задача. Без этого устаревшие запросы будут доходить до конца, хотя их результат ресурс всё равно выбросит.

Обратите внимание, как загрузчик обращается с ошибками. 404 — «такой игры больше нет»: её убрали из каталога, а в избранном `id` остался. Это не повод ломать всю страницу — игру пропускаем. Любой другой неудачный ответ — исключение: `Promise.all` отклонится, ресурс перейдёт в состояние ошибки, и страница покажет «Не удалось загрузить избранное». Здесь уже `fetch`, и проверять `response.ok` приходится самим — как в шаге 1.

## Избранное без GAMES

`FavoritesStore` больше не знает игры, только `id`. Сигнал с `id` мы делаем закрытым `state` и открываем только для чтения — как корзину в главе 9:

```ts core/favorites-store.ts
// id игр в избранном. Массив не меняем, а заменяем новым
private readonly state = signal<number[]>(loadFavorites());
// Снаружи — только чтение: страница «Избранное» загрузит игры по этим id
readonly ids = this.state.asReadonly();
```

`games` из хранилища уходит, а `loadFavorites()` проверяет только, что в `localStorage` лежат целые положительные числа. Есть ли такие игры, теперь решает сервер.

::: task
1. В `core/favorites-store.ts`: закрытый сигнал `state`, открытый `ids = state.asReadonly()`. Уберите `games` и импорт `GAMES`; `loadFavorites()` оставляет в списке только целые числа больше нуля.
2. В `favorites-page.ts` — ресурс `games` на `resource` с `params` из `favorites.ids()` и загрузчиком `loadGames`, который передаёт `abortSignal` в `fetch` и пропускает игры с ответом 404.
3. В `favorites-page.html`: пустое избранное, «Загружаем…», ошибка с «Повторить», сетка игр.
:::

## Что получилось

Превью открыто на «Избранном», а оно пока пустое: «В избранном пока пусто». Запросов в «Сети» нет — `params` вернул `undefined`.

Отметьте сердечком три игры в каталоге, в том числе одну из новых, и вернитесь в «Избранное». В «Сети» — три запроса `GET /api/games/…`, отправленные одновременно, и три карточки. Теперь положите в корзину новую игру и перезапустите превью кнопкой ⟳: игра в корзине осталась.

## Эксперименты

**Убрать из избранного.** Снимите сердечко с одной игры прямо на странице «Избранное». На мгновение — «Загружаем…», потом карточек на одну меньше. В «Сети» — снова запросы на **все** оставшиеся игры. Изменился `ids` — изменились `params` — ресурс загружает всё заново: он не знает, что одна игра просто ушла из списка. Для избранного это терпимо. Как ресурс решает, когда загружать, разберём в последнем шаге главы.

**Ушли, не дождавшись.** Поставьте задержку 1500 мс, на странице «Избранное» снимите сердечко и сразу перейдите в «Каталог». Мы проверили: запросы оставшихся игр в «Сети» — «отменён». Страница уничтожена, ресурс сработал `abortSignal`, и `fetch` прервал запросы. Уберите `signal: abortSignal` из `fetch` и повторите — запросы дойдут до конца.

**Пропавшая игра.** Добавьте первой строкой `main.ts`:

```ts
localStorage.setItem('hod-konem:favorites:v1', '[3, 34, 999]');
```

и перезапустите превью. В «Сети» — три запроса, у `GET /api/games/999` статус `404`. На странице — две игры: «Зельевары» и «Глубокий космос». Пропавшую игру загрузчик пропустил. А вот счётчик в шапке — «♥ 3»: хранилище не знает, что игры 999 нет. Уберите строку из `main.ts`.

::: deep Под капотом: когда resource, а когда httpResource
- Нужен один `GET`-запрос, ответ — JSON: **`httpResource`**. Он работает через `HttpClient`, поэтому видит интерцепторы и подменяется в тестах.
- Несколько запросов в одном значении, не HTTP (IndexedDB, Web Worker, сторонний SDK) или своя обработка ответа: **`resource`** со своим загрузчиком.
- Изменить данные на сервере: **не ресурс**, а `HttpClient` — об этом шаг 8. Документация Angular прямо предупреждает: ресурс отменяет загрузку при новых параметрах, и отправленная им мутация может прерваться на полпути.
:::
