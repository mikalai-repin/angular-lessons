В шаге 4 мы оставили каталогу две проблемы. Поиск отправляет запрос на каждую букву: устаревшие запросы ресурс отменяет, но на сервер они всё равно уходят. И при каждом изменении фильтров сетка пропадает, а на её месте мигают заглушки. Исправим обе.

## Что изменилось в коде

Файла `core/games-data.ts` больше нет. После прошлого шага массив `GAMES` никто не импортировал: каталог, главная, страница игры, корзина и избранное получают игры с сервера. Магазин больше не знает игр, пока не спросит.

## Задержка

Покупатель печатает «кот» за полсекунды. Запрос нужен один — на «кот», когда он перестал печатать. Это называют **задержкой** (debounce): значение «догоняет» источник, только когда тот перестал меняться на заданное время.

В Angular 22 для этого есть функция **`debounced`**:

```ts catalog/catalog.ts
// Строка поиска с задержкой: ресурс, значение которого догоняет q, когда q не менялся 300 мс
private readonly query = debounced(() => this.q(), 300);
```

Первый аргумент — источник, функция, которая читает сигналы. Второй — сколько миллисекунд ждать. Возвращает `debounced` не сигнал, а **ресурс**, со знакомыми `value()`, `isLoading()`, `status()`. Пока покупатель печатает, ресурс «загружается», а `value()` возвращает **прежнее** значение: мы проверили, что во время ожидания там остаётся последняя строка, которую ресурс уже «догнал». Через 300 мс тишины `value()` становится новой строкой.

В запросе каталога вместо `this.q()` — `this.query.value()`:

```ts catalog/catalog.ts
params: {
  q: this.query.value(),
  …
},
```

Ресурс каталога читает `query.value()`, а оно меняется раз в паузу. Значит, и запрос — раз в паузу. Адрес страницы при этом обновляется сразу, на каждую букву: задержан только запрос.

::: warning
`debounced` помечена в Angular 22 как **экспериментальная** (`@experimental 22.0`). В следующих версиях её название или поведение могут измениться. Для учебного проекта это нестрашно, а в рабочем коде экспериментальные API стоит изолировать в одном месте, чтобы при обновлении Angular править код в одной точке. Тот же приём на RxJS — оператор `debounceTime` — мы увидим в главе 12.
:::

## Прежние результаты, пока грузятся новые

Вторая проблема — мигание. При новых параметрах значение ресурса сбрасывается в `undefined`, и шаблон показывает заглушки. Для каталога лучше другое: пока грузятся новые результаты, показывать прежние, приглушив их.

Нужен сигнал «последний полученный ответ»: он меняется, когда приходит новый ответ, а пока ресурс загружается, сохраняет прошлое значение. Это работа для `linkedSignal` из главы 3 — он получает своё прежнее значение в `previous`:

```ts catalog/catalog.ts
// Последний полученный ответ. Пока грузится новый, у ресурса нет значения, — а мы показываем прежний.
// value() ресурса с ошибкой бросает исключение, поэтому сначала спрашиваем hasValue()
protected readonly found = linkedSignal<
  GamesPage | undefined,
  GamesPage | undefined
>({
  source: () =>
    this.games.hasValue() ? this.games.value() : undefined,
  computation: (page, previous) => page ?? previous?.value,
});
```

Пришёл ответ — `source` возвращает его, и `found` становится им. Ресурс загружается или ошибся — `source` возвращает `undefined`, и `found` оставляет прежнее значение. `visibleGames` берёт игры уже из `found`.

В шаблоне сетка теперь в ветке `@else if (found(); as found)`, а пока идёт загрузка, у сетки класс `loading` — в `catalog.css` он делает её полупрозрачной:

```html catalog/catalog.html
<div class="grid" [class.loading]="games.isLoading()">
```

## Статус ресурса

Осталась ошибка. Раньше мы считали так: нет значения и не грузится — значит, ошибка. Теперь значение (прежнее) есть почти всегда, и ошибка спряталась бы под старыми результатами. Нужно спросить ресурс прямо, в каком он состоянии. Для этого есть сигнал **`status()`** — одна из строк: `'idle'`, `'loading'`, `'reloading'`, `'resolved'`, `'error'`, `'local'`. Все статусы разберём в последнем шаге главы, а здесь нужен один:

```html catalog/catalog.html
@if (games.status() === 'error') {
  <p class="error-message">Не удалось загрузить каталог. …</p>
} @else if (found(); as found) {
  …
} @else {
  … заглушки …
}
```

Заглушки остались только для самой первой загрузки, когда показывать ещё нечего.

::: task
1. В `catalog/catalog.ts` добавьте `query = debounced(() => this.q(), 300)` и передавайте в запрос `this.query.value()`.
2. Добавьте `linkedSignal` `found` — последний полученный ответ — и берите `visibleGames` из него.
3. В `catalog.html`: первая ветка — `games.status() === 'error'`, вторая — `found(); as found` с «Найдено игр» из `found.total` и классом `loading` у сетки, последняя — заглушки.
:::

## Что получилось

Наберите в поиске «кот». Мы проверили при задержке ответа 1000 мс и паузе 100 мс между буквами: в «Сети» один запрос, `q=кот`. Пощёлкайте сортировку: сетка не пропадает, а на время загрузки бледнеет.

## Эксперименты

**Медленный покупатель.** Набирайте «мы» с паузой между буквами в полсекунды. Запросов два: на «м» и на «мы». Пауза больше 300 мс — и `debounced` решил, что покупатель закончил. При задержке ответа 1000 мс первый запрос не успел вернуться и был отменён, когда пришла вторая буква. Поменяйте 300 на 1000: задержка станет заметна глазу, и поиск покажется медленным. 200–400 мс — обычный выбор.

**Ошибка поверх результатов.** Включите «Ошибку 500» и смените сортировку. Сетку заменит «Не удалось загрузить каталог». Выключите флажок и нажмите «Повторить»: снова видны прежние, приглушённые результаты, а потом новые. Во время повтора статус — `'reloading'`, не `'error'`, и шаблон показывает `found`.

**Без linkedSignal.** Замените `found` на `computed(() => this.games.hasValue() ? this.games.value() : undefined)`. Мигание вернётся: `computed` не помнит прежних значений. Именно для «новое значение из источника, но с памятью о прошлом» и нужен `linkedSignal`.
