До сих пор магазин только читал данные. Теперь покупатель сможет их менять: на странице игры появится вкладка «Отзывы» со списком отзывов и формой, через которую можно оставить свой.

Учебный бэкенд принимает отзыв запросом `POST /api/games/:id/reviews` с телом `{ rating, text }` и отвечает сохранённым отзывом: с `id`, автором и датой. Входа в магазине пока нет (он появится в главе 14), поэтому отзыв без входа подписан «Гость».

## Список отзывов

Чтение — снова ресурс:

```ts game/game-page.ts
// Отзывы об игре. defaultValue — значение, пока ответа нет: пустой список вместо undefined
protected readonly reviews = httpResource<Review[]>(
  () => `/api/games/${this.id()}/reviews`,
  { defaultValue: [] },
);
```

Тип `Review` добавлен в `core/models.ts`. Второй аргумент `httpResource` — настройки. **`defaultValue`** — что возвращает `value()`, пока ответа нет. С ним тип `value()` — `Review[]`, а не `Review[] | undefined`, и к списку можно дописывать без проверок. От исключения при ошибке `defaultValue` не спасает: по исходнику Angular `value()` ресурса с ошибкой всё равно бросает его. Поэтому шаблон, как каталог в прошлом шаге, сначала проверяет `reviews.status() === 'error'`, потом `isLoading()` — «Загружаем отзывы…», и только затем выводит список.

## Отправка

Отправлять будем не ресурсом. Ресурс сам решает, когда загружать, и отменяет загрузку, если параметры изменились или страница уничтожена. Для чтения это то, что нужно. Для изменения данных — опасно: покупатель нажал «Отправить» и ушёл со страницы, а отзыв не дошёл. Изменения отправляют через `HttpClient` — запросом, который делает ровно одно действие и не отменяется сам:

```ts
this.http.post<Review>(`/api/games/${this.id()}/reviews`, { rating, text })
```

`post<T>(адрес, тело)` отправляет тело как JSON. Так же устроены `put` (заменить) и `delete` (удалить) — ими мы воспользуемся в админке в главе 17.

## Оптимистичное обновление

Можно отправить запрос и ждать ответа, а потом перезагрузить список. Но тогда после нажатия «Отправить» покупатель 300 мс смотрит на прежний список и гадает, сработала ли кнопка. Лучше наоборот: показать отзыв **сразу**, а запрос отправить следом. Если сервер ответит ошибкой — убрать отзыв и сообщить об этом. Такой приём называют **оптимистичным обновлением** (optimistic update): мы рассчитываем, что запрос удастся, а к неудаче готовы.

```ts game/game-page.ts {8,16,21,27,34}
protected addReview(textBox: HTMLTextAreaElement) {
  const text = textBox.value.trim();
  if (!text) {
    return;
  }
  // Черновик: так отзыв будет выглядеть, когда сервер его сохранит
  const draft: Review = {
    id: this.nextDraftId--,
    gameId: this.id(),
    author: 'Вы',
    rating: this.newRating(),
    text,
    date: new Date().toISOString().slice(0, 10),
  };
  // Оптимистичное обновление: отзыв появляется сразу, не дожидаясь ответа сервера
  this.reviews.update((reviews) => [...reviews, draft]);
  textBox.value = '';
  this.reviewError.set('');

  this.http
    .post<Review>(`/api/games/${this.id()}/reviews`, {
      rating: draft.rating,
      text,
    })
    .subscribe({
      // Сервер сохранил отзыв: заменяем черновик настоящим
      next: (saved) =>
        this.reviews.update((reviews) =>
          reviews.map((review) =>
            review === draft ? saved : review,
          ),
        ),
      // Не получилось: убираем черновик и возвращаем текст в поле
      error: () => {
        this.reviews.update((reviews) =>
          reviews.filter((review) => review !== draft),
        );
        textBox.value = text;
        this.reviewError.set(
          'Не удалось отправить отзыв. Попробуйте ещё раз.',
        );
      },
    });
}
```

Разберём по порядку.

- **Черновик** — отзыв, каким он станет после сохранения. Но `id` ему выдаёт не сервер, а мы: отрицательный (`nextDraftId` начинается с −1), чтобы не совпасть с настоящими — сервер нумерует отзывы с 1. По отрицательному `id` шаблон пишет «отправляем…» вместо даты.
- **`reviews.update(…)`** — у ресурса есть `set` и `update`, как у сигнала: значение можно поменять на месте, без запроса. Ресурс при этом переходит в статус `'local'` — «значение задано в коде, а не загружено».
- **`next`** — сервер ответил сохранённым отзывом. Заменяем черновик им: ищем по ссылке `review === draft`, ведь черновик — тот самый объект.
- **`error`** — откат: убираем черновик, возвращаем текст в поле, показываем сообщение. Покупатель ничего не потерял и может нажать «Отправить» ещё раз.

Оценку нового отзыва выбирают знакомым компонентом `Rating` из главы 5: `[value]="newRating()"` и `(valueChange)="newRating.set($event)"`. Текст — `<textarea #reviewText>`, ссылка на элемент из главы 2. С настоящими формами мы познакомимся в главе 13.

::: task
1. Добавьте тип `Review` в `core/models.ts` и ресурс `reviews` с `defaultValue: []` на странице игры.
2. Во вкладке «Отзывы» выведите ошибку загрузки, «Загружаем отзывы…» и список: оценка, автор, дата или «отправляем…», текст. Пустой список — «Отзывов пока нет. Будьте первым!».
3. Под списком — форма: `<app-rating>`, `<textarea #reviewText>` и кнопка «Отправить», которая вызывает `addReview(reviewText)`.
4. Напишите `addReview` с оптимистичным обновлением и откатом при ошибке.
:::

## Что получилось

Откройте вкладку «Отзывы» у «Ночного экспресса»: три отзыва. Напишите свой и нажмите «Отправить». Отзыв сразу в конце списка — от «Вы», с «отправляем…». Через 300 мс подпись меняется на «Гость» и дату: черновик заменил ответ сервера. В «Сети» — `POST /api/games/4/reviews` со статусом `201`; щёлкните по нему — увидите тело запроса `{ rating, text }` и ответ сервера.

## Эксперименты

**Неудача.** Поставьте задержку 1500 мс, включите «Ошибку 500» и отправьте отзыв. Полторы секунды он виден с «отправляем…», потом исчезает: текст вернулся в поле, под формой — «Не удалось отправить отзыв. Попробуйте ещё раз.». Мы проверили всю цепочку при задержке 1500 мс.

**Ушли, не дождавшись.** Выключите «Ошибку 500», оставьте задержку 1500 мс, отправьте отзыв и сразу перейдите в «Каталог». В «Сети» у `POST` статус `201`, не «отменён»: `HttpClient` довёл запрос до конца. Вернитесь к «Ночному экспрессу» — ваш отзыв в списке, теперь уже с сервера. Сравните с шагом 3: там уход со страницы отменял запросы ресурса, и для чтения это правильно.

**Без отката.** Уберите обработчик `error` и повторите «Неудачу». Отзыв останется в списке с «отправляем…» навсегда, хотя сервер его не сохранил, а в консоли — `ERROR HttpErrorResponse`. Оптимистичное обновление без отката обманывает покупателя. Верните обработчик.

::: tip
Чем оптимистичное обновление лучше простого «отправить и перезагрузить список»? Интерфейс отзывается мгновенно. Но у него есть цена: нужно уметь откатить изменение. Для отзыва это легко. Для заказа, оплаты, удаления — обычно честнее показать «отправляем…» и дождаться ответа: ошибка после «Заказ оформлен!» обидит сильнее, чем полсекунды ожидания.
:::
