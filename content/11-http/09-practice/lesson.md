Каталог просит у сервера сразу все найденные игры (`size: 100`), а «Показать ещё» отрезает их порциями уже в браузере. Пока игр 40, это работает. Но настоящий магазин присылал бы сотни карточек, из которых покупатель увидит шесть. Пусть сервер присылает каталог **страницами** — по одной порции на запрос, — а «Показать ещё» просит следующую.

API уже умеет: `GET /api/games?page=2&size=6` — вторая страница по шесть игр. В ответе `page` — номер страницы, `items` — её игры, `total` — сколько игр найдено всего.

::: task
1. **Страница запроса.** Каталог просит у сервера одну страницу: параметры `page` и `size`, размер страницы — `pageSize` из `SHOP_CONFIG` (6).
2. **Номер страницы** — сигнал. «Показать ещё» (щелчок или появление на экране) увеличивает его на один. Новый поиск, фильтр или сортировка — снова страница 1.
3. **Показанные игры** копятся: первая страница заменяет список, следующие дописываются в конец. Пока страница грузится, на экране прежний список — как в шаге 7.
4. **«Показать ещё»** — пока показаны не все найденные игры (`total` из ответа) и пока страница не грузится.
5. `shownCount` и отрезание порций в браузере больше не нужны.
:::

::: hint Подсказка 1: фильтры одним объектом
Номер страницы должен сбрасываться при изменении любого фильтра. Удобно собрать поиск, фильтры и сортировку в один `computed`:

```ts
private readonly filters = computed(() => ({
  q: this.query.value(),
  inStock: this.inStock(),
  rating: this.rating(),
  sort: SORT_PARAMS[this.sort()],
}));
```

Изменился любой фильтр — `computed` вернёт новый объект. Его же можно целиком положить в `params` запроса: `{ ...this.filters(), page: …, size: … }`.
:::

::: hint Подсказка 2: номер страницы со сбросом
«Значение, которое можно менять, но которое сбрасывается при изменении источника» — это `linkedSignal`. Так же был устроен `shownCount` в главе 6:

```ts
protected readonly page = linkedSignal({
  source: this.filters,
  computation: () => 1,
});
```

`showMore()` — `this.page.update((page) => page + 1)`.
:::

::: hint Подсказка 3: список, который копится
Здесь тоже нужен `linkedSignal`, ведь новое значение зависит от прежнего. Источник — ответ сервера или `undefined`, пока ответа нет:

```ts
protected readonly shownGames = linkedSignal<GamesPage | undefined, Game[]>({
  source: () => (this.games.hasValue() ? this.games.value() : undefined),
  computation: (page, previous) => {
    const shown = previous?.value ?? [];
    // Пока страница грузится — прежний список
    // Первая страница — новый список, следующие — в конец прежнего
  },
});
```

Отличить первую страницу от следующих поможет поле `page` в ответе.
:::

::: hint Подсказка 4: когда показывать «Показать ещё»
```html
@if (!games.isLoading() && shownGames().length < found.total) {
  <app-load-more (more)="showMore()" />
}
```

Почему `!games.isLoading()`? `LoadMore` срабатывает и сам, когда появляется на экране. Если оставить его во время загрузки, он может попросить следующую страницу, пока текущая ещё не пришла.
:::

## Проверьте себя

Нажмите «Проверить» — проверка запустит каталог заново, сменит сортировку, нажмёт «Показать ещё» и загрузит все страницы. Или проверьте сами:

- В «Сети» при открытии каталога — запрос с `page=1&size=6`, на экране шесть игр и «Найдено игр: 40».
- «Показать ещё» — запрос с `page=2`, игр двенадцать, первые шесть на месте.
- Смените сортировку — снова `page=1` и шесть игр. Пока грузится новая страница, прежние карточки видны приглушёнными.
- Прокрутите каталог вниз: страницы подгружаются сами, когда «Показать ещё» появляется на экране. На сороковой игре «Показать ещё» исчезает.
- Найдите «кот» — одна игра и никакого «Показать ещё».

## Итоги главы

| Что | Зачем |
|---|---|
| учебный бэкенд, вкладка «Сеть», задержка и «Ошибка 500» | видеть запросы и проверять приложение на медленном и сломанном сервере |
| `HttpClient`, `provideHttpClient()`, `get`, `post` | запросы к серверу; ответ не 2xx — ошибка `HttpErrorResponse` |
| Observable, `subscribe`, `unsubscribe`, `firstValueFrom` | запрос уходит при подписке, отписка его отменяет; промис из Observable |
| `httpResource` | чтение данных сигналами: `value`, `hasValue`, `isLoading`, `error`, `status`, `reload` |
| сигналы внутри функции запроса | новые параметры — новый запрос, устаревший отменяется |
| `resource({ params, loader })`, `abortSignal` | своя загрузка — несколько запросов, не HTTP — с отменой |
| `defaultValue`, `set`, `update` | значение до ответа; изменить значение ресурса на месте |
| `debounced` (экспериментальная) | запрос, когда покупатель перестал печатать |
| `linkedSignal` поверх ресурса | показывать прежние данные, пока грузятся новые; копить страницы |

И главные идеи:

- данные сервера приходят **не сразу** и **не всегда**: у каждого экрана три состояния — загрузка, данные, ошибка;
- для чтения — ресурс: он сам отправляет, повторяет и отменяет запросы; для изменения — `HttpClient`, который доводит запрос до конца;
- у ресурса с ошибкой `value()` бросает исключение — сначала `hasValue()` или `status()`;
- 404 и 500 — разные ошибки: «такого нет» и «не получилось», и покупателю нужны разные ответы.

Магазин теперь получает данные с сервера. Мы уже несколько раз встретили Observable: `HttpClient` возвращает его, а `firstValueFrom` превращает в промис. В главе 12 «RxJS» разберёмся, что такое потоки, зачем они Angular рядом с сигналами и как с их помощью перехватывать каждый запрос — интерцепторами. А перед этим — необязательный шаг «под капотом»: как устроен ресурс внутри.
