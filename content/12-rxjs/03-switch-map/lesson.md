В шапке магазина появилось поле «Быстрый поиск». Покупатель печатает название — под полем список подходящих игр, щелчок — и он на странице игры. Каталог с фильтрами для этого не нужен.

## Что изменилось в коде

Новый компонент `QuickSearch` в `layout/quick-search/` уже подключён в шапку (`header.html`, в строке меню). Шаблон и стили готовы:

```html layout/quick-search/quick-search.html
<input #box class="quick-search-input" type="search" … (input)="search(box.value)" (keydown.escape)="open.set(false)" />
@if (open() && suggestions().length > 0) {
  <ul class="suggestions">
    @for (game of suggestions(); track game.id) {
      <li>
        <a [routerLink]="['/games', game.id]" (click)="choose(box)">{{ game.title }}</a>
      </li>
    }
  </ul>
}
```

В классе — сигналы `suggestions` (подсказки) и `open` (открыт ли список), метод `choose` закрывает список, когда покупатель выбрал игру. А `search` пока написан «в лоб»: запрос на каждое изменение поля.

Напечатайте в поле «кот» и откройте «Сеть»: три запроса — `к`, `ко`, `кот`. Два из них не нужны: покупатель ещё печатал. Теперь сотрите текст — под пустым полем пять игр, которых покупатель не искал. Последним ушёл запрос с пустым `q`, и сервер честно ответил первыми играми каталога.

В главе 11 ту же задачу для каталога решили сигналами: `debounced` + `httpResource`. Здесь решим её на RxJS. Это самый известный пример RxJS в Angular-приложениях — вы встретите его почти в любом проекте, а заодно познакомитесь с главными операторами.

## Поток текстов: Subject

Чтобы применять операторы, ввод покупателя должен стать потоком. Для этого есть **`Subject`** — поток, в который можно отправлять значения самому:

```ts
private readonly texts = new Subject<string>();

protected search(text: string) {
  this.open.set(true);
  this.texts.next(text);
}
```

`next(значение)` — отправить значение всем подписчикам. `Subject` — горячий поток: он не ждёт подписчиков, а кто подписался позже, получит только следующие значения.

## Операторы поиска

Цепочку соберём в конструкторе — по одному оператору на каждое требование.

**`debounceTime(300)`** — «дождаться паузы». Значение проходит, только если после него 300 мс не было новых. Пока покупатель печатает, оператор молчит, а когда он остановился — пропускает последний текст:

```text
texts:        к-о-т-------о-с-т-------->
debounceTime: ------кот---------ост---->
```

**`distinctUntilChanged()`** — пропускает значение, только если оно отличается от предыдущего. Покупатель стёр «т» и напечатал снова — после паузы снова «кот», и повторять запрос незачем.

**`switchMap(функция)`** — главный оператор этого шага. Функция получает значение и возвращает **новый поток** — здесь запрос к серверу. `switchMap` подписывается на этот запрос и передаёт его ответ дальше. А когда приходит следующий текст, он **отписывается от прежнего запроса** и подписывается на новый. Мы знаем, что отписка у `HttpClient` — отмена запроса. Значит, ответ на устаревший текст не придёт никогда: его запрос отменён.

```text
тексты:    --ко------кот--------->
запросы:     \---✗    \----[…]
подсказки: ----------------[…]--->
```

Короткому тексту запрос не нужен. Для него `switchMap` вернёт поток из одного готового значения — `of([])`, пустой список: подсказки исчезнут, когда поле очистили.

```ts layout/quick-search/quick-search.ts
constructor() {
  this.texts
    .pipe(
      map((text) => text.trim()),
      // Ждём паузы в 300 мс: пока покупатель печатает, запросов нет
      debounceTime(300),
      // Текст не изменился («кот» → «ко» → «кот») — запрос не нужен
      distinctUntilChanged(),
      // Новый текст — новый запрос. Прежний, если ответ ещё не пришёл, отменяется
      switchMap((text) =>
        text.length < 2
          ? of([])
          : this.http
              .get<GamesPage>('/api/games', {
                params: { q: text, size: 5 },
              })
              .pipe(
                map((page) => page.items),
                // Сервер не ответил — подсказок нет, но поток живёт дальше
                catchError(() => of([])),
              ),
      ),
    )
    .subscribe((games) => this.suggestions.set(games));
}
```

## Ошибка заканчивает поток

Осталась строка с `catchError`. Мы помним из шага 1: после ошибки поток закончен. Если запрос внутри `switchMap` вернёт ошибку, она пройдёт дальше по цепочке — и закончит **весь** поток поиска. Подписка умрёт, и быстрый поиск перестанет работать до перезагрузки страницы.

`catchError(функция)` ловит ошибку и вместо неё подставляет поток, который вернула функция, — здесь `of([])`: «подсказок нет». Важно, где он стоит: **внутри** `switchMap`, на потоке одного запроса. Ошибка заканчивает только этот маленький поток, а внешний поток текстов о ней не узнаёт и ждёт следующего текста.

::: task
1. Добавьте поле `texts = new Subject<string>()`; `search` отправляет в него текст вместо запроса, `choose` — пустую строку.
2. В конструкторе соберите поток: `map` (обрезать пробелы), `debounceTime(300)`, `distinctUntilChanged()`, `switchMap` — запрос `GamesPage` с параметрами `q` и `size: 5` для текста от двух букв, `of([])` для более короткого. Ошибку запроса замените пустым списком через `catchError` внутри `switchMap`.
3. Подпишитесь: ответ кладите в `suggestions`.
:::

## Что получилось

Напечатайте «кот» — в «Сети» один запрос: `q=кот&size=5`. Под полем «Космические коты». Сотрите текст — подсказки исчезли, запроса нет. Щелчок по подсказке — страница игры, поле пустое, список закрыт.

## Операторы переключения

`switchMap` — один из четырёх похожих операторов. Все они превращают значение в новый поток, а различаются тем, что делать, если пришло новое значение, а прежний поток ещё не закончился:

| Оператор | Прежний поток | Когда брать |
|---|---|---|
| `switchMap` | отменить | поиск, загрузка по выбору: нужен ответ только на последний запрос |
| `mergeMap` | оставить, оба работают одновременно | независимые действия: «В корзину» по разным играм |
| `concatMap` | дождаться, потом начать новый | порядок важен: сохранения по очереди |
| `exhaustMap` | оставить, а новое значение пропустить | кнопка «Оплатить»: повторный щелчок, пока идёт оплата, не нужен |

Для чтения данных почти всегда нужен `switchMap`. Для отправки — осторожнее: `switchMap` может отменить запрос, который меняет данные на сервере, и вы не узнаете, дошёл ли он.

## Эксперименты

**Без паузы.** Уберите `debounceTime(300)` и напечатайте «кот». В «Сети» — `q=ко` со статусом «отменён» и `q=кот` → 200. Запрос на «к» не ушёл вовсе (текст короче двух букв). `switchMap` отменил запрос, на который покупатель уже не ждёт ответа: гонки нет и без паузы. Пауза бережёт сервер — запросов становится меньше. Верните `debounceTime`.

**`mergeMap` вместо `switchMap`.** Снова без `debounceTime` замените `switchMap` на `mergeMap` (и импорт). Теперь оба запроса — `ко` и `кот` — со статусом 200: прежний не отменяется. Здесь ответы приходят по порядку, потому что задержка учебного бэкенда одинаковая. У настоящего сервера ответ на «ко» может прийти позже ответа на «кот» — и под полем окажутся подсказки для старого текста. Верните `switchMap` и `debounceTime`.

**Ошибка без `catchError`.** Уберите `catchError(…)`, включите во вкладке «Сеть» «Ошибку 500» и напечатайте «кот». В консоли — `ERROR HttpErrorResponse`. Выключите «Ошибку 500», сотрите и напечатайте «ост»: в «Сети» тишина. Поток поиска закончился вместе с ошибкой, и подписки больше нет. Верните `catchError` и повторите: после ошибки следующий текст снова отправляет запрос. Только не тот же самый: если после сбоя напечатать «кот» ещё раз, `distinctUntilChanged` решит, что текст не изменился, и запроса не будет. Повторять запрос при сбое сервера мы научим все запросы сразу — в шаге 7.

**Тот же текст.** Напечатайте «кот», дождитесь подсказок, сотрите «т» и сразу напечатайте её снова. Через 300 мс снова «кот» — и `distinctUntilChanged` его не пропустил: нового запроса нет. Уберите `distinctUntilChanged()` — тот же опыт даёт второй одинаковый запрос.

::: tip Сигналы или RxJS?
Каталог в главе 11 ищет через `debounced` и `httpResource`: там отмена устаревших запросов и пауза — свойства ресурса. Оба способа рабочие. Ресурс даёт готовые статусы (`isLoading`, `error`) и не требует подписки. RxJS удобнее, когда шагов обработки много и они про время: пауза, «не повторять то же самое», «отменить прежнее», «повторить при ошибке». Подробное сравнение — в последнем шаге главы.
:::

О подписке в конструкторе: мы нигде не отписываемся. Здесь это не утечка — шапка живёт столько же, сколько приложение. Когда отписка обязательна и как не забыть о ней, — в шаге 6.
