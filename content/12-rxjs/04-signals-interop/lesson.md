Быстрый поиск работает, но в нём два мира, соединённые руками. Шаблон читает сигнал `suggestions`, а наполняет его `subscribe` — вызовом `set`. Текст из поля попадает в поток через `Subject` и `next` в методе `search`. Таких «переходников» в приложении может быть много, и каждый — несколько строк, которые легко написать неправильно: забыть отписку, забыть начальное значение.

Для этого в Angular есть мост между сигналами и потоками — пакет `@angular/core/rxjs-interop`. Две главные функции:

- **`toSignal(поток)`** — сигнал, значение которого — последнее значение потока;
- **`toObservable(сигнал)`** — поток, который присылает каждое новое значение сигнала.

## toSignal: поток → сигнал

```ts
protected readonly suggestions = toSignal(поток, { initialValue: [] });
```

`toSignal` **сразу подписывается** на поток и кладёт каждое его значение в сигнал. Подписку он отменит сам, когда уничтожат компонент (или сервис), в котором его вызвали: для этого он берёт `DestroyRef` и поэтому работает только в контексте внедрения — в инициализаторе поля или конструкторе.

У сигнала значение есть всегда, а у потока до первого значения — нет. `initialValue` — значение сигнала до первого значения потока. Без него сигнал до этого момента вернёт `undefined`, и TypeScript добавит `undefined` к типу. Если поток гарантированно присылает значение сразу при подписке, вместо `initialValue` можно указать `requireSync: true`: тогда `toSignal` проверит это и бросит ошибку, если значения не было.

Ошибку потока `toSignal` не проглатывает: чтение сигнала после неё **бросает** эту ошибку. Поэтому `catchError` в нашем потоке по-прежнему нужен.

## toObservable: сигнал → поток

Текст поиска удобнее держать сигналом: его можно связать с полем (`[value]`) и сбросить из любого метода. А поток из него даёт `toObservable`:

```ts
protected readonly text = signal('');

toObservable(this.text).pipe(…)
```

Подписчик сначала получает **текущее значение** сигнала, а затем каждое новое. Как это устроено: `toObservable` создаёт эффект, который читает сигнал и отправляет значение в поток. Отсюда два свойства, которые стоит помнить:

- значения приходят не в момент `set`, а когда выполняется эффект, — **после** текущего кода;
- два `set` подряд — один запуск эффекта, и поток получит только последнее значение. Промежуточные значения сигнала поток не видит.

Поток завершится сам, когда уничтожат компонент, в котором вызвали `toObservable`.

## Быстрый поиск без переходников

```ts layout/quick-search/quick-search.ts
protected readonly text = signal('');

// Подсказки: поток ответов сервера, превращённый в сигнал. До первого ответа — пустой список
protected readonly suggestions = toSignal(
  toObservable(this.text).pipe(
    map((text) => text.trim()),
    // …те же операторы: debounceTime, distinctUntilChanged, switchMap
  ),
  { initialValue: [] },
);

protected search(text: string) {
  this.open.set(true);
  this.text.set(text);
}

protected choose() {
  this.open.set(false);
  this.text.set('');
}
```

Конструктор с `subscribe`, `Subject` и сигнал, который заполнялся руками, больше не нужны. Поле в шаблоне связано с сигналом, а `choose` больше не трогает элемент поля:

```html layout/quick-search/quick-search.html {2,6}
<input
  [value]="text()"
  (input)="search(box.value)"
  …
/>
<a [routerLink]="['/games', game.id]" (click)="choose()">
```

::: task
1. Замените `Subject` сигналом `text` (начальное значение — пустая строка): `search` и `choose` меняют его через `set`.
2. Сделайте `suggestions` результатом `toSignal(toObservable(this.text).pipe(…), { initialValue: [] })` — с той же цепочкой операторов. Конструктор больше не нужен.
3. В шаблоне свяжите поле с сигналом (`[value]="text()"`), `choose` вызывайте без аргумента.
:::

## Что получилось

Внешне — ничего нового: «кот», один запрос, «Космические коты», выбор подсказки очищает поле. Зато в классе нет ни одного `subscribe`. Подпиской владеет `toSignal`, и он же отпишется.

## Эксперименты

**Что получает поток.** Добавьте первым оператором `tap((text) => console.log('Поток получил:', JSON.stringify(text)))`. При запуске в консоли — `Поток получил: ""`: текущее значение сигнала пришло сразу при подписке. Напечатайте «кот» — три строки, по одной на изменение.

**Два `set` подряд.** Не убирая `tap`, допишите в `search` вторую запись: `this.text.set(text.toUpperCase())`. Напечатайте «кот»: в консоли только `"К"`, `"КО"`, `"КОТ"` — строчных значений поток не увидел, хотя сигнал их получал. Эффект внутри `toObservable` выполнился один раз, когда оба `set` уже прошли. Уберите вторую запись и `tap`.

**Не в контексте внедрения.** Вызовите `toSignal(of(1))` внутри `search`. При вводе в консоли:

```text
ERROR RuntimeError: NG0203: toSignal() can only be used within an injection context such as a constructor, a factory function, a field initializer, or a function used with `runInInjectionContext`.
```

Та же ошибка, что у `effect` и `inject` в главе 8: `toSignal` нужен `DestroyRef`, чтобы отписаться. Уберите вызов.

::: deep Под капотом: мост в 30 строк
Обе функции короткие — их код в `@angular/core/fesm2022/rxjs-interop.mjs`.

`toObservable` создаёт `ReplaySubject(1)` — поток, который помнит последнее значение и сразу отдаёт его новому подписчику, — и эффект, который читает сигнал и вызывает `subject.next(value)`. При уничтожении владельца эффект уничтожается, а поток завершается (`complete`). Чтение сигнала внутри эффекта отслеживается, а отправка в поток — нет (`untracked`): подписчики не становятся зависимостями эффекта.

`toSignal` подписывается на поток и хранит в закрытом сигнале состояние: «значения ещё нет», «значение» или «ошибка». Наружу отдаёт `computed`, который возвращает значение или бросает ошибку. Отписка регистрируется в `DestroyRef`. Поэтому `toSignal` нельзя вызывать внутри `computed` или эффекта: каждый перезапуск создавал бы новую подписку. В режиме разработки Angular проверяет это и бросает ошибку `toSignal() cannot be called from within a reactive context`.
:::
