«Избранное» загружает игры через `resource` и свой загрузчик на `fetch` (шаг 11.6). В загрузчике много ручной работы: передать `abortSignal` в каждый `fetch`, проверить статус, разобрать JSON, собрать ответы через `Promise.all`. И у `fetch` есть недостаток, о котором мы говорили в главе 11: его запросы идут мимо `HttpClient`. Через шаг у `HttpClient` появятся интерцепторы — лог и повтор при сбое, — а запросы «Избранного» их не увидят.

Перепишем загрузку на `HttpClient` и RxJS. Поможет **`rxResource`** — ресурс, который загружает данные не промисом, а потоком.

## rxResource

`rxResource` из `@angular/core/rxjs-interop` — тот же `resource`: у него те же `params`, статусы, `value()`, `isLoading()`, `error()`, `reload()`. Отличие одно: вместо `loader`, который возвращает промис, — **`stream`**, который возвращает Observable:

```ts
protected readonly games = rxResource({
  params: () => …,
  stream: ({ params }) => поток,
});
```

Ресурс подписывается на поток, и каждое значение потока становится значением ресурса. Изменились параметры или уничтожен компонент — ресурс **отписывается** от прежнего потока. Для `HttpClient` отписка — отмена запроса, поэтому `abortSignal` больше не нужен.

## forkJoin: дождаться всех

Нам нужно несколько запросов сразу и ответ, когда придут все, — то, что делал `Promise.all`. В RxJS для этого **`forkJoin`**:

```text
игра 3:   ----[3]|
игра 34:  ------[34]|
forkJoin: ------[[3, 34]]|
```

`forkJoin([поток1, поток2, …])` подписывается на все потоки сразу, ждёт, пока каждый **завершится**, и выдаёт массив их последних значений. Если любой из потоков закончился ошибкой — `forkJoin` тоже заканчивается ошибкой, а от остальных отписывается.

Отсюда важная деталь: `forkJoin([])` от пустого массива сразу завершается, **не выдав ни одного значения**. А для `rxResource` поток, который завершился без значения, — ошибка. Поэтому `params` по-прежнему возвращает `undefined`, когда избранное пусто: ресурс просто не загружается.

## Пропустить 404: catchError и throwError

Игра могла пропасть из каталога — сервер ответит 404, и её надо пропустить, не ломая весь список. Это работа для `catchError`: он ловит ошибку одного запроса. Но ловить **все** ошибки нельзя: если сервер не ответил (500), «Избранное» должно показать «Не удалось загрузить», а не пустой список. Значит, 404 заменяем на `null`, а остальные ошибки отправляем дальше:

```ts account/favorites-page/favorites-page.ts
// Игра по id. Игры больше нет в каталоге (404) — null, другие ошибки идут дальше по потоку
private loadGame(id: number): Observable<Game | null> {
  return this.http.get<Game>(`/api/games/${id}`).pipe(
    catchError((error: unknown) =>
      error instanceof HttpErrorResponse && error.status === 404
        ? of(null)
        : throwError(() => error),
    ),
  );
}
```

`catchError` должен вернуть поток. `of(null)` — поток из одного значения `null`. `throwError(() => error)` — поток, который сразу заканчивается этой ошибкой: так ошибка «пробрасывается» дальше.

Осталось собрать ресурс:

```ts account/favorites-page/favorites-page.ts {1,7-10}
protected readonly games = rxResource({
  params: () => {
    const ids = this.favorites.ids();
    return ids.length > 0 ? ids : undefined;
  },
  // Все запросы сразу, ответ — когда придут все
  stream: ({ params }) =>
    forkJoin(params.map((id) => this.loadGame(id))).pipe(
      map((games) => games.filter((game) => game !== null)),
    ),
});
```

`map` убирает из массива `null` — пропавшие игры. Как и с `filter` в шаге 2, TypeScript понял, что функция в `filter` массива — проверка типа: результат — `Game[]`, без `null`.

::: task
1. Получите `HttpClient` через `inject`. Добавьте метод `loadGame(id)`: запрос игры, 404 — `of(null)`, остальные ошибки — дальше через `throwError`.
2. Замените `resource` на `rxResource`: те же `params`, а вместо `loader` — `stream` с `forkJoin` по всем `id` и `map`, который убирает `null`.
3. Функция `loadGames` на `fetch` больше не нужна — удалите её.

## Что получилось

Внешне «Избранное» прежнее. В «Сети» — по запросу на игру, как раньше, но теперь их отправляет `HttpClient`.

## Эксперименты

**Пропавшая игра.** Как в шаге 11.6, добавьте первой строкой в `main.ts`:

```ts
localStorage.setItem('hod-konem:favorites:v1', '[3, 34, 999]');
```

и перезапустите превью. В «Сети» у `GET /api/games/999` статус 404, на странице — «Зельевары» и «Глубокий космос». Теперь уберите `.pipe(catchError(…))` из `loadGame`, оставив только запрос: на странице «Не удалось загрузить избранное». Одна ошибка закончила весь `forkJoin`. Верните `catchError` и уберите строку из `main.ts`.

**Ушли, не дождавшись.** Отметьте сердечком две-три игры, поставьте задержку 1000 мс, перейдите в «Избранное» и сразу — на главную. Запросы игр в «Сети» — «отменён». Ресурс уничтожен вместе со страницей и отписался от `forkJoin`, а тот — от каждого запроса.

::: deep Под капотом: rxResource поверх resource
`rxResource` — тонкая обёртка: он вызывает обычный `resource` со `stream`, который подписывается на ваш Observable. Каждое значение потока становится значением ресурса, а на событие `abort` у `abortSignal` (новые параметры, `reload`, уничтожение) обёртка отвечает отпиской. Поток может выдать **несколько** значений — ресурс покажет каждое по очереди. А если поток завершился, ничего не выдав, ресурс переходит в ошибку «Resource completed before producing a value». Код — в `@angular/core/fesm2022/rxjs-interop.mjs`, функция `rxResource`.
:::
