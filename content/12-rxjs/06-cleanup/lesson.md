На странице игры со скидкой идут часы: «Скидка действует ещё 08:26:41». Их сигнал даёт `injectNow` из главы 8. Внутри — `setInterval`, а чтобы таймер не пережил компонент, функция регистрирует `clearInterval` в `DestroyRef`. Обе части — запуск и уборку — мы написали руками.

В RxJS есть поток-таймер **`interval(мс)`**: он присылает 0, 1, 2… через равные промежутки. Перепишем часы на нём — и заодно разберём главную ошибку при работе с потоками в компонентах.

## Подписка, которую никто не отменил

Первый вариант напрашивается сам:

```ts shared/now.ts
export function injectNow(periodMs = 1000): Signal<number> {
  assertInInjectionContext(injectNow);
  const now = signal(Date.now());
  interval(periodMs)
    .pipe(
      tap((n) => console.log('Тик', n)),
      map(() => Date.now()),
    )
    .subscribe((time) => now.set(time));
  return now.asReadonly();
}
```

`tap` здесь только для опыта: он покажет, что таймер жив. Часы идут. Теперь перейдите в «Каталог»: «Тик» продолжает печататься — страницы игры нет, а таймер работает. Вернитесь на игру кнопкой ← («Назад») у адресной строки превью: теперь в консоли два счётчика вперемешку — `Тик 6`, `Тик 0`, `Тик 7`, `Тик 1`… Старый таймер и новый.

Это **утечка подписки**. `interval` — поток, который никогда не завершается сам. Подписку держит таймер браузера, а подписка держит функцию из `subscribe` и всё, на что та ссылается: сигнал `now`, а через него — данные уничтоженного компонента. Каждый визит на страницу добавляет ещё один таймер, и они работают, пока открыта вкладка.

Правило: **если подписались сами на поток, который может пережить компонент, — отпишитесь, когда компонент уничтожен**. Такие потоки — `interval`, события роутера, `Subject` в сервисе, события `window` и `document`.

## takeUntilDestroyed

Отписаться можно руками: сохранить `Subscription` и вызвать `unsubscribe()` в `DestroyRef.onDestroy` — так мы сделали в главе 11 с запросом на главной. Но в Angular для этого есть оператор **`takeUntilDestroyed()`** из `@angular/core/rxjs-interop`:

```ts shared/now.ts {5}
interval(periodMs)
  .pipe(
    tap((n) => console.log('Тик', n)),
    map(() => Date.now()),
    takeUntilDestroyed(),
  )
  .subscribe((time) => now.set(time));
```

Он берёт `DestroyRef` текущего контекста внедрения — здесь того, кто вызвал `injectNow`, — и завершает поток, когда тот уничтожается. Завершение идёт вниз по цепочке до подписки, а отписка — вверх, до `interval`, и таймер останавливается.

Вне контекста внедрения (например, в обработчике щелчка) `DestroyRef` нужно передать явно: `takeUntilDestroyed(this.destroyRef)`. И ставьте `takeUntilDestroyed` **последним** оператором перед `subscribe`. Оператор после него может создать подписку, о которой `takeUntilDestroyed` не знает, — например, `switchMap` с запросом внутри.

## Ещё проще: toSignal

Посмотрите, что получилось: подписка, `set` в сигнал, отписка при уничтожении, сигнал наружу. Это ровно то, что делает `toSignal` из шага 4:

```ts shared/now.ts
export function injectNow(periodMs = 1000): Signal<number> {
  // Понятная ошибка, если функцию вызвали вне контекста внедрения
  assertInInjectionContext(injectNow);
  // interval присылает 0, 1, 2… раз в periodMs. Нам нужен не номер, а время
  return toSignal(
    interval(periodMs).pipe(map(() => Date.now())),
    { initialValue: Date.now() },
  );
}
```

`initialValue: Date.now()` — время сразу, до первого тика: иначе первую секунду часы были бы пустыми.

Как выбирать:

- результат потока — **значение**, которое нужно показать или посчитать, — `toSignal`. Подписка и отписка — его забота;
- результат — **действие**: запись в `localStorage`, переход, сообщение — `subscribe` с `takeUntilDestroyed()`.

::: task
1. Перепишите `injectNow` на `interval` с `subscribe`, как в первом фрагменте (с `tap`). Убедитесь, что после ухода со страницы игры «Тик» продолжается, а после возвращения таймеров два.
2. Добавьте `takeUntilDestroyed()` последним оператором. Теперь при уходе тики прекращаются.
3. Замените подписку на `toSignal` с `initialValue: Date.now()`, как в последнем фрагменте. `tap`, `signal` и `DestroyRef` больше не нужны.
:::

## Что получилось

Часы идут как раньше, а в `injectNow` вместо таймера, сигнала и уборки — один вызов `toSignal`. Таймер останавливается вместе с компонентом: `toSignal` отписывается сам.

## Пайп async

Есть третий способ, который не требует отписки: подписаться **в шаблоне** пайпом `async`. Он подписывается на поток, показывает его последнее значение и отписывается, когда шаблон уничтожается. Например, в `Countdown`:

```ts shared/countdown/countdown.ts
protected readonly left$ = interval(1000).pipe(
  map(() => untilMidnight(Date.now())),
);
```

```html shared/countdown/countdown.html
Скидка действует ещё {{ left$ | async | date: 'HH:mm:ss' : 'UTC' }}
```

`AsyncPipe` нужно добавить в `imports` из `@angular/common`. Знак `$` в конце имени часто ставят у потоков: так видно, что это не значение, а поток. Попробуйте — часы работают, но первую секунду после строки «Скидка действует ещё» пусто: до первого значения `async` возвращает `null`. Верните вариант с `left()`.

В существующем коде `async` встречается очень часто: до сигналов это был основной способ показать поток в шаблоне. В новом коде удобнее `toSignal`: значение можно использовать и в шаблоне, и в `computed`, и в коде класса, а начальное значение задаётся явно.

## Когда отписка не нужна

| Подписка | Нужна ли уборка |
|---|---|
| `toSignal`, `rxResource`, пайп `async` | нет — уберут сами |
| `output()` (`.subscribe` у выхода другой директивы) | нет — подписчики снимаются при уничтожении владельца |
| `toObservable(сигнал)` | поток сам завершается вместе с компонентом |
| `HttpClient` | запрос завершится сам, но отписка отменит его при уходе со страницы |
| `interval`, `router.events`, `Subject` сервиса, события `window` | **да**: `takeUntilDestroyed()` |

Если сомневаетесь — добавьте `takeUntilDestroyed()`. Лишняя отписка ничего не ломает, забытая — копит таймеры и подписки.

::: legacy Вы встретите в старом коде: destroy$ и takeUntil
До `takeUntilDestroyed` отписку писали так:

```ts
private readonly destroy$ = new Subject<void>();

ngOnInit() {
  interval(1000)
    .pipe(takeUntil(this.destroy$))
    .subscribe(…);
}

ngOnDestroy() {
  this.destroy$.next();
  this.destroy$.complete();
}
```

`takeUntil(поток)` завершает поток, когда другой поток выдаёт значение, — а `ngOnDestroy` выдавал его вручную. `takeUntilDestroyed` делает то же самое, только `DestroyRef` подставляет Angular: в его коде — `source.pipe(takeUntil(destroyed$))`, где `destroyed$` выдаёт значение из `destroyRef.onDestroy`.
:::
