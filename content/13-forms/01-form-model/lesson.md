В магазине уже есть поля ввода: поиск, промокод, комментарий к заказу. Каждое мы связывали вручную: `[value]` показывает значение, `(input)` записывает новое в сигнал. Для одного поля это нормально. Но настоящая форма — это не одно поле:

- значений много, и вместе они — один объект: контакты, адрес, способ доставки;
- у каждого поля свои правила: обязательное, e-mail без опечаток, пароль не короче четырёх символов;
- у каждого поля есть состояние: покупатель его ещё не трогал, уже ушёл из него, изменил, ждёт ответа сервера;
- форму отправляют: кнопка блокируется на время запроса, ошибки сервера нужно показать у формы;
- одни поля появляются только при определённых условиях, другие повторяются списком.

Писать всё это руками для каждой формы — долго и с ошибками. В Angular для этого есть модуль форм. Форм в нём три вида:

- **шаблонные формы** (template-driven, `ngModel`) — правила проверки пишут прямо в шаблоне;
- **реактивные формы** (`FormGroup`, `FormControl`) — их вы встретите почти в любом существующем проекте;
- **Signal Forms** (`@angular/forms/signals`) — формы на сигналах, новый API. В Angular 22 он публичный (`@publicApi 22.0`).

Курс — про Signal Forms: они построены на тех же сигналах, что и всё остальное в магазине. Реактивные формы разберём в одном шаге — чтобы вы могли читать чужой код. К концу главы у магазина появятся:

- страница входа с проверкой полей и ошибкой «Неверный e-mail или пароль» от сервера;
- форма оформления заказа: контакты, доставка (адрес — только для курьера), открытки к подарку;
- промокод, который проверяет сервер, пока покупатель печатает;
- форма отзыва, где оценку ставят звёздами — нашим компонентом `Rating`;
- в практикуме — отправка заказа на сервер и защита от ухода с заполненной формой.

## Модель и форма

Форма в Signal Forms начинается с **модели формы** — обычного сигнала с данными:

```ts login/login.ts {5-8,10}
import { signal } from '@angular/core';
import { form } from '@angular/forms/signals';

export class Login {
  protected readonly model = signal<LoginData>({
    email: '',
    password: '',
  });
  // Форма — дерево полей поверх модели
  protected readonly loginForm = form(this.model);
}
```

Модель — **единственный источник правды**. Форма не копирует данные к себе: что бы ни произошло с полями, значение лежит в `model`. Покупатель напечатал букву — изменилась модель. Код изменил модель — поле на экране показало новое значение.

`form(model)` возвращает **дерево полей** (`FieldTree`) той же формы, что и данные: у модели есть `email` и `password` — значит, есть и поля `loginForm.email` и `loginForm.password`. Если бы в модели был вложенный объект `contacts: { name, phone }`, было бы и `loginForm.contacts.name`.

Поле — это функция. Её вызов возвращает **состояние поля** (`FieldState`) — набор сигналов:

```ts
this.loginForm.email; // поле
this.loginForm.email(); // состояние поля
this.loginForm.email().value(); // значение: ''
this.loginForm(); // состояние всей формы
```

Сейчас из состояния нам нужно только значение — `value`. Это записываемый сигнал: `loginForm.email().value.set('a@b.c')` запишет значение в модель. Остальные сигналы состояния (ошибки, «тронуто», «изменено») появятся в следующих шагах.

`form` ищет инжектор, как `inject` и `effect`, поэтому вызывать его нужно в контексте внедрения: в инициализаторе поля или в конструкторе.

## Поле ввода и поле формы

Связывает элемент на странице с полем формы директива `FormField` из `@angular/forms/signals`. Её селектор — атрибут `formField`:

```html login/login.html {5}
<label class="field">
  E-mail
  <input
    type="email"
    [formField]="loginForm.email"
  />
</label>
```

Обратите внимание: в привязку передаётся **само поле** — `loginForm.email`, без скобок. Директиве нужно поле целиком, а не значение в эту секунду: она сама будет читать его состояние и записывать в него.

`[formField]` работает в обе стороны:

- показывает значение поля в элементе и обновляет его, когда модель меняется;
- слушает ввод и записывает новое значение в поле — а значит, в модель.

Это те же `[value]` и `(input)`, которые мы писали руками, но для любого элемента формы: `<input>` любого типа, `<textarea>`, `<select>`, флажка, переключателя — и даже для своего компонента (это будет в шаге «Своё поле формы»).

Чтобы видеть модель целиком, выведем её под формой пайпом `json` — как в главе 7:

```html login/login.html
<pre class="debug">{{ model() | json }}</pre>
```

И добавим учебную кнопку: она записывает в модель учётную запись учебного бэкенда. Так проверим вторую сторону связи — от модели к полям:

```ts login/login.ts
protected fillDemo() {
  this.model.set({ email: 'user@example.com', password: 'user' });
}
```

::: task
1. В `login.ts` создайте модель `model` — сигнал `LoginData` с пустыми `email` и `password` — и форму `loginForm = form(this.model)`.
2. Добавьте в `imports` компонента `FormField` (из `@angular/forms/signals`) и `JsonPipe` (из `@angular/common`).
3. В `login.html` свяжите поля ввода с полями формы: `[formField]="loginForm.email"` и `[formField]="loginForm.password"`.

5. Под формой выведите модель: `<pre class="debug">{{ model() | json }}</pre>`.
:::

## Что получилось

Печатайте в поле e-mail — JSON под формой меняется на каждую букву. Нажмите «Заполнить тестовыми данными» — оба поля заполнились, хотя мы не трогали ни один элемент: изменилась модель, и `[formField]` показал новое значение.

Сотрите пароль и напечатайте другой — модель снова следует за полем. Связь двусторонняя, но данные хранятся в одном месте.

## Эксперименты

**Забытый импорт.** Уберите `FormField` из `imports`. В консоли:

```text
NG0303: Can't bind to 'formField' since it isn't a known property of 'input' (used in the 'Login' component template).
```

Та же ошибка, что с `[scr]` в главе 2: без директивы Angular ищет у `<input>` свойство `formField` и не находит. Поля на месте, но ни с чем не связаны — JSON не меняется. В настоящем проекте AOT-сборка остановилась бы с `NG8002`. Верните импорт.

**Значение вместо поля.** Напишите `[formField]="loginForm.email()"` — со скобками. В консоли — `ERROR TypeError: this.field(...) is not a function`: директива получила состояние поля и попыталась вызвать его как поле. Следом — `TimeoutError: Transition was aborted…`: плавная смена страниц из главы 10 не дождалась отрисовки, это следствие первой ошибки. Опечатка в имени поля (`loginForm.mail`) даёт ту же ошибку: такого поля нет, директива получает `undefined`. AOT поймал бы обе ошибки ещё при сборке: `TS2322` для скобок и `TS2551: Property 'mail' does not exist … Did you mean 'email'?` для опечатки — шаблон проверяется по типу модели. Верните как было.

**Форма вне контекста внедрения.** Создайте форму внутри `fillDemo`: `form(signal({ a: '' }))`. При щелчке по кнопке в консоли:

```text
ERROR RuntimeError: NG0203: The `Injector` token injection failed. `inject()` function must be called from an injection context …
```

`form` внутри вызывает `inject(Injector)`, поэтому работает там же, где `inject`. Уберите вызов.

::: deep Под капотом: что делает [formField] с полем ввода
Откройте инструменты разработчика и посмотрите на поле e-mail. У него появился атрибут `name="ng.form0.email"`: директива назвала элемент по пути поля в форме (`form0` — номер формы в приложении). Значение элемента директива задаёт сама — через свойство `value`, как привязка `[value]`.

При вводе директива записывает новое значение в сигнал `value` состояния поля. А этот сигнал не хранит значение сам: он читает `model().email`, а при записи **создаёт новый объект модели** — копию с новым `email` — и кладёт его в `model`. Поэтому `model()` после каждой буквы — новый объект, и всё, что зависит от модели (`computed`, шаблон с пайпом `json`), пересчитывается. Подробно дерево полей разберём в последнем шаге главы.
:::

::: legacy Вы встретите в старом коде: ngModel
В шаблонных формах значение связывают «бананом в коробке» — двусторонней привязкой к полю класса:

```html
<input name="email" [(ngModel)]="email" />
```

`NgModel` — директива из `FormsModule`. Правила проверки там пишут атрибутами в шаблоне (`required`, `minlength` — это тоже директивы), а состояние формы живёт в объектах директив. Значит, форма существует, только пока отрисован шаблон: в классе компонента её нет.
:::
