Настольные игры часто дарят. Магазин бесплатно подписывает открытку к подарку — а то и несколько: «Маше от бабушки», «Пете на день рождения». Сколько открыток, заранее неизвестно: покупатель добавляет их сам, до трёх, и может убрать лишнюю. У каждой открытки — два поля: кому и текст.

Это **список полей**: в модели — массив, а в форме — поле-массив, у которого столько полей-элементов, сколько элементов в массиве.

## Массив в модели

```ts checkout/checkout.ts {1-3,5-9,13}
// Сколько открыток можно добавить к заказу и сколько букв в каждой
const MAX_POSTCARDS = 3;
const POSTCARD_TEXT_MAX = 120;

// Открытка к подарку: кому и что написать
interface Postcard {
  to: string;
  text: string;
}

interface CheckoutData {
  // …contacts, delivery
  postcards: Postcard[];
  comment: string;
}
```

Начальное значение — пустой массив: `postcards: []`.

Поле-массив `checkoutForm.postcards` похоже на массив полей: у него есть `length`, элемент по индексу (`checkoutForm.postcards[0]` — поле первой открытки, у него `to` и `text`), и его можно перебрать в `@for`. Элементы появляются и исчезают **вместе с массивом в модели**: форма следит за моделью и сама создаёт поле для новой открытки.

Поэтому добавить и убрать открытку — значит изменить массив в модели. Как обычно с сигналами — новым массивом:

```ts checkout/checkout.ts
// Список полей растёт и сокращается вместе с массивом в модели
protected addPostcard() {
  this.model.update((order) => ({
    ...order,
    postcards: [...order.postcards, { to: '', text: '' }],
  }));
}

protected removePostcard(index: number) {
  this.model.update((order) => ({
    ...order,
    postcards: order.postcards.filter((_, i) => i !== index),
  }));
}
```

## Правила для каждого элемента

Правила схемы пишут для путей, а у элементов массива пути заранее нет: открыток может быть ноль или три. Для этого — `applyEach`: функция схемы, которая применяется к **каждому** элементу массива — и к тем, что добавят потом:

```ts checkout/checkout.ts
// Правила для каждой открытки списка — и для тех, что добавят потом
applyEach(checkout.postcards, (postcard) => {
  required(postcard.to, { message: 'Кому эта открытка?' });
  maxLength(postcard.text, POSTCARD_TEXT_MAX, {
    message: `Не больше ${POSTCARD_TEXT_MAX} символов`,
  });
});
```

Аргумент `postcard` — путь «любой элемент списка». Его поля — `postcard.to` и `postcard.text`, как у обычной группы.

## Список в шаблоне

```html checkout/checkout.html
<!-- Поле-массив перебирается, как массив: каждый элемент — поле-открытка -->
@for (postcard of checkoutForm.postcards; track postcard; let i = $index) {
  <div class="postcard">
    <label class="field">
      Кому
      <input [formField]="postcard.to" />
      <app-field-errors [field]="postcard.to" />
    </label>
    <label class="field">
      Текст
      <textarea rows="2" [formField]="postcard.text"></textarea>
      <span class="muted">
        {{ postcard.text().value().length }} / {{ postcardTextMax }}
      </span>
      <app-field-errors [field]="postcard.text" />
    </label>
    <button type="button" class="link-button" (click)="removePostcard(i)">
      Убрать открытку
    </button>
  </div>
} @empty {
  <p class="muted">Подпишем открытку к подарку — бесплатно.</p>
}
@if (checkoutForm.postcards.length < maxPostcards) {
  <button type="button" class="link-button" (click)="addPostcard()">
    + Добавить открытку
  </button>
}
```

`track postcard` — ключ по самому полю. Поле открытки — один и тот же объект, пока открытка в списке, даже если соседние убрали. Поэтому при удалении первой открытки Angular удалит её блок, а остальные блоки оставит как есть — с фокусом, выделением текста и состоянием полей.

Кнопкам `type="button"`: форма скоро станет `<form>`, и обычная кнопка внутри неё отправляла бы заказ. Константы `MAX_POSTCARDS` и `POSTCARD_TEXT_MAX` шаблону не видны — он видит только поля класса. Поэтому в классе — `protected readonly maxPostcards = MAX_POSTCARDS` и `postcardTextMax`.

::: task
1. Добавьте в модель массив `postcards: Postcard[]` (начальное значение — `[]`) и константы `MAX_POSTCARDS = 3`, `POSTCARD_TEXT_MAX = 120`.
2. Правила для каждой открытки (`applyEach`): «Кому» обязательно («Кому эта открытка?»), текст — не длиннее `POSTCARD_TEXT_MAX` символов.
3. Методы `addPostcard()` и `removePostcard(index)` меняют массив в модели.
4. В шаблоне — группа «Открытки к подарку»: список открыток с полями «Кому» и «Текст», счётчиком символов и кнопкой «Убрать открытку», надпись «Подпишем открытку к подарку — бесплатно.», пока открыток нет, и кнопка «+ Добавить открытку», пока их меньше трёх.
:::

## Что получилось

Добавьте две открытки, напишите «Маше» и «Пете». Добавьте третью — кнопка «+ Добавить открытку» пропала. Пройдите через пустое «Кому» третьей открытки — «Кому эта открытка?». Уберите первую открытку: остались «Пете» и пустая третья, ошибка — по-прежнему у пустой. Состояние поля («тронуто») переехало вместе с открыткой, а не осталось на месте под индексом 2.

## Эксперименты

**Длинный текст.** Напечатайте в тексте открытки больше 120 символов — после 120-го ввод останавливается, а счётчик показывает `120 / 120`. Это не форма, а браузер: `[formField]` перенёс правило `maxLength` в атрибут `maxlength="120"` (посмотрите в инструментах разработчика). Ошибку «Не больше 120 символов» вы увидите, только если длинный текст попадёт в модель из кода — например, из сохранённого черновика. Правило в форме всё равно нужно: атрибут — подсказка браузеру, а данные проверяет форма.

**Ключ по индексу.** Замените `track postcard` на `track $index`, добавьте три открытки «A», «B», «C» и уберите первую. На экране — «B» и «C», как и раньше, но устроено это иначе. С `track postcard` Angular удалил блок «A», а блоки «B» и «C» не тронул. С `track $index` он удалил **последний** блок, а в первых двух поменял поля: в блоке, где была «A», теперь `[formField]` связан с «B», и так далее. Внешне разницы почти нет, но элементы на странице теперь другие: если бы покупатель печатал в «B», фокус остался бы в блоке, который теперь показывает «C». Верните `track postcard`.

::: tip
Как форма узнаёт, что поле `postcards[2]` теперь стало `postcards[1]`, а не новой открыткой? По объекту элемента в модели: `filter` вернул те же объекты открыток, только без первой. Если бы `removePostcard` создавал **новые** объекты (`map((p) => ({ to: p.to, text: p.text }))`), для формы это были бы новые открытки с нетронутыми полями. Как именно форма помечает объекты, — в последнем шаге главы.
:::
