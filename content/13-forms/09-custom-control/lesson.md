На странице игры есть ещё одна форма — новый отзыв: оценка звёздами и текст. Она написана в главе 11 вручную: сигнал `newRating` для звёзд, элемент `<textarea>` по ссылке `#reviewText`, проверка «текст не пустой» в методе, сигнал `reviewError` для ошибки. Переведём её на Signal Forms.

С текстом всё ясно — `[formField]` на `<textarea>`. А звёзды — наш компонент `Rating` из главы 5. Может ли поле формы быть компонентом?

## Договор поля формы

Может. `[formField]` работает не только со стандартными элементами, но и с любым компонентом, который выполняет **договор поля формы** — интерфейс `FormValueControl<T>` из `@angular/forms/signals`. Обязательное в нём одно:

```ts
readonly value: ModelSignal<T>;
```

Модель (`model()`) из главы 5 — вход и выход сразу: `[formField]` записывает в неё значение поля и слушает её изменения. У `Rating` такая модель уже есть: `readonly value = model(0)`. Значит, звёзды — уже готовое поле формы. Всё остальное в договоре необязательно: если компонент объявил вход или выход с нужным именем, `[formField]` его подключит:

| Член компонента | Что передаёт `[formField]` |
|---|---|
| вход `errors` | ошибки поля |
| входы `disabled`, `readonly`, `hidden` | отключено, только для чтения, скрыто |
| входы `required`, `invalid`, `touched`, `dirty` | остальное состояние поля |
| выход `touch` | компонент сообщает: покупатель закончил с полем |

У `Rating` уже есть вход `readonly` — и форма будет управлять им тоже.

Чего не хватает — выхода `touch`. У `<input>` «тронуто» `[formField]` узнаёт по событию `blur`. У компонента событий элемента нет, поэтому он сообщает сам. Без `touch` поле звёзд никогда не станет «тронутым» (до отправки формы), и `<app-field-errors>` не покажет под ним ошибку.

```ts shared/rating/rating.ts {6-7,10,16-17}
// FormValueControl — договор поля формы: компонент с model() value можно связать с полем через [formField]
@Component({
  selector: 'app-rating',
  host: {
    // …
    // Ушли со звёзд — сообщаем форме: поле «тронуто»
    '(blur)': 'touch.emit()',
  },
})
export class Rating implements FormValueControl<number> {
  readonly value = model(0);
  readonly readonly = input(false, {
    transform: booleanAttribute,
  });
  // Покупатель закончил с полем. Форма слушает этот выход и отмечает поле тронутым
  readonly touch = output();
}
```

`implements FormValueControl<number>` — проверка для TypeScript: если имя или тип члена не совпадут с договором, ошибка будет в классе компонента, а не где-то в шаблоне формы. `(blur)` на хост-элементе работает, потому что у звёзд есть `tabindex`: хост получает фокус при щелчке и при Tab.

## Форма отзыва

```ts game/game-page.ts
// Новый отзыв — форма: оценка звёздами и текст. Компонент Rating — тоже поле формы
private readonly reviewModel = signal({ rating: 5, text: '' });
protected readonly reviewForm = form(
  this.reviewModel,
  (review) => {
    min(review.rating, 1, { message: 'Поставьте оценку — хотя бы одну звезду' });
    required(review.text, { message: 'Напишите пару слов об игре' });
  },
  { submission: { action: () => this.addReview() } },
);
```

Повторный щелчок по той же звезде сбрасывает оценку в 0 (так сделано в главе 5) — отсюда правило `min`.

`addReview` — тот же оптимистичный отзыв из главы 11, только теперь это действие отправки формы: черновик появляется сразу, форма сбрасывается (`reset`), а когда сервер ответил — черновик заменяется настоящим отзывом. Ошибку отправки возвращаем из функции, как в форме входа, — сигнал `reviewError` больше не нужен. При ошибке ещё и возвращаем отзыв в форму: `this.reviewModel.set({ rating, text })`. Запрос отправляем через `firstValueFrom`, чтобы дождаться ответа в `async`-функции.

```html game/game-page.html
<form class="review-form" [formRoot]="reviewForm">
  <!-- Rating — свой компонент, но для формы такое же поле, как textarea -->
  <app-rating [formField]="reviewForm.rating" />
  <app-field-errors [field]="reviewForm.rating" />
  <textarea rows="3" placeholder="Ваш отзыв" aria-label="Текст отзыва"
    [formField]="reviewForm.text"></textarea>
  <app-field-errors [field]="reviewForm.text" />
  @for (error of reviewForm().errors(); track error.kind) {
    <p class="error-message">{{ error.message }}</p>
  }
  <button class="button">Отправить</button>
</form>
```

::: task
1. `Rating`: добавьте `implements FormValueControl<number>`, выход `touch = output()` и на хост — `'(blur)': 'touch.emit()'`.
2. На странице игры замените `newRating` и `reviewError` формой `reviewForm` с моделью `{ rating: 5, text: '' }`: оценка не меньше 1 («Поставьте оценку — хотя бы одну звезду»), текст обязателен («Напишите пару слов об игре»).
3. Сделайте `addReview` действием отправки формы: черновик и сброс формы сразу, потом `POST` через `firstValueFrom`. При ошибке — убрать черновик, вернуть отзыв в форму и вернуть ошибку «Не удалось отправить отзыв. Попробуйте ещё раз.».
4. В шаблоне — `<form [formRoot]>` с `[formField]` на звёздах и тексте, ошибками полей и формы. В `imports` — `FormField`, `FormRoot`, `FieldErrors` и `FieldAria`: директива поставит `aria-invalid` и `aria-describedby` и хосту звёзд.
:::

## Что получилось

Откройте вкладку «Отзывы». Нажмите «Отправить» с пустым текстом — «Напишите пару слов об игре», запроса нет. Щёлкните по правой половине пятой звезды — та же оценка 5, поэтому она сбросилась в 0. Перейдите в текст — под звёздами «Поставьте оценку — хотя бы одну звезду»: звёзды сообщили, что поле тронуто. Поставьте оценку и напишите отзыв — он появился в списке с пометкой «отправляем…», а форма снова пустая, с пятью звёздами.

## Эксперименты

**Без touch.** Уберите `'(blur)': 'touch.emit()'` с хоста. Сбросьте звёзды в 0 (правая половина пятой звезды) и перейдите в текст — ошибки под звёздами нет: форма не знает, что покупатель закончил с ними. Ошибка появится только при отправке — та помечает тронутыми все поля. Верните `(blur)`.

**Форма управляет входом.** Добавьте в схему отзыва правило `readonly(review.rating)`. Звёзды стали картинкой: щелчки не меняют оценку, у хоста `role="img"` и класс `readonly`. Это вход `readonly` нашего `Rating` из главы 5 — теперь его выставляет `[formField]` по правилу формы. Уберите правило.

**Чужое поле.** Свяжите звёзды с текстом: `<app-rating [formField]="reviewForm.text" />`. В превью ошибки нет, а AOT-сборка не пропустит: `TS2322: Type 'string' is not assignable to type 'number'` — тип поля формы не совпадает с типом модели компонента. Верните `reviewForm.rating`.

**Сбой сервера.** Включите во вкладке «Сеть» «Ошибку 500» и отправьте отзыв. Он появился с пометкой «отправляем…», а после ответа `500` пропал, текст вернулся в форму, под ней — «Не удалось отправить отзыв. Попробуйте ещё раз.». Повтор при 5xx из главы 12 здесь не помог: он повторяет только `GET`. Выключите «Ошибку 500».

::: tip
Если компонент хранит значение в другом виде, чем модель формы (например, показывает строку «1 290», а в модели число), пригодится `transformedValue` из `@angular/forms/signals`: сигнал «сырого» значения с функциями `parse` и `format`. Ошибки разбора он сам передаёт полю формы.
:::
