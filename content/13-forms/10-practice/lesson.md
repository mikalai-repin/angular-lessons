Форма оформления заказа собирает контакты, доставку, открытки и комментарий — и всё ещё ничего не отправляет. Самое время: учебный бэкенд принимает заказы.

`POST /api/orders` с телом заказа:

```json
{
  "items": [{ "gameId": 1, "quantity": 2 }],
  "contacts": { "name": "…", "phone": "…", "email": "…" },
  "delivery": { "method": "courier", "address": "…", "callBefore": false },
  "postcards": [],
  "comment": "…",
  "promo": "KNIGHT10",
  "total": 4970
}
```

Ответы сервера:

- `201` и сохранённый заказ с номером — `{ id: 1, … }`;
- `409`, если какой-то игры на складе меньше, чем в корзине. Корзина хранит снимок игры с тем остатком, который был при добавлении, — а склад с тех пор мог опустеть. Сервер объясняет, чего не хватило: `{ message: '«Остров сокровищ»: на складе только 12' }`.

Сервер учебный: заказ живёт, пока не перезапустилось превью.

И ещё одно. В главе 12 мы убрали гард ухода со страницы: комментарий сохранялся черновиком сам. Но контакты, адрес и открытки черновиком не сохраняются. Покупатель заполнил всю форму и случайно щёлкнул по «Каталогу» — всё пропало. Гард нужно вернуть — для формы.

::: task
1. **Форма.** Поля оформления и кнопка «Оформить заказ» — внутри `<form>`, связанного с формой. Пустая форма не отправляется: ошибки появляются у полей.
2. **Отправка.** Заказ уходит `POST /api/orders` с позициями корзины (`items`: `gameId` и `quantity`), контактами, доставкой, открытками, комментарием, кодом промокода (или `null`) и суммой к оплате.
3. **Ожидание.** Пока заказ отправляется, кнопка заблокирована и пишет «Оформляем…».
4. **Успех.** Вместо формы — «Заказ №… оформлен» с номером из ответа сервера и ссылка в каталог. Корзина очищена, черновик комментария удалён из `localStorage`.
5. **Нет на складе.** При ответе `409` покажите у формы сообщение сервера. Другие ошибки — «Не удалось оформить заказ. Попробуйте ещё раз».
6. **Уход со страницы.** Если покупатель менял форму, а заказ ещё не оформлен, уход со страницы спрашивает «Данные заказа не сохранятся. Уйти со страницы?». «Отмена» оставляет на оформлении. После оформления заказа — уходить без вопроса.
:::

::: hint Подсказка 1: что уже есть
Отправка формы — как в форме входа и форме отзыва: `<form [formRoot]="checkoutForm">` и настройки формы третьим аргументом `form`: `{ submission: { action: () => this.placeOrder() } }`. Действие — `async`-функция: запрос через `HttpClient` и `firstValueFrom`, ошибка — объект `{ kind, message }` в ответе функции. Ошибки всей формы — в `checkoutForm().errors()`, состояние отправки — `checkoutForm().submitting()`.
:::

::: hint Подсказка 2: тело заказа
Почти всё уже лежит в модели формы: `const { contacts, delivery, postcards, comment } = this.model()`. Позиции — из корзины: `this.cart.items().map((item) => ({ gameId: item.game.id, quantity: item.quantity }))`. Промокод — `this.cart.promo()?.code ?? null`, сумма — `this.toPay()`.
:::

::: hint Подсказка 3: номер заказа
Номер нужен и шаблону (что показать), и гарду (есть ли что терять). Заведите сигнал `orderId = signal<number | null>(null)` и запишите в него `id` из ответа. В шаблоне — `@if (orderId(); as id) { … } @else { …форма… }`.
:::

::: hint Подсказка 4: текст ошибки сервера
Тело ответа с ошибкой лежит в `HttpErrorResponse.error`. У учебного бэкенда это `{ message }`:

```ts
if (error instanceof HttpErrorResponse && error.status === 409) {
  return { kind: 'out-of-stock', message: error.error.message };
}
```
:::

::: hint Подсказка 5: гард
Гард ухода (`CanDeactivateFn<Checkout>`) — как в главе 10: получает компонент страницы и возвращает `true` (уйти) или `false` (остаться). Компоненту нужен открытый метод «есть ли что терять»: форма изменена покупателем (`checkoutForm().dirty()`), а заказ ещё не оформлен. Гард: `!checkout.hasUnsavedChanges() || confirm('…')`. Не забудьте `canDeactivate` у маршрута `checkout`.
:::

## Проверьте себя

Нажмите «Проверить» — проверка положит в корзину 13 «Островов сокровищ» (на складе 12), попробует отправить пустую форму, уйти с заполненной, оформит заказ, получит `409`, уменьшит количество в корзине и оформит снова. Или проверьте сами:

- «Оформить заказ» с пустой формой — ошибки у полей, в «Сети» нет `POST /api/orders`.
- Заполните имя и телефон и щёлкните «Каталог» — вопрос. «Отмена» — вы на оформлении.
- В «Сети» поставьте задержку 3000 мс и оформите заказ — три секунды «Оформляем…» на серой кнопке. Затем — «Заказ №1 оформлен», «В корзине: 0».
- Уйдите после оформления в каталог — вопроса нет: терять больше нечего.
- Ответ `409` вручную получить трудно: в корзине должно быть больше игр, чем на складе, а магазин сам не даёт положить больше остатка. Этот случай проверяет «Проверить» — подделанной корзиной.

## Итоги главы

Вы написали четыре формы на Signal Forms — вход, оформление заказа, промокод и отзыв — и разобрались, как они устроены:

- **модель формы** — обычный сигнал, единственный источник правды. `form(модель)` строит над ней **дерево полей**, а `[formField]` связывает поле с элементом страницы в обе стороны;
- **схема** описывает правила один раз, при создании формы: встроенные (`required`, `email`, `minLength`…), свои (`validate`), перекрёстные (`valueOf`), асинхронные (`validateHttp`, состояние `pending`), условные (`hidden`, `applyWhen`, `disabled`). Схемы складываются из частей (`schema`, `apply`, `applyEach`) и живут отдельно от компонентов;
- **состояние поля** — сигналы: `value`, `errors`, `valid`/`invalid`, `touched`, `dirty`, `pending`, `hidden`, `disabled`. Как и `computed`, они пересчитываются сами;
- **отправка** — `FormRoot` и `submission.action`: тронуть все поля, не отправлять с ошибками, `submitting()` на время запроса, ошибки сервера — как ошибки формы;
- **своё поле формы** — любой компонент с `model()` `value` и, по желанию, выходом `touch` и входами состояния;
- **реактивные формы** (`FormGroup`, `FormControl`) — следующий шаг, чтобы читать существующий код.

В главе 14 форма входа заработает по-настоящему: токен из ответа сервера магазин будет хранить, отправлять с каждым запросом и забудет при выходе. Появятся «Войти» в шапке, страница «Мои заказы» — с заказами, оформленными после входа, — и гард, который не пустит в кабинет без входа.
