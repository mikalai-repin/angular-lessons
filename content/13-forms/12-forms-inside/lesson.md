Мы пользовались формами весь урок: `form(модель)`, `checkoutForm.contacts.name`, `errors()`, `valueOf`. Снаружи это выглядит как магия: откуда у формы поля, если мы их не объявляли? Как запись в поле попадает в модель? Почему правило выполняется, только когда его читают?

Ответы — в исходниках `@angular/forms/signals` (файл `@angular/forms/fesm2022/_validation_errors-chunk.mjs`). Разберём их на опыте.

Этот шаг без задания. В коде новый файл `forms-inside.ts` — функция `exploreForms` создаёт маленькую форму вне компонента и печатает в консоль, что с ней происходит. Её вызывает `main.ts`, когда приложение запустилось: форме нужен инжектор, и вне конструктора компонента его передают явно — `form(model, схема, { injector })`. Демо реактивной формы из прошлого шага убрано.

Вывод в консоли:

```text
1. Схема получила путь: object
2. Форма — это функция: function | поле то же самое: true
3. Новый корень: true | новый contacts: true | те же postcards: true
4. Проверок имени до чтения: 0
   после двух чтений: 1
   после записи: 1
   форма верна: false | проверок: 2
5. Символы на открытке: Symbol() | JSON: {"to":"Пете"}
   после перестановки тронута первая: true
   после { ...postcard }: true
   после { to: postcard.to }: false
6. Схема выполнилась раз: 1
```

Пройдём по строкам.

## Схема: дерево путей

Строка 1 печатается из функции схемы: `typeof path.contacts.name` — `object`. Путь схемы — объект, хотя мы не объявляли у него поля `contacts`. Это `Proxy` — объект JavaScript, который перехватывает обращения к своим свойствам. Каждое обращение `path.contacts` создаёт (или берёт уже созданный) **узел пути** с ключами `['contacts']`, а `path.contacts.name` — узел `['contacts', 'name']`. Правило `validate(path.contacts.name, …)` не проверяет ничего — оно записывает функцию в узел пути: «полю по этому адресу — такая логика».

Функция схемы выполняется при создании формы и больше никогда (строка 6). Из её работы получается дерево логики: какие правила, условия `hidden`/`disabled`, `applyWhen` и `applyEach` относятся к какому месту формы. Поэтому путь нельзя унести в другую схему (`NG01908`, шаг «Схемы»): узлы путей принадлежат той схеме, которая их создала.

## Форма: дерево узлов

```text
model ── signal({ contacts, postcards })
  │
корневой узел ── value = model
  ├─ contacts ── value = model().contacts
  │    ├─ name ── value = contacts().name
  │    └─ phone
  └─ postcards
       ├─ [0] ── объект «Маше»
       └─ [1] ── объект «Пете»
```

`form()` создаёт **корневой узел поля** (`FieldNode`) над моделью. У каждого узла — своё состояние: сигналы «тронуто», «изменено», ошибки, «скрыто». Дочерние узлы создаются **лениво** — когда к ним впервые обратились или когда у них есть правила.

Само поле, которое мы держим в руках (`order`, `order.contacts`), — тоже `Proxy`, только над функцией `() => узел` (строка 2: `typeof order` — `function`). Вызов `order()` возвращает узел — у него и есть `value`, `errors`, `touched`. А обращение `order.contacts` прокси перехватывает и отдаёт поле дочернего узла. Узел один на всё время жизни поля, поэтому `order.contacts === order.contacts` — `true`, и `track postcard` в `@for` работает.

## Значение: сигнал над сигналом

У корневого узла значение — сама модель. А у дочернего — **вычисляемый сигнал над значением родителя**: `computed(() => родитель()[ключ])`. Чтение `order.contacts.name().value()` проходит по цепочке до `model()`.

Запись идёт обратно, вверх: `set` у значения дочернего узла копирует объект родителя с новым свойством — `{ ...contacts, name: 'Маша' }` — и записывает копию в значение родителя, а тот — в своего родителя. В итоге в `model` оказывается **новый корневой объект** (строка 3): новый корень и новый `contacts`, но тот же массив `postcards` — его запись не касалась. Это знакомое по главе 3 правило: сигналы сравнивают значения по ссылке, поэтому данные меняют, создавая новые объекты, а нетронутые части переиспользуют.

Список дочерних узлов хранит `linkedSignal` от значения узла (глава 3): значение изменилось — список пересчитывается, но уже созданные узлы для тех же ключей **сохраняются**. Поэтому «тронуто» у поля имени не сбрасывается от того, что изменилась модель.

## Правила: вычисляемые сигналы

Ошибки узла — `computed`, который вызывает функции правил этого узла. Отсюда строка 4:

- пока ошибки никто не читал, правило не выполнялось ни разу — `0`;
- два чтения подряд — одно выполнение: значение не менялось, `computed` вернул запомненный результат;
- запись в поле ничего не выполнила: `computed` только помечен «устаревшим»;
- чтение `order().valid()` спросило дочерние узлы — и правило выполнилось второй раз.

Это ровно поведение `computed` из главы 3. Правило — обычный код внутри вычисляемого сигнала, поэтому оно и зависит от всего, что прочитало: `valueOf` соседнего поля, `this.cart.subtotal()` в проверке промокода.

Состояния родителя тоже вычисляются из детей: форма «тронута», если тронут хоть один потомок; верна, если верен каждый. Узел, который скрыт, отключён или только для чтения, правила не выполняет вовсе — его ошибки пусты.

## Массивы: метка на объекте

Как форма узнаёт открытку «Пете», когда она переехала с индекса 1 на индекс 0? Индекс не подходит: он меняется. Форма **метит объект элемента** символом — записывает в объект открытки свойство с ключом-`Symbol`, уникальным для этого массива (строка 5). В JSON символы не попадают, поэтому на сервер уходит чистое `{"to":"Пете"}`.

Дальше всё следует из этой метки:

- переставили элементы — у объекта «Пете» та же метка, и его узел (вместе с «тронуто») переехал на индекс 0;
- копия через `{ ...postcard }` копирует и символьные свойства — метка на месте, узел тот же;
- новый объект `{ to: postcard.to }` — метки нет, для формы это новая открытка с новым узлом, «тронуто» — `false`.

Отсюда практическое правило: меняя массив в модели формы, переносите объекты элементов как есть (`filter`, перестановка) или копируйте через spread. Собранный заново объект — это новый элемент для формы.

## Директива [formField]

`FormField` знает узел своего поля и делает три вещи:

- переносит значение из сигнала `value` в элемент (для `<input>` — свойство `value`) и обратно — при вводе;
- переносит правила в атрибуты: `required`, `minlength`, `maxlength`, `disabled`, а у числовых полей и дат — `min` и `max`;
- регистрирует себя в узле: так узел знает, к какому элементу перевести фокус (`focusBoundControl()`).

В режиме разработки директива ещё и следит эффектом, не скрыто ли её поле: скрытое поле на странице — это и есть предупреждение `NG01916` из шага «Условные поля».

Если элемент — компонент с `model()` `value`, директива работает с моделью компонента вместо свойства элемента. Поэтому `Rating` стал полем формы без единой строчки про формы.
