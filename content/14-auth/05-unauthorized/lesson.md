У токена есть срок. Учебный бэкенд выдаёт токены на час, но в этом шаге — всего на **30 секунд**: так урок настроил сервер. Если вы вошли в прошлом шаге, выйдите: у вас часовой токен. Войдите, подождите полминуты и щёлкните «Каталог». Вместо игр — «Не удалось загрузить каталог», а в шапке по-прежнему «Пользователь» и «Выйти». В «Сети» — `GET /api/games…` с ответом `401` «Токен истёк».

Магазин считает покупателя вошедшим, а сервер — нет. Пока это так, любой запрос с токеном будет падать. Правильная реакция одна: сессия закончилась — выйти и предложить войти снова.

## Где ловить 401

Ответ `401` может прийти на любой запрос: каталог, отзыв, заказ. Ловить его в каждом компоненте — та же проблема, что с заголовком: долго и легко забыть. А интерцептор видит **ответы** всех запросов — значит, и `401` поймает в одном месте.

Ответ приходит потоком, который вернул `next(req)`. Ошибку в потоке ловит оператор `catchError` из RxJS (глава 12):

```ts core/auth-interceptor.ts {1-2,6-17}
const auth = inject(AuthStore);
const router = inject(Router);
// …токен, условие…
return next(
  req.clone({ setHeaders: { Authorization: `Bearer ${token}` } }),
).pipe(
  catchError((error: unknown) => {
    if (
      error instanceof HttpErrorResponse &&
      error.status === 401 &&
      auth.isLoggedIn()
    ) {
      auth.logOut();
      router.navigateByUrl('/login');
    }
    // Ошибку отдаём дальше
    return throwError(() => error);
  }),
);
```

Разберём по частям.

**Только запросы с токеном.** `catchError` стоит в той ветке, где токен уже добавлен. Запрос без токена — например, вход с неверным паролем — тоже получает `401`, но это «неверный пароль», а не «сессия закончилась». Его обработает форма входа.

**Только если покупатель считался вошедшим.** `401` на `GET /api/me` при запуске — это `restore`: токен из прошлого визита истёк. Покупатель ещё не вошёл, `isLoggedIn()` — `false`, и интерцептор его не трогает: `restore` сам забудет токен, а покупатель останется на той странице, которую открыл, — гостем.

**Ошибку — дальше.** Интерцептор не «съедает» ответ: `throwError(() => error)` — новый поток, который сразу завершается той же ошибкой. Каталог, форма отзыва, оформление заказа узнают о неудаче и сделают своё: снимут состояние загрузки, уберут черновик отзыва. Интерцептор лишь добавляет общую реакцию.

**`inject` — до `return`.** Функция интерцептора выполняется в контексте внедрения, а `catchError` вызовет свою функцию позже — когда придёт ответ. Тогда контекста уже нет. Поэтому `Router` и `AuthStore` берём сразу, в начале интерцептора.

::: task
1. Возьмите в интерцепторе `AuthStore` и `Router` через `inject` в начале функции.
2. К потоку `next(…)` для запросов с токеном добавьте `catchError`: ответ `401`, а покупатель считается вошедшим, — `auth.logOut()` и переход на `/login`. Ошибку в любом случае верните дальше: `throwError(() => error)`.
:::

## Эксперименты

**Без условия «вошёл».** Уберите из условия `auth.isLoggedIn()`. Войдите, откройте каталог, подождите полминуты и нажмите ⟳. Превью открылось на странице входа, а не в каталоге: `401` на `GET /api/me` пришёл ещё до первой навигации, и интерцептор отправил на `/login` того, кто хотел только посмотреть каталог. Верните условие.

**`inject` в обработчике ошибки.** Перенесите `inject(Router)` внутрь `catchError`: `inject(Router).navigateByUrl('/login')`. Войдите, подождите полминуты, «Каталог». Вы вышли — «Войти» в шапке, — но остались в каталоге с «Не удалось загрузить каталог». В консоли — `GET /api/games?… → undefined`: дальше по цепочке ушёл уже не ответ `401`, а другая ошибка. Чтобы её увидеть, добавьте в `loggingInterceptor` в обработчик `error` строку `console.log(String(error));` и повторите:

```text
Error: NG0203: The `Router` token injection failed. `inject()` function must be called from an injection context …
```

Та же ошибка, что `inject` в обработчике щелчка в главе 6. Верните оба файла как было.
