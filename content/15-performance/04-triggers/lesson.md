Отзывы теперь загружаются после игры, но всё равно загружаются — каждый раз, хотя вкладку «Отзывы» открывают не все. Хотелось бы другого правила: отзывы нужны, когда покупатель их **увидел**. Для этого у `@defer` есть триггеры.

## Триггеры

Триггер пишут в скобках после `@defer`:

| Триггер | Когда срабатывает |
|---|---|
| `on idle` | браузер освободился (так по умолчанию) |
| `on viewport` | элемент появился в области видимости |
| `on interaction` | по элементу щёлкнули или нажали клавишу на нём |
| `on hover` | на элемент навели мышь или перевели на него фокус |
| `on timer(2s)` | прошло столько-то времени (`500ms`, `2s`) |
| `on immediate` | сразу, как только блок появился в шаблоне |
| `when условие` | выражение стало истинным |

Несколько триггеров через `;` — блок запустит тот, что сработает **первым**: `@defer (on viewport; on timer(10s))`.

Сработав, блок больше не возвращается к заглушке. Это касается и `when`. Условие стало истинным — содержимое создано, а когда оно снова станет ложным, содержимое останется. Чтобы убирать и показывать, нужен `@if`. `@defer` — про «когда загрузить и создать в первый раз».

## За каким элементом следить

`on viewport`, `on interaction` и `on hover` следят за элементом. За каким — два варианта:

- без параметра — за заглушкой. Тогда `@placeholder` обязателен и в нём ровно **один** корневой элемент;
- с именем ссылки на элемент в шаблоне — за этим элементом: `<h2 #reviewsTitle>…</h2>` и `@defer (on viewport(reviewsTitle))`. Элемент должен быть в том же шаблоне, что и блок.

У `on viewport` можно передать и объект настроек: `on viewport({ rootMargin: '200px' })` — сработать, когда до элемента осталось 200 пикселей прокрутки. Ссылку тогда пишут в нём же: `{ trigger: reviewsTitle, rootMargin: '200px' }`. Так блок загрузится чуть раньше, чем покупатель до него докрутит.

## Отзывы — когда открыли вкладку

Вкладки из главы 6 прячут неактивное содержимое атрибутом `hidden`. Скрытый элемент не занимает места на экране, поэтому для браузера он «не виден». Значит, `on viewport` у заглушки во вкладке «Отзывы» сработает именно тогда, когда покупатель открыл вкладку:

```html game/game-page.html {1,3-4,7-11}
@defer (on viewport) {
  <app-game-reviews [gameId]="game.id" />
} @placeholder {
  <p class="muted">Загружаем отзывы…</p>
} @loading (after 100ms; minimum 500ms) {
  <p class="muted">Загружаем отзывы…</p>
} @error {
  <p class="error-message">
    Не удалось загрузить отзывы. Обновите страницу.
  </p>
}
```

Заглушка и блок загрузки говорят одно и то же. Покупатель видит заглушку только в тот момент, когда открыл вкладку, а значит, загрузка уже началась.

Появился и `@error`: теперь чанк грузится по действию покупателя, когда что угодно могло случиться со связью. Повторить загрузку из `@error` нельзя: блок остаётся в состоянии ошибки до перезагрузки страницы. Поэтому и текст такой.

::: task
В `game-page.html` поставьте блоку отзывов триггер `on viewport`. Заглушка — «Загружаем отзывы…» (`<p class="muted">`). Добавьте `@error` с текстом «Не удалось загрузить отзывы. Обновите страницу.» (`<p class="error-message">`).
:::

## Что получилось

Перезапустите превью. Во вкладке «Сеть» — только `GET /api/games/4`. Ни чанка, ни отзывов. Откройте вкладку «Отзывы» — и только теперь `GET /chunk-defer-1.js`, а за ним `GET /api/games/4/reviews`. Покупатель, который не дошёл до отзывов, не заплатил за них ничем.

## Эксперименты

**Чанк не загрузился.** Откройте игру, во вкладке «Сеть» включите «Ошибка 500» и только потом откройте «Отзывы». `GET /chunk-defer-1.js` — `500`, и на месте отзывов — сообщение из `@error`. Выключите «Ошибку 500» и щёлкните по вкладкам туда-обратно: ничего не меняется, блок так и остался в ошибке. Откройте другую игру и её вкладку «Отзывы» — вместо отзывов то же сообщение: состояние загрузки одно на шаблон, как и в прошлом шаге. Перезапустите превью — всё работает.

**Без заглушки.** Удалите `@placeholder` целиком. Страница игры не откроется, а в консоли:

```text
ERROR Error: defer on trigger with no target name must have a placeholder block
```

Следить не за чем — JIT отказывается компилировать шаблон. В настоящем проекте эту ошибку покажет сборка: `NG8019: Trigger with no target can only be placed on an @defer that has a @placeholder block`. Верните заглушку.

**Два элемента в заглушке.** Разбейте текст заглушки на два абзаца `<p>`. В превью ничего не изменится. А AOT такой шаблон не соберёт: `NG8020: Trigger with no target can only be placed on an @defer that has a @placeholder block with exactly one root element node`. Ещё одна ошибка, которую видно только при сборке. Верните один абзац.

**По щелчку и по наведению.** Сделайте заглушку кнопкой, а триггер — `on interaction`:

```html
@defer (on interaction) {
  <app-game-reviews [gameId]="game.id" />
} @placeholder {
  <button class="link-button">Показать отзывы</button>
} …
```

Откройте вкладку — «Показать отзывы», и в «Сети» тихо. Щелчок — чанк, отзывы. Замените `on interaction` на `on hover`: отзывы загрузятся, как только мышь окажется над кнопкой. `on hover` слушает `mouseenter`, `mouseover` и `focusin`, `on interaction` — `click` и `keydown`. Верните `on viewport`.

**Ссылка на несуществующий элемент.** Напишите `on viewport(reviewsTitle)`, не создав элемента `#reviewsTitle`. Превью промолчит, а отзывы не загрузятся никогда: следить не за чем. AOT скажет прямо: `NG8010: Trigger cannot find reference "reviewsTitle"`. Верните `on viewport`.

::: tip
`@defer (on interaction)` с кнопкой «Показать» — хорошая замена `@if` с флажком. Кнопка не просто показывает блок: в настоящей сборке его код начинает грузиться только по щелчку.
:::

::: deep Под капотом: кто следит за триггерами
Каждый триггер компилируется в свою инструкцию: `ɵɵdeferOnIdle()`, `ɵɵdeferOnViewport(…)`, `ɵɵdeferOnTimer(10000)`, `ɵɵdeferWhen(значение)`. Строка `on viewport({ rootMargin: '200px' })` становится `ɵɵdeferOnViewport(0, -1, { rootMargin: "200px" })`.

- `on idle` — `requestIdleCallback` (где его нет — `setTimeout`);
- `on viewport` — общий `IntersectionObserver` на все блоки с одинаковыми настройками, как наша директива `InView` из главы 7;
- `on interaction` и `on hover` — обычные слушатели событий на элементе. Сработал триггер — Angular снимает слушатели и наблюдение;
- `when` — привязка, как `[disabled]`: при каждой проверке шаблона Angular сравнивает значение с прошлым и запускает загрузку, когда оно стало истинным. Обратного пути у этой инструкции нет.
:::
