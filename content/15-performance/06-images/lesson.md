На большинстве страниц магазина больше всего весят обложки. Как браузер их грузит, решает, насколько быстро покупатель увидит страницу. В главе 7 мы написали директиву `LazyImage`: обложка получает `src`, только когда `IntersectionObserver` сказал, что она на экране. Директива учебная. В настоящем проекте для картинок есть готовая директива Angular — `NgOptimizedImage`. Она делает больше и следит за ошибками, которые легко не заметить.

## Что не так с картинками

Три частые беды:

1. **Лишние загрузки.** Картинки далеко внизу грузятся вместе с первым экраном и отнимают у него сеть.
2. **Сдвиг вёрстки.** Пока картинка не загрузилась, браузер не знает её размера. Потом она приходит, и текст под ней прыгает вниз.
3. **Главная картинка в общей очереди.** Самый крупный элемент первого экрана браузеры называют **LCP** (Largest Contentful Paint). На странице игры это обложка. Пока она не видна, страница для покупателя «ещё грузится». А браузер не знает, что эту картинку нужно грузить первой.

Для первой беды у браузера есть атрибут `loading="lazy"`. Для второй — `width` и `height`: по ним браузер заранее знает пропорции и резервирует место. Для третьей — `fetchpriority="high"`. `NgOptimizedImage` расставляет всё это сам и в режиме разработки ругается, если что-то не так.

## `NgOptimizedImage`

Директива из `@angular/common`, селектор — `img[ngSrc]`. Вместо `src` пишут `ngSrc`, и обязательно `width` и `height`:

```html shared/game-card/game-card.html {3-5}
<img
  class="cover"
  [ngSrc]="game().cover"
  width="300"
  height="400"
  [alt]="game().title"
/>
```

- `ngSrc` — адрес картинки. `src` директива поставит сама;
- `width` и `height` — **собственный** размер картинки или хотя бы её пропорции. Обложки у нас 300 × 400. На экране обложка может быть любого размера — это решает CSS;
- по умолчанию директива ставит `loading="lazy"`, `fetchpriority="auto"`, `decoding="auto"`.

Картинке, которую нужно грузить первой, добавляют `priority`. Тогда директива ставит `loading="eager"`, `fetchpriority="high"` и `decoding="sync"`:

```html game/game-page.html {6}
<img
  class="cover"
  [ngSrc]="game.cover"
  width="300"
  height="400"
  priority
  [alt]="game.title"
/>
```

Атрибуты `width` и `height` браузер превращает в CSS-размер картинки. Если в CSS задана только ширина, высота останется 400 пикселей — обложку растянет. Поэтому `.cover` получает `height: auto`: высоту посчитает `aspect-ratio`.

## Первый ряд карточек

В каталоге, на главной и в избранном самые крупные картинки первого экрана — обложки первого ряда. Какая из них станет LCP, решают доли пикселя. Карточки одинаковые, но сетка делит ширину на колонки с дробной частью, и одна обложка выходит чуть больше остальных. У нас при ширине превью 500 пикселей LCP — первая обложка каталога, а при 508 — третья. Заранее этого не знает ни Angular, ни мы. Поэтому `priority` получают все карточки, которые могут оказаться в первом ряду.

Сколько их, зависит от ширины экрана: в превью шириной 500 пикселей в ряду три карточки, шириной 950 — шесть. Панель превью занимает около трети окна, так что шести с запасом хватит. Это число — в настройках магазина. Слишком много `priority` тоже плохо: больше десяти — и Angular предупредит (`NG02966`); шесть — в пределах. В старте шага в `core/shop-config.ts` появилось поле:

```ts core/shop-config.ts
priorityCovers: number; // сколько первых обложек списка грузить в первую очередь
…
priorityCovers: 6,
```

Решает страница — только она знает, в каком порядке идут карточки. Поэтому у `GameCard` появляется вход:

```ts shared/game-card/game-card.ts
// Обложку грузить в первую очередь: карточка — первое, что видно на странице
readonly priority = input(false, { transform: booleanAttribute });
```

```ts catalog/catalog.ts
// Первые обложки — на первом экране: их грузим в первую очередь
protected readonly priorityCovers = this.config.priorityCovers;
```

```html catalog/catalog.html
<app-game-card [game]="game" [priority]="$index < priorityCovers">
```

Есть ловушка. `NgOptimizedImage` читает `priority` **один раз**, когда картинка создана: браузер уже начал её загружать, и менять приоритет поздно. Если значение потом изменится, директива в режиме разработки бросит ошибку `NG02953`. А в каталоге карточки переезжают: после «Показать ещё» и смены сортировки игра с седьмого места может оказаться на втором. Карточки при этом не пересоздаются — `@for` с `track game.id` их переставляет.

Выход подсказывает сам текст ошибки: картинку с другим `priority` нужно создать заново. Поэтому в `game-card.html` — две ветки `@if`:

```html shared/game-card/game-card.html {1,10}
@if (priority()) {
  <img
    class="cover"
    [ngSrc]="game().cover"
    width="300"
    height="400"
    priority
    [alt]="game().title"
  />
} @else {
  <img
    class="cover"
    [ngSrc]="game().cover"
    width="300"
    height="400"
    [alt]="game().title"
  />
}
```

Карточка попала в первые шесть — `@if` создаст новую картинку с `priority`. Выпала из них — новую без него.

::: task
1. **Карточка.** В `game-card.ts` импортируйте `NgOptimizedImage` из `@angular/common` вместо `LazyImage` и добавьте вход `priority` (`input(false, { transform: booleanAttribute })`). В `game-card.html` замените обложку на две ветки `@if (priority())` с `ngSrc`, `width="300"`, `height="400"` — как в примере. В `game-card.css` в правило `.cover` добавьте свойство `height: auto`.
2. **Страница игры.** Импортируйте `NgOptimizedImage` в `game-page.ts`; обложка — с теми же размерами и `priority`, в `game-page.css` у `.cover` — `height: auto`.
3. **Списки.** На главной («Хиты»), в каталоге и в избранном передайте карточкам `[priority]="$index < priorityCovers"`. Поле `priorityCovers` страница берёт из `SHOP_CONFIG`: у каталога и главной настройки уже внедрены, избранному внедрите их сами.
4. **Уборка.** Удалите файл `shared/lazy-image.ts` и стили `.lazy` из `styles.css`.
:::

## Что получилось

Внешне магазин не изменился. Откройте DevTools браузера: у обложки на странице игры — `loading="eager" fetchpriority="high"`, у остальных — `loading="lazy"`. Консоль превью чистая на каждой странице.

Обратите внимание, как изменилась ленивая загрузка. Наша `LazyImage` грузила обложку, когда та появлялась на экране: на главной сразу загружались 3 обложки из 11. С `loading="lazy"` в нашем замере браузер на главной высотой около 2200 пикселей скачал сразу все 11. Он начинает загрузку заранее, пока картинка ещё далеко от экрана, а насколько заранее — решает сам, по скорости сети. Обложка успевает загрузиться до того, как до неё докрутили. Ленивая загрузка браузера экономит на картинках, которые очень далеко, — в длинных лентах и каталогах.

## Эксперименты

**Без размеров.** Уберите у обложки на странице игры `width` и `height`. Страница развалится — пропадут название и цена, — а в консоли ошибка:

```text
ERROR RuntimeError: NG02954: The NgOptimizedImage directive … has detected that these required attributes are missing: "width", "height". Including "width" and "height" attributes will prevent image-related layout shifts.
```

Директива проверяет атрибуты при создании и не даёт забыть про сдвиг вёрстки. AOT эту ошибку не ловит: это проверка во время выполнения, в режиме разработки. Верните атрибуты.

**Без `height: auto`.** Уберите правило из `game-page.css`. Обложка вытянется в высоту, а в консоли — предупреждение `NG02952`:

```text
… the aspect ratio of the rendered image does not match the image's intrinsic aspect ratio.
Intrinsic image size: 300w x 400h (aspect-ratio: 0.75).
Rendered image size: 160w x 400h (aspect-ratio: 0.40).
```

Директива сравнила пропорции, которые нарисовал браузер, с пропорциями самой картинки. Верните правило.

**Без `priority`.** Уберите `priority` у обложки на странице игры и перезапустите превью:

```text
NG02955: The NgOptimizedImage directive … has detected that this image is the Largest Contentful Paint (LCP) element but was not marked "priority".
```

Директива подписалась на замер LCP в браузере (`PerformanceObserver`) и узнала свою картинку. Верните `priority`.

**Без `@if`.** Оставьте в `game-card.html` одну картинку с `[priority]="priority()"`, а в каталоге на время опыта передайте `[priority]="$index < 3"`. Откройте каталог и выберите сортировку «По рейтингу». В консоли — `` NG02953: … has detected that `priority` was updated after initialization ``, а пара карточек осталась без названия: ошибка оборвала их отрисовку. Верните обе ветки и `priorityCovers`.

**Только первая.** Передайте `[priority]="$first"` и перезапустите превью при разной ширине его панели. При одной ширине консоль чистая, при другой — `NG02955` про другую обложку первого ряда. Верните `priorityCovers`.

## Как в настоящем проекте

Обложки нашего магазина — маленькие SVG, их одинаково удобно показывать любого размера. Фотографии обычно хранят в CDN для картинок, который отдаёт картинку нужной ширины по адресу. Для них у `NgOptimizedImage` есть **загрузчики**: `provideImgixLoader`, `provideCloudinaryLoader` и другие, или свой через токен `IMAGE_LOADER`. С загрузчиком директива сама строит `srcset`: телефон скачает картинку шириной 300 пикселей, а не 1200. Без загрузчика `srcset` не строится.

При серверном рендеринге (SSR, глава 20) директива ещё и добавляет в `<head>` `<link rel="preload">` для картинок с `priority`.
