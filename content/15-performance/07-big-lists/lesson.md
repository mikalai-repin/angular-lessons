Самое тяжёлое в интерфейсе — обычно не один сложный компонент, а сотня простых: строки таблицы, карточки каталога, сообщения в ленте. В этом шаге кода для магазина нет. Мы измерим, сколько стоит длинный список, и разберём три способа сделать его дешевле.

## Из чего состоит цена списка

Каждая карточка `GameCard` — это компонент: экземпляр класса, его сигналы, структура представления, привязки, обработчики событий и около двадцати узлов DOM. Список платит за карточки в три разных момента:

1. **Создание** — когда список появляется. Цена растёт с числом карточек.
2. **Обновление** — когда что-то изменилось. В Angular 22 компоненты по умолчанию `OnPush`, а состояние — в сигналах. Поэтому при изменении одной карточки проверяется только она (журнал проверок из главы 6). Это почти бесплатно.
3. **Пересоздание** — когда список изменился, а `@for` не узнал старые элементы. Тогда он удаляет карточки и создаёт заново — платит за создание ещё раз.

С обновлением сигналы и `OnPush` справляются сами. Осталось следить за созданием и пересозданием.

## Пересоздание: `track`

Как `@for` узнаёт элементы, решает выражение `track` из главы 4. Мы измерили, сколько карточек создаёт каталог при смене сортировки «По умолчанию» → «По рейтингу» (на экране 6 карточек):

| `track` | Создано карточек | Что произошло |
|---|---|---|
| `game.id` | 4 | две игры остались на экране — их карточки переставлены |
| `$index` | 0 | все 6 карточек остались, но получили другие игры |
| `game` | 6 | все пересозданы, в консоли `NG0956` |

`track game` сравнивает объекты, а сервер на каждый запрос присылает новые. Angular сам предупреждает: `NG0956: The configured tracking expression (track by identity) caused re-creation of the entire collection of size 6`.

`track $index` создаёт меньше всех, но обманчиво дёшев. Карточка, которая показывала «Остров сокровищ», теперь показывает другую игру: перерисовано всё её содержимое, а всё, что карточка помнила о своей игре, досталось чужой. Правило из главы 4 в силе: `track` — по устойчивому ключу данных, то есть по `id`.

## Создание: опыт с тысячей карточек

Проверим, сколько стоит создать тысячу карточек. Временно добавьте на главную кнопку, которая показывает подборку «Со скидкой», повторённую по кругу тысячу раз. В `home.ts`:

```ts home/home.ts
// Опыт: тысяча карточек — подборка «Со скидкой» по кругу
protected readonly showMany = signal(false);
protected readonly many = computed(() => {
  const items = this.sale.value()?.items ?? [];
  if (items.length === 0) return [];
  return Array.from({ length: 1000 }, (_, i) => items[i % items.length]);
});
private readonly injector = inject(Injector);

protected toggleMany() {
  const start = performance.now();
  this.showMany.update((show) => !show);
  // Angular обновил DOM — сколько это заняло
  afterNextRender(
    () => console.log(`Отрисовка: ${Math.round(performance.now() - start)} мс`),
    { injector: this.injector },
  );
}
```

Импорты — `Injector`, `afterNextRender`, `computed`, `signal` из `@angular/core`. В `home.html` перед заголовком «Со скидкой»:

```html home/home.html
<button class="button" (click)="toggleMany()">Тысяча карточек</button>
@if (showMany()) {
  <div class="grid">
    @for (game of many(); track $index) {
      <app-game-card [game]="game" />
    }
  </div>
}
```

Здесь `track $index` честный: игры повторяются, и `id` у них не уникален.

Нажмите кнопку. У нас в превью это заняло 70–90 мс: 1000 компонентов и около 21 000 узлов DOM вместо трёхсот. И это только работа Angular — `afterNextRender` срабатывает до того, как браузер посчитает раскладку и нарисует. На вашем компьютере числа будут другими, а на слабом телефоне — больше. Нажмите ещё раз — карточки удаляются, это тоже не бесплатно.

Тысяча карточек — это не экзотика: лента без конца после пары минут прокрутки, таблица заказов в админке, журнал событий.

## Три способа дешевле

**1. Показывать меньше.** Самый простой и самый действенный способ. Страницы, «Показать ещё», фильтры — наш каталог показывает по шесть карточек и грузит следующие с сервера. Покупатель редко листает дальше третьей порции.

**2. Создавать по мере прокрутки.** Обёрните карточку в отложенный блок:

```html home/home.html
@for (game of many(); track $index) {
  @defer (on viewport) {
    <app-game-card [game]="game" />
  } @placeholder {
    <div class="skeleton"></div>
  }
}
```

Заглушка — серый блок размером с карточку (`.skeleton` из глобальных стилей): она держит место, чтобы прокрутка была честной. Нажмите кнопку: у нас — 4–11 мс. Карточек на странице по-прежнему 12 — новые ещё не видны. Прокрутите вниз: у нас каждые 800 пикселей прокрутки создавали примерно шесть новых карточек. «Чанк» в «Сети» загрузился один раз — на всю тысячу блоков. В настоящей сборке чанка здесь не было бы вовсе: `GameCard` есть на главной и без `@defer`. Выигрыш этого способа — во времени создания, а не в размере кода.

Минус: созданные карточки остаются. Докрутите до конца — и в DOM снова тысяча карточек. Способ хорош, когда до конца почти никто не доходит.

**3. Виртуальная прокрутка.** В DOM живут только видимые строки и небольшой запас. Прокрутили — те же элементы получают новые данные, а пустое место сверху и снизу изображают отступы. Тысяча строк или миллион — элементов на странице одинаково мало.

Своими руками это сложно: нужно знать высоту строк, следить за прокруткой, переиспользовать представления. Готовое решение — директивы прокрутки из Angular CDK (Component Dev Kit, пакет `@angular/cdk/scrolling`). CDK — набор инструментов команды Angular для тех, кто пишет свои компоненты:

```ts
import {
  CdkFixedSizeVirtualScroll,
  CdkVirtualForOf,
  CdkVirtualScrollViewport,
} from '@angular/cdk/scrolling';

@Component({
  selector: 'app-games-table',
  imports: [
    CdkFixedSizeVirtualScroll,
    CdkVirtualForOf,
    CdkVirtualScrollViewport,
  ],
  template: `
    <cdk-virtual-scroll-viewport itemSize="40" class="viewport">
      <div *cdkVirtualFor="let game of games(); trackBy: byId" class="row">
        {{ game.title }}
      </div>
    </cdk-virtual-scroll-viewport>
  `,
  styles: `
    .viewport { height: 400px; }
    .row { height: 40px; }
  `,
})
export class GamesTable {
  readonly games = input.required<Game[]>();
  // trackBy — то же, что track в @for: по чему узнавать строку
  protected readonly byId = (index: number, game: Game) => game.id;
}
```

- `<cdk-virtual-scroll-viewport>` — окно прокрутки фиксированной высоты;
- `itemSize="40"` — высота одной строки: по ней CDK считает, какие строки видны;
- `*cdkVirtualFor` — замена `@for` для виртуального списка. Это **структурная директива** со звёздочкой: так в Angular писали циклы до блоков `@for` (глава 4). Для виртуальной прокрутки отдельного блока нет, поэтому CDK использует директиву.

В превью CDK нет — этот код не запустится. Мы проверили его сборкой AOT с `@angular/cdk` 22.2.1.

Виртуальная прокрутка проще всего, когда строки одинаковой высоты, — у таблиц и списков. Сетку карточек с переносом по ширине виртуализировать сложнее, и магазину с «Показать ещё» она не нужна.

## Ещё о скорости списков

- **Вычисления — в `computed`, а не в методах шаблона.** Метод в шаблоне выполняется при каждой проверке компонента (глава 2), `computed` — только когда изменились его сигналы (глава 3). В списке разница умножается на число строк.
- **Форматирование — чистыми пайпами.** Чистый пайп пересчитывается, только когда изменились его аргументы (глава 7).
- **Тяжёлое внутри строки — в `@defer`.** График, карта, редактор в строке, которую раскрыли, — в отложенный блок с `on interaction`.
- **Сначала измерить.** Медленно бывает совсем не там, где кажется. В браузере для этого есть вкладка Performance в DevTools, а для Angular — расширение Angular DevTools с профайлером: он показывает, какие компоненты проверялись и сколько это заняло.

Когда закончите опыты, нажмите «Сброс» — код вернётся к старту шага.
