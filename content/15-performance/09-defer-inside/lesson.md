В этой главе мы честно оговаривались: «в настоящей сборке код уходит в отдельный чанк, а превью его изображает». Посмотрим, что именно делает компилятор с блоком `@defer`, как Angular грузит чанк во время работы и почему в превью без особых мер загрузки не было бы вовсе. Кода для магазина в этом шаге нет.

## Что делает компилятор AOT

Мы собрали страницу игры из шага про предзагрузку компилятором AOT — `ngc` из пакета `@angular/compiler-cli`, тем же компилятором, который использует `ng build`. В исходнике шаблона:

```html
@defer (on viewport; prefetch on idle) {
  <app-game-reviews [gameId]="game.id" />
} @placeholder { … } @loading (after 100ms; minimum 500ms) { … } @error { … }
```

В скомпилированном `game-page.js` (сокращено):

```js
import { Component, computed, inject, input, numberAttribute } from '@angular/core';
// …импорты Countdown, PricePipe, Rating, Tabs — на месте,
// а `import { GameReviews } from './game-reviews/game-reviews'` пропал

const GamePage_Conditional_3_Defer_44_DepsFn = () => [
  import("./game-reviews/game-reviews").then(m => m.GameReviews)];

function GamePage_Conditional_3_Defer_40_Template(rf, ctx) { … }        // основной блок
function GamePage_Conditional_3_DeferLoading_41_Template(rf, ctx) { … }  // @loading
function GamePage_Conditional_3_DeferPlaceholder_42_Template(rf, ctx) { … }
function GamePage_Conditional_3_DeferError_43_Template(rf, ctx) { … }

// в функции шаблона страницы:
i0.ɵɵdefer(44, 40, GamePage_Conditional_3_Defer_44_DepsFn, 41, 42, 43, 0, null,
  i0.ɵɵdeferEnableTimerScheduling);
i0.ɵɵdeferOnViewport(0, -1);
i0.ɵɵdeferPrefetchOnIdle();
```

Три вещи:

1. **Статического импорта `GameReviews` больше нет.** Вместо него — функция загрузки зависимостей `…_DepsFn` с динамическим `import()`. Сборщик видит динамический импорт и выносит `game-reviews.ts` вместе с модулями, которые нужны только ему, в отдельный файл — чанк. Из списка `dependencies` компонента `GameReviews` тоже исчез: до загрузки шаблон о нём не знает.
2. **У каждого блока — своя функция шаблона**, как у тела `@if` или `@for`. Блок `@defer` — контейнер, в который Angular в разное время вставляет одно из четырёх представлений.
3. **Триггеры — отдельные инструкции.** `ɵɵdefer` описывает блок: номера шаблонов, функцию загрузки, настройки `@loading`. `ɵɵdeferOnViewport` и `ɵɵdeferPrefetchOnIdle` подписываются на свои события.

## Когда чанка не будет

Компилятор выносит зависимость, только если может её убрать из основного кода:

- она standalone (в нашем курсе других нет);
- в этом файле она используется **только** в основном блоке `@defer`.

Мы проверили это тем же `ngc`:

| Что в коде | Функция загрузки |
|---|---|
| `GameReviews` только в `@defer` (и в `imports`) | `() => [import("./game-reviews/game-reviews")…]` |
| ещё и `protected readonly x = GameReviews` в классе | `() => [GameReviews]`, статический импорт на месте |
| `GameReviews` только в `@placeholder`, в основном блоке — разметка | `null`, статический импорт на месте |
| в блоке только разметка | `null` |

Во втором случае блок по-прежнему ждёт триггера, но код уже загружен вместе со страницей. Компилятор не предупреждает: так тоже можно, но без выгоды по размеру. Заглушка, блок загрузки и блок ошибки нужны сразу, поэтому всё, что в них, загружается со страницей.

## Что происходит во время работы

У блока два разных состояния, и хранятся они в разных местах.

**Загрузка зависимостей — одна на шаблон.** Она хранится в описании скомпилированного шаблона (`TView`), общем для всех экземпляров компонента: `NOT_STARTED` → `IN_PROGRESS` → `COMPLETE` или `FAILED`. Поэтому чанк отзывов грузится один раз, а после ошибки все страницы игр показывают `@error` до перезагрузки.

**Что показано — у каждого экземпляра своё:** `Placeholder` → `Loading` → `Complete` или `Error`.

```text
триггер (или prefetch)
  │
  ▼
загрузка: NOT_STARTED → IN_PROGRESS
  │ Promise.allSettled(DepsFn())
  ├── все загрузились → COMPLETE
  │     определения компонентов —
  │     в реестр шаблона блока
  └── хоть одна ошибка → FAILED
```

Когда чанк загрузился, Angular достаёт из модуля определение компонента (`ɵcmp`) и добавляет его в реестр директив шаблона основного блока — тот самый реестр, по которому сопоставляются селекторы (глава 7). Теперь `<app-game-reviews>` в этом шаблоне — компонент, и блок можно создавать.

Если в момент срабатывания триггера загрузка ещё идёт (`prefetch` не успел), блок показывает `@loading` и ждёт того же обещания: второго запроса нет. Если загрузка уже `COMPLETE`, блок сразу создаёт содержимое, минуя `@loading`. Пока чанк грузится, Angular держит задачу в `PendingTasks`: приложение считается «нестабильным», и серверный рендеринг (глава 20) и тесты будут ждать.

## Почему в превью загрузки нет

Превью компилирует шаблоны в браузере, компилятором JIT. JIT получает компонент уже после сборки, со всеми импортами — в том числе `GameReviews` в `imports`. Выносить нечего: код уже загружен. Поэтому функции загрузки JIT не передаёт вовсе. В исходниках компилятора так и написано: шаблон компонента для JIT разбирается с `deferBlockDependencies` = `undefined`, и у каждого блока функция — `null`.

С `null` Angular считает загрузку законченной через микрозадачу: `Promise.resolve().then(…)`. Без особых мер блок `@loading (after 100ms)` в JIT не появился бы никогда, а `prefetch` и `@error` ничего бы не меняли.

Поэтому превью курса подкладывает свою функцию загрузки.

В режиме разработки у Angular есть служебный токен `ɵDEFER_BLOCK_DEPENDENCY_INTERCEPTOR`: перед загрузкой зависимостей блока Angular спрашивает его и даёт подменить функцию загрузки.

Такие токены с `ɵ` — внутренние, для инструментов. В коде приложений их не используют.

Среда превью создаёт платформу с этим токеном заранее, до вашего `bootstrapApplication`. Его функция вместо `null` просит у учебного бэкенда «файл» `/chunk-defer-N.js` — с задержкой и ошибкой из вкладки «Сеть».

Отличия от настоящей сборки остаются:

- в превью «грузится» **каждый** блок, даже тот, у которого в сборке функция загрузки — `null`: превью не знает, что вынес бы компилятор;
- в превью «чанк» ничего не содержит — код уже загружен;
- номера чанков в превью — порядок загрузки, а в сборке — имена файлов, которые выбирает сборщик.

Состояния блока, порядок запросов, `@loading`, `@error` и `prefetch` ведут себя так же, как в сборке AOT.

## Как это проверить в настоящем проекте

В главе 20 мы перенесём магазин в проект Angular CLI. Там после `ng build` отдельный файл отзывов появится среди файлов сборки, а во вкладке Network в DevTools будет видно, как он скачивается при открытии вкладки «Отзывы».

::: tip
В тестах (глава 16) у `TestBed` есть настройка `deferBlockBehavior`. По умолчанию — `Playthrough`: блок проходит состояния сам, как в приложении. С `Manual` состояния переключает тест — так можно проверить и заглушку, и блок ошибки без настоящей сети.
:::
