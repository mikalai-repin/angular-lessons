## Черновик игры

Форма редактирует не `Game`, а **черновик** — `GameDraft`. В нём только то, что меняет администратор: без `id`, рейтинга и тегов — их ведёт сервер. И числа в нём — `number | null`:

```ts admin/game-schema.ts
export interface GameDraft {
  title: string;
  category: Game['category'];
  cover: string;
  price: number | null;
  oldPrice: number | null;
  inStock: number | null;
  players: { min: number | null; max: number | null };
  playTime: number | null;
  age: number | null;
  description: string;
}
```

Почему `null`: админ может стереть число целиком. Для модели с числом или `null` директива `[formField]` записывает пустое поле `<input type="number">` как `null` (так сделано в `@angular/forms/signals`). Цена до скидки `null` — скидки нет, `toDraft` переводит отсутствующее `oldPrice` игры в `null`.

Правила — в схеме, как у оформления заказа. Новое здесь — `min`, правило для чисел:

```ts admin/game-schema.ts
required(game.price, { message: 'Нужна цена' });
min(game.price, 1, { message: 'Цена — больше нуля' });
```

`min` пропускает `null`: пустое поле — забота `required`. Цену до скидки сравниваем с ценой своим правилом — оно читает соседнее поле через `valueOf`, как перекрёстная проверка телефона и e-mail в главе 13:

```ts admin/game-schema.ts
validate(game.oldPrice, ({ value, valueOf }) => {
  const oldPrice = value();
  const price = valueOf(game.price);
  return oldPrice !== null && price !== null && oldPrice <= price
    ? { kind: 'old-price', message: 'Цена до скидки — больше цены' }
    : undefined;
});
```

## Модель из ответа сервера

В главе 13 модель формы с самого начала была известна: пустые поля входа, пустой заказ. Здесь данные придут с сервера — позже, чем создаётся компонент. А `form()` нужна модель сразу, в поле класса.

Значит, модель должна существовать с самого начала и замениться, когда придёт игра. Это `linkedSignal` из главы 9 — записываемый сигнал, который пересчитывается от источника:

```ts admin/game-edit/game-edit.ts {1-3}
private readonly draft = linkedSignal<GameDraft>(() =>
  this.game.hasValue() ? toDraft(this.game.value()) : EMPTY,
);
protected readonly gameForm = form(this.draft, gameSchema, {
  submission: { action: () => this.save() },
});
```

Пока игра грузится, черновик — `EMPTY`, пустая игра. Пришёл ответ — черновик стал игрой с сервера. Админ печатает — форма пишет в тот же `draft`, как в любой записываемый сигнал. А если ресурс загрузит другую игру (сменился `id` в адресе), черновик снова начнётся с неё. Формы, пока данных нет, на экране нет: шаблон показывает её внутри `@if (game.hasValue())`.

::: warning
Не пишите `signal(EMPTY)` и `effect(() => draft.set(…))`: эффект для переноса данных из одного сигнала в другой — ровно то, от чего предостерегает документация Angular (глава 9). `linkedSignal` делает это без эффекта.
:::

## Поля — отдельным компонентом

Те же поля понадобятся форме **новой** игры в практикуме. Поэтому они вынесены в `GameFields`, а сама форма осталась у страницы. Компонент полей получает дерево полей входом:

```ts admin/game-fields/game-fields.ts
readonly fields = input.required<FieldTree<GameDraft>>();
```

```html admin/game-fields/game-fields.html
@let game = fields();
<label class="field">
  Название
  <input [formField]="game.title" />
  <app-field-errors [field]="game.title" />
</label>
```

`FieldTree<GameDraft>` — то же, что `gameForm`: у формы и её частей один тип, «дерево полей». Так `FieldErrors` из главы 13 получал одно поле, а `GameFields` получает всё дерево. Состояние — значения, ошибки, «тронуто» — живёт в форме, а не в компоненте полей.

Категория — `<select>` с вариантами из `@for`: `[formField]` работает с ним так же, как с полем ввода.

## Сохранение

```ts admin/game-edit/game-edit.ts
private async save() {
  try {
    await firstValueFrom(
      this.http.put<Game>(`/api/games/${this.id()}`, this.draft()),
    );
    this.router.navigate(['..'], { relativeTo: this.route });
    return undefined;
  } catch (error) {
    return {
      kind: 'server',
      message:
        error instanceof HttpErrorResponse && error.status === 400
          ? error.error.message
          : 'Не удалось сохранить. Попробуйте ещё раз',
    };
  }
}
```

`PUT` — «замени игру этой». Ответ `400` значит, что сервер не принял данные, и в его теле — почему. Это сообщение и вернём форме. Сохранили — `navigate(['..'], { relativeTo: this.route })`: на уровень выше от `/admin/games/4`, в таблицу.

## Маршрут и крошки

Страница игры — `games/:id`. Чтобы в крошках было «Админка › Игры › Ночной экспресс», таблица и страница игры становятся детьми маршрута `games` без компонента — у него только крошка:

```ts admin/admin.routes.ts {2-11}
{
  path: 'games',
  data: { breadcrumb: 'Игры' },
  children: [
    { path: '', component: GamesTable, title: 'Игры' },
    {
      path: ':id',
      component: GameEdit,
      resolve: { breadcrumb: gameTitleResolver },
    },
  ],
},
```

Резолвер — тот же `gameTitleResolver`, что у страницы игры в магазине: он грузит название для крошки и заголовка вкладки. А ресурс игры на странице помечен `CACHE`, как в магазине: ту же игру только что загрузил резолвер, второй запрос не нужен.

2. В `game-edit.ts` — `draft` через `linkedSignal` от ресурса игры и форма `gameForm` со схемой `gameSchema`; отправка — `save()`: `PUT /api/games/:id`, затем таблица; ошибка `400` — сообщение сервера.

## Эксперименты

**Сервер проверяет сам.** Введите цену 2990.5 и сохраните. Правило `min` такую цену пропустило — она больше единицы. А сервер ответил `400`, и под формой его сообщение: «Цена — целое число рублей больше нуля». Форма проверяет то, что удобно проверить заранее, сервер — всё.

**Права — тоже на сервере.** В `AuthStore` замените `isAdmin` на `computed(() => true)` и войдите покупателем. Админка открылась, форма заполнилась (игры читать можно всем), а «Сохранить» — «Не удалось сохранить», в «Сети» `PUT /api/games/4` → `403`. Верните как было и войдите администратором.

**Цена до скидки.** Поставьте цену до скидки равной цене: под полем «Цена до скидки — больше цены». Сотрите поле совсем: ошибка исчезла — `null` значит «скидки нет», и сохранение уберёт скидку с игры.

::: deep Под капотом: почему PUT, а не PATCH
`PUT` заменяет ресурс целиком: что не прислали — того нет. Поэтому форма отправляет весь черновик, а учебный бэкенд из `oldPrice: null` делает игру без скидки. `PATCH` меняет только присланные поля — с ним «убрать скидку» пришлось бы передавать отдельно. Какой метод выбрать, решает API сервера; `HttpClient` умеет оба: `http.put`, `http.patch`.
:::
