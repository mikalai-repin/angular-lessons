Последнее, чего не хватает админке, — добавить игру. Форма та же, что у редактирования, и почти всё для неё уже есть: черновик, схема, поля, сервис раздела, гард. Новое — обложка: её нужно не напечатать, а **загрузить файлом**.

- В `games-table.css` — стили панели `.toolbar` над таблицей: поиск и кнопка рядом.

## Как загружают файл

`<input type="file">` отдаёт выбранный файл в `input.files` — объект `File`. JSON файл не перевезёт, поэтому его отправляют в теле **`FormData`** — как браузер отправил бы обычную HTML-форму с файлом:

```ts
const body = new FormData();
body.append('file', file);
this.http.post<{ url: string }>('/api/covers', body);
```

Тело `FormData` уходит как `multipart/form-data`. Заголовок `Content-Type` `HttpClient` для `FormData` не ставит — его ставит браузер, вместе с границей между частями тела. Поставьте его сами — `headers: { 'Content-Type': 'multipart/form-data' }`, — и граница потеряется: учебный бэкенд ответит `400` «Не удалось разобрать тело multipart/form-data: нет границы (boundary)».

Учебный бэкенд принимает картинки SVG, PNG, JPEG и WebP до 1 МБ и отвечает адресом: `{ "url": "/uploads/1-cover.svg" }`. Другой файл — `415` «Обложка — картинка SVG, PNG, JPEG или WebP», большой — `413` «Файл больше 1 МБ». Во вкладке «Сеть» у запроса видно описание файла.

Обложка в форме — **адрес**, строка. Файл уходит на сервер сразу, как только его выбрали, а в поле формы попадает адрес, который вернул сервер. Тогда `POST /api/games` остаётся обычным JSON, а черновик — тем же `GameDraft`.

::: tip
Учебный бэкенд хранит файл в памяти превью, а адрес `/uploads/…` превью показывает из этой памяти — как будто картинка лежит на сервере. Настоящий сервер сохранил бы файл в хранилище и отдавал бы по этому адресу. После перезапуска превью загруженных обложек нет — как и добавленных игр.
:::

## Поле формы из своего компонента

Поле обложки — не `<input>`, а компонент: картинка, выбор файла, «Загружаем…», ошибка сервера. Чтобы связать его с формой через `[formField]`, компонент выполняет договор `FormValueControl<string>` — как звёзды `Rating` в главе 13:

```ts admin/cover-upload/cover-upload.ts
export class CoverUpload implements FormValueControl<string> {
  readonly value = model('');
  readonly touch = output();
```

`value` — значение поля (адрес обложки): форма и читает его, и пишет. `touch` — «админ закончил с полем», форма отметит его тронутым и покажет ошибки.

::: task
1. **Маршрут.** `new` — ребёнок `games` с компонентом `GameNew`, заголовком и крошкой «Новая игра» и тем же гардом `unsavedChangesGuard`. Над таблицей — `<div class="toolbar">` с полем поиска и ссылкой-кнопкой «+ Новая игра» (`class="button"`, `routerLink="new"`).
2. **Сервис.** `AdminGames.create(draft)` — `POST /api/games`, запись «Добавлена игра «…»» в журнал, вернуть игру из ответа. `uploadCover(file)` — `FormData` с файлом в поле `file`, `POST /api/covers`, вернуть `url` из ответа.
3. **Поле обложки.** `CoverUpload.upload(input)`: взять файл, пока он грузится — `uploading`, загрузить через `uploadCover` и положить адрес в `value`; ошибка — сообщение сервера в `error` (а если его нет — «Не удалось загрузить обложку»), перед новой загрузкой ошибку сбросить; в конце — `touch` и очистить `input.value`, чтобы тот же файл можно было выбрать снова.
4. **Поля игры.** В `GameFields` после названия — `<div class="field">` «Обложка» с `<app-cover-upload [formField]="game.cover" />` и ошибками поля. В схеме — обязательная обложка: «Загрузите обложку».
5. **Страница.** `GameNew`: черновик `NEW_GAME` в сигнале, форма со схемой, `hasUnsavedChanges()`. «Добавить» — `create`, сбросить форму и перейти в таблицу с поиском по названию новой игры: `?q=<название>`. Ошибка `400` — сообщение сервера у формы. В шаблоне — как у редактирования, кнопка «Добавить» («Добавляем…» во время отправки).
:::

::: hint Подсказка 1: почему new раньше :id
Роутер перебирает детей по порядку и берёт первый подходящий. `:id` подходит к любому слову, в том числе к `new`. Поставьте `new` после `:id` и откройте `/admin/games/new`: откроется страница редактирования, в крошке «Игра не найдена», в «Сети» `GET /api/games/new` → `404`.
:::

::: hint Подсказка 2: где взять файл
В шаблоне поле уже передаёт себя в метод: `(change)="upload(file)"`, где `#file` — сам `<input>`. Выбранный файл — `input.files?.[0]`; если админ закрыл окно выбора без файла, там `undefined`.
:::

::: hint Подсказка 3: ошибка сервера
Ошибка `HttpClient` — `HttpErrorResponse`. Тело ответа сервера — в `error.error`, а текст учебного бэкенда — в `error.error.message`. `finally` выполнится и после успеха, и после ошибки: там удобно выключить `uploading` и сообщить `touch`.
:::

::: hint Подсказка 4: переход с поиском
`this.router.navigate(['..'], { relativeTo: this.route, queryParams: { q: game.title } })` — на уровень выше от `/admin/games/new` и с параметром. Перед переходом — `this.gameForm().reset()`, иначе гард спросит про несохранённые изменения.
:::

## Проверьте себя

- Нажмите «Добавить» с пустой формой: под названием «Нужно название», под обложкой «Загрузите обложку», под ценой «Нужна цена». В «Сети» — ни одного `POST /api/games`.
- Выберите текстовый файл: под полем «Обложка — картинка SVG, PNG, JPEG или WebP», в «Сети» `POST /api/covers` → `415`. Выберите картинку: появилось превью, ошибка исчезла.
- Добавьте игру: вы в таблице, в поиске её название, она в строке таблицы. На сводке — «Добавлена игра «…»». В каталоге магазина у неё ваша обложка.
- Начните заполнять новую игру и щёлкните «← Игры»: окно «Изменения не сохранятся».
- Откройте старую игру на редактирование: у неё тоже есть поле обложки — `GameFields` общий. Загрузите другую картинку и сохраните.

Кнопка «✓ Проверить» проверит всё это сама.

## Как в настоящем проекте

Большие файлы показывают с полосой загрузки. `HttpClient` умеет сообщать о ходе отправки — событиями `HttpEventType.UploadProgress` с `reportUploadProgress: true`. Но только через `XMLHttpRequest`: по умолчанию в Angular 22 запросы идут через `fetch` (`FetchBackend`), и с этой опцией запрос падает с ошибкой:

```
NG02824: The FetchBackend does not support upload progress reporting. Please use `withXhr()` on your `provideHttpClient()` configuration if you want to report upload progress.
```

В проекте с полосой загрузки к `provideHttpClient` добавляют `withXhr()`. В превью этого не сделать: учебный бэкенд перехватывает только `fetch`.

## Итоги главы

- **Раздел** — ленивый файл маршрутов с макетом и `<router-outlet>`; гард `canMatch` на родителе закрывает весь раздел, а права на данные и изменения проверяет сервер — на каждом запросе.
- **Таблица** — состояние в адресе: сортировка, поиск, страница — query-параметры и входы компонента. Прежний ответ на время загрузки — `linkedSignal`, номера страниц — `computed`, `aria-sort` и `aria-current` — для диктора и для CSS.
- **Форма с данными с сервера** — модель через `linkedSignal` от ресурса; поля — отдельным компонентом с входом `FieldTree`; `min` для чисел; ошибка `400` сервера — ошибкой формы.
- **Сервис раздела** — `providers` маршрута и `@Service({ autoProvided: false })`: свой инжектор окружения, видимый только разделу. Живёт до конца приложения, если не включить `withAutoCleanupInjectors()`.
- **Кэш** очищается после каждого успешного изменения: интерцептор не знает, какие ответы устарели.
- **Динамический компонент** — `createComponent` с `inputBinding`/`outputBinding`, хост-элемент в DOM, `attachView`, `destroy`. На нём — окно подтверждения с промисом ответа и гард, который этого ответа ждёт.
- **Загрузка файла** — `FormData` в `POST`, адрес файла — в поле формы, поле — свой компонент с `FormValueControl`.

Магазин и админка готовы. Всё состояние в них — сервисы на сигналах: корзина, избранное, вход, журнал админки. В следующей главе посмотрим, как то же самое делает самая распространённая библиотека состояния в мире Angular — NgRx: что она добавляет к нашим сервисам и когда она того стоит.
