Покупатель открыл несколько игр, ушёл подумать, вернулся на главную — и не помнит, как называлась та, с котиками. Поможем ему: на главной под приветствием — блок **«Вы смотрели»** с обложками последних открытых игр. Самая свежая — первой, всего не больше четырёх, список переживает перезапуск.

## `signalMethod`

Страница игры загружает игру ресурсом: сначала её нет, потом она есть, потом — при переходе на другую игру — снова загрузка и новая игра. Хранилищу нужно запоминать **каждую** загруженную игру. Можно написать `effect` в странице, который читает ресурс и зовёт метод хранилища. А можно сделать сам метод «умеющим» принимать сигнал.

**`signalMethod`** из `@ngrx/signals` — это `rxMethod` без RxJS (шаг 5). Он превращает функцию в метод, который принимает значение **или** сигнал (функцию, которая читает сигналы):

```ts
const log = signalMethod<number>((n) => console.log(n));
log(5);                // 5 — один раз
log(() => count());    // при каждом новом значении count
```

С сигналом метод заводит `effect` и вызывает функцию на каждое новое значение. Читает он **только** то, что внутри переданной функции: сигналы, которые прочитает сама обработка, не отслеживаются. А эффект создаётся в контексте внедрения того, **кто вызвал** метод, — если вызвать его в конструкторе страницы, слежение закончится вместе со страницей.

::: task
1. **Хранилище** `core/recent-store.ts`: `{ providedIn: 'root' }`, коллекция игр `withEntities<Game>()`, `withStorage` с ключом `'hod-konem:recent:v1'` (сохранять игры по порядку, при восстановлении — только объекты с целым `id` и строкой `title`, не больше четырёх).
2. **Метод** `remember` на `signalMethod<Game | undefined>`: `undefined` — ничего не делать; иначе игра становится первой, а лишние — после четвёртой — забываются. Открыли игру снова — она переезжает в начало, а не появляется второй раз.
3. **Страница игры**: в конструкторе `inject(RecentStore).remember(…)` с функцией, которая возвращает загруженную игру или `undefined`.
4. **Главная**: под приветствием, если список не пуст, — заголовок `<h2 class="section-title">Вы смотрели</h2>` и список `<ul class="recent">`, в каждом `<li>` — ссылка `[routerLink]="['/games', game.id]"` с обложкой `<img [src]="game.cover" [alt]="game.title" width="300" height="400" />`.
:::

::: hint Подсказка 1: из чего собрать хранилище
Посмотрите на корзину: `withEntities`, затем `withStorage` с `save` и `restore`. Здесь проще — у игры есть `id`, `entityConfig` и `selectId` не нужны. `restore` возвращает `setAllEntities(…)` от проверенного массива.
:::

::: hint Подсказка 2: игра — в начало
Функции коллекций можно передать в один `patchState` подряд. «Переехать в начало» — это убрать (`removeEntity`) и добавить первой (`prependEntity`): `prependEntity` с уже занятым id ничего не делает, как `addEntity`. Лишние — `removeEntities(список id)`: посчитайте его из `store.ids()` **до** изменений — все id, кроме этой игры, начиная с четвёртого: три остаются, четвёртой встанет новая.
:::

::: hint Подсказка 3: что передать из страницы
Не `this.game.value()`: если сервер ответил ошибкой (например, 404), чтение значения бросит исключение и страница не отрисуется. Передайте функцию: `() => this.game.hasValue() ? this.game.value() : undefined`. Она читает сигналы ресурса, поэтому `signalMethod` вызовет обработку при каждой новой игре.
:::

## Проверьте себя

- Откройте 5–6 разных игр, вернитесь на главную: последние четыре, самая свежая — слева. Откройте вторую из них снова — она переехала в начало.
- Перезапустите превью ⟳ — список на месте.
- Откройте адрес несуществующей игры, например `/games/999`: «Игра не найдена», в список она не попала.
- Испортите сохранённое: первой строкой в `main.ts` — `localStorage.setItem('hod-konem:recent:v1', '[1, "мусор", {"id": "x"}]');`. Главная открылась без ошибок и без блока «Вы смотрели». Уберите строку.
- Кнопка «✓ Проверить» откроет игры по очереди (в том числе одну дважды и одну несуществующую) и сверит список на главной и в `localStorage`.

## Как в настоящем проекте

Такой список часто держат на сервере — у вошедшего покупателя он виден на всех устройствах. Тогда `withStorage` уступает место запросам: `remember` отправляет `POST`, а список загружается `rxMethod` или ресурсом. Устройство хранилища почти не меняется — меняется расширение, которое отвечает за сохранение. В этом и сила расширений: хранилище описывает **что** у него есть и **что** с этим делать, а **где** оно хранится — отдельная часть.

## Итоги главы

- **Signal Store** — хранилище из частей: `withState` — состояние, `withComputed` — производные, `withMethods` — действия, `withHooks` — жизнь, `withProps` — зависимости, `withLinkedState` — состояние, зависящее от другого. Каждая часть видит только части выше. Снаружи состояние только читают, меняют — `patchState` внутри. Члены с `_` — закрытые.
- **Коллекции** — `withEntities`: `entityMap` и `ids`, готовые функции обновления `addEntity`, `updateEntity`, `removeEntity`, `setAllEntities`, `prependEntity`.
- **Свои расширения** — `signalStoreFeature`: общий код для нескольких хранилищ с проверкой типов по тому, к чему подключили.
- **Асинхронность** — `rxMethod` с операторами RxJS и `tapResponse`, без RxJS — `signalMethod`.
- **События** — `eventGroup`, `injectDispatch`, `withReducer`, `withEventHandlers`: отправитель не знает получателей.
- **Классический Store** — одно состояние, действия, чистые редьюсеры, селекторы, эффекты NgRx и журнал каждого изменения. Больше кода — зато весь поток данных на виду.
- И главное — библиотека **не обязательна**. Всё, что мы сделали в этой главе, магазин умел и до неё: корзина, избранное, сохранение. NgRx даёт единые правила, готовые решения для частых задач и инструменты отладки — это стоит того в большой команде и большом приложении.

Последний шаг главы — без кода: заглянем внутрь `signalStore` и соберём вместе, когда библиотека нужна. А потом начинается последняя часть курса: в главе 19 мы спустимся под капот самого Angular — компилятор, представления, обнаружение изменений и сигналы изнутри.
