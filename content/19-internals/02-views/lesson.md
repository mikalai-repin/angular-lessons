Функция шаблона из прошлого шага создаёт узлы по номерам: `elementStart(11, 'a', 6)`. Блок обновления сравнивает значение привязки «с прошлым». Где лежат узел номер 11 и это прошлое значение? Чего стоит Angular каждая карточка из двенадцати на главной? В этом шаге заглянем в структуры, с которыми работают все инструкции, — **представления**.

## Вкладка «Дерево»

Начнём сверху. Откройте вкладку **«Дерево»** под превью. Это компоненты на странице в порядке DOM: `App`, внутри — `Header`, `Breadcrumbs`, страница `Home`, в ней карточки `GameCard` со звёздами `Rating`. Щелчок по строке раскрывает поля экземпляра: у сигналов — вид (`signal`, `computed`, `input`, `model`, `linkedSignal`) и значение, у остальных полей — значение. Наведение на строку подсвечивает компонент в приложении. Пока вкладка открыта, дерево обновляется раз в секунду.

Раскройте первую `GameCard` и нажмите у неё «В корзину»: `inCart` станет `1`, `available` уменьшится на единицу. У `cover` написано «ещё не вычислен»: запрос `viewChild` — тоже вычисляемый сигнал, а его ещё никто не читал. Он понадобится только в полёте обложки.

Дерево компонентов — то, что видит разработчик. Сам Angular хранит больше: у каждого компонента и у каждого блока `@if`, `@for` — своё **представление**.

## Журнал представлений

В коде шага появилась папка `debug/` с помощником `view-log.ts`. По Alt + щелчку по любому элементу превью он печатает в консоль представление, в котором Angular создал этот элемент. Помощник читает внутренние структуры через `ɵgetLContext` из `@angular/core` и константы из исходников Angular 22.2 — только для изучения.

::: task
Включите журнал в `main.ts`: когда приложение запустится, вызовите `logViewOnAltClick()`.
:::

```ts main.ts {6-7}
import { logViewOnAltClick } from './debug/view-log';

bootstrapApplication(App, appConfig)
  // Alt + щелчок по элементу — его представление в консоли
  .then(() => logViewOnAltClick())
  .catch((err) => console.error(err));
```

## LView — массив

Alt + щелчок по названию первой карточки (щелчок с Alt не переходит по ссылке):

```
<a> — узел 11 шаблона GameCard (компонент), ячейка 39 его LView
TNode узла: тег a, атрибуты [1,"title-link",3,"routerLink"]
LView — массив из 122 ячеек:
  0–27 заголовок: HOST <app-game-card>, FLAGS Attached, PARENT RepeaterContext (встроенное), CONTEXT GameCard
  28–63 узлы: 28: LContainer[1], 29: LContainer[0], 30: <span>, …, 38: <h2>, 39: <a>, 40: "Шахматы «Класс", 41: LView Rating, 42: DecimalPipe, …
  64–91 привязки: 64: 0, 65: 4, 66: Array(2), 67: "Шахматы «Классика»", …, 81: -1, …, 90: 8, 91: Array(2)
  92–121 прочее: number ×18, RouterLink, string ×3, undefined, Rating, Tooltip, null ×3, boolean ×2
TView GameCard (компонент) — общий для 12 таких представлений на странице
```

**Представление** экземпляра компонента, `LView` (logical view), — обычный массив JavaScript. Он делится на четыре участка:

```
LView карточки «Шахматы»
 0–27   заголовок: HOST, TVIEW, FLAGS,
        PARENT, CONTEXT, INJECTOR…
28–63   узлы: decls = 36
64–91   привязки: vars = 28
92–121  директивы, инжекторы элементов
```

- **Заголовок** — 28 служебных ячеек. `HOST` — элемент-хост `<app-game-card>`, `CONTEXT` — экземпляр `GameCard` (это и есть `ctx` в функции шаблона), `PARENT` — представление, в котором стоит хост, `FLAGS` — флаги (о них — в следующем шаге), `TVIEW` — общая часть, о ней ниже.
- **Узлы** — по ячейке на каждый номер из функции шаблона, со смещением 28. `elementStart(11, 'a', 6)` положил `<a>` в ячейку 39. Ячейка 41 — `<app-rating>`, но в ней не элемент, а `LView` компонента `Rating`: представления дочерних компонентов лежат прямо в массиве родителя. В ячейке 42 — экземпляр пайпа `number`: `pipe(14, 'number')` из прошлого шага.
- **Привязки** — прошлые значения. 36 узлов + 28 привязок — ровно `decls` и `vars` из определения компонента. `64: 0` — номер выбранной ветки `@if (priority())`, `65: 4` — ветка `@case ('strategy')`, `67` — название. `90: 8` и `91: Array(2)` — память `pureFunction1(26, …)`: аргумент (`id` игры) и массив `['/games', 8]`, 64 + 26 = 90.
- **Прочее** — экземпляры директив на элементах (`RouterLink` на `<a>`, `Rating` и `Tooltip` на `<app-rating>`) и данные инжекторов элементов.

**LContainer** — то, что лежит на месте `@if`, `@for`, `@switch`: массив с заголовком из 10 ячеек и списком встроенных представлений. `LContainer[1]` в ячейке 28 — ветка с `priority`, в ней одна картинка; `LContainer[0]` в ячейке 29 — пустая ветка `@else`. Каждая строка `@for` — отдельное встроенное `LView` в контейнере. Поэтому у карточки `PARENT` — встроенное представление с контекстом `RepeaterContext`: строка `@for` на главной. Из таких вложенных массивов и состоит **дерево представлений** из главы 6.

**Эксперимент.** Нажмите «В корзину» у этой же карточки и снова Alt + щелчок по названию. Изменилась одна ячейка: `81: -1` стало `81: 35`. Это номер ветки `@if (inCart() > 0)`: появилась строка «В корзине: 1 шт.». Остальные привязки не изменились, и Angular их в DOM не писал.

## TView — общее на всех

Alt + щелчок по названию второй карточки. Массив другой: `67: "Глубокий космос"`, `90: 34`. Но последняя строка та же: `TView GameCard — общий для 12 таких представлений`.

**TView** (template view) — всё, что у карточек общее:

- `template` — функция шаблона из прошлого шага;
- `data` — **TNode** для каждого узла: тег, атрибуты, какие директивы на нём нашлись, куда идут входы. Строка «TNode узла» в журнале — из неё;
- `blueprint` — заготовка `LView`. Новое представление Angular создаёт копией этого массива (`tView.blueprint.slice()`) и заполняет заголовок;
- `bindingStartIndex` и `expandoStartIndex` — где начинаются привязки (64) и «прочее» (92).

`TView` компонента создаётся один раз на тип и хранится в определении: `GameCard.ɵcmp.tView`. Создаёт его первая карточка — в **первом проходе создания** (`firstCreatePass`): строит TNode, сверяет элементы с селекторами директив (глава 7), запоминает результаты. Остальные одиннадцать карточек получают готовое.

Отсюда ответ на вопрос, чего стоит компонент. Двенадцать карточек — это двенадцать массивов по 122 ячейки, их DOM-узлы и экземпляры директив. Код шаблона, TNode и результаты сопоставления директив — по одному на тип. В таком массиве нет ни замыканий, ни объектов на каждую привязку — только значения. Поэтому делить интерфейс на мелкие компоненты не страшно: сам компонент Angular почти ничего не стоит.

## Как элемент находит своё представление

Как журнал по щелчку нашёл массив? Angular записывает в элементы свойство **`__ngContext__`** — номер `LView` (в нашем запуске у `<a>` первой карточки — `22`). `ɵgetLContext(элемент)` находит представление по номеру в общем реестре и возвращает его вместе с номером ячейки. Номер получают не все элементы, а только элементы верхнего уровня шаблона и хосты директив. У `<span>` внутри `<p class="meta">` номера нет: для него функция поднимается по DOM до ближайшего элемента с номером. После первого обращения в `__ngContext__` вместо номера оказывается найденный объект.

Такое же поле есть у экземпляра компонента — номер представления, в котором стоит его хост (во вкладке «Дерево» мы это поле прячем). Через эти номера отладочные функции `ng.getComponent` и `ng.getInjector` связывают DOM, экземпляры и представления.

**Эксперимент.** Alt + щелчок по заголовку «Настольные игры для всей семьи» на главной. Узел 1 шаблона `Home`, а `PARENT` — `Home (корневое)`. Страницу создаёт роутер, а не шаблон `App`. Компонент, созданный из кода (`<router-outlet>`, `createComponent` из главы 17), получает **корневое** представление-обёртку со своим хостом. Сама обёртка лежит в `LContainer` на месте `<router-outlet>`.

::: deep Инжектор элемента — тоже ячейки LView
В главе 8 мы разбирали `NodeInjector` — инжектор элемента — и фильтр Блума на 256 бит. Его данные лежат в «прочем» участке `LView`. На каждый элемент с директивами — 9 чисел: 8 по 32 бита (256 бит фильтра) и ссылка на инжектор родителя. В карточке директивы стоят на двух элементах: `<a>` (`RouterLink`) и `<app-rating>` (`Rating`, `Tooltip`). Отсюда `number ×18` в журнале. Отдельного объекта-инжектора нет, пока его не попросят: `inject(Injector)` или `ng.getInjector` создают обёртку над этими ячейками.
:::

Что запомнить:

- `LView` — массив на каждый экземпляр компонента и на каждую ветку `@if` и строку `@for`: заголовок, узлы, прошлые значения привязок, директивы;
- `TView` — общее для всех экземпляров одного шаблона: функция шаблона, TNode, заготовка массива. Создаётся один раз;
- дерево представлений — вложенные массивы: дочерние компоненты лежат в ячейках родителя, встроенные представления — в `LContainer`.

В следующем шаге посмотрим на ячейку `FLAGS`: по ней Angular решает, какие из этих массивов обновлять при проверке.
