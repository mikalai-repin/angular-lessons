Во врезках «Вы встретите в старом коде» мы не раз упоминали **zone.js**: раньше проверку в Angular запускала она. Большинство существующих приложений до сих пор на ней: при переводе их на зонлесс вы встретите все её следствия. В этом шаге переведём «Ход конём» на zone.js, посмотрим журналом, что изменилось, и разберём, почему от неё отказались.

## Что делает zone.js

zone.js — отдельная библиотека. При загрузке она **подменяет** асинхронные API браузера: `setTimeout`, `setInterval`, `Promise`, `queueMicrotask`, `addEventListener`, `requestAnimationFrame`, `XMLHttpRequest`, `MutationObserver` и ещё несколько. Подменённый `setTimeout` запоминает, в какой **зоне** его вызвали, и выполняет колбэк в ней же. Зона — контекст, который знает, когда в нём начинается и заканчивается каждая задача.

Angular создаёт свою зону `angular` (класс `NgZone`) и запускает приложение в ней. Всё, что приложение делает асинхронно, остаётся в этой зоне. Когда очередная задача — щелчок, таймер, ответ сервера — закончилась и очередь микрозадач опустела, зона сообщает об этом (`onMicrotaskEmpty`). Angular вызывает `ApplicationRef.tick()` в режиме `Global` от самого корня.

Получается, что Angular **не знает**, что изменилось. Он знает только, что «что-то могло измениться», и проверяет всё, до чего дотянется.

## Включаем

::: task
Переведите магазин на zone.js. Первой строкой `main.ts` импортируйте `'zone.js'`, а в провайдеры `app.config.ts` добавьте `provideZoneChangeDetection()` из `@angular/core`.
:::

```ts main.ts {1-2}
// zone.js — первым: он подменяет setTimeout, Promise, addEventListener до того, как ими кто-то воспользуется
import 'zone.js';
import { bootstrapApplication } from '@angular/platform-browser';
```

```ts app.config.ts {3-4}
providers: [
  provideBrowserGlobalErrorListeners(),
  // Проверки по zone.js — как в приложениях до перехода на зонлесс
  provideZoneChangeDetection(),
  // …
],
```

Импорт без имён (`import 'zone.js'`) выполняет модуль ради побочного действия — подмены API. В проекте Angular CLI zone.js подключают не в `main.ts`, а в `angular.json`: `"polyfills": ["zone.js"]`. Тогда сборщик кладёт её в отдельный файл, который грузится раньше приложения.

## Что получилось

Магазин работает как прежде. Разница — в журнале проверок. При запуске появились строки:

```
Проверка [—]: шаблоны не обновлялись
```

Их запустил не планировщик: никто ему не сообщал, отсюда `[—]`. Их запустила зона: при запуске приложение выполняет много асинхронных задач, и после каждой зона просит проверку. Шаблоны при этом не обновились: компоненты OnPush, они ничем не помечены. Нажмите «В корзину» — строка та же, что без зоны: событие помечает путь до корня, сигналы — свои шаблоны. Зона только добавляет лишние обходы.

## Эксперимент: обычное поле в таймере

В главе 3 счётчик в обычном поле, который меняет `setTimeout`, застревал: в зонлесс-приложении проверку никто не запускает. Добавьте в `Header`:

```ts layout/header/header.ts
protected seconds = 0;

constructor() {
  setInterval(() => this.seconds++, 1000);
}
```

и в начало `header.html` — `<span>Секунд: {{ seconds }}</span>`.

С zone.js каждую секунду в журнале — `Проверка [—]: шаблоны не обновлялись`, а на экране по-прежнему «Секунд: 0». Зона запустила проверку, но шапка — OnPush, и никто её не пометил.

Теперь поставьте `changeDetection: ChangeDetectionStrategy.Eager` шапке и `App`:

```
Проверка [—]: App (Eager), Header (Eager), App (Eager), Header (Eager)
```

Счётчик пошёл: «Секунд: 3», «4», «5». Режим `Global` от корня обновляет `CheckAlways`-представления, а цепочка от корня до шапки теперь вся `Eager`. Если оставить `Eager` только у шапки, «Секунд: 0»: до неё не дойти через OnPush-`App`. Вторая пара в строке — повторная проверка режима разработки из прошлого шага: она тоже идёт в режиме `Global` от корня и снова обходит `Eager`-представления.

Так и работали приложения до сигналов. У всех компонентов была стратегия `Default` (сейчас `Eager`), и зона после каждой задачи проверяла всё дерево. Удобно — обычное поле «просто работает». Дорого — каждый таймер, каждое движение мыши со слушателем, каждый ответ сервера проверяет весь экран.

## Зона и выход из неё

Выведите в конструкторе шапки `Zone.current.name` (`Zone` — глобальная переменная zone.js) — будет `angular`. Код вне Angular, например модуль `main.ts` до запуска, выполняется в корневой зоне `<root>`. Чтобы таймер не будил проверки, его запускают **вне** зоны Angular:

```ts
inject(NgZone).runOutsideAngular(() =>
  setInterval(() => this.seconds++, 1000),
);
```

Строки `Проверка [—]` каждую секунду пропали, «Секунд: 0» больше не меняется даже с `Eager`. В приложениях на zone.js так прятали от Angular частые события: прокрутку, `mousemove`, анимации. А чтобы вернуть результат на экран, вызывали `zone.run(() => …)`.

## Ошибки конфигурации

Уберите `import 'zone.js'`, оставив провайдер:

```
RuntimeError: NG0908: In this configuration Angular requires Zone.js
```

Верните импорт и добавьте в провайдеры ещё и `provideZonelessChangeDetection()`:

```
NG0914: The application is using zoneless change detection, but is still loading Zone.js. …
NG0408: Both provideZoneChangeDetection and provideZonelessChangeDetection are provided. This is likely a mistake. …
```

Это предупреждения: приложение работает в зонлесс-режиме, но зона загружена зря.

## Почему от неё отказались

- **Лишние проверки.** Зона не знает, что изменилось, и запускает проверку после каждой задачи, даже чужой. Мы видели это строками `[—]`.
- **Подмена глобальных API.** Выведите в консоль `String(Promise)`: `function ZoneAwarePromise() { [native code] }`. Через обёртки работает весь код на странице, включая сторонние библиотеки.
- **Нативный `async`/`await` не перехватить.** `await` продолжает функцию через внутренний механизм движка, а не через подменяемый `Promise`. Поэтому сборщик Angular CLI, увидев zone.js в `polyfills`, переписывает `async`-функции в генераторы. Так в исходниках `@angular/build`: «Native async/await is not supported with Zone.js. Disabling support here will cause esbuild to downlevel async/await». Код становится больше и медленнее.
- **Размер.** `zone.min.js` — 35 КБ, 12,6 КБ в gzip, и он загружается раньше приложения.

Сигналы дают Angular то, чего у зоны не было: точное знание, **какой** шаблон устарел. Поэтому в Angular 22 зонлесс — по умолчанию.

## Как в настоящем проекте

Перевести приложение с zone.js на зонлесс: убрать `zone.js` из `polyfills` (и `zone.js/testing` из тестов), убрать `provideZoneChangeDetection()`. В Angular 22 зонлесс — по умолчанию, отдельный провайдер не нужен. Дальше — найти места, где шаблон показывает обычное поле, которое меняется не в обработчике его события: таймеры, подписки, колбэки сторонних библиотек. Такие поля нужно сделать сигналами. Помогает `provideCheckNoChangesConfig({ exhaustive: true, interval: … })` из прошлого шага: повторная проверка по таймеру ловит такие поля ошибкой `NG0100`.

::: legacy Вы встретите в старом коде: NgZone
`constructor(private zone: NgZone)`, `this.zone.run(() => …)` после колбэка сторонней библиотеки, `runOutsideAngular` вокруг слушателей прокрутки, `zone.onStable` / `onMicrotaskEmpty` («дождаться, пока Angular всё отрисует»), `fakeAsync` и `tick()` в тестах (глава 16), `polyfills: ["zone.js"]` в `angular.json`. В зонлесс-приложении `NgZone` остаётся пустышкой (`NoopNgZone`): `run` просто вызывает функцию.
:::
