В главе 3 мы нарисовали граф сигналов и разобрали push-pull: запись рассылает пометки, чтение проверяет и пересчитывает. В прошлом шаге этот механизм решил, что одиннадцать карточек обновлять не нужно: потребители грязные, а значения прежние. Чтобы это решение не было магией, разберём сигналы на детали. Angular собирает `signal`, `computed` и `effect` из **примитивов** — публичного подпути `@angular/core/primitives/signals`. Соберём из них свою маленькую систему и посмотрим на версии узлов.

## Старт шага

Магазин снова без zone.js — как до прошлого шага. В `debug/` появилась **лаборатория** `signal-lab.ts`, `main.ts` запускает её до приложения: `runSignalLab()`. В лаборатории — два сигнала, цена и количество, вычисляемый итог и наш «эффект» `watch`, который печатает итог. Тело `watch` — задание. Пока оно пустое, в консоли только заголовки опытов.

Примитивы — API для авторов фреймворков и библиотек: из них собран сам `@angular/core`. В приложении пишут `signal`, `computed` и `effect`.

## Узел

У каждого сигнала есть **узел** — объект в свойстве с символом `SIGNAL` (его читал помощник графа в главе 3). Важные поля узла (`ReactiveNode`):

- `value` — значение;
- `version` — номер версии значения. Растёт, только когда значение **действительно** изменилось;
- `dirty` — «возможно, устарел» (у `computed` и потребителей);
- `producers`, `consumers` — связи с производителями и потребителями. В связи с производителем записано, какую его версию потребитель видел при последнем чтении (`lastReadVersion`);
- `lastCleanEpoch` — в какую **эпоху** узел последний раз проверен.

Эпоха — глобальный счётчик записей: каждая запись в любой сигнал увеличивает его на единицу.

`signal()` из `@angular/core` — тонкая обёртка над примитивом. Её код в Angular 22.2:

```js
function signal(initialValue, options) {
  const [get, set, update] = createSignal(initialValue, options?.equal);
  const signalFn = get;
  signalFn.set = set;
  signalFn.update = update;
  signalFn.asReadonly = signalAsReadonlyFn.bind(signalFn);
  // … в режиме разработки — debugName и toString
  return signalFn;
}
```

## Чтение и запись

**Чтение** сигнала вызывает `producerAccessed(узел)`. Если сейчас есть **активный потребитель** (выполняется `computed`, эффект или блок обновления шаблона), между ними появляется связь, и в неё записывается текущая версия производителя.

**Запись** — `signalSetFn`:

```js
function signalSetFn(node, newValue) {
  if (!node.equal(node.value, newValue)) {
    node.value = newValue;
    node.version++;
    producerIncrementEpoch();
    producerNotifyConsumers(node);
  }
}
```

Если значение равно прежнему (по умолчанию — `Object.is`), не происходит ничего. Иначе растут версия и эпоха, а `producerNotifyConsumers` проходит по потребителям и помечает их `dirty`, а те — своих. Вычислений на этом пути нет (push). У кого есть хук `consumerMarkedDirty`, тот реагирует: потребитель-шаблон вызывает `markAncestorsForTraversal` (прошлый шаг), эффект ставит себя в очередь.

**Проверка** — pull. Грязный потребитель, прежде чем выполняться, спрашивает `consumerPollProducersForChange`: у кого из производителей версия не совпадает с запомненной? Производителя-`computed` функция сначала приводит в актуальное состояние: тот пересчитывается, только если изменились версии **его** производителей. Новую версию он получает, только если результат не равен прежнему. Это и есть отсечение по равенству из главы 3.

## Свой эффект

Примитив `createWatch(fn, schedule, allowSignalWrites)` создаёт узел-потребитель:

- `fn` выполняется как активный потребитель: всё, что она прочитала, становится её зависимостями;
- когда узел пометили грязным, он вызывает `schedule(watcher)`. **Когда** выполнить `watcher.run()` — решаете вы;
- `run()` сначала сверяет версии и вызывает `fn`, только если что-то изменилось;
- `notify()` помечает узел вручную — так делают первый запуск.

::: task
Допишите `watch` в `debug/signal-lab.ts`: создайте узел `createWatch(fn, schedule, false)`. `schedule` получает наблюдателя — выполните его `run()` микрозадачей (`queueMicrotask`). Первый запуск — тоже через расписание: вызовите `notify()` у результата `createWatch`.
:::

```ts debug/signal-lab.ts
function watch(fn: () => void) {
  const handle = createWatch(
    fn,
    (watcher) => queueMicrotask(() => watcher.run()),
    false,
  );
  // Первый запуск — тоже через schedule
  handle.notify();
}
```

Третий аргумент, `allowSignalWrites`, — разрешить ли `fn` записывать в сигналы. Эффектам Angular запись разрешает (глава 3), нашему `watch` она не нужна.

## Что получилось

```
Итог 1990; вычислений total: 1; версии: price 0, quantity 0, total 1
— Две записи подряд
Итог 5970; вычислений total: 2; версии: price 0, quantity 2, total 2
— Запись того же значения
— Другие значения, тот же итог
Вычислений total: 3; версии: price 1, quantity 3, total 2
```

1. Первый запуск: `watch` прочитал `total`, тот вычислился один раз. Версия `total` — 1: появление первого значения тоже изменение.
2. Две записи в `quantity` подряд — две версии (`quantity 2`), но **один** запуск `watch`: первая запись поставила его в очередь, вторая застала уже грязным. `total` пересчитан тоже один раз — лениво, когда `watch` его прочитал.
3. `setPrice(1990)` — значение то же: ни версии, ни пометок, ни вывода.
4. Цена 2985 и количество 2 — итог снова 5970. `total` пересчитан (`вычислений: 3`), но его версия осталась 2: результат равен прежнему. `watch` проснулся, сверил версии, увидел у `total` прежнюю — и не вызвал `fn`. Строки «Итог» нет.

Пункт 4 — то, что в прошлом шаге случилось с одиннадцатью карточками. Только там вместо `watch` был потребитель-шаблон, а вместо `total` — `available` и `inCart`.

## Эксперимент: новый объект каждый раз

Пусть `total` возвращает объект: `return { sum: price() * quantity() };`, а `watch` печатает `total().sum`. В пункте 4 теперь появляется строка `Итог 5970; вычислений total: 3; … total 3`. Объект новый, `Object.is` его не узнаёт, версия растёт — и потребитель обновляется, хотя на экране ничего не изменилось бы. Передайте `createComputed` второй аргумент — функцию равенства `(a, b) => a.sum === b.sum` — и строка снова пропадёт: `total 2`. В `computed` и `signal` из `@angular/core` это опция `equal`. Запомните этот опыт — он понадобится в практикуме. Верните `total` число.

::: deep Эпохи: быстрый путь
Зачем эпоха, если есть версии? `computed`, у которого нет живых потребителей (его читают изредка, вне шаблонов и эффектов), не получает пометок `dirty`: на нём нет связей, по которым идёт push. Поэтому при каждом чтении он должен проверить версии своих производителей. Эпоха позволяет не делать и этого. Узел помнит `lastCleanEpoch`, и если с тех пор не было **ни одной** записи в сигналы — эпоха та же, — значение заведомо актуально: `producerUpdateValueVersion` возвращается сразу. У живых узлов быстрый путь другой: не `dirty` — значит, актуален.
:::

## Как устроен `effect`

Эффект Angular — тот же узел-потребитель, только с готовым расписанием. Его запуск (`runEffect`) начинается так же, как наш `run`: если это не первый запуск и версии производителей не изменились — выход. Расписание — то, что мы видели в главе 3. Эффект компонента выполняется при проверке его представления (`runEffectsInView`), корневой — через планировщик Angular (источник `корневой эффект` в журнале проверок).

Что запомнить:

- узел сигнала хранит значение, версию и связи; версия растёт только при реальном изменении;
- запись помечает потребителей без вычислений, проверка сверяет версии и пересчитывает только нужное;
- `computed`, который каждый раз создаёт новый объект, ломает отсечение по равенству: его потребители обновляются всегда. Лечится опцией `equal` или несколькими `computed` с примитивными значениями.
