Проект создан, но в нём заготовка «Hello, hod-konem». Перенесём в него магазин. Код — это полдела: в превью у магазина были ещё обложки игр и учебный бэкенд, который отвечал на запросы `/api/…`. В настоящем проекте бэкенд станет отдельным сервером на Node.js, а `ng serve` научится пересылать ему запросы.

## Пакеты: NgRx

В главе 18 магазин стал использовать NgRx, а `ng new` его не ставит. Список пакетов с версиями — в README архива:

```bash
npm install --save-exact @ngrx/effects@22.0.1 @ngrx/operators@22.0.1 @ngrx/signals@22.0.1 @ngrx/store@22.0.1
```

Загляните после этого в `package.json`:

```json
"dependencies": {
  "@angular/core": "^22.2.0",
  "@angular/router": "^22.2.0",
  "@ngrx/signals": "22.0.1",
  "@ngrx/store": "22.0.1",
  "rxjs": "~7.8.0"
},
"devDependencies": {
  "@angular/cli": "^22.2.1",
  "typescript": "~6.0.2",
  "vitest": "^5.0.0"
}
```

Версии записаны **диапазонами** (semver):

- `^22.2.0` — любая `22.x.y` не ниже `22.2.0`: новые возможности и исправления, но не новая основная версия. Поэтому в прошлом шаге установились 22.2.3 и 22.2.4;
- `~7.8.0` — только исправления: `7.8.x`;
- `22.0.1` без значка — ровно эта версия. Так записывает флаг `--save-exact`.

Какие версии **на самом деле** установлены, помнит `package-lock.json`. Его хранят в git: `npm install` на другой машине поставит ровно то же. В `dependencies` — то, что нужно приложению во время работы, в `devDependencies` — инструменты сборки и тестов.

## Бэкенд

В превью среда выполнения подменяла `fetch`: запросы `/api/…` уходили в функцию учебного бэкенда, не покидая браузер. Здесь тот же код бэкенда (`server/backend.mjs` — это `backend.js` из превью без изменений) работает внутри обычного HTTP-сервера `server/api.mjs`:

```js server/api.mjs
const backend = createBackend({ originalFetch, report });

createServer(async (request, response) => {
  // Запрос Node.js → Request из Fetch API → бэкенд → Response
  const result = await backend.handle(new Request(url, init));
  response.writeHead(result.status, …);
  response.end(…);
}).listen(3000);
```

Бэкенду нужен Node.js 22+: в нём, как в браузере, есть `Request`, `Response` и `crypto.subtle` для подписи токенов. Запустите его в отдельном терминале:

```bash
node server/api.mjs
```

```text
Учебный бэкенд «Ход конём»: http://localhost:3000/api/games
```

Откройте этот адрес — сервер ответит JSON со списком игр. Каждый запрос он пишет в терминал (`GET /api/games → 200 (306 мс)`): это ваша вкладка «Сеть». Задержка, как в превью, 300 мс; без неё — `LATENCY=0 node server/api.mjs`. Данные живут в памяти до перезапуска сервера.

## Прокси

Магазин просит `/api/games` — относительный адрес, то есть у того же сервера, откуда загружена страница: `http://localhost:4200`. А бэкенд — на порту 3000. Можно было бы написать в коде полный адрес `http://localhost:3000/api/games`, но тогда браузер увидит запрос на **другой источник** (origin): понадобятся настройки CORS на сервере, а в продакшене адрес всё равно другой.

Проще научить `ng serve` пересылать такие запросы. Это **прокси** сервера разработки. Его настройки — в `proxy.conf.json` из архива:

```json proxy.conf.json
{
  "/api": { "target": "http://localhost:3000" },
  "/uploads": { "target": "http://localhost:3000" }
}
```

Запросы с путём `/api/…` (и `/uploads/…` — загруженные в админке обложки) `ng serve` отправит на порт 3000, а ответ вернёт браузеру как свой. Подключаем файл в `angular.json`, в цели `serve`:

```json angular.json {3-5}
"serve": {
  "builder": "@angular/build:dev-server",
  "options": {
    "proxyConfig": "proxy.conf.json"
  },
  "configurations": { … }
}
```

То же можно передать флагом `ng serve --proxy-config proxy.conf.json`, но запись в `angular.json` не нужно помнить.

::: task
1. Установите пакеты NgRx.
2. Добавьте `proxyConfig` в `angular.json`.
3. В `src/index.html` поставьте `lang="ru"` и заголовок `<title>Ход конём</title>`: его видно, пока приложение не запустилось и не поставило свой.
4. Запустите в одном терминале `node server/api.mjs`, в другом — `ng serve`.
:::

Удобно завести для бэкенда скрипт в `package.json`: `"api": "node server/api.mjs"` — и запускать его как `npm run api`.

## Что получилось

На `http://localhost:4200/` — магазин. Каталог, страница игры, корзина, вход (`user@example.com` / `user`, администратор — `admin@example.com` / `admin`), админка — всё работает, и ни одной строчки кода магазина менять не пришлось. В консоли браузера — привычные журналы: действия Store, «Корзина: пусто», запросы интерцептора.

Отличия от превью вы заметите сразу:

- адрес — без `/app/`: приложение открыто напрямую, а не в iframe. Перезагрузка `/catalog` работает: `ng serve` отдаёт `index.html` на любой адрес, который не файл, и роутер разбирается сам;
- корзина и вход — пустые: `localStorage` у `localhost:4200` свой, не тот, что у курса;
- «Сеть» — это вкладка Network инструментов разработчика браузера. Запросы `/api/…` в ней идут к `localhost:4200`: браузер не знает, что за ним прокси.

**Эксперимент.** Остановите бэкенд (Ctrl+C) и обновите страницу. Вместо хитов — «Не удалось загрузить хиты», в Network — `502 Bad Gateway` (дважды: повтор из главы 12), а в терминале `ng serve`:

```text
[vite] http proxy error: /api/games?sort=rating&size=4
AggregateError [ECONNREFUSED]:
```

Прокси работает, но ему некуда переслать запрос. Запустите бэкенд снова.

**Эксперимент.** Уберите `proxyConfig` из `angular.json` и перезапустите `ng serve`. Хиты снова не загрузятся, но коварнее: в журнале интерцептора — `GET /api/games?… → 200`. Откройте ответ в Network: это `index.html`, `Content-Type: text/html`. Без прокси сервер разработки считает `/api/games` адресом страницы приложения и отдаёт `index.html` — а `HttpClient` не может разобрать HTML как JSON. Верните `proxyConfig`.

## Angular DevTools

В превью были вкладки «Шаблон» и «Дерево». У настоящего проекта есть официальный инструмент — расширение **Angular DevTools** для Chrome и Firefox. Оно добавляет в инструменты разработчика свою вкладку, а в ней (по документации angular.dev):

- **Components** — дерево компонентов и директив; у выбранного — его состояние, которое можно посмотреть и поменять;
- **Profiler** — запись обнаружения изменений: какие компоненты проверялись и сколько это стоило;
- **Injector Tree** — иерархия инжекторов: окружения и элементов;
- **Router Tree** — дерево маршрутов приложения.

DevTools работает только со сборкой для разработки — той, что даёт `ng serve`. Он держится на том же отладочном API, что наши помощники главы 19, а продакшен-сборка его вырезает. На собранном для продакшена сайте расширение скажет «We detected an application built with production configuration».

::: tip
Отлаживать код можно и без расширения: `ng serve` собирает с картами исходников (`sourceMap` в конфигурации `development`), поэтому во вкладке Sources браузера — ваши `.ts`-файлы, и точки останова ставятся прямо в них.
:::

::: deep Под капотом: почему бэкенд переехал без правок
Учебный бэкенд с самого начала написан на Fetch API: на вход — `Request`, на выход — `Response`. В превью их создавал подменённый `fetch`, здесь — несколько десятков строк `server/api.mjs`, которые превращают запрос Node.js (`IncomingMessage`) в `Request` и записывают `Response` обратно в ответ Node.js. Единственное, что бэкенд получает снаружи, — функцию загрузки данных: в превью она ходила за `/backend/data/games.json`, здесь читает `server/data/games.json` с диска.

Этот же приём — обработчик на `Request`/`Response` — использует сервер рендеринга Angular, который мы подключим в шаге 7. Там он пригодится ещё раз.
:::
