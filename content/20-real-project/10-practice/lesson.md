В шаге 9 статическая сборка отказалась работать: маршрут `catalog` рендерится на сервере, а сервера у статического хостинга нет. Сделаем магазин, который можно положить на любой хостинг файлов: всё, что можно, — пререндерить при сборке, остальное — отдать браузеру.

Практикум выполняется в проекте CLI: кода в редакторе он не меняет, и кнопки «Проверить» у него нет — проверять будете сами, по файлам сборки и в браузере.

::: task
1. В `angular.json` переключите сборку на статический вывод: `"outputMode": "static"`.
2. В `app.routes.server.ts` сделайте каталог (`catalog`) пререндеренным.
3. Страницы игр `games/:id` тоже пререндерьте — все 40. Список `id` получите у бэкенда во время сборки.
4. Если игру добавят в админке после сборки, её страницы в `dist` не будет. Пусть такую страницу рисует браузер.
5. Соберите (бэкенд должен работать) и убедитесь, что пререндерено 42 страницы. Запустите статический сервер на папке `dist/hod-konem/browser` и откройте страницу игры — с JavaScript и без.
:::

::: hint Подсказка 1: что сказала сборка
Ошибка из шага 9 — «Route '/catalog' is configured with server render mode, but the build 'outputMode' is set to 'static'» — называет первый маршрут, который мешает. Режим `Server` в статической сборке невозможен: у каждого маршрута остаются `Prerender` и `Client`.
:::

::: hint Подсказка 2: параметры для games/:id
Шаг 7 показал, что `Prerender` без списка параметров не соберётся. Список даёт асинхронная функция `getPrerenderParams` в описании маршрута: она возвращает массив объектов вида `{ id: '4' }` — по одному на страницу. Функция работает в контексте внедрения: внутри можно вызвать `inject(HttpClient)`. Сколько игр отдаёт `/api/games` за раз, задаёт параметр `size`.
:::

::: hint Подсказка 3: страница, которой нет в сборке
У маршрута `Prerender` с параметрами есть поле `fallback` — что делать с адресом, которого не было в списке: `PrerenderFallback.Server`, `Client` или `None`. Без сервера подходит только один вариант.
:::

::: hint Подсказка 4: как проверить
Пререндеренные страницы — это файлы: `dist/hod-konem/browser/games/4/index.html`. Список всех — в `dist/hod-konem/prerendered-routes.json`. Простейший статический сервер:

```bash
cd dist/hod-konem/browser
python3 -m http.server 4500
```
:::

## Решение

```ts src/app/app.routes.server.ts
import { inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import {
  PrerenderFallback,
  RenderMode,
  ServerRoute,
} from '@angular/ssr';
import { firstValueFrom } from 'rxjs';
import { GamesPage } from './core/models';

export const serverRoutes: ServerRoute[] = [
  // Главная и каталог без фильтров — при сборке
  { path: '', renderMode: RenderMode.Prerender },
  { path: 'catalog', renderMode: RenderMode.Prerender },
  {
    path: 'games/:id',
    renderMode: RenderMode.Prerender,
    // Какие страницы игр собрать — все игры каталога
    async getPrerenderParams() {
      const http = inject(HttpClient);
      const page = await firstValueFrom(
        http.get<GamesPage>('/api/games', { params: { size: 100 } }),
      );
      return page.items.map((game) => ({ id: String(game.id) }));
    },
    // Игру добавили после сборки — её страницу нарисует браузер
    fallback: PrerenderFallback.Client,
  },
  // Остальное — только в браузере
  { path: '**', renderMode: RenderMode.Client },
];
```

```text
Prerendered 42 static routes.
Application bundle generation complete.
```

Главная, каталог и 40 игр. В `dist/hod-konem/` теперь нет кода сервера: папка `server` пуста, всё нужное — в `browser/`.

## Проверьте себя

- В `dist/hod-konem/browser/games/4/index.html` заголовок — `<title>Ночной экспресс — Ход конём</title>`: его поставила наша `ShopTitleStrategy` ещё при сборке.
- Со статическим сервером `http://localhost:4500/games/4/` открывается с JavaScript и без. С JavaScript страница **работает даже без бэкенда**: в журнале нет ни одного запроса `/api/…`. Данные игры лежат в самой странице, в `ng-state`, и кэш передачи HTTP (шаг 8) отдал их `HttpClient`.
- А `http://localhost:4500/cart` — `404`. Файла `cart/index.html` нет: корзина — маршрут `Client`. Статическому хостингу нужно правило: «адрес, которому не нашлось файла, — отдать `index.csr.html`». У каждого хостинга оно записывается по-своему (в настройках перенаправлений), а у сервера SSR из шага 7 это правило уже встроено.
- `python3 -m http.server` на адрес `/games/4` без слеша отвечает `301` на `/games/4/` — так этот сервер находит `index.html` в папке. Роутер после запуска показывает адрес без слеша. Другие хостинги ведут себя по-разному; это тоже настраивается.

У статической версии есть цена. Цены и остатки на страницах игр — **на момент сборки**, и браузер покажет именно их: ответ API приехал в `ng-state`. Изменили цену в админке — пересоберите сайт. Поэтому магазину с часто меняющимися данными ближе вариант с сервером из шага 7, а статика хороша для страниц, которые меняются редко. Верните в проекте `"outputMode": "server"` и режимы шага 7 — дальше мы будем исходить из них.

## Итоги главы

Магазин переехал из превью в настоящий проект и прошёл весь путь до выпуска:

- **Angular CLI**: `ng new` создаёт проект по тем же соглашениям, что курс; `angular.json` описывает цели (`build`, `serve`, `test`, `lint`) и их сборщики; строгость TypeScript и шаблонов включена по умолчанию.
- **Перенос**: код — в `src/app`, обложки — в `public/`, учебный бэкенд — отдельный сервер на Node.js; `ng serve` пересылает ему `/api` через прокси.
- **Сборка**: `ng build` показывает начальные и ленивые части; бюджет поймал разросшийся `main`, а ленивые страницы с формами вернули его в норму.
- **Строгие шаблоны**: ошибки, которые превью показывало пустым местом или «не числом», — ошибки сборки с точным местом; расширенная диагностика — о подозрительном коде.
- **Генераторы и линтер**: `ng generate`, `ng add`, `ng update`; `ng lint` нашёл заглушённые ошибки, мёртвый импорт и вопросы доступности.
- **Тесты**: 46 тестов главы 16 прошли без правок — в jsdom и в браузере, с отчётом о покрытии.
- **SSR**: код приложения выполняется и на сервере — API браузера только через DI (`BROWSER_STORAGE`) или в `afterNextRender`; режимы `Prerender`, `Server`, `Client` для каждого маршрута; `allowedHosts` против SSRF.
- **Гидратация**: браузер принимает серверный DOM, ответы API переезжают в странице, события до гидратации повторяются, а блоки `@defer` с `hydrate` оживают по требованию.
- **Деплой**: `isDevMode` и окружения, сервер Node.js или статический хостинг.

В превью вы учили Angular; здесь — увидели, как с ним работают каждый день. В следующей главе — обратная задача: прочитать код большого приложения на Angular, написанного не нами, и понять, почему оно устроено так.
