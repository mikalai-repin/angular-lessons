Покупатель выбирает между тремя похожими играми и открывает их страницы по очереди, чтобы вспомнить, у какой ниже цена и сколько игроков. Удобнее поставить их рядом в таблице. А когда список выбран, его хочется отправить другу или родным: «вот что я хочу на день рождения». Своё избранное у «Хода конём» уже есть, но живёт оно в `localStorage` одного браузера.

В этом варианте вы сделаете две вещи: **сравнение** до трёх игр и **ссылку на избранное**, которую можно открыть на чужом компьютере без входа.

## Задание

::: task
**Сравнение**

1. На каждой карточке игры есть кнопка с классом `compare`: щелчок добавляет игру к сравнению, повторный — убирает. Кнопка игры, которая уже в сравнении, — с `aria-pressed="true"`.
2. Сравнивать можно **не больше трёх** игр. Когда три уже выбраны, кнопки `compare` остальных карточек выключены (`disabled`). Граница держится и в коде: даже если включить кнопку в обход `disabled`, четвёртая игра не добавится.
3. В меню шапки есть ссылка на `/compare`, в её тексте — сколько игр в сравнении (например, «Сравнение: 2»).
4. Страница `/compare` — таблица `<table>`: по столбцу на игру, в первой строке — названия игр, дальше строки с подписями «Цена», «Игроки», «Время», «Возраст», «Рейтинг» (подпись — в первой ячейке строки, рейтинг — числом). У ячейки с самой низкой ценой и у ячейки с самым высоким рейтингом — класс `best`.
5. У каждой игры в таблице есть кнопка «Убрать». Без игр страница вместо таблицы пишет «Нечего сравнивать».

**Список желаний**

6. На странице избранного `/account/favorites` (когда оно не пустое) есть ссылка «Поделиться списком». Её адрес — `/wishlist?ids=…` с id игр из избранного через запятую: `/wishlist?ids=12,3,7`.
7. Страница `/wishlist` показывает карточки игр из параметра `ids` в том же порядке. Она открывается **без входа** и не меняет избранное того, кто её открыл.
8. Мусор в адресе (`abc`, `0`, `-1`) и игры, которых нет в каталоге (сервер отвечает 404), пропускаются. Нет ни одного верного id — страница пишет «Список пуст».
9. Новый адрес с другим `ids` (ссылку открыли, когда страница уже открыта) показывает новый список без перезагрузки.
:::

Всё остальное — на ваше усмотрение: как выглядит кнопка, где стоит ссылка, что ещё есть в таблице. В старте уже лежат заготовки: `core/compare-store.ts`, `compare/compare-page.*` и `wishlist/wishlist-page.*`. Маршрутов для них нет — их добавите вы.

## С чего начать

Прежде чем писать код, ответьте себе на вопросы из [шага 22.1](step:22-final-project/01-choose-project).

- **Где живёт сравнение?** Его меняет карточка, читает шапка и страница `/compare` — значит, в общем месте. Сколько ему жить: до перезагрузки или дольше? Задание этого не требует, решите сами.
- **Где живёт чужой список?** Не в Store и не в `localStorage`: тогда ссылка открывала бы список того, кто её открыл. Весь список — в адресе.
- **Что хранить в сравнении** — id или игры целиком? Карточка знает игру целиком, а таблице нужны цена, игроки и рейтинг.

Начните со сравнения: кнопка на карточке, которая пишет в консоль, потом счётчик в шапке, потом страница.

::: hint Подсказка 1: какие главы вспомнить
Общее состояние на сигналах в сервисе — [глава 9](step:09-app-state/01-store). Параметры адреса во входах компонента — `withComponentInputBinding` и [query-параметры](step:10-routing/04-query-params) из главы 10: он уже включён в `app.config.ts`, так же устроены фильтры каталога в `catalog.ts`. Загрузка игр по списку id — `FavoritesPage` (`account/favorites-page/favorites-page.ts`), её написали в [шаге 12.5](step:12-rxjs/05-rx-resource). Ленивые маршруты — `loadComponent` в `app.routes.ts`.
:::

::: hint Подсказка 2: сервис сравнения
Приватный сигнал со списком игр, наружу — только чтение (`asReadonly()`) и методы. Счётчик и «заполнено ли» — `computed`. Проверка границы — в методе добавления, а `disabled` у кнопки — только удобство: кнопку можно включить из инструментов разработчика.

```ts
toggle(game: Game) {
  if (this.has(game)) {
    this.remove(game);
  } else if (!this.isFull()) {
    this.list.update((games) => [...games, game]);
  }
}
```

Число 3 — не магическое: вынесите его в константу с понятным именем.
:::

::: hint Подсказка 3: таблица и лучшие значения
Таблица строится по строкам, поэтому `@for` по играм — внутри каждой строки `<tr>`. Лучшие значения — один `computed` на странице: минимум цен и максимум рейтингов. Ячейка сравнивает своё значение с ним:

```html
<td [class.best]="game.price === best()?.price">
  {{ game.price | price }}
</td>
```

Пайпы для игроков, времени и цены уже есть в `shared/`: `players`, `duration`, `price`. Рейтинг числом с запятой — встроенный `number`.
:::

::: hint Подсказка 4: ссылка и параметр ids
Ссылку с параметром строит `routerLink` с `queryParams`: `[queryParams]="{ ids: ids().join(',') }"`. Запятую роутер в адресе не кодирует.

На странице списка параметр приходит во вход. Строку из адреса превращает в массив чисел `transform`, а пустой адрес — это `undefined`:

```ts
readonly ids = input<number[], string | undefined>([], {
  transform: toIds,
});
```

`toIds` разбивает строку по запятым, оставляет целые положительные числа и убирает повторы. Дальше — как в `FavoritesPage`: `rxResource` с `forkJoin` и `catchError` для 404, только `params` читают вход, а не Store.
:::

::: hint Подсказка 5: маршруты
Обе страницы — ленивые маршруты верхнего уровня. У `/wishlist` нет гарда: друг, который открыл ссылку, не входил в магазин.

```ts
{
  path: 'wishlist',
  loadComponent: () =>
    import('./wishlist/wishlist-page').then((m) => m.WishlistPage),
  title: 'Список желаний',
  data: { breadcrumb: 'Список желаний' },
},
```
:::

## Проверьте себя

Нажмите «✓ Проверить». Проверка стартует с избранным из трёх игр и без входа, отмечает три первые игры каталога, пробует добавить четвёртую, смотрит таблицу и убирает игры, затем открывает ссылку «Поделиться списком» и адреса с мусором в `ids`.

Когда проверка пройдёт, проверьте сами то, чего она не смотрит:

- карточки на главной и в избранном тоже с кнопкой «Сравнить» — ведь это одна и та же карточка;
- таблица из трёх игр помещается в превью шириной 500 пикселей;
- ссылка `/wishlist?ids=1,1,1` показывает одну игру, а не три одинаковые;
- откройте «Сеть» и задайте задержку 2 секунды: что видно на странице списка, пока игры загружаются? А при ошибке сервера?

## Идеи сверху

- Сравнение переживает перезагрузку: `effect` с `localStorage`, как корзина в [главе 9](step:09-app-state/02-persistence), или Signal Store с `withStorage` из [шага 18.4](step:18-ngrx/04-custom-feature).
- Кнопка «Скопировать ссылку» рядом с «Поделиться списком» (`navigator.clipboard.writeText`). Полный адрес даст `location.origin` и `Router.serializeUrl`.
- На странице списка — кнопка «Добавить всё в избранное». Подумайте, через какое действие Store это сделать.
- Ссылка со ста id отправит сто запросов. Ограничьте длину списка — сколько игр разумно хотеть сразу?

## Образец

«Решение» покажет образец. Сравнение в нём — сервис `CompareStore` с сигналом игр и границей в `toggle`, лимит — константа `COMPARE_LIMIT`. Таблица — `ComparePage` с одним `computed` лучших значений: одну игру сравнивать не с чем, и тогда он возвращает `null`. Список желаний — `WishlistPage` со входом `ids` и `rxResource`, как в `FavoritesPage`.

Загрузка игр по списку id нужна обеим страницам, поэтому образец выносит её из `FavoritesPage` в новый сервис `GamesByIds` (`core/games-by-ids.ts`) с методом `load(ids)`, и обе страницы вызывают его в `stream`. Если вы скопировали эти полтора десятка строк в `WishlistPage`, проверка пройдёт, но две копии разойдутся при первой же правке: например, когда в API появится запрос «игры по списку id». Если ваше решение устроено иначе и проходит проверку, оно не хуже образца: сравните, в чём разница и что из неё следует.
