# Процесс написания главы

## 0. Подготовка

```bash
npm install
npm run dev           # dev-сервер на http://localhost:5180 — нужен для всех проверок
node tools/e2e/checks/platform.mjs   # платформа в порядке? должно быть «Всё прошло»
```

Прочитайте:

- строки главы в `docs/course-plan.md` — план шагов (ориентир, а не закон);
- что глава добавляет в магазин — `docs/project-app.md`;
- **последний шаг предыдущей главы** целиком (`content/<глава>/<последний шаг>/solution/*`) — стартовая точка новой главы;
- раздел «Открытые вопросы» в `docs/modern-angular.md` и строки `docs/archive/verified-facts.md` по API главы (поиск по слову).

## 1. Сверка API до написания кода

Никаких утверждений об API по памяти. В интернете и в памяти модели много Angular 2–17. Перед главой выпишите все API, которые она вводит, и проверьте каждое:

```bash
T=node_modules/@angular/core/types        # типы: core.d.ts и чанки _*-chunk.d.ts
F=node_modules/@angular/core/fesm2022     # код — для поведения и значений по умолчанию
# экспорты собраны списками `export { … }`: искать «declare function X», а не «export declare function X»
python3 -c "…"                            # для поиска удобнее Python + re, чем grep в zsh
```

Что проверять:

- сигнатуры и названия параметров;
- **стабильность**: теги `@publicApi <версия>`, `@experimental`, `@developerPreview`, `@deprecated` в JSDoc;
- **значения по умолчанию** — в v22 многое поменялось (OnPush, зонлесс, standalone);
- **поведение** — читать реализацию в `fesm2022`, а не только комментарии;
- **поведение в JIT** — если API связан с компилятором (`@defer`, сигнальные входы, `host`, `templateUrl`), проверить запуском в превью, а не только по документации.

Новые проверенные факты записывайте в `docs/archive/verified-facts.md`.

## 2. Код шагов

**Шаг хранит только изменения** — правила цепочки (`startFrom`, `base`/`baseHash`, `removedIn…`) описаны в `lesson-format.md`. Код главы, пока она пишется, генерирует Python-скрипт `tools/authoring/chNN-gen.py` (образец — `ch22-gen.py`): общие куски — строковые константы, шаги — **полные снимки** кода. Полный код прошлой главы он читает через `step_dir(путь)` и правит помощниками `rep` (замена, которая обязана найти якорь) и `cut` из `tools/authoring/steps.py` — код прошлой главы не перенабирается. Запись — только через `write_steps(ROOT, steps, base='09-app-state/05-practice')`: он форматирует снимки, сам вычисляет, что изменилось, пишет только это, ставит `base`/`baseHash` первому шагу и подсказывает, какие `removedIn…` нужны во frontmatter. Целиком посмотреть шаг — `npm run step <…/шаг/solution>`.

Когда глава готова, источник правды — `content/`, правки готовых глав — прямо в нём. Генераторы глав 1–15 удалены (они есть в истории git: главы 1–9 — последний раз в коммите `6624d67`, главы 10–15 — до коммита следующей главы); `ch22-gen.py` оставлен образцом (генераторы глав 16–21 — в истории git до коммита следующей главы; у `ch22-gen.py` есть и шаги `custom` с общим стартом и `removedInStart`): снимки шагов строятся цепочкой правок `edit(снимок, файл, (старое, новое), …)` поверх предыдущего, новые файлы — `put(снимок, **{'путь': код})`, удалённые — `drop(снимок, 'путь')`, шаг без решения — `{'start': снимок}`, заготовки — строками с `// TODO`. `python3 tools/authoring/chNN-gen.py dump <папка>` пишет полные отформатированные снимки шагов (`<папка>/<шаг>/<start|solution>`) — их сразу можно гонять `run-dir.mjs`/`exp.mjs`, не записывая главу в `content/`.

Правила:

- первый шаг главы — `startFrom: custom`, его старт — очищенное решение последнего шага прошлой главы; `write_steps` пишет в `start/` только отличия, а в `lesson.md` — `base` и `baseHash`. Правка прошлой главы ломает хеш: `npm run validate` скажет, какую главу пересобрать (`python3 tools/authoring/format-content.py <глава>`). Что убрали или вынесли в файлы, объясняется в тексте первого шага;
- если старт отличается от прошлого решения хотя бы строкой `// TODO`, шаг тоже `custom` (и только тогда у него есть `start/` — с изменёнными файлами; если `write_steps` не записал `start/` у шага `custom` или записал у `previous`, валидатор скажет об этом);
- новый файл, появившийся в шаге, — тоже `custom`; в старте лежит заготовка с `// TODO`;
- интерфейс магазина должен помещаться в превью **500 × 600** без растягивания панелей;
- после генерации: `npm run validate` — полный код всех шагов собирается и проверяется по настоящим типам `@angular/*` (в `.content-check/`);
- правка файла в шаге N действует во всех следующих шагах главы, которые этот файл не меняют. Это удобно (исправил один раз), но изменение расходится молча: после правок старых шагов — `npm run validate`, `run-chapter` и `checks/*` главы.

## 3. Проверка запуском до текста

```bash
node tools/e2e/run-dir.mjs content/03-signals/02-signal/solution          # консоль, запросы, адрес, текст, скриншот
node tools/e2e/run-dir.mjs content/10-routing/03-params/solution /games/8  # с начального адреса
```

Обязательно:

- консоль без ошибок и без предупреждений Angular (`NG0xxx`) — кроме тех, что шаг показывает намеренно;
- текст страницы — тот, что обещает урок;
- скриншот — откройте и посмотрите глазами (вёрстка в 500 px, переполнение, пустые места).

Для экспериментов из текста создайте временную папку (scratchpad) с копией шага и правкой и запустите её тем же `run-dir.mjs`; сценарий действий (клики, ввод, переходы) — через `tools/e2e/exp.mjs`:

```js
// сценарий.mjs
export default async ({ page, pageText, navigate, wait }) => {
  await page.type('.search', 'шах');
  await wait(500);
  console.log(await pageText());
  await navigate('/cart');
};
```

В `tools/e2e/lib.mjs` есть всё для своих проверок:

- чистое превью: `compileDir`, `openPreview(browser, compiled, { url, backend, waitMs })`, `collect` (ошибки среды и запросы бэкенда), `pageText`, `appUrl`, `navigate`; образец — `checks/preview.mjs`;
- интерфейс платформы: `openCourse('/chapter/step', { onDialog, ignoreConsole })` открывает платформу с чистым прогрессом и возвращает помощники проверки главы — `expect`, `frame()` (iframe превью, после перезапуска — последний), `consoleText`, `title`, `count`, `showSolution`, `nextStep`, `checkConsoleClean`, `runWithCode` (код эксперимента подкладывается в сохранённый прогресс шага), `finish`; `clean()` — текст без неразрывных пробелов; образцы — `checks/platform.mjs` и `checks/chNN-*.mjs`.

## 4. Текст уроков

По `docs/writing-guide.md`. Структура шага: зачем → объяснение → код с подсветкой строк → `::: task` → «Что получилось» → эксперименты → «Как в настоящем проекте» → `::: deep` / `::: legacy`. Практикум: `::: task` со списком, `::: hint` от общего к конкретному, «Проверьте себя», «Итоги главы» с мостиком к следующей главе.

## 5. Проверка каждого утверждения в тексте

Самый важный этап. Каждое фактическое утверждение и **каждый предложенный эксперимент** («уберите X — увидите Y») проверяется кодом или исходниками. Особенно:

- тексты и коды ошибок (`NG0xxx`) — только увиденные в консоли;
- «Angular обновит / не обновит экран» — проверить запуском (OnPush по умолчанию меняет многие привычные ответы);
- «этот запрос отменится / не отменится» — по вкладке «Сеть» или логу учебного бэкенда;
- порядок хуков и эффектов — логом в консоли.

Найденные ошибки черновиков записывайте строкой в `docs/archive/draft-errors.md` — это память проекта (там больше 130 случаев). Выводы из них:

- **Числа в тексте — только посчитанные** на коде того места урока, где они стоят (до задания и после него они разные). Номера `id`, строк, ячеек берите из данных или скриптом, а не на глаз.
- **Эксперимент проверяйте на коде того шага, о котором текст**, а не на решении последнего шага: позднее появившийся код может скрыть ошибку.
- **Реактивность — только запуском.** Обработчик в шаблоне помечает представление грязным; `linkedSignal` и `computed` ленивы и отсекают по равенству, поэтому видят прочитанные значения, а не историю переходов. Интуиция «сбросится», «обновится», «сработает на каждую букву» ошибалась много раз.
- **JIT и AOT расходятся.** «Ошибка будет видна» проверяйте и в превью, и в `ngc --strictTemplates`.
- **Где на самом деле окажется ошибка.** Её может поймать чужой `catch`, она может уйти дальше по цепочке вместо ответа или упасть раньше в другом месте. Цитируйте то, что напечатала консоль.
- **JSDoc бывает устаревшим**: значения по умолчанию сверяйте с кодом в `fesm2022`.
- **История версий** («появилось в Angular 14.2», «до 21 было на zone.js») и **слова о документации** («angular.dev советует…») пишите, только если нашли в исходниках или нашли цитату. Не проверить — не писать.
- **Ложные выводы из инструментов**: `page.click` Puppeteer по ссылке может не сработать, `navigate` в `exp.mjs` ждёт затишья (гонки не видны), консоль платформы сворачивает одинаковые строки. После щелчка печатайте адрес, гонки проверяйте щелчками из страницы.
- **Состояние от прошлых шагов**: `localStorage` и токены переживают переход между шагами. Опыт, который зависит от «чистого» состояния, должен сказать ученику, что сбросить.
- **Вёрстка — глазами**: в превью 500 px тексты карточек и кнопок переносятся; смотрите скриншот.
- **Квиз**: каждый вариант — на утверждении урока; неверный вариант, который урок прямо не опровергает, заменяйте (раздел 6а).

Вывод из курса PixiJS: **не доверяйте себе**. Если утверждение нельзя проверить, лучше его не писать.

## 6. Регистрация и прогон в платформе

```bash
# добавить папку главы в content/course.json → chapters
npm run validate                                  # структура, цепочка start/solution, YAML, типы
node tools/e2e/run-chapter.mjs 03-signals         # все шаги в интерфейсе: «Решение», консоль, ошибки
```

`run-chapter` должен закончиться строкой `Ошибки страницы: []`. Если в главе есть взаимодействие (формы, роутинг, корзина), напишите проверку в `tools/e2e/checks/chNN-*.mjs` на `openCourse` из `lib.mjs`: клики, ввод, переходы, состояние после «перезагрузки». Числа из этих проверок можно цитировать в тексте («мы проверили: …»).

Переходы между шагами кнопкой «Далее» (а не только `goto`) — обязательно: в курсе PixiJS именно так нашлась гонка синхронизации TS-воркера Monaco.

**Практикум получает `check.ts`** (формат — `lesson-format.md`). Проверка проверяет каждый пункт задания по результату на экране. Готова, когда:

- `node tools/e2e/checks/step-checks.mjs <глава>` — старт не проходит с понятной подсказкой, решение проходит;
- «мутации» — решение с типичными ошибками (убрать привязку, границу, сброс, `providers` в компоненте вместо общего сервиса) не проходит, и подсказка указывает на ошибку. Удобно сценарием в scratchpad: полный код решения (`readDir`), замены, код в сохранённый прогресс шага (как `runWithCode`), щелчок «Проверить», текст `.check-result`. Мутация, которую проверка не ловит, — либо дыра в проверке, либо ошибка, которая в этом приложении не видна (тогда не делайте вид, что она проверяется: так убрана проверка `setQuantity` в 9.5 — границы держит `Quantity`).

## 6а. Квиз главы

`content/<глава>/quiz.yaml` — после текста всех шагов (формат — `lesson-format.md`, правила — `writing-guide.md`, «Квиз главы»). Для каждого вопроса — строка «на каком утверждении какого `lesson.md` основан ответ»; утверждения, которых в тексте нет, в квиз не попадают. Цитата нужна и против неверных вариантов, которые не очевидно неверны: вариант «неверен по смыслу», но текстом не опровергнут, — замените заблуждением, которое урок опровергает прямо. Код в вопросе — как в уроке: упрощённый код, который не запускали, может вести себя иначе. После — сверка вторым взглядом (свежий агент или вычитка): факты, однозначность, длина вариантов (правильный самый длинный не чаще чем в трети вопросов — проверяется скриптом по `options[0].length`). Затем `npm run validate` и `node tools/e2e/checks/quiz.mjs` (интерфейс квиза на главах 1–2; после правок в `src/quiz/` — обязательно). `npm run validate` не запускайте в нескольких процессах одновременно: он пересоздаёт общую папку `.content-check/` и падает с `ENOTEMPTY`/`TS2307`.

## 7. Документация

Глава готова, когда все утверждения и эксперименты проверены запуском (и по исходникам, где речь о поведении), решения и заготовки проходят `ngc --strictTemplates` без ошибок и предупреждений (`node tools/e2e/aot-chapter.mjs <глава>`), `npm run validate`, `run-chapter` и `checks/chNN-*.mjs` главы чистые, а квиз главы написан и сверен с текстом (раздел 6а). Тогда:

- `docs/archive/steps.md` — фактическая таблица шагов главы; в `docs/course-plan.md` — одна строка о главе вместо плана;
- `docs/roadmap.md` — отметить главу; технический долг — в `docs/archive/roadmap-history.md`, в `roadmap.md` — только то, что нужно для следующего шага;
- `docs/project-app.md` — что магазин получил, структура файлов, если изменилась;
- `docs/archive/verified-facts.md` — новые проверенные факты; `docs/modern-angular.md` — только если факт меняет правило для всех глав;
- ловушки — в `docs/archive/traps.md` (в «Главные ловушки» ниже — только если она касается почти каждой главы);
- «Код магазина на конец последней главы» ниже — опись новой главы; опись самой старой из оставшихся — в `docs/archive/shop-code.md`.

# Главные ловушки

Самые частые; полный список (около 100) — `docs/archive/traps.md`, искать по слову. Подводные камни кода платформы — в `architecture.md`.

- **В `content/` у шага только изменения.** Полный код — `npm run step <…/шаг/solution> [папка]`, в Python — `step_dir()` из `tools/authoring/steps.py`. Копировать папку шага (`cp -r`, `shutil.copytree`) нельзя.
- **Копия шага для опыта — в папку `<имя>/solution`, каждая в своей родительской папке** (`runs/<имя>/step/solution`): иначе `readStepDir` молча соберёт пустое приложение или смешает соседние опыты.
- **Изменили шаг прошлой главы — сломали `baseHash` следующей**: `python3 tools/authoring/format-content.py <глава>`. Переписали frontmatter первого шага главы — верните `base:`/`baseHash:` из `git diff`.
- **`npm run validate` — один процесс и не во время `checks/*`**: он пересоздаёт `.content-check/`, Vite шлёт волну перезагрузок. Правки `content/` во время длинных проверок тоже роняют их.
- **Новая глава или новая зависимость платформы не видна на запущенном dev-сервере** (`504 Outdated Optimize Dep`, проверка не находит шагов): перезапустите `npm run dev` или поднимите второй сервер на 5181 (`BASE_URL=http://localhost:5181`).
- **Адресная строка превью перезапускает приложение и учебный бэкенд**, `navigate` в `exp.mjs` — нет.
- **`localStorage` превью общий с платформой**: корзина и токены переживают шаги и главы. `openCourse` начинает с `localStorage.clear()`; подделать данные — строкой `localStorage.setItem(…)` первой в `main.ts` копии.
- **Щелчки в Puppeteer**: в чистом превью по ссылкам — `page.$eval(sel, (el) => el.click())`; в iframe платформы — `elementHandle.click({ offset })`; `confirm()` — свой `onDialog` и щелчок через `setTimeout`.
- **Консоль платформы сворачивает одинаковые строки подряд** (`.console-count`); в `exp.mjs` — не сворачивает.
- **Ширина ASCII-схем в тексте урока — не больше 46 символов.** Код уроков — как кнопка «Формат» (`shared/lesson-prettier.json`, ширина 64).
- **Node**: по умолчанию 20.19; Angular CLI, `ng test`, Vitest 5 — Node 24.15 через nvm (скрипты `ng-test.mjs`, `ng-build.mjs` берут его сами). `ngc` работает и на Node 20. `@angular/compiler-cli` — только ESM, скрипты `.mjs`.
- **zsh**: `*.d.ts` и `$x[?]` без кавычек — glob («no matches found»); `echo ====` — «not found»; `echo '…\n…'` разворачивает `\n`; `grep -E` с кириллицей ненадёжен. Для поиска — Python; длинную правку с кириллицей — файлом-скриптом в scratchpad (`# -*- coding: utf-8 -*-`).
- **Временные файлы** — в scratchpad сессии или `tools/e2e/out/` (в `.gitignore`), не в `/tmp`.
- **YAML во frontmatter и квизе**: `@`, `{`, `[`, `: ` — в кавычках.
- **Циклические импорты между файлами превью не поддерживает**: родитель-потомок через DI — токен в файле потомка + `useExisting`.
