# Сквозной проект: «Ход конём»

Интернет-магазин настольных игр. Ученик строит его с нуля, от одной карточки товара в главе 1 до приложения с каталогом, корзиной, оформлением заказа, входом и админкой.

В курсе PixiJS сквозным проектом была готовая открытая игра, которую ученик в конце сравнивал с оригиналом. Здесь готового эталона под MIT с современным Angular нет, поэтому проект — свой. Роль «настоящего кода» для разбора в части 3 играет исходный код angular.dev (см. в конце документа).

## Почему магазин

Магазин естественно требует почти всего Angular, и каждая возможность появляется из настоящей потребности, а не «для галочки»:

| Потребность магазина | Что изучаем |
|---|---|
| Карточка товара, список карточек | компоненты, шаблоны, `input()`, `@for` |
| Счётчик в корзине, сумма, скидки | сигналы, `computed`, `linkedSignal` |
| Кнопка «В корзину» в карточке, а корзина в шапке | `output()`, сервисы, DI |
| Каталог → товар → корзина → заказ | роутинг, параметры, ленивые маршруты |
| Каталог с сервера, поиск, фильтры, страницы | HTTP, `httpResource`, RxJS, `debounced` |
| Оформление заказа, вход, отзыв | формы, валидация, асинхронная валидация |
| Личный кабинет и админка только для своих | гарды, интерцепторы (токен) |
| Тяжёлый блок отзывов и рекомендаций | `@defer` |
| Анимация добавления в корзину | `animate.enter`/`animate.leave` |
| «Не сломать при правке» | тесты на `TestBed` |

Тема настольных игр выбрана, потому что она нейтральная, понятная и визуальная (обложки, количество игроков, время партии, возраст), а у товара много полей для фильтров и форм.

## Экраны

| Экран | Путь | Что на нём |
|---|---|---|
| Главная | `/` | Подборки («Новинки», «Для двоих»), баннер |
| Каталог | `/catalog?q=&category=&players=&page=` | Поиск, фильтры, сортировка, страницы; состояние фильтров в URL |
| Игра | `/games/:id` | Обложка, описание, характеристики, «В корзину», отзывы (`@defer`), «Похожие» |
| Корзина | `/cart` | Позиции, количество, удаление, промокод, итог |
| Оформление | `/checkout` | Форма: контакты, доставка (условные поля), оплата; гард «корзина не пуста»; защита от ухода с несохранённой формой |
| Вход | `/login` | Форма входа, возврат на исходную страницу |
| Кабинет | `/account/orders` | Мои заказы (только после входа) |
| Админка | `/admin/games`, `/admin/games/:id/edit` | Таблица товаров, редактирование (ленивый раздел, роль admin) |
| 404 | `**` | Страница «Нет такой страницы» |

## Файлы приложения (целевая структура к концу части 2)

Структура повторяет то, что создаёт Angular CLI, но без папки `src/`. Имена файлов — по стилю Angular 22 (`cart.ts`, а не `cart.component.ts`; проверено по `@schematics/angular@22.2.1`).

```

app.config.ts                provideRouter, provideHttpClient, …
app.routes.ts                маршруты
core/
  cart.ts                    CartStore: позиции, сумма, количество (сигналы), сохранение в localStorage
  auth.ts                    AuthStore, текущий пользователь, токен
  auth.guard.ts              гард входа и роли
  auth.interceptor.ts        добавляет токен к запросам
  games-api.ts               запросы к /api/games
  models.ts                  типы Game, CartItem, Order, User
shared/
  game-card/                 карточка игры (ts + html + css)

```

## Данные и учебный бэкенд

Бэкенд работает внутри превью (см. `architecture.md`, «Учебный бэкенд»): обработчики — `public/backend/backend.js`, данные — `public/backend/data/*.json`. Сейчас 12 игр; до главы 11 (страницы, фильтры) расширить до ~40 и пересоздать обложки `npm run covers`. У каждой игры есть поле `color` — цвет обложки для скрипта.

```ts
interface Game {
  id: number;
  slug: string;
  title: string;          // «Каркассон»
  cover: string;          // /assets/covers/carcassonne.svg
  price: number;          // в рублях, целое
  oldPrice?: number;
  category: 'family' | 'strategy' | 'party' | 'cooperative' | 'kids';
  players: { min: number; max: number };
  playTime: number;       // минуты
  age: number;            // 8+
  rating: number;         // 0..5
  inStock: number;        // остаток на складе
  description: string;
  tags: string[];
}
```

**Названия игр** — только вымышленные или общественное достояние (шахматы, го, нарды, домино), чтобы не использовать чужие товарные знаки: «Остров сокровищ», «Драконья почта», «Зельевары» и т. п. Список — при подготовке данных.

**Обложки** — свои простые SVG (цвет игры, узор, силуэт коня, название), генерирует `scripts/build-covers.mjs` → `public/assets/covers/<slug>.svg`. Лицензионных вопросов нет.

### Маршруты API

| Метод и путь | Что делает | Глава |
|---|---|---|
| `GET /api/games?q=&category=&players=&inStock=&sort=&page=&size=` | Страница каталога: `{ items, total, page, size }`; `sort`: `price`, `-price`, `rating`, `title`; `size` по умолчанию 12; `q` ищет по названию и тегам | 11 |
| `GET /api/games/:id` | Игра (по `id` или `slug`) или 404 | 11 |
| `GET /api/categories` | Категории | 11 |
| `GET /api/games/:id/reviews` | Отзывы | 11, 15 |
| `POST /api/games/:id/reviews` | Новый отзыв (нужен токен) | 13, 14 |
| `POST /api/login` | `{ email, password }` → `{ token, user }` или 401 | 13, 14 |
| `GET /api/me` | Текущий пользователь по токену или 401 | 14 |
| `POST /api/refresh`, `POST /api/logout` | **План (до главы 14):** обновление короткоживущего access-токена по refresh-токену, отзыв токена; срок жизни токена задаёт урок (`backend: { tokenTtl }`), чтобы показать 401 и обновление | 14 |
| `GET /api/promo/:code` | Проверка промокода (для асинхронной валидации) | 13 |
| `POST /api/orders`, `GET /api/orders` | Заказы | 13 |
| `PUT /api/games/:id`, `POST /api/games`, `DELETE /api/games/:id` | Админка (роль admin) | 17 |
| `GET /api/email-available?email=` | Асинхронная проверка e-mail | 13 |

Учётные записи: `user@example.com / user` и `admin@example.com / admin`, токены `token-user` и `token-admin` (заголовок `Authorization: Bearer …`). Промокоды: `KNIGHT10` (−10 %), `CHESS500` (−500 ₽ от 3000 ₽). `POST /api/orders` уменьшает остаток на складе и отвечает 409, если игр не хватает. Это учебный бэкенд, и в тексте урока об этом сказано.

## Что приложение получает по главам

| Глава | Что добавляется в магазин |
|---|---|
| 1 | Корневой компонент с названием магазина |
| 2 | Карточка одной игры из данных (`core/models.ts`, `core/games-data.ts`): обложка, рейтинг, цена и скидка, «нет в наличии», поиск по Enter (привязки) |
| 3 | Переключатель игр, выбор количества (`linkedSignal`), корзина из позиций (`CartItem`) в сигнале: количество и сумма в шапке, мини-корзина с итогом и бесплатной доставкой, лог корзины (`effect`) |
| 4 | Каталог-сетка плиток (`@for`), наличие (`@if`/`@else if`), бейдж категории (`@switch`), корзина строками с «−/+/×» (`$index`, `$even`), живой поиск с `@empty`, фильтр «Только в наличии» и сортировка. Большая карточка, переключатель и выбор количества убраны (вернутся на странице игры) |
| 5 | Компоненты `GameCard` (`input()`/`output()`, стикеры «Хит»/«Скидка» через `ng-content`, хост-элемент), `Rating` (звёзды, `model()`, фильтр «Рейтинг от» с половинками, `readonly`), `Quantity` (`− N +` в строках корзины) — в `shared/` |
| 6 | Фокус на поиске, ленивый расчёт размеров, `DestroyRef` |
| 7 | Пайпы цены и «2–4 игрока», директива подсказки |
| 8 | `CartStore` в DI, шапка и карточки работают с одной корзиной |
| 9 | Корзина: количество, промокод, сохранение в `localStorage` (`effect`) |
| 10 | Маршруты: главная, каталог, игра, корзина, 404; ленивая загрузка |
| 11 | Каталог и игра с сервера; загрузка, ошибки, поиск, фильтры в URL |
| 12 | RxJS-поиск с отменой запросов; интерцептор; `toSignal` |
| 13 | Оформление заказа, вход, отзыв — Signal Forms с валидацией |
| 14 | Авторизация: `AuthStore`, вход и выход, сессия после перезагрузки, токен в интерцепторе, реакция на 401, гард входа с `returnUrl`, роли в шапке, «Мои заказы» |
| 15 | Анимация корзины, `@defer` для отзывов, оптимизация картинок |
| 16 | Тесты на корзину, карточку, каталог |
| 17 | Админка: ленивый раздел, гард роли, таблица, форма редактирования |
| 18 | NgRx: корзина и фильтры каталога на Signal Store, та же корзина на классическом Store |
| 20 | Перенос в проект Angular CLI, AOT-сборка, SSR, деплой |

## Разбор «настоящего» кода (часть 3)

Кандидат — **angular.dev** (папка `adev/` в репозитории [angular/angular](https://github.com/angular/angular), лицензия MIT): большое приложение на последней версии Angular от авторов фреймворка, со встроенным редактором и туториалами — то есть родственник нашей платформы.

Проверить на этапе подготовки части 3:

- [ ] лицензия и коммит, который берём (`reference/` как в курсе PixiJS: копия только для чтения, не в git, скрипт `npm run reference`);
- [ ] какие части интересны и читаемы (роутинг, `@defer`, SSR/пререндеринг, встроенный редактор на WebContainers);
- [ ] запасной кандидат — небольшой открытый проект на Angular 21+ (например, официальные примеры документации).
