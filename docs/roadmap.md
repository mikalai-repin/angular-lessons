## Следующий шаг

**Глава 22 «Финальный проект»** (часть 3) по `docs/course-plan.md` и `docs/authoring-process.md`. Глава пишется **итерациями, по одной на сессию** (между ними `/clear`, чтобы не раздувать контекст и расход лимита). В начале каждой сессии: прочитать `docs/authoring-process.md` целиком, `docs/writing-guide.md`, `docs/modern-angular.md` и этот раздел; в конце — отметить итерацию здесь.

Решения по формату (02.11.2026):

- три варианта, каждый — отдельный шаг: **А** — сравнение игр и список желаний с публичной ссылкой; **Б** — конструктор подарочного набора (многошаговая форма); **В** — своё приложение на 80 % пройденного API (чек-лист без проверки);
- у шага есть задание и подсказки от общего к конкретному, но нет пошагового решения; кнопка «Решение» показывает **образец**, а не эталон, и текст говорит об этом прямо;
- у А и Б есть `check.ts`: каждый пункт задания проверяется по результату на экране, плюс мутации (`authoring-process.md`, раздел 6);
- у главы есть короткий квиз (6–8 вопросов) по решениям, принятым в проектах;
- в учебном бэкенде нет хранения списков желаний: публичная ссылка в А делается на клиенте, id лежат в адресе (`/wishlist?ids=…`). Б отправляет набор в существующий `/api/orders`. Если понадобится новый адрес бэкенда, сначала решить, не обойтись ли без него (правка `public/backend/` и `cli-project/server/api.mjs` — обе сразу).

Итерации:

   - **вариант В делается в проекте Angular CLI** («Скачать» поверх проекта 20.2 или `ng new`, `ng generate`), без `check.ts`, как практикум 20.10: в шаге — требования-минимум, идеи, чек-лист самопроверки;
