# Как писать уроки

## Читатель

Разработчик, который уверенно пишет на JS/TS и знает веб (HTML, CSS, DOM), но **ни разу не работал с Angular**. Возможно, знает React или Vue — тогда сравнение помогает, но опираться на него нельзя. Поэтому:

- синтаксис JS/TS, `async/await`, классы, модули, DOM и CSS **не объясняем**;
- всё про Angular — компоненты, шаблоны, сигналы, обнаружение изменений, DI, роутер, формы, компилятор — **объясняем с нуля**: каждый новый термин определяем при первом появлении;
- декораторы TypeScript объясняем коротко при первой встрече (глава 1): ученик мог их не видеть;
- сравнения с React/Vue — только во врезках `::: tip` и только когда они действительно помогают («`computed` похож на `useMemo`, но зависимости находит сам»);
- не пишем «просто», «очевидно», «как известно».

## Тон

- Обращаемся на **«вы»**, дружелюбно и без канцелярита.
- Короткие предложения. Один абзац — одна мысль.
- Объясняем **зачем**, а не только **как**: сначала проблема, потом решение. Лучше всего — проблема, которую ученик видит в превью прямо сейчас («Мы поменяли поле `count`, а на экране по-прежнему 0. Почему?»).
- Не переводим имена API: `signal`, `inject`, `HttpClient`. Термины — по словарю (`glossary.md`): «сигнал», «внедрение зависимостей», «привязка свойства».
- Используем «ё», кавычки «ёлочки» и тире «—».
- Название проекта — «Ход конём», в кавычках-ёлочках.

## Структура шага

Типичный шаг — 300–900 слов и **одна** новая идея.

1. **Зачем.** 1–2 абзаца: какую проблему решаем, что увидим в итоге.
2. **Объяснение.** Суть понятия, при необходимости аналогия или схема. Для понятий с деревьями и потоками (дерево компонентов, инжекторы, граф сигналов, жизненный цикл, навигация роутера) нужна схема — ASCII или SVG.
3. **Код.** Минимальный фрагмент с подсвеченными новыми строками. Каждая неочевидная строка разобрана в тексте. Если меняются `.ts` и `.html` — два блока с именами файлов.
4. `::: task` — что именно сделать в редакторе.
5. **Что получилось.** Что видно в превью, что в консоли или во вкладке «Сеть». Если не так — типичная причина и типичная ошибка Angular (с кодом `NG0xxx`).
6. **Эксперимент** (по возможности): «Уберите `track` и посмотрите, что напишет компилятор», «Поставьте задержку 3 секунды во вкладке „Сеть“». Эксперименты — главный способ закрепить понимание.
7. **Как в настоящем проекте** (когда есть отличие от превью): «В проекте Angular CLI эта ошибка появилась бы при сборке, а не в браузере».
8. `::: deep` — «Под капотом»; `::: legacy` — «Вы встретите в старом коде».

Шаг 1 каждой главы — вводный: что будем делать и что получится в конце (скриншот).

## Правила для кода

- **Только современный Angular 22.** Список запрещённого и замены — `docs/modern-angular.md`. Устаревшее показываем только в `::: legacy` и только после современного варианта.
- Компоненты standalone, без `standalone: true` и без `changeDetection: OnPush` (это значения по умолчанию).
- Поля, которые использует только шаблон, — `protected`; то, что не меняется, — `readonly`: `protected readonly count = signal(0)`. Так делает стиль Angular (проверить актуальный style guide на angular.dev при написании главы 2).
- Зависимости — `inject()` в поле, не в конструкторе.
- Шаблоны — в отдельном `.html`, стили — в `.css`, начиная с шага 1.4. Встроенный `template` — только в коротких демо и в тестах.
- Импорты именованные: `import { Component, signal } from '@angular/core'`.
- TypeScript в строгом режиме, без лишних типов: аннотируем то, что помогает пониманию (параметры, публичное API сервисов, модели данных в `models.ts`).
- Комментарии в коде — на русском, короткие, объясняют «зачем».
- Тексты интерфейса — на русском; цены — пайпом с локалью `ru`, а до главы 7 — просто числом с «₽».
- Магические числа и строки выносим в константы или токены.
- Код шага растёт постепенно: ученик не должен получать 50 новых строк за раз.

## Размер превью

Превью — около трети окна: примерно **500 × 600** на ноутбуке, меньше на телефоне. Магазин должен нормально выглядеть в 480 пикселей по ширине без растягивания панелей: вёрстка «от мобильной», сетка карточек `auto-fill`. CSS магазина общий и появляется в шаге 1.4 готовым файлом `styles.css` (глобальные стили), чтобы ученик не тратил время на вёрстку: курс про Angular, а не про CSS.

## Проверка фактов

- Любое утверждение об API проверяем по типам и исходникам установленной версии `@angular/*` (`node_modules/@angular/*/types/*.d.ts`, `fesm2022/*.mjs`), а при сомнениях — экспериментом в превью.
- Особенно осторожно — со значениями по умолчанию (в v22 они другие, чем в статьях: OnPush, зонлесс, standalone) и со стабильностью API (`@experimental`, `@developerPreview` — говорим ученику прямо).
- Утверждения о производительности подкрепляем объяснением механизма, а лучше — замером в шаге.
- Не выдумываем названия методов, опций и кодов ошибок. Код `NG0xxx` в тексте — только увиденный в консоли.
- **Отличия JIT (превью) от AOT (настоящий проект)** называем явно, когда они видны ученику: ошибки шаблонов во время выполнения, `@defer`, размер приложения.

## Пример фрагмента шага

> ## Сигнал
>
> Мы нажимаем «В корзину», в консоли видно, что `count` растёт, а на экране по-прежнему «В корзине: 0». Angular просто не знает, что поле изменилось: он не следит за обычными полями класса.
>
> **Сигнал** (`signal`) — это значение в обёртке, которая сообщает Angular о каждом изменении. Шаблон, который прочитал сигнал, Angular обновит сам.
>
> ```ts app.ts {1,4}
> protected readonly count = signal(0);
>
> protected addToCart() {
>   this.count.update((n) => n + 1);
> }
> ```
>
> ```html app.html {1}
> <p>В корзине: {{ count() }}</p>
> ```
>
> Обратите внимание на скобки: `count()` — это вызов. Сигнал — функция, которая возвращает текущее значение и заодно сообщает Angular: «этот шаблон зависит от меня».
>
> ::: task
> Сделайте поле `count` сигналом, а в `addToCart` увеличивайте его через `update`.
> :::
